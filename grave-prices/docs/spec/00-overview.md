# מחירוני קברים — מבט-על

המסמך המחייב: `docs/owner-brief.md`. המבחן שלו: **לשנות מחיר ולהדפיס מחירון — בנפרד לתושבי הארץ ולחו"ל, או
שניהם בדף אחד — בכמה לחיצות, בלי לגעת בשנים הקודמות.** כל מה שלא משרת את המבחן הזה — לא נבנה.

"קטנטונת": מסך אחד של רשימת מחירונים, מסך אחד של מחירון (צפייה / עריכה / הדפסה), ומסך מפתח. שתי פרוסות, ושלישית קצרה כשהגיע מחירון חו"ל.

> ⚠️ **עודכן בפרוסה 03** (`03-per-audience.md`): מחירון חו"ל הגיע במבנה אחר לגמרי, וההנחה של שאלה 6 נפלה.
> **מחירון שייך לקבוצה אחת, ולכל שורה מחיר אחד.** מה שכתוב כאן על "שורות משותפות" ו"מחיר לכל קבוצה" — מוחלף שם.

## 1. המונחים

| מונח | מה זה | בקוד |
| --- | --- | --- |
| **מחירון** | גרסה אחת עם "בתוקף החל מ-<תאריך>". 02/01/2024 ו-15/03/2025 הם שני מחירונים | `edition` |
| **קבוצה** | למי המחיר: **תושבי ישראל** / **תושבי חו"ל**. שתיים, קבועות | `audience` (`il`, `abroad`) |
| **שורה** | שורה במחירון: כותרת, כותרת משנה או שורת מחיר. שייכת למחירון | `row` |
| **מחיר** | סכום בשקלים שלמים לשורה אחת ולקבוצה אחת. ריק = אין מחיר לקבוצה הזו | `price` |

**שורות משותפות, מחיר לכל קבוצה.** לכל מחירון רשימת שורות אחת, ולכל שורת מחיר שני מחירים — לישראל ולחו"ל. כך
"דף משותף" הוא אותן שורות עם שתי עמודות, ו"דף נפרד" הוא אותן שורות עם עמודה אחת.

**הנחה (שאלה 6):** מחירון חו"ל טרם הגיע. מניחים שמבנהו זהה לישראל עם מחירים אחרים. שורה בלי מחיר לקבוצה — לא
מודפסת בדף הנפרד שלה, ובדף המשותף מופיע בעמודה שלה "—". כשהמחירון יגיע — הבקרה תעביר, והאפיון יעודכן אם צריך.

**ניהול לפי "בתוקף החל מ-"** — לא לפי שם הקובץ (שאלה 9).

## 2. מודל הנתונים

SQLite אחד: `grave-prices/data/app.sqlite`. מוסכמות: `id` פנימי; `pid` — 12 תווים אקראיים (אותיות קטנות וספרות),
הוא בלבד מופיע בכתובות וב-API; זמנים ב-UTC ISO-8601.

```
users       id, sub UNIQUE, name, email, is_dev, created_at, last_seen_at
editions    id, pid, effective_from DATE UNIQUE, signatures JSON, created_by, created_at, updated_at
rows        id, edition_id, sort, kind, indent, label
prices      row_id, audience, amount INTEGER NULL           PK(row_id, audience)
audit       id, at, user_id, action, edition_id NULL, details JSON
```

- **`kind`** — אחד מ: `section` (כותרת חלקות, ממורכזת, מודגשת עם קו), `subsection` (קבורת שדה/מכפלה), `heading`
  (כותרת משנה בלי מחיר, מודגשת), `item` (שורת מחיר), `fee` (תשלום נלווה "**", אותיות קטנות, עם מחיר), `note`
  (הערה "**", אותיות קטנות, בלי מחיר). רק ל-`item` ו-`fee` יש `prices`.
- **`indent`** — 0 או 1 (שורות מוזחות תחת כותרת משנה, כמו "הנפטר בחינם…").
- **`label`** — טקסט עם סימון מצומצם: `**מודגש**`, `__קו תחתון__`, `((קטן ורגיל))`. כל השאר — טקסט רגיל, מוצג
  מוברח (escape). אין HTML בתווית.
- **`signatures`** — `[{"name","role"}]`, שלוש במחירונים הקיימים, לפי הסדר מימין לשמאל (שאלה 12).
- **הקבוצות** קבועות בקוד: `il` — "תושבי ישראל", `abroad` — "תושבי חו"ל"; מטבע ₪ לשתיהן (שאלה 7).
- **סכום** — שקלים שלמים, 0 ומעלה. מוצג `16,947` עם `₪` בעמודה משלו, כמו במקור.

### נתוני ההתחלה

`docs/spec/seed/editions.json` — שני מחירוני ישראל, מועתקים מה-PDF מילה במילה ומחיר במחיר (נבדק: סכום כל
המחירים 574,099 ב-2024 ו-584,979 ב-2025). מחירי חו"ל — `null`. נטען פעם אחת, במיגרציה, רק כשאין מחירונים במסד.
הקוד מעתיק את הקובץ לתוך האפליקציה (`docs/` אינו קוד ריצה).

נייר המכתבים — `docs/spec/seed/letterhead-top.jpg` (לוגו "ארגון קהילות יהודי צפון אפריקה בירושלים") ו-
`letterhead-bottom.jpg` (פרטי קשר), שחולצו מה-PDF של 2025 ברזולוציה המקורית (300dpi). נכסים קבועים של האפליקציה.

## 3. ההדפסה — הלב של האפליקציה

עמוד A4 לאורך, כמו המקור (`team/source/israel-2025-03-15.pdf` הוא הדוגמה):

1. נייר מכתבים עליון — ברוחב הדף.
2. "מחירון חברה קדישא לעדת המערבים" (מודגש, גדול) · "רכישת אחוזת קבר ל<קבוצה>" · "המחירון בתוקף החל מ- DD/MM/YYYY".
3. השורות לפי `kind` ו-`indent`; המחיר בצד שמאל, `₪` משמאלו, כמו במקור.
4. שלוש חתימות בשורה: שם מעל תפקיד.
5. נייר מכתבים תחתון — בתחתית הדף.

**ארבע אפשרויות בכפתור "הדפסה"** — שתי התצורות של הבעלים, ושתי קבוצות בודדות (שאלה 13 — כותרת הדף המשותף):

| תצורה | מה מודפס |
| --- | --- |
| **תושבי ישראל** | עמוד אחד, עמודת מחיר אחת, "לתושבי ישראל" |
| **תושבי חו"ל** | עמוד אחד, עמודת מחיר אחת, "לתושבי חו"ל" |
| **דף נפרד לכל קבוצה** | שני עמודים בהדפסה אחת: ישראל, מעבר עמוד, חו"ל |
| **שתיהן בדף אחד** | עמוד אחד, "לתושבי ישראל ולתושבי חו"ל", שתי עמודות מחיר עם כותרת: "תושבי ישראל" · "תושבי חו"ל" |

ההדפסה היא HTML + `@media print` + `window.print()`. "PDF" = "שמירה כ-PDF" של הדפדפן. בלי ספריית PDF בשרת.

בלי שילוב עם עורך התמלילים או תבניות המסמכים בגרסה הזו (שאלה 14 — ברירת מחדל). הרחבה אפשרית בעתיד: פתיחת
המחירון בעורך דרך `platform/docs/embed.md`.

## 4. הארכיטקטורה מול הפלטפורמה

- **תיקייה:** `grave-prices/`, PHP 8.3 + JS בלי בנייה. API יחיד: `api.php?action=…`, JSON.
- **שער:** `"gate": true`, `"restricted": true` (כבר ב-`app.json`) — רק מי שהמנהל אישר ישירות. אין כתובת ציבורית:
  `"public"` לא נדרש.
- **התחברות** (`platform/docs/auth.md`, `sso.md` סעיף 0): מחוברת — `$_SERVER['PLATFORM_USER']`, חשבון משלה
  מקושר ל-`sub`, נפתח מיד בכניסה ראשונה; מנותקת — "כניסה עם הכלים הדיגיטליים" דרך `sso.php` בלבד (בלי סיסמה משלה).
  עוגייה משלה: `gp_session`. דוגמה לקריאה (לא `require`): `document-templates/lib/platform.php`.
- **מי עושה מה:** כל משתמש מורשה רואה, מדפיס ועורך (שאלה 3 — "פנימי"). **מפתח** (`is_dev`) = מי ש-
  `platform_admin` שלו `true`; רק הוא רואה את מסך המפתח.
- **DevLoop** — דרך המודול המשותף (`devloop/README.md`), קידומת `GP-`, אסימון `gpd_`, יומן מובנה.
  הרישום ב-`devloop/apps.json` — אצל הבקרה.
- **נתונים בשרת** — רק `grave-prices/data/` (כבר קיימת; ה-`--exclude` ב-`deploy.yml` — הבקרה מוודאת לפני
  פרוסה 01).
- **ענן MBE ותוספים: לא צריך** (שאלה 8). אין ספק חיצוני, אין סודות.
- **עצמאית:** אין `require` מחוץ לתיקייה, אין קישור "חזרה לכלים", אין `../` ב-HTML/JS.
- **עיצוב המסכים** — הסקיל `phone-first-design`. **עיצוב ההדפסה** — כמו המקור, לא כמו המסכים.
