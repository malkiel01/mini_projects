# 02 — שינוי מחירים ומחירון חדש

**הפרוסה האחרונה.** בסופה עובר המבחן של `owner-brief.md`: משנים מחיר ומדפיסים — בכמה לחיצות, בלי לגעת
במחירונים הקודמים. נבנית על 01.

## 1. מה בונים

1. **מצב עריכה במסך המחירון** — כפתור ✏️ עריכה. כל מחיר הופך לשדה מספר (שקלים שלמים, ריק = אין מחיר לקבוצה).
   שמירה **אוטומטית** בעזיבת שדה, עם סימון "נשמר ✓" ליד השדה; שגיאה — השדה נשאר אדום עם ההודעה.
2. **מחירון שכבר בתוקף** (תאריכו ≤ היום) — לפני השינוי הראשון במצב עריכה: "המחירון הזה כבר בתוקף. לתקן אותו?"
   (שאלה 10). אישור תקף עד סוף מצב העריכה. מחירון עתידי — בלי שאלה.
3. **יומן לכל שינוי** — `audit` `price` עם `{row, audience, old, new}`. במסך המחירון: "📜 שינויים" — רשימת
   השינויים במחירון הזה (מתי, מי, שורה, קבוצה, ישן → חדש). כך הערך הקודם לעולם לא אובד.
4. **שורות** — במצב עריכה: עריכת תווית (עם הסימון של `00-overview.md` ותצוגה מיידית), סוג, הזחה; ➕ שורה מתחת;
   🗑️ מחיקה (עם אישור); ↑↓ הזזה. השינוי חל **רק על המחירון הזה**. ביומן: `row-add`, `row-edit`, `row-delete`,
   `row-move`.
5. **חתימות** — עריכת שם ותפקיד של שלוש החתימות, למחירון הזה בלבד (שאלה 12).
6. **מחירון חדש** — ➕ במסך הבית:
   - תאריך "בתוקף החל מ-" (חובה, ייחודי; ברירת מחדל — היום).
   - "על בסיס": מחירון קיים (ברירת מחדל — האחרון). מועתקים השורות, המחירים והחתימות.
   - **העלאה באחוז** (שאלה 11): לכל `section` שדה אחוז (ברירת מחדל 0), ושדה אחד לתשלומים הנלווים (`fee`); לכל
     קבוצה בנפרד או לשתיהן (ברירת מחדל — שתיהן). מחיר חדש = `round(old × (1 + p/100))` לשקל. מחיר ריק נשאר ריק.
   - יצירה → נפתח המחירון החדש במצב עריכה. ביומן: `edition-create` עם הבסיס והאחוזים.
7. **מחיקת מחירון** — רק מחירון שתאריכו בעתיד, עם אישור (טעות בפתיחה). מחירון שהיה בתוקף — לא נמחק לעולם.
8. **שינוי תאריך** של מחירון — רק כשהוא בעתיד, ובלי להתנגש בתאריך קיים.

## 2. מה לא בונים

העלאה באחוז על מחירון קיים (רק בפתיחת חדש — אחר כך מתקנים ידנית); ייבוא; השוואה בין מחירונים; "ביטול" של שינוי
(היומן מראה את הערך הקודם, ומקלידים אותו).

## 3. ה-API (בנוסף ל-01)

| action | גוף | הערה |
| --- | --- | --- |
| `price-set` | `pid, row, audience, amount\|null, confirm_in_effect` | בלי `confirm_in_effect` על מחירון בתוקף → 409 `{"error","need_confirm":true}` |
| `row-save` | `pid, row?, after?, kind, indent, label` | חדשה כש-`row` חסר; אותו כלל 409 |
| `row-delete`, `row-move` | `pid, row, (dir)` | אותו כלל 409 |
| `signatures-set` | `pid, signatures[3]` | אותו כלל 409 |
| `edition-create` | `effective_from, base_pid, raise{section_sort\|"fee": {il, abroad}}` | |
| `edition-update` | `pid, effective_from` | רק עתידי |
| `edition-delete` | `pid` | רק עתידי |
| `history` | GET `pid` | שינויי היומן של המחירון |

`row` מזוהה ב-`pid` משלו (שורות מקבלות `pid` במיגרציה של הפרוסה הזו). כל כתיבה — בטרנזקציה, עם CSRF, ונרשמת ביומן.
אימות: `amount` שלם 0–10,000,000; `kind` מהרשימה; `indent` 0/1; `label` עד 200 תווים, לא ריק; תאריך תקין.
