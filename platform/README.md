# פלטפורמה — משפחת האפליקציות

דף הכלים הראשי (`index.html` שבשורש) הופך מדף כרטיסים פתוח לכולם
ל"אפליקציה שמכילה אפליקציות": נכנסים עם שם משתמש וסיסמה, וכל משתמש רואה
את **משפחת האפליקציות שלו** — רק מה שהמנהל התיר לו, מסודר בקטגוריות.

> מצב: **אפיון שאושר** (2026-10-11). השלבים נבנים לפי הטבלה למטה.

---

## הרעיון: משפחה של אפליקציות

כמו חבילה של אפליקציות מאותו בית: לכל משתמש המשפחה שלו, וכל אחת מהן היא
אפליקציה שלמה בפני עצמה. "משפחה" כאן היא **חבילת האפליקציות של המשתמש** —
לא קבוצה של אנשים, ואין שיתוף בין משתמשים.

- **הפלטפורמה עצמה ניתנת להתקנה** כאייקון אחד במכשיר. בפנים — כל האפליקציות
  של המשתמש.
- **"להוריד את כל המשפחה"** — כפתור אחד ששומר במכשיר את כל האפליקציות שמותרות
  למשתמש (ככל שהן מסוגלות לעבוד בלי רשת), כך שהן נפתחות גם בלי חיבור.
- **ובמקביל כל אפליקציה ניתנת להתקנה לבד**, כאייקון משלה — למי שרוצה רק אחת.

## ההכרעות

### 1. אבטחה: קודם הסתרה, אחר כך שער אמיתי

הסתרת כרטיס אינה חוסמת: כל כלי יושב בתיקייה שנגישה ישירות ב-URL. לכן שני
שלבים, ובכל אחד ברור מה הוא מבטיח ומה לא:

| שלב | מה הוא נותן | מה הוא **לא** נותן |
| --- | --- | --- |
| הסתרה | כניסה, וכל משתמש רואה רק את הכרטיסים שלו | מי שמכיר כתובת — נכנס |
| שער | כל בקשה לתיקיית כלי עוברת בדיקת session והרשאה | — |

**מנגנון השער:**

- **קבצים סטטיים** (HTML, JS, CSS, תמונות) — כלל ב-`.htaccess` שבשורש מעביר
  כל בקשה לתיקיית כלי דרך `platform/gate.php`, שבודק ומגיש את הקובץ.
- **קבצי PHP** — בדיקה שרצה לפני הקובץ, דרך `auto_prepend_file`. אם PHP בשרת
  רץ כ-FPM/CGI זה נעשה ב-`.user.ini`, ואם כ-mod_php — ב-`.htaccess`.
  **איזה מהשניים — לא ידוע.** לכן לפני השער פורסים קובץ בדיקה קטן, והמשתמש
  פותח אותו בדפדפן.
- **נתיבים ציבוריים** עוקפים את השער. הם מוצהרים בקובץ הרישום של הכלי
  (ראה סעיף 3) — למשל:

| כלי | נתיב ציבורי | למה |
| --- | --- | --- |
| הטמעת נתונים | `sign.html`, `track.html` | לקוחות חותמים מקישור |
| קייטרינג | `index.html`, `api.php` (חלקית) | התפריט הציבורי להזמנות |
| מצלמות | `upload.php`, `cron.php` | המצלמות והמתזמן, לא בני אדם |
| מטלות לקלוד | `health.php` | בדיקת חיים |
| סורק וואטסאפ / דפדפן מנוהל | נקודות ה-API של האנדרואיד | אפליקציה נייטיב עם אסימון משלה |

הרשימה הסופית תיבנה כלי אחר כלי בשלב השער, מתוך הקוד — לא מהזיכרון.

**כלים עם כניסה משלהם** (git-deploy, מתכונים, מצלמות, נגרות, מטלות לקלוד,
וואטסאפ, דפדפן מנוהל, מנהל הקייטרינג) — נשארים כמו שהם. השער מחליט מי מגיע
לכלי; הכלי ממשיך לבקש את הסיסמה שלו. כניסה אחת לכולם (SSO) — שלב עתידי
ונפרד, אם בכלל.

### 2. משתמשים ואחסון

- **SQLite** ב-`platform/data/platform.sqlite`. כל `platform/data/` מוחרגת
  ב-`deploy.yml` — בלי זה הפריסה הבאה תמחק את כל המשתמשים.
- סיסמאות ב-`password_hash` / `password_verify`.
- CSRF: אסימון ב-session, נבדק בכל בקשה משנה.
- הגבלת ניסיונות: 5 כשלים → נעילה של 15 דקות, לפי שם משתמש ולפי IP.
- עוגייה `HttpOnly`, `Secure`, `SameSite=Lax`; `session_regenerate_id` בכניסה.

**טבלאות (טיוטה):**

```
users          id, username, password_hash, display_name, role(admin|user),
               status(pending|active|blocked), created_at, last_login_at
categories     id, slug, name, icon, sort
app_overrides  app_id, category_id, hidden, installable_approved
grants         user_id, kind(app|category), target, allowed
login_attempts key, count, locked_until
```

### 3. רישום האפליקציות: `app.json` בכל תיקייה

במקום כרטיס ידני ב-`index.html`, כל כלי מצהיר על עצמו:

```json
{
  "id": "carpentry-3d",
  "name": "נגרות בתלת מימד",
  "icon": "🪚",
  "description": "…",
  "category": "design",
  "entry": "index.html",
  "version": "1.4",
  "links": [{ "label": "כניסה לאפליקציה", "href": "" }],
  "public": ["share/*"],
  "install": {
    "pwa": true,
    "offline": false,
    "apk": null,
    "store": null
  }
}
```

- הפלטפורמה סורקת `*/app.json` בזמן ריצה — אין שלב בנייה.
- **אפליקציה חיצונית** (בדומיין אחר, למשל `kadisha/`): תיקייה עם `app.json` ו-README בלבד, ו-`entry` /
  `links[].href` הם כתובות `https://` מלאות. בדף מסומנת ↗. השער ומעקב הכניסות לא חלים עליה (הבקשות
  לא עוברות בשרת הזה), ולכן `"gate": true` אסור בה. APK חיצוני — `install.apk` בכתובת https.
- `category` היא ברירת מחדל. המנהל יכול להעביר קטגוריה במסד.
- **שורת הגרסה המשותפת בתחתית `index.html` מבוטלת.** לכל כלי גרסה משלו
  ב-`app.json`. כך נעלמת נקודת ההתנגשות היחידה בין הצ'אטים.
- `CLAUDE.md` ו-`.claude/COORDINATION.md` יעודכנו: "כלי חדש = `app.json`",
  ולא "כרטיס ב-`index.html`".

### 4. הרשאות

- **משתמש חדש** — נרשם בעצמו, ונשאר `pending` ולא רואה כלום עד שהמנהל מאשר.
- **המנהל** רואה הכול, ומקצה לכל משתמש **קטגוריות שלמות** או **אפליקציות
  בודדות**. הרשאה לאפליקציה גוברת על הקטגוריה (אפשר להתיר קטגוריה ולחסום בה
  אפליקציה אחת).
- **המנהל הראשון** — מסך התקנה בדף הראשי, שמופיע רק כשאין אף משתמש, ודורש
  קוד חד-פעמי. הקוד מגיע מסוד GitHub חדש, `PLATFORM_SETUP_CODE`, שהפריסה כותבת
  לשרת. אחרי יצירת המנהל הדף נסגר לתמיד.

### 5. התקנה והורדה — שתי דרכים, ושתיהן

| דרך | מה זה בפועל | למי |
| --- | --- | --- |
| **הורדה קלה** | התקנה מהדפדפן (PWA) — של כל המשפחה, או של אפליקציה בודדת. ולאפליקציות נייטיב — הורדת APK ישירה מהשרת | כל אחד, בלי חשבון בחנות |
| **מהחנות** | קישור לדף האפליקציה ב-Google Play (לנייטיב, או PWA עטוף ב-TWA) | אפליקציות שיש להן דף בחנות |

למתכונים כבר יש בנייה ל-Google Play (`recipes-twa.yml`, TWA) — היא המקרה
הראשון של "מהחנות".

- **מי קובע:** `app.json` מצהיר מה הכלי **מסוגל** (`pwa`, `offline`, `apk`,
  `store`); המנהל **מאשר** בממשק. מה שלא אושר — לא מוצג.
- **"להוריד את כל המשפחה"**: ה-service worker של הפלטפורמה שומר במכשיר את
  קבצי האפליקציות שמסומנות `offline: true` ומותרות למשתמש. כלי שתלוי בשרת
  (מסד נתונים, AI) מותקן כאייקון אבל דורש רשת — וזה נאמר במפורש בכרטיס.
- ביציאה מהחשבון — המטמון נמחק, כדי שמי שמקבל את המכשיר אחריך לא יראה את
  האפליקציות שלך.

### 6. הפעלה מתוך הדף

לחיצה על אפליקציה פותחת אותה **במסך מלא** (ניווט רגיל), עם פס דק "חזרה
למשפחה". לא iframe: מצלמה, service worker וכניסות פנימיות מסתבכים בתוך מסגרת.

### 7. `index.html` נשאר `index.html`

rsync רץ בלי `--delete`, ו-Apache מגיש `index.html` לפני `index.php`. לכן
הדף הראשי נשאר `index.html`: מעטפת סטטית שמבקשת את הנתונים מ-
`platform/api.php` ומציגה מסך כניסה או את המשפחה.

## מה בנוי

```

  check-apps.php        שער הפריסה: כל app.json תקין. CLI בלבד
  build-gate.php        בפריסה: .user.ini ו-.htaccess לכלים עם "gate": true. CLI בלבד
  gate.php              מגיש קבצים סטטיים של כלי, אחרי בדיקת הרשאה
  gate-prepend.php      רץ לפני כל PHP של כלי (auto_prepend_file)
  lib/gate.php          ההכרעה — בלי שמות גלובליים, כי רץ בתוך הכלים
  assets/app.js         המעטפת: כניסה, הרשמה, התקנה, והאפליקציות
  manifest.webmanifest  המשפחה כאפליקציה מותקנת (start_url/scope: home/)
  home/index.php        הבית של האפליקציה המותקנת — index.html שבשורש, עם <base>
  assets/icons/         אייקוני המשפחה
  assets/admin.js       ממשק המנהל (#admin): משתמשים והרשאות, קטגוריות ואפליקציות
  assets/app.css
  lib/registry.php      סריקת */app.json ואימות
  lib/access.php        קטגוריות במסד, שיוך והסתרת אפליקציות, ומי רואה מה
  lib/admin.php         פעולות המנהל (admin_state, admin_*)
  lib/auth.php          משתמשים, התחברות, הגבלת ניסיונות, קוד ההתקנה
  lib/db.php            SQLite ומיגרציות
  lib/http.php          JSON ושגיאות
  lib/setup-code.php    נכתב בפריסה בלבד: ה-hash של PLATFORM_SETUP_CODE. לא בגיט
  lib/.htaccess         חסום מהדפדפן
```

**עיצוב** (2026-10-15): שפת "הטלפון קודם" (`.claude/skills/phone-first-design`) עם זהות משלה —
מותג אינדיגו, כותרת בהירה דביקה (לוגו ושם · ⚙️ ניהול עם מונה ממתינים · תפריט משתמש עם התקנה,
הורדה ויציאה), ומצב כהה אוטומטי. האפליקציות: בטלפון — שורות בתוך מסגרת; במחשב — גריד כרטיסים;
חיפוש מעל 4 אפליקציות. אפליקציה עם כמה כניסות או עם התקנה נפתחת בגיליון בחירה.

`index.html` שבשורש הוא מעטפת שטוענת את `platform/assets/app.js`. הטקסט מוצב
כ-`textContent` ולא כ-HTML, והקישורים מוגבלים לנתיב יחסי בתוך תיקיית הכלי.

**התחברות:** העוגייה `mp_session` (HttpOnly, SameSite=Lax, ונתיבה שורש האתר —
כדי שבשלב השער תגיע גם לכלים) מחזיקה אסימון אקראי; במסד נשמר רק ה-hash שלו.
לא session של PHP: בשרת משותף הוא נמחק אחרי 24 דקות בלי פעילות.

**ממשק המנהל** (`#admin`, קישור "⚙️ ניהול" בפס העליון):

- **משתמשים** — רשימה עם חיפוש (שם / שם משתמש), סינון לפי מצב (הכול · ממתינים · פעילים ·
  חסומים, עם מונה) ומיון (נרשמו לאחרונה · כניסה אחרונה · שם). ממתינים תמיד למעלה, עם ✓ / ✕
  ישירות בשורה; אישור פותח מיד את גיליון המשתמש לבחירת ההרשאות. לחיצה על שורה — גיליון:
  מצב, תפקיד, תאריך הרשמה, כניסה אחרונה, פעולות, איפוס סיסמה והרשאות. חסימה (מנתקת מיד בכל
  המכשירים), ביטול חסימה, מחיקה, הפיכה למנהל.
- **איפוס סיסמה** — המנהל קובע סיסמה זמנית (מוצעת אקראית, להעתקה ומסירה). המשתמש מתנתק מכל
  המכשירים, ובכניסה הבאה חייב לבחור סיסמה משלו (`users.must_change_pw`). כל משתמש יכול להחליף
  סיסמה מהתפריט האישי (`api.php?action=password`) — ושאר המכשירים שלו מתנתקים. מנהל לא יכול לחסום, למחוק או להוריד את
  עצמו, ותמיד נשאר לפחות מנהל פעיל אחד.
- **`"restricted": true` ב-`app.json`** — הרשאה לקטגוריה לא פותחת את האפליקציה;
  רק "✓ מותר" ישירות עליה (בעורך מופיע "🔒 רק באישור ישיר"). גם השער מכבד את זה.
- **הרשאות** — לכל קטגוריה "הכול" (כולל אפליקציות שיתווספו אליה), ולכל
  אפליקציה: לפי הקטגוריה / מותר / חסום. ליד כל אפליקציה — האם המשתמש רואה אותה.
- **קטגוריות** — שינוי שם ואייקון, סדר, הוספה, ומחיקה של קטגוריה ריקה. הקטגוריות
  נזרעות פעם אחת מ-`categories.json`; קטגוריה חדשה בקובץ נכנסת לסוף, ומחוקה
  לא חוזרת.
- **אפליקציות** — העברה לקטגוריה אחרת, והסתרה מכולם.

**התראה על הרשמה חדשה** (Web Push): בראש לשונית המשתמשים — "🔔 התראה על כל הרשמה חדשה":
הפעלה / בדיקה / כיבוי לכל מכשיר. כל הרשמה שולחת התראה לכל המכשירים של המנהלים הפעילים, ולחיצה
עליה פותחת את `#admin`. הקוד (`lib/push.php`) הועתק מ-`catering-menu/push.php` — VAPID והצפנה
ב-openssl, בלי ספריות; המפתחות והמנויים בטבלאות `push_vapid` / `push_subs` במסד (כבר מוחרג).
ההתראה מוצגת ב-`family-sw.js`. **באייפון** Push עובד רק מאפליקציה שהותקנה למסך הבית (iOS 16.4+).
בנוסף: מונה ממתינים על ⚙️ בכותרת ובלשונית המשתמשים.

**מעקב כניסות** (לשונית "📊 שימוש"): השער רושם כל פתיחה של דף באפליקציה (`record_visit` ב-
`lib/gate.php`, אחרי שהבקשה הותרה) בטבלה `visits` — אפליקציה, משתמש (או אורח בדף ציבורי), זמן,
ומכשיר מקוצר ("iPhone · Safari"). רק ניווט (`Sec-Fetch-Dest: document`), לא fetch, תמונות או
iframe; אותו משתמש באותה אפליקציה בתוך 30 דקות — פעם אחת. רוטציה: מדי פעם נמחק מה שישן משנה,
ותקרה של 200,000 שורות. כשל ברישום לעולם לא עוצר את הכלי. רק אפליקציות עם `"gate": true` נספרות.
בממשק: 7 / 30 / 90 יום — סך כניסות, משתמשים ייחודיים, גרף יומי (לפי שעון ישראל), ולכל אפליקציה
(גיליון: גרף, מי נכנס, כניסות אחרונות). בגיליון של משתמש — לאילו אפליקציות נכנס. הטבלה במסד
הפלטפורמה, שכבר מוחרג מהפריסה.

**הרשאה תלויה בהרשאה, וניתוק בלחיצה** (החלטת בעל המערכת, 2026-10-18): כדי להיכנס לאפליקציה צריך
חשבון בפלטפורמה **ו**הרשאה לאפליקציה בחשבון — זה השער, והוא נשאר בכל האפליקציות. לכל אפליקציה יש
בממשק המנהל (אפליקציות) "🔌 מחוברת": מורידים את הסימון → היא **מנותקת** — השער מעביר הכול (טבלה
`app_detached`, נבדקת ב-`lib/gate.php` בכל בקשה, בלי פריסה), מעקב הכניסות לא נרשם, והיא עומדת לבד עם
הכניסה שלה, כמו קדישא. היא עדיין מוצגת בפלטפורמה למי שיש לו הרשאה. מחברים מחדש — באותה לחיצה.
אפליקציה חיצונית או בלי `"gate"` ב-app.json — עומדת לבד תמיד.

**הפלטפורמה היא חנות/משגר, לא מעטפת** (החלטת בעל המערכת, 2026-10-18): היא מתווכת בין המשתמש
לאפליקציות — גישה קלה, והתקנה למי שאפשר. אפליקציה נפתחת בחלון/לשונית משלה (`target=_blank`),
והפלטפורמה נשארת מאחור; כך האפליקציה המותקנת של הכלים הדיגיטליים לא "נתקעת" באפליקציה האחרונה.
`?next=` מכובד רק מיד אחרי כניסה, ובכל מצב אחר נמחק מהכתובת. התקנה/APK/חנות מוצגים לכל מי שרואה
את האפליקציה; המנהל יכול להסתיר.

**אכיפת PWA ובדיקת התקנה אמיתית** (`lib/pwa.php`, `assets/pwa-beacon.js`, `pwa.php`, `lib/installs.php`):
השער מוסיף לכל דף של אפליקציה מחוברת (HTML סטטי ב-`gate.php`, דף PHP ב-`gate-prepend.php`) סקריפט, ו-
manifest לאפליקציה שאין לה (`pwa.php?app=` — אייקון מ-`assets/app-icons/`, שנוצר ב-`tools/app-icons.mjs`).
כך **כל אפליקציה מחוברת ניתנת להתקנה**, בלי לגעת בקבצים שלה. ל-manifest קיים — בהגשה מתווספים
`related_applications` ו-`pwa-launch=1` ב-start_url (וה-id המקורי נשמר). הסקריפט בודק **במכשיר**:
נפתחה מהאייקון שלה (מצב אפליקציה + `pwa-launch`) / `getInstalledRelatedApps` / `beforeinstallprompt` /
`appinstalled` — ומדווח (`install_report`); בלשונית דפדפן בטלפון מציג פס "התקנה" (בלחיצה, או ההסבר
המדויק). הפלטפורמה מציגה רק מה שאומת: "✓ מותקנת — נפתחה מהאייקון / הדפדפן אישר", "לא מותקנת", או "עוד
לא נבדק". APK — דפדפן לא יכול לבדוק, ולא מוצג עליו כלום. אפליקציה מנותקת — בלי תוספות.
**רק בדף שאינו ציבורי, ורק למשתמש מחובר לפלטפורמה.** דף שב-`public` (טופס ללקוח, תפריט, קישור צפייה)
שייך ללקוח של האפליקציה — הוא לא מקבל את הסקריפט, את ה-manifest ואת הפס, ולא נשמר אצלו מזהה מכשיר.
`"install": {"banner": false}` ב-app.json — בלי הפס "התקנה" גם למשתמשים מחוברים (בדיקת ההתקנה נשארת).
חריג: דף ציבורי מקבל את הסקריפט כשהפלטפורמה ביקשה זאת במפורש — `?pwa-install` (הכפתור "התקנה כאפליקציה";
נשמר 15 דקות בעוגייה `platform-pwa-install`, כי אפליקציה עם כניסה משלה מעבירה מיד ל-login ומאבדת את
הפרמטר) או `?pwa-launch` (נפתחה מהאייקון שלה). בלי זה אפליקציה שהדף הראשי שלה ציבורי, כמו ניהול
פרויקטים, לא הייתה ניתנת להתקנה מהפלטפורמה.

**כניסה מאוחדת** (לשונית "🔗 חיבורים"): "כניסה עם חשבון כלים דיגיטליים" לאפליקציות — גם בדומיין אחר.
חשבון הפלטפורמה הוא זהות; לכל אפליקציה חשבונות משלה, מקושרים (והמייל קובע). **בלי קודים ובלי סודות:**
אפליקציה מצהירה `"sso": {"return": [...]}` ב-app.json ומופיעה אצל המנהל דלוקה — מתג אחד מכבה. `platform/sso.php`
מחזיר זהות חתומה (Ed25519, `sso_keys`), והאפליקציה בודקת אותה במפתח הציבורי (`sso.php?action=key`). המדריך:
`platform/docs/sso.md`.

**הגנות:** כל בקשה משנה היא JSON עם הכותרת `X-Platform` (אתר זר לא יכול לשלוח
כזו), ופעולות של משתמש מחובר דורשות גם `X-CSRF`. 5 כשלי כניסה → נעילה של 15
דקות לפי שם משתמש ולפי IP; גם קוד ההתקנה וההרשמה מוגבלים לפי IP.

## השער (שלב 4)

בדיקת השרת (2026-10-11): LiteSpeed, PHP 8.3. `rewrite` ב-`.htaccess` עובד גם על
קובץ קיים; `.user.ini` עם `auto_prepend_file` עובד; `php_value` ב-`.htaccess` —
לא.

**איך זה עובד:** אפליקציה שב-`app.json` שלה `"gate": true` —

- **קבצים סטטיים** — `build-gate.php` (רץ בפריסה) מוסיף בראש ה-`.htaccess` של
  הכלי בלוק rewrite שמעביר כל קובץ שאינו PHP ל-`platform/gate.php`. שם: בדיקת
  הרשאה, ואז הגשה (עם ETag, 304 ו-Range לווידאו). הקובץ נגזר מהכתובת המקורית,
  שהשרת כבר בדק מול חוקי ה-`.htaccess` של הכלי — לכן `data/` חסומה נשארת חסומה,
  ופנייה ישירה ל-`gate.php` מחזירה 404. סיומת שאינה ברשימה (`.py`, `.sh`, `.apk`…)
  לא עוברת בשער בכלל.
- **קובצי PHP** — `.user.ini` בתיקיית הכלי מריץ את `platform/gate-prepend.php`
  לפני כל סקריפט. מותר → הסקריפט רץ כרגיל; אחרת → עצירה.
- **מי עובר:** מנהל — תמיד. משתמש פעיל — לפי ההרשאות (אותה לוגיקה כמו בדף
  הראשי). אחרים: דף → הפניה לכניסה עם `?next=` וחזרה לכלי אחריה; כל בקשה אחרת →
  JSON (401/403), כדי שאפליקציה או מכונה יקבלו שגיאה ברורה ולא דף HTML.
- **נכשל סגור** — תקלה במסד ההרשאות חוסמת (503), לא פותחת.
- הקבצים שנוצרים בפריסה (`.user.ini`, הבלוק ב-`.htaccess`) אינם בגיט.

**כתובות ציבוריות** — `"public"` ב-`app.json`, יחסיות לתיקיית הכלי:

```json
"gate": true,
"public": ["view.html", "assets/**", "api.php?action=view|view-assembly"]
```

`*` אינו חוצה `/`, `**` כן. `?key=a|b` — רק כשהפרמטר (מ-GET, POST או גוף JSON)
הוא אחד הערכים.

> ⚠️ **כל פעולה שלקוח בלי חשבון בפלטפורמה מגיע אליה חייבת להופיע ב-`public`** — הדף, הנכסים, **וכל**
> `action` של ה-API שהדף קורא לו. פעולה שחסרה נחסמת בשקט: הלקוח מקבל 401 "נדרשת כניסה", ומי שבודק
> כשהוא מחובר לפלטפורמה לא רואה שום תקלה. לבדוק כל שינוי בדף ציבורי **בחלון גלישה בסתר**, ולעבור על
> כל קריאה ל-API שבו מול הרשימה. `check-apps.php` בודק רק שהתבניות תקינות — לא שהן שלמות.

**קישור עם `#`** (`#invite=…`, `#reset=…`): מה שאחרי `#` לא מגיע לשרת, ולכן אינו ב-`?next=`. הדפדפן
משאיר אותו בכתובת אחרי הפניית השער, ו-`goNext` ב-`app.js` מחזיר אותו לכלי אחרי הכניסה.

**מי מאחורי השער** (הוכרע 2026-10-11, אחרי סקירת הקוד של כל כלי):

| רמה | כלים |
| --- | --- |
| חסום לגמרי | database-analyzer, frame-browser, pdf-merger, sketches-3d, sukkah-sketch, git-deploy, file-merger (חוץ מקובצי ה-PWA) |
| חסום, עם `public` | camera-app (הגשר, העלאות, cron), carpentry-3d (קישור הצפייה ללקוח), catering-menu (התפריט הציבורי וההזמנות), claude-tasks (ה-API — יש לו אסימוני עובד משלו), data-embed-for-clients (חתימה ומעקב), renovation-punchlist (סנכרון), whatsapp-ai-scanner ו-guarded-browser (אפליקציות האנדרואיד) |
| בלי שער | recipes-app (דומיין משלו `recipes.mbe-plus.com` — העוגייה לא מגיעה אליו — ומשתמשים והרשמה משלו), greeting-cards (אפליקציית האנדרואיד שלה היא WebView על דף הכלי) |

כלי חדש עם כתובות שמכונה או לקוח ניגשים אליהן — להוסיף אותן ל-`public` לפני
`"gate": true`. כתובת ציבורית אינה פרוצה: הכלי ממשיך לבדוק בה את מה שבדק עד
היום (אסימון, קישור סודי, כניסה משלו).

**כיבוי שער:** `"gate": false`. ה-`.user.ini` שכבר בשרת נשאר (rsync בלי
`--delete`), אבל השער רואה שהוא כבוי ומעביר הכול.

## התקנה והורדה (שלב 5)

- **הפלטפורמה תמיד נפתחת על רשימת האפליקציות** — הטווח (scope) של האפליקציה המותקנת הוא רק
  `platform/home/`, לא שורש האתר. כשהטווח כלל את כל הכלים, כלי שנפתח "תפס" את חלון הפלטפורמה,
  ופתיחה חוזרת שלה החזירה את הכלי האחרון. עכשיו כלי נפתח מחוץ לטווח — בדפדפן, או באפליקציה המותקנת
  שלו — ו-`launch_handler: navigate-existing` מחזיר את החלון לרשימה בכל לחיצה על האייקון.
  ה-`id` נשאר `../`, כך שהתקנה קיימת מתעדכנת ולא נכפלת (באייפון — צריך להתקין מחדש).
  התקנה ישנה (פתוחה כאפליקציה, אבל לא מ-`platform/home/`) מקבלת בראש הרשימה פס כתום "צריך להתקין
  מחדש", עם הצעדים לפי המכשיר — בלי זה היא ממשיכה לפתוח כלים בתוך החלון שלה.
- **המשפחה כאייקון אחד** — `platform/manifest.webmanifest` ו-
  `family-sw.js` בשורש. כפתור "📲 התקנה" בכותרת **תמיד גלוי** (חוץ מבתוך האפליקציה המותקנת),
  ופס הזמנה בראש דף האפליקציות (נסגר ב-✕, נזכר במכשיר). הלחיצה פותחת גיליון לפי המכשיר:
  כרום/Edge/אנדרואיד עם `beforeinstallprompt` — "התקנה עכשיו" בלחיצה אחת; **אייפון** — שלושה
  צעדים עם סמל השיתוף (שיתוף ← "הוספה למסך הבית" ← "הוספה"), והפניה לספארי מדפדפן אחר;
  אנדרואיד בלי הצעה — דרך תפריט ⋮; מחשב — סמל ההתקנה בשורת הכתובת. אחרי התקנה (`appinstalled`)
  הכפתור והפס נעלמים.
- **המשפחה היא PWA מלאה** (נבדק מול האתר החי ב-Chromium: `getInstallabilityErrors` ריק). ה-manifest
  כולל צילומי מסך (`assets/screenshots/`, narrow + wide) — כך באנדרואיד נפתח חלון התקנה עשיר כמו
  בחנות — קטגוריות, וקיצור דרך "ניהול". `platform/.htaccess` מגיש `.webmanifest` עם
  `application/manifest+json` (בלי זה השרת שלח בלי Content-Type).
- **אנדרואיד:** "התקנת אפליקציה" מתקינה אפליקציה אמיתית (WebAPK — מסך מלא, ברשימת האפליקציות);
  "הוספה למסך הבית" היא רק קיצור דרך לדפדפן. ההסבר בגיליון אומר את זה במפורש.
- **זיהוי "כבר מותקן" גם מלשונית בדפדפן:** פתיחה מתוך האפליקציה המותקנת (standalone) או
  `appinstalled` רושמים `platform:installed` ב-localStorage — משותף לאפליקציה ולדפדפן, כך שגם
  הלשונית יודעת. בכרום באנדרואיד גם `getInstalledRelatedApps` (`related_applications` ב-manifest).
  `beforeinstallprompt` מוחק את הסימון (הוסרה). מותקן → בלי כפתור ובלי פס; בתפריט "✓ מותקן במכשיר".
- **"⬇️ הורדה למכשיר"** — שומר את כל האפליקציות של המשתמש שמסומנות
  `"install": {"offline": true}`: הדף, מה שהוא טוען (כולל ספריות CDN ומודולים),
  ואת רשימת האפליקציות. בלי רשת הדף הראשי והאפליקציות האלה נפתחים מהמטמון.
  מה שאפליקציה טוענת רק בזמן ריצה נשמר בפתיחה הראשונה אחרי ההורדה.
- **ה-service worker לא מפריע:** נוגע רק בבקשות GET לקבצים סטטיים, לרשימת
  האפליקציות ול-CDN. API, וידאו והעלאות — לא נוגע. תמיד קודם רשת. כלי עם
  service worker משלו — שלו גובר בתיקייה שלו.
- **ביציאה מהחשבון** — המטמון נמחק (נשארת רק המעטפת, בלי מידע אישי).
- **לכל אפליקציה** (`"install"` ב-`app.json`): `pwa` (ברירת מחדל — יש לה
  `manifest.webmanifest`), `apk` (https או נתיב יחסי), `store` (play.google.com).
  מוצגים לכל מי שרואה את האפליקציה (מאז 2026-10-18, "חנות"); המנהל יכול להסתיר — "📲 התקנה והורדה" בממשק המנהל.

| מה | אפליקציות כרגע |
| --- | --- |
| offline | pdf-merger, sukkah-sketch, sketches-3d |
| pwa (מזוהה לבד) | file-merger, recipes-app, renovation-punchlist, carpentry-3d |
| apk | whatsapp-ai-scanner, guarded-browser, greeting-cards — קישור הורדה ישיר מ-Release ב-GitHub (תגים `wascanner-apk`, `guarded-browser-apk`, `greeting-cards-apk`), שה-workflow של כל אחד מעדכן בכל בנייה מ-main |
| store | אין עדיין — המתכונים (`com.mbeplus.recipes`) יקבלו קישור כשיפורסמו |
