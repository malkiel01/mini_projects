# התחברות: הפלטפורמה והאפליקציות — האפיון

הוכרע עם המשתמש ב-2026-10-19. המסמך הזה הוא החוק; `sso.md` הוא המדריך הטכני לאפליקציה.

## 1. שלושה סוגי אנשים

| מי | איך נכנס | חשבון |
| --- | --- | --- |
| **משתמש פלטפורמה** | מייל + סיסמה (בשלב הבא גם Google) | בפלטפורמה |
| **משתמש אפליקציה** — צוות, מי שיש לו גישה פנימה | לפי סעיף 2 | באפליקציה, **מקושר** לחשבון הפלטפורמה |
| **משתתף מבחוץ** — לקוח שממלא טופס, עו"ד בפרויקט | קישור אישי שמשתמש אפליקציה שלח (לפעמים עם קוד / Google — אבטחה של הקישור, לא חשבון) | **אין**: לא באפליקציה ולא בפלטפורמה |

המשתתף מבחוץ לא נוגע בשום דבר במסמך הזה. הקישורים שלו נשארים ב-`public` של האפליקציה, כמו היום.
מי מהם שרוצה להיות משתמש באפליקציה — נרשם כמו כל משתמש.

## 2. איך משתמש אפליקציה נכנס

| | אפליקציה **מחוברת** | אפליקציה **מנותקת** |
| --- | --- | --- |
| שער הפלטפורמה | חובה | אין |
| כניסה דרך הפלטפורמה | **היחידה** — ואוטומטית, בלי לחיצה ובלי מסך | אחת מהאפשרויות |
| מסך "המשך בתור ___" | אין | פעם אחת לכל אפליקציה, כמו בגוגל |
| שם משתמש וסיסמה של האפליקציה | **חסום** | לפי ההגדרה בניהול הפלטפורמה |
| Google ודומיו (של האפליקציה) | אין | לפי ההגדרה בניהול הפלטפורמה |
| "ניתוק חשבון" ומעבר לכניסה נפרדת | אין | אפשר |

## 3. ההרשאה בפלטפורמה היא האישור

- **אין אישור כפול.** ההרשאה לאפליקציה בחשבון הפלטפורמה (המנהל מאשר) היא האישור. מי שמגיע לאפליקציה
  דרך הפלטפורמה ואין לו בה חשבון — החשבון נפתח מיד, פעיל, בלי אישור נוסף של מנהל האפליקציה.
- **ההרשאה נבדקת בכל כניסה, בכל אפליקציה.** בוטלה ההרשאה → השער (באפליקציה מחוברת) והכניסה דרך
  הפלטפורמה (גם במנותקת) מציגים: "אין לך הרשאת גישה לאפליקציה הזו — פנו למנהל".

## 4. קישור חשבונות — תמיד

- **כל חשבון באפליקציה שאיננו משתתף מבחוץ מקושר לחשבון פלטפורמה** — באפליקציה מחוברת זו חובה.
- **איחוד סמוי לפי מייל:** חשבון אפליקציה קיים (גם כזה שנוצר כשהאפליקציה הייתה מנותקת, בשם משתמש
  וסיסמה משלה) מתקשר אוטומטית לחשבון הפלטפורמה באותו מייל, בכניסה הראשונה דרך הפלטפורמה.
- **אין חשבון פלטפורמה באותו מייל → חסום** עד שנפתח חשבון בפלטפורמה; אז, אם יש לו הרשאה, הוא נכנס
  לחשבון שלו באפליקציה (אותו חשבון, אותם נתונים).
- **אפליקציה מנותקת:** הקישור לא חובה (אפשר להיכנס בסיסמה משלה). כשהיא **מתחברת** שוב — כל חשבון בה
  חייב קודם להתקשר לפלטפורמה (כמו למעלה).

## 5. חשבון הפלטפורמה

- נזכר **חצי שנה מהשימוש האחרון**, ומתחדש בכל שימוש — בפלטפורמה ובכל אפליקציה מחוברת.
- **יציאה מהפלטפורמה** = יציאה מכל האפליקציות המחוברות. יציאה מאפליקציה מנותקת לא נוגעת בפלטפורמה.

## 6. הניהול — שליטה לתמיד

- ⚙️ ← אפליקציות, בשורה של כל אפליקציה: **מחוברת / מנותקת**, ו**שיטות הכניסה** כשהיא מנותקת
  (סיסמה משלה, Google, כניסה עם הכלים הדיגיטליים — זו תמיד פתוחה).
- ניתוק אינו מחיקה: האפליקציה נשארת ברשימה, ואפשר לחבר אותה שוב בכל רגע.
- אפליקציה מנותקת לא עוברת בשער, ולכן הפלטפורמה לא **כופה** עליה — האפליקציה **קוראת** את ההגדרות
  (`sso.php?action=config`) ומקיימת אותן. כך השליטה נשמרת גם בדומיין אחר.

## 7. מה הפלטפורמה נותנת לאפליקציה (הפירוט הטכני — `sso.md`)

| מה | איך |
| --- | --- |
| מחוברת: מי המשתמש | השער מעביר את הזהות לכל בקשת PHP: `$_SERVER['PLATFORM_USER']` (JSON) — אין redirect, אין מסך |
| מנותקת: "כניסה עם הכלים הדיגיטליים" | `sso.php` — זהות חתומה (Ed25519), מסך אישור פעם אחת |
| האם מחוברת, ואילו שיטות כניסה פתוחות | `sso.php?action=config&client=<id>` |
| הרשאה | נבדקת בשער ובכניסה — זהות ניתנת רק למי שיש לו הרשאה |

- כניסה לפלטפורמה עם Google — השלב הבא.
- חברה קדישא — עצמאית לגמרי; תצטרף לכל זה בעתיד.
