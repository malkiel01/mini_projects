# כניסה מאוחדת — המדריך לאפליקציה

"כניסה עם חשבון כלים דיגיטליים": אפליקציה (בריפו או בדומיין אחר) מזהה משתמש דרך הפלטפורמה,
בלי לשתף איתה משתמשים, מסד או עוגייה. **בלי קודים ובלי סודות להעתיק:** האפליקציה מצהירה על עצמה
ב-app.json, והפלטפורמה מחזירה זהות **חתומה** שהאפליקציה בודקת במפתח ציבורי.

- **חשבון הפלטפורמה הוא זהות.** נמסרים רק מזהה (`sub`), שם (`name`) ומייל (`email`) — לא סיסמה,
  לא הרשאות, לא רשימת אפליקציות.
- **לאפליקציה יש חשבונות משלה**, מקושרים לזהות. הכניסה בסיסמה של האפליקציה — רק כשהיא **מנותקת**
  והמנהל השאיר אותה פתוחה (סעיף 0).
- **המייל קובע** (החלטת בעל המערכת): אותו מייל = אותו אדם. סעיף 4.
- הקוד: `platform/sso.php`, `platform/lib/sso.php`.

## 0. מחוברת או מנותקת — מה האפליקציה עושה

החוק: `platform/docs/auth.md`. בקצרה:

| | מחוברת (השער פעיל) | מנותקת |
| --- | --- | --- |
| מי המשתמש | `$_SERVER['PLATFORM_USER']` — השער כותב אותו לכל בקשת PHP | זרימת `sso.php` (סעיף 2) |
| כניסה בסיסמה / Google של האפליקציה | **חסומה** | לפי `login` ב-config |
| מסך אישור | אין | פעם אחת (הפלטפורמה מציגה) |

```
GET platform/sso.php?action=config&client=<id>
→ {"app":"…","connected":true,"login":{"platform":true,"password":false,"google":false}}
```

**מחוברת:** `$_SERVER['PLATFORM_USER']` הוא JSON — `{"sub","name","email","email_verified","platform_admin"}`
(`platform_admin` — `true` למנהל הפלטפורמה: כך אפליקציה יודעת מי הבעלים שלה, למשל מי מקבל את מסך התפקידים
בפעם הראשונה. התפקידים **בתוך** האפליקציה — שלה, לא של הפלטפורמה) — ויש בו ערך
רק למשתמש מחובר לפלטפורמה **עם הרשאה** לאפליקציה. המפתח אינו `HTTP_*`, כך שאי אפשר לזייף אותו
בבקשה. בכל בקשה:

1. יש `PLATFORM_USER` → החשבון באפליקציה המקושר ל-`sub` (סעיף 4: קישור, ואיחוד לפי מייל). אין חשבון →
   **פותחים אותו מיד, פעיל** — ההרשאה בפלטפורמה היא האישור. אם ה-session של האפליקציה שייך ל-`sub`
   אחר (מישהו אחר נכנס לפלטפורמה) — מחליפים.
2. אין `PLATFORM_USER` (רק בדף ציבורי, כי השער חוסם את השאר) → אין משתמש. מוחקים את ה-session של
   האפליקציה — כך יציאה מהפלטפורמה היא יציאה מהאפליקציה.
3. חשבון באפליקציה שאין לו חשבון פלטפורמה באותו מייל — **חסום** עד שייפתח לו חשבון בפלטפורמה.
4. משתתף מבחוץ (קישור אישי לטופס / לפרויקט) — לא נוגעים: הכתובות שלו ב-`public`, בלי חשבון.

**מנותקת:** קוראים את config. `login.password` / `login.google` — מציגים או מסתירים את הכניסות של
האפליקציה. "כניסה עם הכלים הדיגיטליים" תמיד פתוחה (סעיף 2). כשהאפליקציה מתחברת שוב — כל חשבון בה חייב
להתקשר לפלטפורמה (כמו במחוברת).

## 1. ההצהרה — שורה אחת ב-app.json

```json
"sso": { "return": ["https://migdalor.mbe-plus.com/sso/callback"] }
```

כתובות החזרה המותרות — https מלאה, התאמה מדויקת. אחרי הפריסה האפליקציה מופיעה אצל המנהל
(⚙️ ← 🔗 חיבורים) **דלוקה**; המנהל יכול לכבות במתג. אפליקציה חיצונית (בדומיין אחר) — אותה שורה ב-
`app.json` של תיקיית הרישום שלה כאן (למשל `kadisha/app.json`).

## 2. הזרימה

```
אפליקציה                                       פלטפורמה (https://mbe-plus.com/mini_projects/)
  "כניסה עם חשבון כלים דיגיטליים"
   │ ── redirect ──▶ platform/sso.php?client=<id>&state=<אקראי>&return=<כתובת חזרה>
   │                   לא מחובר → מסך הכניסה הרגיל, וחזרה לכאן
   │                   פעם ראשונה → "X מבקשת לזהות אותך — המשך / ביטול"
   │ ◀── redirect ── <return>?token=<זהות חתומה>&state=<…>   (או ?error=access_denied&state=…)
   האפליקציה בודקת את החתימה במפתח הציבורי — בלי בקשה נוספת לפלטפורמה
```

- **`client`** — ה-`id` מה-app.json.
- **`state`** — 8–200 תווים אקראיים, נשמרים ב-session של האפליקציה. חובה, ונבדק בחזרה.
- **`token`** — `<payload>.<signature>`, שניהם base64url. החתימה (Ed25519) על מחרוזת ה-payload כמו
  שהיא. ה-payload הוא JSON:

```json
{"iss":"https://mbe-plus.com/mini_projects/","aud":"migdalor","sub":"17","name":"דנה לוי",
 "email":"dana@example.com","email_verified":true,"state":"…","return":"https://…/sso/callback",
 "iat":1792268603,"exp":1792268723,"jti":"…"}
```

- **המפתח הציבורי** — `https://mbe-plus.com/mini_projects/platform/sso.php?action=key` →
  `{"alg":"Ed25519","key":"<base64url>","issuer":"…"}`. אפשר לשמור אותו בהגדרות האפליקציה, או לקרוא
  ולשמור במטמון. זה מפתח **ציבורי** — אין בו סוד.

### מה האפליקציה חייבת לבדוק (כולם!)

1. החתימה תקינה במפתח הציבורי.
2. `aud` = ה-id שלה. (זהות שנחתמה לאפליקציה אחרת — נדחית.)
3. `state` = מה שנשמר ב-session, ואז למחוק אותו (שימוש חד-פעמי).
4. `return` = כתובת החזרה שלה, ו-`exp` עוד לא עבר.

## 3. דוגמה ב-PHP (`sodium`)

```php
const PLATFORM = 'https://mbe-plus.com/mini_projects/platform/sso.php';
const CLIENT   = 'migdalor';
const RETURN_URL = 'https://migdalor.mbe-plus.com/sso/callback';
const PLATFORM_KEY = '<מ-sso.php?action=key>';   // ציבורי — מותר בקוד

// הכפתור: /sso/start
session_start();
$_SESSION['sso_state'] = bin2hex(random_bytes(16));
header('Location: ' . PLATFORM . '?' . http_build_query([
    'client' => CLIENT, 'state' => $_SESSION['sso_state'], 'return' => RETURN_URL,
]));

// החזרה: /sso/callback
session_start();
$state = $_SESSION['sso_state'] ?? '';
unset($_SESSION['sso_state']);
if ($state === '' || !hash_equals($state, $_GET['state'] ?? '')) exit('state לא תואם');
if (isset($_GET['error'])) exit('הכניסה בוטלה');

$b64 = fn($s) => base64_decode(strtr($s, '-_', '+/'));
[$payload, $sig] = array_pad(explode('.', $_GET['token'] ?? '', 2), 2, '');
if (!sodium_crypto_sign_verify_detached($b64($sig), $payload, $b64(PLATFORM_KEY))) exit('חתימה לא תקינה');
$id = json_decode($b64($payload), true);
if (($id['aud'] ?? '') !== CLIENT || ($id['state'] ?? '') !== $state
    || ($id['return'] ?? '') !== RETURN_URL || ($id['exp'] ?? 0) < time()) exit('זהות לא תקפה');

// מכאן — של האפליקציה: קישור קיים, ואם אין — איחוד לפי מייל (סעיף 4)
$account = find_account_by_platform_user($id['sub']);
if (!$account && !empty($id['email'])) {
    $account = find_account_by_email($id['email']);
    if ($account) link_platform_user($account, $id['sub']);   // + רישום ביומן
}
if (!$account) exit('אין חשבון מקושר — פנו למנהל המערכת');
login_as($account);
```

## 4. איחוד לפי מייל

החלטת בעל המערכת: **המייל קובע.** משתמש שנכנס דרך הפלטפורמה, ובאפליקציה כבר יש חשבון באותו מייל —
זה אותו אדם, והחשבונות מתאחדים:

1. יש קישור `sub ↔ חשבון` → נכנסים לחשבון המקושר.
2. אין קישור, ו-`email` לא `null` → מחפשים חשבון באותו מייל (בלי תלות באותיות גדולות/קטנות).
   נמצא → **מקשרים אוטומטית**, רושמים ביומן של האפליקציה, ונכנסים.
3. אין קישור ואין חשבון באותו מייל → **חשבון חדש, פעיל**, באותו מייל ושם. זהות ניתנת רק למי שיש לו הרשאה
   לאפליקציה בפלטפורמה — וזה האישור; בלי אישור נוסף של מנהל האפליקציה (docs/auth.md, סעיף 3).

- `email` — המייל שהמשתמש אימת בהרשמה (קישור במייל). משתמש ותיק, שנרשם לפני שהיה אימות: שם המשתמש
  כשהוא כתובת מייל; אחרת `null`, ואז רק קישור ידני.
- `email_verified: true` — המייל אומת בקישור. `false` — משתמש ותיק; את הזהות שלו אישר המנהל כשאישר את
  ההרשמה. בכל מקרה זהות נחתמת רק למשתמש פעיל. אפליקציה זהירה יכולה לאחד אוטומטית רק כש-`true`.

## 5. ניתוק

המשתמש (תפריט אישי ← "🔗 חיבורים לאפליקציות") או המנהל (גיליון המשתמש / האפליקציה ב-🔗 חיבורים)
מנתקים — והכניסה הבאה מבקשת אישור מחדש. המנהל יכול גם לכבות את הכניסה המאוחדת לאפליקציה כולה.

## 6. הזמנת משתמשים מהאפליקציה

אפליקציה שהלקוחות שלה נכנסים **דרך הפלטפורמה** (מגדלור — כל ההורים; החלטת בעל המערכת, 2026-10-20) פותחת להם
חשבון בעצמה: חשבון בפלטפורמה עם הרשאה **לאפליקציה הזו בלבד**, והזמנה במייל לבחירת סיסמה. בלי מנהל באמצע.

**ההצהרה** ב-app.json — המפתח הציבורי של האפליקציה (Ed25519, כמו `docs/embed.md` סעיף 1; המפתח הפרטי — במסד
שלה, לא בגיט):

```json
"provision": { "key_url": "https://mbe-plus.com/mini_projects/<app>/api.php?action=platform_key" }
```

`key_url` מחזיר `{"client":"<app>","keys":[{"kid":"…","alg":"Ed25519","key":"<base64>"}]}` — וחייב להיות ב-`public`.

**הבקשה** — שרת-לשרת, חתומה בדיוק כמו `docs/embed.md` סעיף 2 (`action` = `provision`):

```
POST platform/provision.php
X-Embed-Client / X-Embed-Time / X-Embed-Nonce / X-Embed-Signature
{"email":"parent@example.com","name":"שם ההורה","grant":true,"next":"/mini_projects/<app>/parent/"}
```

| תשובה | מה קרה |
| --- | --- |
| `{"status":"invited","sub":"…"}` | חשבון חדש (פעיל, בלי סיסמה) + הרשאה לאפליקציה + מייל עם `#invite=…`. גם לחשבון שהוזמן ועוד לא בחר סיסמה — הזמנה חדשה |
| `{"status":"granted","sub":"…"}` | יש כבר חשבון באותו מייל — נוספה לו הרשאה לאפליקציה (שאר ההרשאות שלו לא משתנות) |
| `{"status":"blocked"}` | החשבון חסום בפלטפורמה — לא נגעו בו |
| `grant:false` → `revoked` / `unknown` | ההרשאה לאפליקציה הוסרה (החשבון נשאר) |

- **`next`** — לאן המוזמן מגיע אחרי שבחר סיסמה. רק כתובת בתוך תיקיית האפליקציה; בלי — ה-`entry` שלה.
- **הקישור** — 7 ימים, חד-פעמי. המוזמן בוחר סיסמה ונכנס ישר ל-`next`. מכאן — מייל וסיסמה, כמו כל משתמש.
- **`sub`** — מזהה המשתמש בפלטפורמה; אותו `sub` שיגיע ב-`$_SERVER['PLATFORM_USER']` (סעיף 0). שומרים אותו
  בחשבון באפליקציה — וכך הקישור מיידי, בלי חיפוש לפי מייל.
- ההרשאה היא הרשאה רגילה (גיליון המשתמש אצל המנהל): המנהל יכול לראות, להסיר או לחסום.
- הקוד: `platform/provision.php`, `platform/lib/provision.php`.
