# בקשה לצ'אט הפלטפורמה: הזדהות מאוחדת ("כניסה עם חשבון mbe-plus")

> נכתב בצ'אט של מגדלור (`guarded-browser/`). **הקובץ הזה אינו משנה את הפלטפורמה** — הוא
> הדרישות, להעברה לצ'אט שאחראי על `platform/`. ההחלטה והבנייה שם.

## המטרה

חשבון mini_projects ישמש **זהות** לכמה אפליקציות, בלי שהאפליקציות יחלקו משתמשים, מסד או עוגייה
עם הפלטפורמה (CLAUDE.md: "אפליקציה פנימית עצמאית מהמעטפת"). כמו "הזדהות לאומית" — חשבון
אחד שמזדהים בו, ובכל אתר חשבון נפרד שמקושר אליו.

הצרכן הראשון: מגדלור (קונסולת המפתח, ובהמשך הורים). אחריו — כל אפליקציה שתרצה.

## הזרימה (בסגנון OAuth, מינימלי)

```
אפליקציה                          פלטפורמה
   │ ── redirect ──▶ /platform/sso.php?client=migdalor&state=…&return=…
   │                     │ לא מחובר → מסך הכניסה הרגיל, ואז חזרה לכאן
   │                     │ "מגדלור מבקשת לזהות אותך — אישור"
   │ ◀── redirect ── return?code=…&state=…
   │ ── POST /platform/sso.php?action=token (code + client_secret) ──▶
   │ ◀── { sub: <platform_user_id>, name, iat, exp } ──
```

## דרישות

1. **רישום לקוחות** — כל אפליקציה צרכנית רשומה עם `client_id`, `client_secret` (נשמר כ-hash),
   ורשימת כתובות חזרה מותרות (התאמה מדויקת, https בלבד). בלי זה — redirect פתוח.
2. **`code` חד-פעמי**, תקף 60 שניות, קשור ל-`client_id` ולכתובת החזרה.
3. **`state`** — מוחזר כמו שהוא; האפליקציה בודקת אותו (CSRF).
4. **מה נמסר** — מזהה המשתמש בפלטפורמה ושם תצוגה. לא סיסמה, לא הרשאות, לא רשימת אפליקציות.
5. **מסך אישור** — פעם ראשונה לכל אפליקציה; אחר כך נזכר.
6. **ניתוק** — המשתמש (או מנהל הפלטפורמה) יכול לבטל את ההסכמה לאפליקציה.
7. **עובד בין דומיינים** — האפליקציה יכולה לשבת בתת-דומיין (`migdalor.mbe-plus.com`); הקשר הוא
   הפניות ובקשת שרת-לשרת, לא עוגייה משותפת.
8. **הגבלת קצב** על `token`, ורישום ביומן.

## מה נשאר באחריות האפליקציה (לא בפלטפורמה)

- טבלת הקישורים (`platform_user_id` ↔ חשבון פנימי), ומי מחבר ומנתק — במגדלור, המפתח.
- החלטה מה עושים עם זהות שאינה מקושרת (במגדלור: "אין חשבון מקושר — פנה למנהל המערכת").
- הכניסה בסיסמה שלה נשארת, תמיד. ההזדהות המאוחדת היא דרך נוספת, לא מחליפה.
