# דפדפן מנוהל

אפליקציית אנדרואיד נייטיב שהיא דפדפן, שהכניסה אליה מותנית בהרשמה, ושמנהל קובע לכל משתמש בנפרד מה מותר לו לפתוח ומתי.

## למה נייטיב, ולא דף אינטרנט

הגרסה הקודמת (`frame-browser/`) פתחה אתרים בתוך `iframe`, ונתקלה בקיר: אתר יכול לאסור הטמעה ב-`X-Frame-Options` או ב-`frame-ancestors`, ואין מה לעשות בנידון מהצד שלנו.

**‏WebView נייטיב טוען את הדף כמסמך עליון.** אין הטמעה, ולכן שתי הכותרות האלה אינן חלות עליו כלל. גם מסך אתגר של שירות הגנה נפתר מעצמו — זה דפדפן אמיתי, עם עוגיות, JS והיסטוריה משלו.

כל שכבת האבחון שנבנתה כדי לעקוף את בעיית ההטמעה מיותרת כאן.

## מה יש כאן

```
guarded-browser/
  lib/policy.php        מנוע ההרשאות — טהור, בלי DB ובלי HTTP
  lib/schema.php        סכימת SQLite
  lib/db.php            חיבור, שליפות, מדידת זמן, יומן
  lib/auth.php          הרשמה, כניסה, אסימוני מכשיר, CSRF
  lib/ui.php            עטיפת HTML לפאנל
  api/index.php         נקודת הקצה של האפליקציה
  admin/                פאנל הניהול
  data/                 בסיס הנתונים. מוחרג מהפריסה
  tests/                בדיקות
  android/              אפליקציית האנדרואיד (Kotlin)
```

## מודל ההרשאות

### שלושה מצבי גלישה — לכל משתמש בנפרד

המצב אינו הגדרה של האפליקציה אלא **הרשאה של המשתמש**. אותה אפליקציה היא קיוסק סגור לאחד ודפדפן חופשי לאחר.

| מצב | מה המשתמש רואה |
| --- | --- |
| `kiosk` | רק האריחים שהוגדרו לו. אין שורת כתובת |
| `allowlist` | שורת כתובת, אבל רק מה שברשימה נפתח |
| `free` | הכול פתוח חוץ ממה שנאסר במפורש |

### שלושה גבולות ניווט — לכל כלל בנפרד

| `scope` | מה נפתח |
| --- | --- |
| `exact` | רק הכתובת המדויקת |
| `domain` | הדומיין וכל תת-דומייניו |
| `domain_plus` | הדומיין לניווט, **וכל משאב נלווה מכל מקור** |

‏`domain_plus` הוא ברירת המחדל המומלצת, וזו הסיבה: דף לגיטימי טוען נגן, גופנים ותמונות מדומיינים אחרים. חסימתם אינה מהדקת את ההרשאה — היא שוברת בדיוק את הדף שהותר.

**‏`deny` גובר על `allow` תמיד, בלי קשר לסדר.** כלל אוסר שאפשר לנטרל בהוספת כלל מתיר אחריו אינו כלל אוסר.

### תנאים נוספים

ימים מותרים · חלון שעות יומי (כולל חלון שחוצה חצות) · מכסת צפייה יומית · משך ישיבה מרבי · תוקף לחשבון · מספר מכשירים · הורדות · חסימת צילום מסך · שמירת היסטוריה.

## הסדר שבו נבדקים התנאים

מהכללי לפרטני, ועוצרים בראשון שנכשל. **הסדר אינו קוסמטי:** לומר "הכתובת אינה ברשימה" למשתמש שמכסתו נגמרה זו תשובה נכונה טכנית ומטעה לחלוטין — היא שולחת אותו לבקש כלל נוסף במקום לומר לו לחזור מחר.

```
מצב החשבון → תוקף → יום מותר → חלון שעות → מכסה יומית → משך ישיבה → כללי הכתובות
```

## אכיפה כפולה, ומי מכריע

האכיפה קיימת בשני מקומות, וזה מכוון:

- **באפליקציה** (`android/.../Policy.kt`) — כל לחיצה על קישור היא הכרעה, ופנייה לשרת על כל אחת הייתה הופכת גלישה לבלתי שמישה.
- **בשרת** (`lib/policy.php`) — בכל רענון מדיניות, בכל ניווט, ובכל פעימה.

**השרת הוא מקור הסמכות.** לקוח שנפרץ יכול להיתקע על מדיניות ישנה, לא להמציא לעצמו חדשה: גם ההיתר וגם רשימת הכללים מגיעים מהשרת, ופעימה שנדחית סוגרת את הדפדפן.

שני המנועים חייבים להכריע זהה. `tests/policy.php` ו-`android/.../PolicyEngineTest.kt` בודקים בכוונה את אותם מקרים; רגרסיה באחד מהם היא כתובת שצד אחד מתיר והשני חוסם.

## שתי נקודות אכיפה ב-WebView

```kotlin
shouldOverrideUrlLoading  // ניווט — לאן המשתמש הולך
shouldInterceptRequest    // כל משאב — תמונה, סקריפט, נגן
```

בלי השנייה, דף מותר יכול להיות מעטפת שטוענת בתוכה תוכן אסור. חסימה מוחזרת כתשובה ריקה ולא כ-`null` — `null` פירושו "טען כרגיל", כלומר בדיוק ההפך מהכוונה.

## התקנה

### שרת

1. להעלות את התיקייה (הפריסה האוטומטית עושה זאת).
2. לפתוח `admin/setup.php` וליצור את המנהל הראשון. **המסך נועל את עצמו** מיד אחר כך.
3. משתמשים נרשמים מהאפליקציה ומופיעים בפאנל כ"ממתינים לאישור".

בסיס הנתונים נוצר לבד ב-`data/app.sqlite`. הפריסה מחריגה אותו, ולכן הוא שורד העלאות קוד.

### אפליקציה

אין SDK של אנדרואיד בסביבת הפיתוח, ולכן ה-APK נבנה ב-GitHub Actions:

```
Actions → Build Android APK → Run workflow
```

ה-artifact הוא APK **בחתימת debug** — מספיק להתקנה ידנית בטלפון, לא לחנות. כתובת השרת נקבעת בזמן הבנייה (`-PapiBase=...`) ואינה מקודדת בקוד.

## אבטחה

- **סיסמאות** — `password_hash` ב-Argon2id כשזמין.
- **אסימוני מכשיר** — 32 בתים אקראיים; בבסיס הנתונים נשמר רק ה-SHA-256 שלהם. דליפת הטבלה אינה מספיקה כדי להתחזות למכשיר.
- **ניתוק מיידי** — השעיה מוחקת את האסימונים. הפעימה הבאה נדחית, והדפדפן נסגר.
- **הגבלת קצב** — 8 ניסיונות כניסה כושלים ברבע שעה.
- **‏CSRF** — כל טופס בפאנל נושא אסימון. הפאנל משנה הרשאות, וטופס שנשלח מאתר אחר בזמן שהמנהל מחובר הוא בדיוק התרחיש שצריך למנוע.
- **`data/`** — חסום ב-`.htaccess`, ובנוסף `index.php` שמחזיר 404.
- **מנהל אינו יכול להשעות את עצמו** — אחרת אפשר לנעול את הפאנל בלחיצה.

## בדיקות

```
php guarded-browser/tests/policy.php        # 54 — מנוע ההרשאות בבידוד
php guarded-browser/tests/integration.php   # 34 — סכימה ושאילתות אמיתיות
```

בדיקות האנדרואיד רצות ב-CI לפני כל בנייה (`./gradlew test`).

## מה לא נבדק

**האפליקציה לא הורצה מעולם.** אין SDK בסביבה, והיציאה ממנה חסומה לכל אתר מלבד גיטהאב. הקוד עובר את הבדיקות שאפשר להריץ כאן, וה-APK הראשון שייבנה ב-CI הוא הפעם הראשונה שהוא ירוץ.
