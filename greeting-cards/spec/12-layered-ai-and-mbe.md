# 12 — קובץ שכבות מה-AI, ותמיכה ב-‎`.mbe` של חבילת היצירה

נכתב ב-2026-10-25, לבקשת בעל המערכת. **זה הנושא החשוב ביותר בסטודיו העיצוב.**

> "אני רוצה שהצ'אט יחזיר לנו ממש קובץ עם שכבות — וקטורי או כמו פוטושופ — קובץ שאפשר לערוך בו גם את התמונה שהצ'אט
> יצר, לא רק את הטקסט. והנושא העיקרי: שהתוכנה תתמוך בקובץ ‎mbe שבחבילת העיצוב."

---

## 1. המצב היום, ולמה הוא לא מספיק

| היום | הבעיה |
| --- | --- |
| הצ'אט מייצר **תמונה אחת שטוחה** (רקע + קישוטים + אנשים, הכול בפיקסלים אחד ליד השני) | אי אפשר להזיז את הקשת, להחליף את העיר, להסיר עץ, לשנות צבע של אלמנט. רק להחליף את כל התמונה |
| ה-JSON מוסיף **רק טקסטים** מעל התמונה | הטקסטים עריכים; התמונה — לא |
| הקובץ שלנו (`design.json` / ‎`.gcard`) | פורמט פרטי. רק סטודיו העיצוב פותח אותו |

**היעד:** כל דבר שהצ'אט יצר הוא שכבה נפרדת שאפשר לבחור, להזיז, לשנות גודל וצבע, להסתיר, למחוק ולהחליף. והקובץ
הוא ‎`.mbe` — אותו קובץ שנפתח גם בעיצוב הרסטר (פוטושופ), בווקטורי (אילוסטרייטור) ובעימוד של חבילת היצירה.

## 2. מה זה "תמונה עריכה" — שלוש רמות

| רמה | מה עריך | איך נוצר | איכות | מתי |
| --- | --- | --- | --- | --- |
| **א. שכבות רסטר נפרדות** | כל אלמנט (רקע, דמות, מסגרת, פרח) הוא PNG שקוף משלו: הזזה, גודל, סיבוב, שקיפות, מחיקה, החלפה, פילטרים. **פיקסלים** — בעיצוב הרסטר | הצ'אט מייצר כל שכבה כתמונה נפרדת עם רקע שקוף | צילומי / ציורי מלא | ברירת המחדל |
| **ב. שכבות וקטור** | כל צורה: צבע, מדרג, קו, צורה, נקודות. הגדלה בלי איבוד איכות | הצ'אט **כותב SVG** (קוד, לא תמונה), ואנחנו ממירים לשכבות וקטור | איור שטוח / לוגו / קישוט — לא צילומי | קישוטים, מסגרות, אייקונים, לוגו |
| **ג. פירוק תמונה שטוחה לשכבות** | תמונה קיימת (גם מצ'אט רגיל) מתפרקת לרקע + אובייקטים, והרקע **מושלם** מאחוריהם | מודל ייעודי בשרת: הפרדת שכבות / הסרת רקע + השלמת רקע | תלוי במודל | כשיש AI ישיר (אסימונים) |

**שילוב — היעד:** רקע ברמה א', דמויות ואובייקטים ברמה א' (שקופים), קישוטים ומסגרות ברמה ב', טקסטים — שכבות טקסט.
תמונה ישנה (או מצ'אט שלא תומך בשכבות) — רמה ג'.

## 3. איך הצ'אט מחזיר שכבות — לפי מסלול

### מסלול 1: צ'אט + סקיל (בלי עלות לנו)

הסקיל משתנה מ"תמונה אחת" ל**תוכנית שכבות**:

1. השאלון — כמו היום (הוא טוב).
2. הצ'אט מציג **תוכנית שכבות** בטקסט: "רקע: שמיים ועיר בשקיעה · שכבה 2: קשת מוזהבת (שקופה) · שכבה 3: עצי זית
   (שקופה) · קישוט: מפריד יהלום (וקטורי) · טקסטים: 4". המשתמש מאשר או משנה.
3. הצ'אט מייצר את השכבות **אחת-אחת** (תמונה בכל תשובה, כי זו מגבלת ChatGPT): הרקע **בלי** האובייקטים, ואז כל אובייקט
   על **רקע שקוף**. קישוטים — כקוד SVG בתשובת טקסט.
4. "מעולה" ← **קובץ אחד**: ‎`.mbe` (או ‎`.gcard`) שבונה כלי הקוד של ChatGPT, עם כל השכבות במקומן.
   בלי כלי קוד — JSON + הורדת התמונות, כמו היום.

**מה לבדוק לפני שמתחייבים (🧪):**
- האם ChatGPT באמת מחזיר PNG **שקוף** ("transparent background") — ובאיזה אחוז מהמקרים.
- האם השכבות **מתאימות** זו לזו: אותה תאורה, אותה פרספקטיבה, אותו סגנון. שכבות שנוצרו בנפרד נוטות "לא להתחבר".
- האם כלי הקוד של ChatGPT ניגש לתמונות שיצר (בצילום מ-23.10 הוא יצר ‎`.gcard` עם תמונה — כנראה כן).
- כמה סבבים המשתמש מוכן לעבור. 5 שכבות = 5 תשובות.

### מסלול 2: AI ישיר באסימון (שלב 5 באפיון — `05-ai-direct-tokens.md`)

האפליקציה עצמה קוראת למודל, ולכן אין מגבלה של "תמונה אחת בתשובה":
- **יצירה בשכבות:** מודל תמונה עם רקע שקוף (למשל `gpt-image-1` עם `background: transparent`) — קריאה לכל שכבה,
  במקביל, עם אותה הנחיית סגנון. רקע — קריאה אחת בגודל הדף.
- **פירוק תמונה קיימת (רמה ג'):** מודל הפרדת שכבות (משפחת "image → layered RGBA") או שילוב של חיתוך אובייקטים
  + השלמת רקע (inpainting). כל אובייקט ← שכבה שקופה, והרקע ← שכבה שלמה.
- **וקטור:** מודל שפה שכותב SVG לקישוט, או המרת תמונה פשוטה לווקטור (vectorize).
- הכול נכנס לשכבות במסמך, וזה נשמר כ-‎`.mbe`.

**ההכרעה לבעל המערכת:** איזה ספק (OpenAI / Google / מודל פתוח בשרת), ועלות לשכבה. בלי מפתח — מסלול 1 בלבד.

### מסלול 3: עריכה אחרי — בתוכנות החבילה

כשהקובץ הוא ‎`.mbe`, "לערוך את התמונה עצמה" לא חייב להיבנות מחדש בסטודיו:
- **"פתיחה בעיצוב הרסטר"** — אותו קובץ נפתח בפוטושופ של החבילה: מחיקה, מברשת, שכפול, מסכות, תיקון צבע, (בעתיד)
  הסרת אובייקט ומילוי חכם. שמירה ← חזרה לסטודיו עם השינויים.
- **"פתיחה בווקטורי"** — עריכת נקודות וצורות של שכבות הווקטור.
- בסטודיו עצמו נשארת העריכה המהירה: מיקום, גודל, צבע, טקסט, פילטרים בסיסיים, חיתוך, מסכה.

זה בדיוק "Canva + פוטושופ" מהאפיון (`02-vision.md`): הסטודיו הוא ה-Canva, הרסטר של החבילה הוא הפוטושופ, והקובץ ביניהם
אחד.

## 4. תמיכה ב-‎`.mbe` בסטודיו

### מה צריך

| יכולת | פירוט |
| --- | --- |
| **פתיחה** | ‎`.mbe` מהמכשיר, מהצ'אט (קובץ / שיתוף), ומספריית הקבצים של החבילה (אם יש) |
| **שמירה וייצוא** | "💾 שמירה כ-‎.mbe" — עם `renditions/preview.png` (חובה) ו-`image.png` מלא |
| **שמור את מה שלא הבנת** | שכבה / שדה שהסטודיו לא מכיר (למשל מסכה מהרסטר) — נשמר כמו שהוא, מוצג מ-`renditions` אם אפשר, ומסומן "🔒 נערך ברסטר" |
| **מזהה ויומן** | `manifest.id` נשמר; כל שמירה מוסיפה שלב ל-`history/` (פורמט 1.1) |
| **מידע פרטי** | נמענים, תפקידי שכבות (`role`), תצוגה — ב-`apps/greeting-cards/` |

### מיפוי: המסמך שלנו ↔ ‎`.mbe`

| `design.json` (היום) | ‎`.mbe` | הערה |
| --- | --- | --- |
| `page.width/height` (px) | `surfaces[0]` ‏`type: "page"`, ‏`size`; ‏`units: "px"` | `units` — רשימה פתוחה בסכמה. 🧪 לוודא עם הליבה ש-`px` מקובל, או להמיר ל-`pt` |
| `page.background` / `gradient` | שכבת `vector` תחתונה: מלבן בגודל הדף עם `fill.color` / `fill.gradient` | `gradient` שלנו (זווית CSS) → `from`/`to` |
| שכבה `image` | שכבת `raster`: ‏`src: media/<sha256>.png`, ‏`box`, ‏`opacity`, ‏`visible`, ‏`locked` | חיתוך, מסכה, היפוך ופילטרים — 🧪 איך הרסטר מייצג אותם; עד אז ב-`apps/greeting-cards/` + ייצוג |
| שכבה `shape` / `element` / `icon` | שכבת `vector`, פריט נתיב: `d` (פקודות מוחלטות `M L C Q Z`), ‏`fill`, ‏`stroke` | הנתיבים שלנו כוללים `A`/`H`/`V`/`S`/`T` — **ממירים** ל-`C`/`L` בייצוא. צורה חיה — `shape` |
| שכבה `text` | פריט `type: "text"` בשכבת `vector`: `text`, ‏`box`, ‏`font`, ‏`align`, ‏`lineHeight`, ‏`fill` | צל → `effects: [{type: "shadow"}]`; קו מתאר → `stroke`; רקע לטקסט — 🧪 (קבוצה: מלבן + טקסט) |
| `{{משתנה}}` + `merge` | הטקסט כמו שהוא; הרשימה ב-`apps/greeting-cards/merge.json` | |
| `role`, `name` | `name` של השכבה; `role` ב-`apps/greeting-cards/` | |

**`kind`:** המסמך שלנו מערבב רסטר, וקטור וטקסט בעמוד אחד. הצעה: `kind: "design"` (רשימה פתוחה), או `layout` עם עמוד
אחד. **הכרעה של הצ'אט המתכלל.**

### איך הקוד מגיע (בלי תלות חיה — כלל החבילה)

- ליבת הפורמט (`creative-suite/mbe-core/src/js`) מסונכרנת **כעותק** ל-`greeting-cards/editor/js/mbe/` — שורה ב-
  `creative-suite/mbe-core/apps.json` (בבעלות הצ'אט המתכלל) ו-`tools/sync`.
- הממיר `design ↔ mbe` — בסטודיו (`js/mbe-io.js`), כמו `raster-studio/assets/js/mbe-io.js`.
- PHP — רק אם צריך שמירה בשרת (`lib/mbe/`).

## 5. הצטרפות לחבילת היצירה

**בעל המערכת הציע לצרף את הסטודיו לחבילה.** מה זה אומר:

| מה | פירוט |
| --- | --- |
| חבר בצוות | שורה ב-`creative-suite/team/roster.json` — ‏`role: "design-studio"`, ה-session של הצ'אט הזה, בבעלות `greeting-cards/` |
| הקובץ | ‎`.mbe` הוא פורמט השמירה העיקרי; ‎`.gcard` נשאר לייבוא מצ'אטים ישנים |
| משותף | **בינה מלאכותית לשכבות** — גם לרסטר יש שלב ר3 (הסרת רקע, מילוי, החלפת רקע). לפי "כלל השתיים" — מודול משותף, לא שניים |
| תלות | הליבה (‎`.mbe`); גאומטריה (וקטורי) — להמרת נתיבים; שכבות וצבע (רסטר) — להצגת שכבות רסטר עם מסכות ומצבי מיזוג |
| מה לא משתנה | הסטודיו נשאר אפליקציה עצמאית (משתמשים, נתונים, APK), ממוקד בטלפון ובתבניות — ה-Canva של החבילה |

**הבקשה נשלחת לצ'אט המתכלל** (הוא מחליט על צירוף, על `kind` ועל `apps.json`).
