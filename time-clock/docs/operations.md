# שעון נוכחות — תפעול: גיבוי, שחזור ותקלות

## 1. איפה הנתונים
| מה | איפה | הערה |
| --- | --- | --- |
| כל המידע: חברות, עובדים, דיווחים, תיקונים, היעדרויות, יומן | `time-clock/data/time-clock.sqlite` | מצב WAL: לצידו `-wal` ו-`-shm` |
| אישורי מחלה (מידע רפואי) | `time-clock/data/certs/` | שם אקראי לכל קובץ; הרשומה במסד, הקובץ בתיקייה |

- הפריסה (`deploy.yml`) מחריגה את `data/*.sqlite*` ואת `data/certs/`, ורצה בלי `--delete`: הפריסה לא דורסת ולא מוחקת אותם.
- **אין גיבוי אוטומטי של האפליקציה הזו.** ב-`deploy.yml` יש גיבוי רק לאפליקציות אחרות (למשל `payments/data/backups/`). אם לשרת יש גיבוי כללי (מהאחסון), אני לא יודע אם הוא כולל את `data/`.
- **אובדן `data/` = אובדן כל הדיווחים.** אי אפשר לשחזר אותם מהקוד.

## 2. איך מגבים (בטוח גם כשהמסד בשימוש)
העתקת קובץ ה-`.sqlite` לבדו בזמן פעילות עלולה להניב גיבוי פגום, כי חלק מהכתיבות עוד ב-`-wal`. לכן:

```php
<?php // php backup.php /path/to/time-clock/data /path/to/backups
[$data, $out] = array_slice($argv, 1);
$dest = $out . '/time-clock-' . gmdate('Ymd-His') . '.sqlite';
$p = new PDO('sqlite:' . $data . '/time-clock.sqlite');
$p->exec("VACUUM INTO " . $p->quote($dest));          // עותק עקבי, גם בזמן כתיבה (SQLite 3.27 ומעלה)
$q = new PDO('sqlite:' . $dest);
if ($q->query('PRAGMA integrity_check')->fetchColumn() !== 'ok') { unlink($dest); fwrite(STDERR, "הגיבוי פגום\n"); exit(1); }
echo $dest, "\n";
```
נבדק מקומית (SQLite 3.45): העתק נוצר ועבר `integrity_check`. אם בשרת הגרסה ישנה יותר, `sqlite3 time-clock.sqlite ".backup out.sqlite"` עושה אותו דבר.

**אישורי המחלה:** מעתיקים את `data/certs/` כמות שהיא (קבצים רגילים, אין בעיית WAL). את הגיבוי של התיקייה ושל המסד לוקחים **באותו רגע**, כדי שלא יהיו רשומות בלי קובץ.

## 3. שחזור
1. לעצור כתיבה: אין כלי לכך; בפועל מתאמים שעה שקטה (העמדה והעובדים כותבים בכל כניסה ויציאה).
2. להחליף את `time-clock.sqlite` בגיבוי, ולמחוק את `time-clock.sqlite-wal` ו-`-shm` הישנים.
3. להחזיר את `data/certs/` מאותו גיבוי.
4. לפתוח את האפליקציה: המיגרציות (`CREATE TABLE IF NOT EXISTS`, `ALTER` חד-פעמי) משלימות אוטומטית עמודות שנוספו אחרי הגיבוי.
5. לבדוק: מסך "היום" נטען, כרטיס עובד נפתח, ואישור מחלה אחד נפתח.
- **מה נאבד:** כל דיווח אחרי זמן הגיבוי. עובדים יצטרכו לדווח מחדש או לבקש תיקון.

## 4. הקשר לפרטיות ולשמירה
- אישור מחלה נמחק אוטומטית בתום משך השמירה (ברירת מחדל 7 שנים), **אבל עותק בגיבוי לא יימחק**. לכן גיבוי שנשמר שנים מחזיק גם אישורים שנמחקו.
- **הצעה:** לשמור גיבויים מוגבלים בזמן (למשל 30 יום), ולא להפיץ אותם. החלטה על כך — שלך ושל איש מקצוע, וגם תנאי לדף הפרטיות.
- גיבוי הוא עותק מלא של מידע אישי ורפואי: לאחסן בהרשאה מצומצמת, ולא בתיקייה נגישה מהאינטרנט.
