# סורק וואטסאפ חכם

שאילת שאלות בשפה חופשית על היסטוריית הוואטסאפ שלך: "מי התכתב איתי ב-16
בחודש?", "מי שלח אסמכתא על תשלום מעל 500 ₪?" — והבינה עונה על סמך
ההודעות שנקלטו.

## למה המבנה הזה, ולא "כפתור אחד בדפדפן"

הבקשה המקורית הייתה דף בדפדפן בטלפון שבלחיצת כפתור סורק את כל הוואטסאפים.
**דף בדפדפן אינו יכול לקרוא אפליקציה אחרת** — זו חומת בידוד של מערכת
ההפעלה, לא פער שאפשר לתכנת סביבו. וגם ה-WhatsApp Business API הרשמי מקבל
רק הודעות חדשות שמגיעות מרגע החיבור, בלי היסטוריה ובלי החשבון הפרטי.

הדרך היחידה שבה תוכנה במכשיר **קוראת** את מה שמוצג בוואטסאפ היא **שירות
נגישות** של אנדרואיד — אותו מנגנון שקוראי מסך משתמשים בו. לכן המערכת
מפוצלת לשלושה חלקים:

```
┌─ אפליקציית הגשר (אנדרואיד) ─┐   ┌─ השרת (PHP) ─┐   ┌─ הדפדפן ─┐
│ שירות נגישות קורא את מסך    │──▶│ אחסון מוצפן   │◀──│ שאלות     │
│ הוואטסאפ ומזרים הודעות      │   │ + מנוע בינה   │   │ ותשובות   │
└────────────────────────────┘   └───────────────┘   └───────────┘
```

- **הדפדפן בטלפון** הוא הדף שבו שואלים ומקבלים תשובות (זה מה ש"יושב
  בטלפון" מהבקשה המקורית).
- **הגשר** הוא אפליקציית האנדרואיד שקוראת את הוואטסאפ בפועל.
- **השרת** שומר את ההודעות (מוצפנות) ומריץ את הבינה — כך אפשר לשאול מכל
  מכשיר. השמירה בשרת נבחרה במפורש.

## מצב הפיתוח — מה עובד ומה שלד

| חלק | מצב |
| --- | --- |
| שרת: אחסון מוצפן, בליעה, מניעת כפילויות, שאלה-תשובה רב-ספקית | **עובד ונבדק** (`tests/flow.php`) |
| דפדפן: התקנה, כניסה, חשבונות, שאלות, הגדרות, אסימון צימוד | **עובד** |
| גשר אנדרואיד: התחברות, שירות נגישות, בליעה לשרת | **שלד** — נבנה ב-CI, טרם רץ על מכשיר |

השלד של הגשר עוקב אחרי אותו דפוס כמו `guarded-browser/android`: הקוד עובר
בנייה ב-GitHub Actions, וההרצה הראשונה על מכשיר אמיתי היא הבדיקה הראשונה
של לוגיקת הסריקה.

## הצד שעובד: השרת

```
whatsapp-ai-scanner/
  index.html          דף הבעלים (עברית, RTL, מהנייד קודם)
  assets/             css / js / icon
  api/index.php       נקודת הקצה — בעלים וגשר
  lib/
    db.php            SQLite, סכימה, שורת הבעלים
    crypto.php        הצפנת ההודעות והמפתח במנוחה (משותף עם claude-tasks)
    auth.php          כניסת בעלים (עוגייה) + אסימון גשר (Bearer)
    accounts.php      חשבונות הוואטסאפ שהוגדרו
    ingest.php        קליטת אצוות, INSERT OR IGNORE נגד כפילויות
    query.php         איסוף הודעות בחלון + בניית הקשר + פנייה למודל
    settings.php      הגדרות ה-AI של הבעלים
    ai.php            שכבת רב-ספקים (Anthropic/OpenAI/Google), משותף
  data/               מסד מוצפן + מפתח. מוחרג מהפריסה, חסום ב-.htaccess
  tests/flow.php      בדיקת קצה-לקצה בלי רשת ובלי מפתחות
  android/            אפליקציית הגשר (Kotlin) — נבנית ב-CI
```

### פרטיות ואבטחה

- **הצפנה במנוחה.** גוף כל הודעה, שם השולח ושם הצ'אט נשמרים מוצפנים
  (`crypto.php`, sodium/GCM). המפתח יושב ב-`data/secret.key`, בקובץ נפרד
  מהמסד ובהרשאות בעלים בלבד. מי שמשיג רק את אחד מהם אינו מקבל דבר. זו אותה
  שכבה שמגינה על הסודות ב-`claude-tasks`.
- **`data/` חסומה** לגישה ישירה מהדפדפן (`.htaccess`), ומוחרגת מהפריסה כדי
  ש-`rsync` לא ידרוס את מסד ההודעות של המשתמש.
- **שני ערוצי הרשאה נפרדים.** הבעלים נכנס בסיסמה ומקבל עוגייה; הגשר מזדהה
  באסימון צימוד. אסימון גשר שדלף יכול רק להזרים הודעות — לא לקרוא
  היסטוריה ולא לשנות הגדרות. אפשר לגלגל אותו ("גלגל אסימון חדש") ולנתק
  מכשיר שאבד.
- **מפתח ה-AI מוצפן** ומוחזר לדפדפן רק כזנב בן 4 תווים לזיהוי.

### מגבלת ההקשר בשאלות

היסטוריית וואטסאפ שלמה גדולה מכל חלון הקשר של מודל, ולכן `query.php` מצמצם
לפני הפנייה: לפי טווח תאריכים (אם צוין) ולכל היותר 400 ההודעות העדכניות
בחלון. זו גישת **חלון**, לא חיפוש סמנטי על כל ההיסטוריה. שאלה רחבה בלי
טווח תאריכים תתבסס על העדכניות בלבד, והתשובה אומרת זאת.

## אפליקציית הגשר (אנדרואיד)

```
android/app/src/main/
  java/com/mbeplus/wascanner/
    SetupActivity.kt    כתובת שרת, אסימון, מזהה חשבון, הפעלת השירות
    ScannerService.kt   שירות הנגישות — קורא את מסך הוואטסאפ
    Api.kt              POST לשרת, ext_id יציב נגד כפילויות
    Store.kt            הגדרות מוצפנות במכשיר (EncryptedSharedPreferences)

```

### מה שירות נגישות **כן ולא** יכול

שירות נגישות רואה רק את מה שמצויר על המסך כרגע. **אין לו גישה למסד ההודעות
של וואטסאפ.** לכן "לסרוק את כל ההיסטוריה" פירושו לגלול בצ'אט ולתת לשירות
לראות בועה אחרי בועה. הבליעה מסירה כפילויות (`ext_id`), כך שגלילה חוזרת על
אותו קטע בטוחה.

- מזהי ה-view (`message_text`, `conversation_contact_name`) נכונים לגרסאות
  וואטסאפ רבות אך **וואטסאפ משנה אותם בין גרסאות**. הם נקודת התחלה
  לכוונון, לא חוזה.
- **פתוח וטרם מומש:** גלילה אוטומטית לאיסוף היסטוריה, פענוח בועת התאריך
  לחותמת זמן מדויקת, והסקת כיוון ההודעה (נכנסת/יוצאת) מהמיקום. אלה הרכיבים
  שהכי תלויים בגרסה ומחייבים מכשיר אמיתי — ולכן הם מסומנים `TODO` בקוד ולא
  נוחשו.

### בנייה

אין SDK של אנדרואיד בסביבת הפיתוח, ולכן ה-APK נבנה ב-GitHub Actions:
Actions → **Build WA-Scanner bridge APK** → Run workflow. ה-artifact הוא
APK בחתימת debug להתקנה ידנית. כתובת השרת נקבעת בזמן הבנייה (`-PapiBase`).

## חובה לדעת: זה החשבון שלך בלבד

הכלי קורא את הוואטסאפ **שלך**, במכשיר **שלך**, לפי בקשתך המפורשת. שירות
נגישות דורש הפעלה ידנית של המשתמש בהגדרות המערכת — אנדרואיד לא מאפשר
להפעילו בשקט, בכוונה.

- **אין להשתמש בו כדי לקרוא וואטסאפ של אדם אחר.** זו חדירה לפרטיות, ולרוב
  גם עבירה על החוק.
- אוטומציה של קריאת וואטסאפ עשויה לנגוד את **תנאי השימוש של וואטסאפ**, עד
  כדי חסימת החשבון. זה סיכון של המשתמש, ומכאן ההפרדה: הגשר קורא בלבד ואינו
  שולח הודעות בשם המשתמש.
- ההודעות של אנשים אחרים שמופיעות בצ'אטים שלך נשמרות מוצפנות בשרת שלך.
  מחיקת חשבון מוחקת גם את כל ההודעות שנקלטו תחתיו (מיידית, `ON DELETE
  CASCADE`).

## מה עוד לא הוכרע

- **חיפוש על פני כל ההיסטוריה** (מעבר לחלון של 400) — דורש אינדקס וקטורי
  (embeddings/RAG). כרגע חלון בלבד.
- **גלילה אוטומטית** בגשר לאיסוף היסטוריה עמוקה.
- **מדיה ואסמכתאות כתמונה** — כרגע נקלט טקסט בלבד. זיהוי אסמכתת תשלום
  שהגיעה כתמונה ידרוש OCR או מודל ראייה.
- **פענוח זמן מדויק** מבועת התאריך של וואטסאפ.
