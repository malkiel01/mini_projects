# השלמות לשיפוץ

ניהול רשימת הפינישים שנשארו בסוף שיפוץ. לכל השלמה: **תמונות או סרטונים**,
**תיאור קצר**, **תיאור מפורט**, **על מי המטלה מוטלת** ו**מעקב אחרי הביצוע**.

הכלי נבנה לשימוש בסיור באתר, בטלפון וביד אחת: מצלמים את הליקוי, כותבים מה חסר,
מסמנים אחראי — וממשיכים.

## מה יש בפנים

* **תיעוד ויזואלי** — צילום ישיר מהמצלמה, סרטון, או בחירה מהגלריה. לכל קובץ
  נוצרת תמונה ממוזערת (גם לסרטונים — פריים מתוך הסרטון), ותמונות גדולות
  מכווצות ל‑1600px לפני השמירה.
* **סטטוס** — פתוח / בתהליך / בוצע, עם סימון מהיר בלחיצה אחת ופס התקדמות כללי.
* **אחראי ומיקום** — שדות חופשיים עם השלמה אוטומטית מהערכים שכבר בשימוש,
  ומשמשים גם לסינון.
* **עדיפות ותאריך יעד** — השלמות שעבר זמנן מסומנות באדום.
* **סינון ומיון** — לפי סטטוס, אחראי, מיקום, חיפוש חופשי, ומיון לפי תאריך יעד,
  דחיפות או מיקום.
* **עבודה ללא אינטרנט** — האפליקציה נשמרת כ‑PWA וניתנת להתקנה על מסך הבית.

## איפה נשמרים הנתונים

מקור האמת הוא הדפדפן: הכול נכתב ל‑IndexedDB, כולל הקבצים עצמם (כ‑Blob, לא
כ‑base64). האפליקציה עובדת במלואה כך — בלי שרת, בלי חשבון ובלי העלאה לשום מקום.

מעבר לזה יש שתי דרכים להעביר את הרשימה:

1. **גיבוי מקומי** — ייצוא לקובץ JSON יחיד עם המדיה בתוכו, וייבוא במכשיר אחר.
   מתאים להעברה חד־פעמית.
2. **סנכרון מול שרת** (אופציונלי) — ראו למטה.

## סנכרון בין כמה אנשים

`api.php` הוא שרת סנכרון קטן, מבוסס קבצים, בלי מסד נתונים. מי שמעלה אותו לשרת
PHP מקבל רשימה משותפת בין כל מי שמחזיק באותו אסימון — בעל הבית, הקבלן ובעלי
המקצוע, כל אחד מהמכשיר שלו.

**התקנה:**

1. להעלות את התיקייה לשרת עם PHP, ולוודא ש‑`data/` ניתנת לכתיבה.
2. לפתוח את האפליקציה, ובהגדרות להזין את כתובת התיקייה (למשל
   `https://example.com/renovation-punchlist/`).
3. האסימון נוצר אוטומטית בבקשה הראשונה ונשמר ב‑`data/config.json` — להעתיק
   אותו משם לשדה "אסימון גישה", ולחלוק אותו עם שאר המשתמשים.

**איך זה מתנהג:** כל מחזור סנכרון דוחף שינויים מקומיים, מעלה קבצים חדשים, מושך
שינויים מהשרת ומוריד קבצים חסרים. בהתנגשות מנצחת הרשומה עם `updatedAt` המאוחר.
מחיקות נשמרות כ‑tombstones ולכן מתפשטות בין המכשירים במקום "לחזור לחיים"
בסנכרון הבא.

`data/` חסומה לגישה ישירה דרך `.htaccess` — הן `config.json` והן המדיה מוגשים
רק דרך `api.php`, אחרי בדיקת אסימון.

## תחזוקה

כל הנתיבים יחסיים, כך שהתיקייה עובדת מכל מיקום בשרת.

האפליקציה רושמת service worker (עבודה ללא אינטרנט) בהיקף
`.../renovation-punchlist/` בלבד — הוא לא נוגע בשאר הכלים בריפו.
**אחרי כל שינוי בקבצים כאן חובה להעלות את `CACHE_VERSION` ב‑`service-worker.js`**,
אחרת מבקרים חוזרים ימשיכו לקבל את הגרסה הישנה מהמטמון.

### מבנה

| קובץ | תפקיד |
| --- | --- |
| `assets/js/db.js` | שכבת IndexedDB — משימות, מדיה, הגדרות, חותמות זמן לסנכרון |
| `assets/js/media.js` | תמונות ממוזערות, כיווץ, שליפת פריים מסרטון |
| `assets/js/sync.js` | מחזור הסנכרון והמיזוג מול השרת |
| `assets/js/app.js` | הממשק: רשימה, סינון, עורך, מציג מדיה, גיבוי |
| `api.php` | שרת הסנכרון (אופציונלי) |
