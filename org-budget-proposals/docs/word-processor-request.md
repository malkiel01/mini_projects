# בקשה לצ'אט הפלטפורמה: עורך תמלילים — אפליקציה משלו, ותוסף לאפליקציות אחרות

> נכתב בצ'אט של הצעות תקציב (`org-budget-proposals/`), לפי בקשת בעל המערכת (2026-10-20).
> **הקובץ הזה אינו משנה את הפלטפורמה ולא בונה את העורך** — הוא האפיון, להעברה לצ'אט הפלטפורמה.
> שם מחליטים, פותחים צ'אט חדש לעורך, ומחזירים לכאן הנחיות חיבור (מה קוראים, מה שולחים, איך מזדהים).

## המטרה

עורך מלל **ממש כמו Word** — עימוד, סרגל כלים, כותרות, הדגשה, ריווח, פסקאות, מספור עמודים, תמונות
עם גלישת טקסט — שנבנה **פעם אחת** ומשמש כמה אפליקציות.

1. **אפליקציה רגילה בפלטפורמה** — `word-processor/` ("עורך תמלילים"), עם `app.json`, משתמשים משלה
   ומסמכים משלה, כמו כל אפליקציה (CLAUDE.md: "אפליקציה פנימית עצמאית מהמעטפת").
2. **תוסף** — אפליקציה אחרת מטמיעה את העורך בתוך המסך שלה. **בלי שם משתמש וסיסמה בעורך**: האפליקציה
   המארחת מזדהה מול העורך בטוקן ישיר, והמשתמש שלה עורך מיד.

הצרכן הראשון: **הצעות תקציב** — "תכנית העבודה" (ההקדמה של ההצעה), שהיום היא תיבת טקסט עם `# ` ו-`- `.

## א. העורך — מה הוא יודע לעשות

כל אלה — גם באפליקציה עצמה וגם כתוסף. "כמו Word" = מה שהמשתמש רואה בעריכה הוא מה שיודפס.

### עימוד ותצוגה
- **עמודים אמיתיים על המסך** (A4 / Letter, לאורך / לרוחב), שוליים, מעבר עמוד ידני, ותצוגה של איפה
  כל עמוד נגמר — תוך כדי הקלדה.
- זום (כמו בעריכה כטבלה כאן: ברירת מחדל מותאמת למסך, − / + / התאמה).
- מימין לשמאל כברירת מחדל, ופסקה משמאל לימין לפי בחירה; מספרים ואנגלית בתוך עברית — בסדר הנכון.

### סרגל כלים
- **כותרות** — סגנונות: כותרת 1–3, כותרת מסמך, רגיל; כל סגנון ניתן לעריכה (גופן, גודל, צבע, קו תחתון, ריווח).
- **גופן** — מרשימה של גופנים עם עברית (Arial, David, Frank Ruehl, Narkisim, Miriam ועוד), **גודל**,
  **מודגש**, *נטוי*, קו תחתון, קו חוצה, צבע טקסט והדגשה, כתב עילי ותחתי.
- **פסקה** — יישור (ימין / מרכז / שמאל / מיושר), הזחה, **ריווח שורות** (1 / 1.15 / 1.5 / 2 / מדויק),
  **ריווח לפני ואחרי פסקה**, **ריווח בין תווים**.
- **רשימות** — תבליטים, ממוספרות (1. 2. / א. ב. / i. ii.), רב-רמות.
- **טבלאות** — הוספה, שורות ועמודות, מיזוג תאים, גבולות ומילוי.
- ביטול / ביצוע מחדש, העתקת עיצוב, **הדבקה מ-Word עם העיצוב**.

### מספור עמודים — כמה אפשרויות
- מיקום: למעלה / למטה; ימין / מרכז / שמאל.
- תבנית: `1` · `עמ' 1` · `1 מתוך 12` · `- 1 -` · אותיות (א, ב, ג).
- מתחיל מ-מספר נבחר; בלי מספר בעמוד הראשון; כותרת עליונה ותחתונה עם טקסט חופשי.

### תמונות
- הוספה (העלאה, הדבקה, גרירה), שינוי גודל בגרירה, חיתוך פשוט, סיבוב.
- **גלישת טקסט** כמו ב-Word: בשורה עם הטקסט · ריבוע · צמוד · מעל ומתחת · מאחורי הטקסט · לפני הטקסט.
- יישור, מרחק מהטקסט, כיתוב מתחת לתמונה.

### פלט
- **Word (‎.docx)** נאמן — העיצוב, העמודים, מספור העמודים, התמונות והגלישה.
- **PDF** — מהתצוגה (או מהשרת), כמו מה שעל המסך.
- **HTML** נקי — לתצוגה בתוך אפליקציה אחרת.
- ייבוא מ-Word (‎.docx) — לפחות כותרות, עיצוב תווים ופסקאות, רשימות, טבלאות ותמונות.

## ב. המלצה טכנית (ההחלטה — בצ'אט הפלטפורמה / העורך)

- **מנוע עריכה בקוד פתוח, לא מאפס:** ProseMirror / TipTap (MIT) — מבנה מסמך מוגדר, היסטוריה,
  הדבקה, הרחבות. עמודים אמיתיים ומספור עמודים — הרחבה משלנו מעל המנוע (חישוב שבירה לפי גובה, כמו
  שנעשה כאן באקסל: `org-budget-proposals/lib/export.php`, `Sheet::paginate`).
- **לא** CKEditor / TinyMCE: העימוד (pagination) ופלט Word אצלם בתשלום.
- **לא** OnlyOffice / Collabora: נאמנות מלאה ל-Word, אבל דורשים שרת מסמכים (Docker) — לא רץ ב-cPanel.
- **פלט Word בשרת (PHP)** — כמו שעושים כאן היום (`export_docx`, WordprocessingML ידני, מימין לשמאל,
  שדות עמוד); או בדפדפן עם `docx` (npm, MIT). שני הכיוונים עובדים בלי שרת נוסף.
- המסמך נשמר כ-JSON של המנוע (המקור) + HTML (לתצוגה). Word ו-PDF — נגזרים ממנו.

## ג. התוסף — איך אפליקציה אחרת מטמיעה את העורך

### ההזדהות: טוקן ישיר, בלי משתמש וסיסמה

```
דפדפן (אפליקציה מארחת)        שרת האפליקציה המארחת            עורך התמלילים
        │ פתיחת "עריכה" ──────▶ │
        │                       │ POST word-processor/api.php?action=embed_session
        │                       │   { client, secret, doc, user:{id,name}, can:"edit"|"view", page? } ──▶
        │                       │ ◀── { embed_url (טוקן חד-פעמי, 60 שניות), doc } ──
        │ ◀── embed_url ────────│
        │ iframe src=embed_url ───────────────────────────────────────▶ │ טוקן ← סשן עריכה למסמך הזה בלבד
        │ ◀════════════════ postMessage: ready / change / saved / height / close ═══════▶ │
```

1. **רישום לקוחות** — כל אפליקציה מארחת רשומה בעורך: `client_id`, `client_secret` (נשמר כ-hash),
   ו**מקורות מותרים** (origin) להטמעה. כמו `sso.php` — שורה ב-app.json של המארחת והמנהל מאשר?
   או רישום בממשק המנהל של העורך — להחלטתכם.
2. **הסוד נשאר בשרת המארח** — הדפדפן מקבל רק `embed_url` עם טוקן חד-פעמי, קצר, קשור למסמך, ללקוח,
   למשתמש ולהרשאה (עריכה / צפייה).
3. **בתוך ה-iframe** — הסשן של העורך בזיכרון (Bearer), **לא עוגייה**: כך זה עובד גם כשהמארחת יושבת
   בדומיין אחר (עוגיות צד שלישי חסומות), וגם אחרי שאפליקציה יוצאת לדומיין משלה.
4. **השער** — לעורך `"gate": true`, וכתובות ההטמעה (`embed.html`, `api.php?action=embed_*`) ב-`"public"`:
   המשתמש של המארחת אינו משתמש פלטפורמה עם הרשאה לעורך. ההגנה — הטוקן.
5. **מי עורך** — שם המשתמש מגיע מהמארחת (`user.name`), לרישום "נערך על ידי" ולהיסטוריה. העורך לא
   פותח לו חשבון.
6. **CSP / `frame-ancestors`** — רק המקורות המותרים של הלקוח.

### איפה המסמך יושב

המלצה: **העורך הוא שירות מסמכים** — המסמך והתמונות נשמרים בעורך, במרחב של הלקוח
(`client:doc`), והמארחת שומרת רק את מזהה המסמך. ולצד זה **API שרת-לשרת** (עם `client_secret`)
שבו המארחת מקבלת הכול, בכל רגע:

| פעולה | מה מחזירה | לשם מה (בהצעות תקציב) |
| --- | --- | --- |
| `doc_create` / `doc_copy` | מזהה מסמך חדש (העתק — גם עם החלפת שנה בטקסט) | הצעה חדשה "על בסיס" השנה הקודמת |
| `doc_export?format=html` | HTML נקי + תמונות | מסך המסמך / PDF של ההצעה |
| `doc_export?format=ooxml` | גוף WordprocessingML + קבצי התמונות | שילוב בתוך ה-Word שההצעה מייצרת (לא קובץ נפרד) |
| `doc_export?format=docx` / `pdf` | קובץ שלם | הורדה של ההקדמה לבד |
| `doc_export?format=text` | טקסט עם שורות | אקסל (תא טקסט), חיפוש |
| `doc_import` | — | העברת תכנית העבודה הקיימת (`# ` / `- `) למסמך |
| `doc_delete` | — | מחיקת הצעה |

כך אפליקציה שיוצאת לדומיין משלה ממשיכה לעבוד (העורך הוא שירות), ויכולה גם לייצא את כל המסמכים שלה
ולהתנתק ממנו.

### מצב "קטע" — כשהמסמך הוא חלק ממסמך גדול
בהצעות תקציב ההקדמה היא קטע בתוך מסמך שהמארחת בונה (שער, ריכוז, קופות). אז:
- המארחת שולחת ב-`embed_session` את **הגדרות העמוד שלה** (`page`: גודל, שוליים, גופן ברירת מחדל,
  גדלים, מספור עמודים) — העורך מציג את הקטע בדיוק כמו שהוא ייראה במסמך.
- **בקשה לבעל המערכת להכריע:** האם בעריכת קטע העורך גם **משנה** את הגדרות העמוד ומספור העמודים
  (ומחזיר אותן למארחת, שתשמור אותן ב"עיצוב המסמך" שלה), או רק מציג אותן? ההמלצה: משנה ומחזיר —
  כך יש מקום אחד לעימוד, בתוך העורך, ו"🖋️ עיצוב המסמך" שבהצעות תקציב מצטמצם לקישור אליו.

### אירועי postMessage (מוצע)
- עורך ← מארחת: `ready`, `change {dirty}`, `saved {doc, version}`, `height {px}` (כשמוטמע בלי מסגרת
  קבועה), `page {settings}` (מצב קטע), `error {message}`.
- מארחת ← עורך: `save`, `set_page {settings}`, `focus`, `readonly {bool}`.
- כל הודעה נבדקת לפי `origin` משני הצדדים.

## ד. מה ייעשה בהצעות תקציב (בצ'אט הזה, אחרי ההנחיות)

1. **"שער ותכנית"** — תיבת הטקסט של תכנית העבודה מתחלפת בעורך המוטמע (מסך מלא בטלפון, חלון רחב במחשב).
2. **מעבר חד-פעמי** — `doc_import` לכל תכנית עבודה קיימת (`# ` פרק, `## ` כותרת, `- ` תבליט).
3. **הצעה חדשה על בסיס קודמת** — `doc_copy` עם החלפת השנה, במקום `year_shift`.
4. **הפלט** — Word: גוף ה-OOXML של העורך בתוך הקובץ; מסך / PDF: ה-HTML; אקסל: טקסט (או HTML פשוט).
5. **עיצוב המסמך** — לפי ההכרעה במצב "קטע".
6. בלי עורך זמין (העורך לא עונה) — ההקדמה מוצגת לקריאה מה-HTML האחרון ששמרנו, ועריכה — "העורך לא זמין כרגע".

## ו. שאלות פתוחות

1. מיקום המסמכים — בעורך (מומלץ) או אצל המארחת?
2. רישום לקוחות — ב-app.json של המארחת ואישור מנהל (כמו `sso`), או בממשק של העורך?
3. מצב קטע — העורך משנה את הגדרות העמוד ומחזיר (מומלץ), או רק מציג?
4. עריכה במקביל של שני אנשים באותו מסמך — עכשיו (נעילה: "פתוח לעריכה אצל X") או בהמשך (שיתוף בזמן אמת)?
5. גרסאות — היסטוריה של המסמך (מי, מתי, שחזור) — בשלב הראשון?
