# אפליקציית מצלמות

ניהול מצלמות IP מהדפדפן, בתוך אוסף הכלים: שידור חי, הקלטה (ידני / רציף /
לפי אדם / לו"ז), נגן עם ציר זמן יומי, צילומי מסך, וקיטלוג בתיקיות נושא.

| מסמך | מה בו |
| --- | --- |
| [`SPEC.md`](./SPEC.md) | **האפיון, מוכרע.** מקור האמת, כולל מה נדחה ולמה |
| [`lib/db.php`](./lib/db.php) | הסכימה (SQLite): משתמשים, מצלמות, גשרים, הקלטות, נושאים, פקודות, יומן |
| [`lib/auth.php`](./lib/auth.php) | חשבונות, כניסה, שלושה תפקידים |
| [`lib/cameras.php`](./lib/cameras.php) | מצלמות ותיקיות; מה הגשר מקבל |
| [`lib/recordings.php`](./lib/recordings.php) | הקטלוג: הקלטות, נושאים, סימניות, ציר זמן |
| [`lib/ingest.php`](./lib/ingest.php) | קליטה מתיבת ה-FTP, ממוזערות, מדיניות מחיקה, תחזוקה |
| [`lib/bridge.php`](./lib/bridge.php) | צד השרת של הגשר: צימוד, heartbeat, פקודות, חי |
| [`api.php`](./api.php) · [`upload.php`](./upload.php) · [`media.php`](./media.php) · [`cron.php`](./cron.php) | הנקודות שהדפדפן והגשר פונים אליהן |
| [`bridge/bridge.py`](./bridge/bridge.py) · [`bridge/install.sh`](./bridge/install.sh) | הגשר שרץ ברשת הביתית |

## איך זה עובד — בשתי שורות

השרת (Bluehost) לא יכול להגיע למצלמה שמאחורי הראוטר. לכן **המצלמה דוחפת
אליו ב-FTP** (עובד מיד, אירועים וצילומים), ו**גשר קטן ברשת הביתית** מוסיף
חי, PTZ והקלטה בכל המצבים. שניהם נכנסים לאותו קטלוג. ההסבר המלא ב-`SPEC.md` §2.

## הפעלה ראשונה

1. לפתוח את הדף → מסך ההתקנה יוצר את המנהל (מחוברת לפלטפורמה: הנכנס הראשון הוא המנהל).
2. **+ מצלמה** — מספיק שם. המפתח (למשל `cam-1`) הוא שם תיקיית ה-FTP.
3. **FTP** (בלי גשר): ב-cPanel → FTP Accounts, חשבון שתיקיית הבית שלו היא
   `…/camera-app/data/inbox/<מפתח>`. באפליקציית Reolink → הגדרות → FTP:
   השרת, המשתמש והסיסמה של החשבון; העלאת וידאו+תמונה באירוע. הקבצים
   נקלטים תוך דקה מסיום ההעלאה.
4. **cron** (מומלץ, לא חובה): cPanel → Cron Jobs, כל דקה:
   `php -q /home/<user>/public_html/mini_projects/camera-app/cron.php`.
   בלעדיו הקליטה רצה "בדרך אגב" כשמישהו משתמש בדף או כשהגשר מדווח.
5. **גשר** (לחי, PTZ, רציף, ידני): מסך "גשרים" → + גשר → קוד. על הקופסה:
   `curl -fsSL <שרת>/camera-app/bridge/install.sh | sudo bash -s -- <שרת>/camera-app/ <קוד>`.
   ואז בעריכת המצלמה: כתובת, סיסמה, גשר.

## כניסה דרך הכלים הדיגיטליים (הפלטפורמה)

לפי `platform/docs/auth.md` ו-`sso.md` סעיף 0. הקוד: `lib/auth.php`, "כניסה דרך הפלטפורמה".

- **מחוברת** (השער פעיל): מי שיש לו הרשאה נכנס **אוטומטית** — `$_SERVER['PLATFORM_USER']`.
  החשבון נמצא לפי `sub`, ואם אין — לפי **המייל** שבחשבון (המנהל ממלא אותו בעריכת משתמש). אין
  התאמה → מסך חד-פעמי: "יש לי כבר חשבון" (שם משתמש וסיסמה ישנים, 5 ניסיונות → רבע שעה נעילה) או
  "אין לי חשבון" — חשבון חדש, פעיל, **צופה** (אין כאן הרשמה עצמית, אז התפקיד הנמוך). מי שבחר חדש
  ונזכר — מחבר את הישן ב"החשבון שלי".
- מחוברת — חסומים: כניסה והתקנה בסיסמה, יצירת משתמש עם סיסמה, שינוי ואיפוס סיסמה. יציאה — מהפלטפורמה.
- **הסיסמאות לא נמחקות.** מנותקת (אין `PLATFORM_USER`) — הכניסה בסיסמה חוזרת לעבוד, כמו קודם.
- מערכת ריקה ומחוברת: הנכנס הראשון הוא המנהל (במקום מסך ההתקנה).
- הגשר, ההעלאות וה-cron לא השתנו — הם בטוקן / במפתח, לא במשתמש.

## התקנה בטלפון — PWA, APK וחנות

לפי `platform/docs/rollout.md` צעד 6, בתבנית של המתכונים (מועתקת, לא משותפת).

- **PWA:** `manifest.webmanifest` + `service-worker.js` (רשת קודם; `*.php`, `data/` ו-`bridge/` — תמיד
  מהשרת, הקלטה לא נשמרת במטמון). המניפסט, ה-SW, האייקונים ו-`privacy.html` — ב-`public` של `app.json`.
- **אנדרואיד (TWA):** `android/` — חבילה `com.mbeplus.camera`, תופסת קישורים רק ב-`/mini_projects/camera-app/`.
  נבנית ב-`.github/workflows/camera-app-twa.yml` בכל שינוי ב-`android/`, חתומה בסוד `ANDROID_KEYSTORE_PASSWORD`.
- **תיקיית החנות:** Release `camera-app-store` — `camera-app.apk`, `camera-app.aab`, `store-listing.zip`
  (`android/STORE.md` + `android/store/`), `assetlinks.json`, `build.json`. מה ממלאים ב-Play Console — `android/STORE.md`.
- **התמונות:** `node camera-app/tools/store-assets.mjs` — אייקונים, סמלי אנדרואיד, באנר וצילומי מסך (390px,
  נתוני הדגמה על שרת זמני) מ-`assets/icon.svg`.
- **בלי כיוון מסך קבוע** (`orientation: any`): וידאו מהמצלמה נוח לראות לרוחב.

## הרצת הבדיקות

```bash
bash    camera-app/tools/api-check.sh      # 49 בדיקות על שרת PHP אמיתי: התקנה → FTP → קטלוג → גשר → חי → הרשאות
node    camera-app/tools/ui-check.mjs      # הממשק ב-Chromium ברוחב טלפון, כל המסכים, בלי שגיאות JS ובלי גלישה לרוחב
bash    camera-app/tools/platform-check.sh # הכניסה דרך הפלטפורמה: איחוד לפי sub/מייל, מסך החיבור, נעילה, מנותקת
python3 camera-app/tools/bridge-check.py   # מדיניות ההעלאה של הגשר, וצימוד+heartbeat מול שרת אמיתי (בלי ffmpeg)
```

כולן על תיקיות זמניות; לא נוגעות בנתונים אמיתיים.

## נתונים בשרת

`data/camera-app.sqlite`, `data/secret.key`, `data/media/`, `data/inbox/` ו-`data/live/`
נוצרים בשרת ואינם בגיט. **חמש שורות ה-`--exclude` כבר ב-`deploy.yml`**, מאותו
commit שבו נכתב `db.php`. בלעדיהן פריסה מוחקת הקלטות ואת מפתח ההצפנה — ואין
שחזור. `data/.htaccess` חוסם את הכול ל-Apache; מדיה מוגשת רק ב-`media.php` למחובר.

## מה עדיין לא

ראה `SPEC.md` §12: דיבור דו-כיווני, ONVIF לאירועים ו-PTZ, צפייה מסונכרנת,
חיתוך קליפ בשרת, זיהוי פנים, התראות Push, 2FA. וגם: הגשר נבדק כאן בלי
ffmpeg ובלי מצלמה — ההרצה הראשונה מול ה-E1 Zoom האמיתית היא הבדיקה
שתאמת את מסלול ההקלטה והחי מקצה לקצה.
