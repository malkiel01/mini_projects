# אקדמיית סייבר התקפי — מה הבעלים צריך

המסמך המחייב של הצוות. מי שמשנה אותו: רק הבקרה, ורק לפי מה שהבעלים אמר.

## 1. במילים של הבעלים

> "אני מאשר להתחיל בפיתוח אפליקציית Web חדשה בשם Offensive Cyber Academy Dashboard בתוך mini_projects,
> בהתאם לכללי המאגר ולארכיטקטורה הקיימת."

ההנחיות שהגיעו עם הבקשה (דרך מנהל הצוותים, 23.11.2026):

**ארכיטקטורה מחייבת**
1. קוד הדשבורד יושב ב-mini_projects.
2. מאגר האקדמיה (`malkiel01/offensive-cyber-academy`) הוא מקור האמת לסילבוס, למשימות ולהתקדמות.
3. אין לשכפל את קוד האקדמיה, ואין לפתוח Repository נוסף.
4. JSON הוא פורמט הנתונים הראשי.
5. בשלב הראשון הדשבורד לקריאה בלבד.
6. כרגע משתמש אחד, בעל האקדמיה; התכנון מאפשר להרחיב הרשאות בעתיד.
7. אין לחבר נתונים אישיים לפני שמאגר האקדמיה פרטי ואבטחת הגישה אומתה.

**ממשק** — רספונסיבי, עברית, RTL, למחשב ולטלפון:
- מסך ראשי עם תמונת מצב לימודית
- סילבוס מלא, עד רמת מחקר אבטחה מתקדם
- פירוק כל מסלול לשלבים, מודולים, נושאים ומיומנויות
- מעקב התקדמות בכל רמה
- הבחנה בין נושא **שנלמד** לבין יכולת **שהוכחה במבחן מעשי**
- משימות: פתוחות, פעילות, חסומות, הושלמו
- מבחנים, הערכות וראיות להוכחת יכולת
- פערי ידע, דרישות קדם והמלצות להמשך
- ציר זמן של פעילות והתקדמות
- תכנון שמאפשר בעתיד כמה משתמשים ותפקידים

**אין להציג נתוני דוגמה כהישגים אמיתיים של התלמיד.** כל נתון דוגמה מסומן בבירור כדוגמה.

**פיתוח**
- שלוש שכבות נפרדות: UI, נתונים, אינטגרציה.
- נתוני דוגמה לא אישיים שתואמים לסכמת ה-JSON.
- חיבור עתידי למאגר GitHub פרטי — דרך צד השרת, בהרשאות מינימליות. אסימון לעולם לא מגיע לדפדפן.
- אסור לכתוב למאגר האקדמיה. שינוי בסכמה — מדווחים למנהל האקדמיה דרך הבעלים.
- בדיקות רלוונטיות, ו-Pull Request.

**גבולות סמכות (גוברים על השיטה הרגילה)**
- אין מיזוג ל-`main` — גם לא של השלד — עד שהבעלים כותב במפורש "למזג".
- כל העבודה בענף אחד, `claude/cyber-academy-dashboard`, עם PR אחד ל-`main` בטיוטה.
- אין שינויים באף אפליקציה אחרת.

## 2. מה נגזר מזה

1. **חוזה הנתונים** — `dashboard/data/schema/v1/academy.schema.json` במאגר האקדמיה, קומיט `cc85ac1`
   (`schemaVersion: "1.0.0"`): `tracks`, `competencies`, `tasks`. הדשבורד מאמת כל snapshot מול החוזה
   ומסרב (בהודעה ברורה) למה שלא תואם — לא "מנחש".
2. **שכבות:**
   - **אינטגרציה** — `lib/academy-source.php`: מקור `local` (נתוני דוגמה, פעיל) ומקור `github` (Contents API,
     אסימון fine-grained `Contents: Read` למאגר אחד, ב-`data/config.json`, מטמון ב-`data/cache/`) — **כבוי
     ומוגן בדגל**, ולא נדלק בשלב הזה.
   - **נתונים** — `api/` בצד השרת מחזיר JSON מנורמל לדפדפן; האסימון לא יוצא ממנו.
   - **UI** — `assets/js/` קורא רק את ה-API.
3. **דוגמה מסומנת:** כל snapshot ממקור `local` מוצג עם פס קבוע "נתוני דוגמה — לא הישגים אמיתיים", בכל מסך.
4. **"נלמד" מול "הוכח":** `theory_demonstrated` / `learning` = נלמד; `practice_demonstrated` / `mastered` =
   הוכח במעשה. שני מדדים נפרדים בכל רמה — לעולם לא אחוז אחד.
5. **מה שהסכמה v1 לא מכילה** (שלבים, מודולים, נושאים, מבחנים, ראיות כאובייקט, ציר זמן, המלצות, משתמשים) —
   המסך קיים, ומציג "אין עדיין נתונים בחוזה v1" במקום להמציא. הפער נרשם ב-`docs/schema-gaps.md` לבעלים
   ולמנהל האקדמיה.
6. **הרשאות:** משתמש אחד היום, דרך שער הפלטפורמה (`gate` + `restricted`); שכבת תפקידים (`viewer` לבד כרגע)
   כך שתפקידים נוספים יתווספו בלי לשנות מסכים.
