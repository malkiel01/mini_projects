# אפיון — אפליקציית מתכונים

אפליקציה מרובת משתמשים לניהול מתכונים: מתכונים פרטיים לכל משתמש, ומתכונים
ציבוריים לכולם.

**המסמך הזה מוכרע.** מה שלא הוכרע נמצא בשני מקומות בלבד: פרק 11 (עובדות שחסרות
לי) ופרק 12 (מה נדחה בכוונה מהשלב הראשון). כל השאר הוא החלטה.

הסכימה עצמה: [`SCHEMA.sql`](./SCHEMA.sql).

---

## 1. המסגרת

| | מי רואה | תגובות | פתק פרטי |
| --- | --- | --- | --- |
| **מתכון פרטי** | רק בעליו | ללא | כן |
| **מתכון ציבורי** | כל המשתמשים | כן | כן |

מתג אחד שעובר לשני הכיוונים: מתכון נכתב בשקט כפרטי, מתפרסם כשהוא מוכן, ואפשר
להחזיר אותו. הנתונים יושבים בשרת, כי משתמש שנכנס ממכשיר אחר חייב לראות את
המתכונים שלו ומתכון ציבורי חייב להיראות לאחרים.

**העיצוב נבנה לטלפון ומתרחב למסך גדול, לא הפוך.** המטבח הוא המקום שבו קוראים
מתכון, ושם יש טלפון.

## 2. חשבונות

**הרשמה חופשית** — כל אדם באינטרנט נרשם לבד ונכנס. זו ההכרעה שהפכה את הפרויקט
מכלי משפחתי לאתר פתוח, וממנה נגזר כל פרק 10 (אבטחה ומגבלות).

| מה | הכרעה |
| --- | --- |
| הרשמה | שם משתמש (ייחודי), דוא"ל, סיסמה |
| סיסמה | `password_hash(PASSWORD_DEFAULT)`, מינימום 8 תווים |
| אימות דוא"ל | **נדרש** — קישור אישור לפני כניסה ראשונה. ההגנה הזולה ביותר מהרשמות אוטומטיות |
| שכחתי סיסמה | איפוס בדוא"ל, אסימון חד־פעמי בתוקף שעה |
| פרופיל | **שם תצוגה** בלבד (ברירת מחדל: שם המשתמש). אין תמונת פרופיל — היא מדיה נוספת בלי תמורה בשלב הזה |
| התחברות | `session_start()` של PHP, כמו ב-`claude-tasks` |

**מנהל** — חובה, לא אופציה, בגלל ההרשמה החופשית. הרשאותיו: למחוק כל מתכון
ציבורי, למחוק כל תגובה, לחסום משתמש, ולנהל את רשימות התגים הסגורות. מתכון
**פרטי** של משתמש אחר אינו נגיש למנהל — פרטי הוא פרטי.

## 3. המתכון

### 3.1 חלקים ושלבים

מתכון מחולק ל**חלקים**, ולכל חלק רשימת רכיבים ושלבי הכנה ממוספרים משלו.

```
עוגת גבינה
├─ בצק פירורים   → רכיבים + שלבים 1,2
├─ מלית גבינה    → רכיבים + שלבים 1,2,3
└─ זיגוג שמנת    → רכיבים + שלבים 1,2
```

**מתכון פשוט הוא חלק אחד בלי שם**, והחלוקה אינה מוצגת לו בכלל. כך יש מבנה אחד
בקוד ולא שניים, ומי שמקליד סלט לא רואה שום דבר מיותר.

- **תמונה לשלב** — אופציונלית, מוצגת בתוך השלב, ונכנסת גם לגלריית המתכון.
- **שלב שמפנה לחלק אחר** ("ליצוק את המלית על הבצק") נשאר טקסט חופשי. הפנייה
  מובנית היא מורכבות בלי תמורה — המבשל מבין.

### 3.2 רכיבים — שתי שכבות

**זו ההכרעה החשובה ביותר במסמך**, ועליה נשענות רשימת הקניות והמרת המנות.

| שכבה | מה זה | מי משתמש בה |
| --- | --- | --- |
| **טקסט חופשי** | "2 כוסות", "חבילה", "קצת" | מה שהמבשל קורא |
| **ערך מחושב** | `300` + `גרם` + מוצר מקטלוג | מה שהאפליקציה מחשבת בו |

```
מוצג:      2 כוסות קמח  (300 גרם)
נשמר:      free_text="2 כוסות"  amount=300  unit=גרם  product_id=<קמח>
מתחבר ל:   300 גרם + 200 גרם ממתכון אחר = חצי קילו
```

- **רשימת היחידות סגורה**: גרם, ק"ג, מ"ל, ליטר, כוס, כף, כפית, יחידה, חבילה,
  קורט. המרת מנות מחייבת שהאפליקציה תבין את היחידה, ו"קצת" אינו יחידה.
- **הקטלוג גדל מעצמו**: מוצר שאינו בו נכתב חופשי ונכנס אליו, ובפעם הבאה מוצע
  בהשלמה אוטומטית. אין קטלוג סגור לתחזק, ואין כאוס.
- **רכיב בלי כמות מותר** ("מלח לפי הטעם") — פשוט אינו משתתף בחישובים.
- **טווח נתמך** ("2-3 ביצים") — `amount_min` ו-`amount_max`.
- **רכיב אופציונלי מסומן**, ומופיע ברשימת הקניות כשורה מסומנת כלא־חובה.
- **מי ממלא את הערך המחושב**: האפליקציה מציעה המרה מטבלת משקלים (כוס קמח ≈ 150
  גרם), והכותב מאשר או מתקן. **ההמרה מוצעת ולא נכפית** — מי שיודע מה הכוס שלו
  שוקלת יתקן, ומי שלא יקבל קירוב סביר.

### 3.3 מנות והמרה

מספר מנות נרשם במתכון, ושינויו מעדכן את הכמויות. **ההמרה היא תצוגה בלבד ואינה
נשמרת** — אחרת שתי המרות רצופות מעגלות שגיאות זו על גב זו.

עיגול: **שבר למחצית ולרבע** (4½ ביצים), עיגול רגיל לשאר. המרת יחידות חכמה
(1500 גרם → 1.5 ק"ג) אינה בשלב הראשון.

### 3.4 מדיה

| | הכרעה |
| --- | --- |
| **סרטונים** | גם קישור (יוטיוב וכדומה) וגם העלאה לשרת |
| תקרה לסרטון | **20MB**, `mp4` בלבד |
| כמה סרטונים | עד 3 למתכון |
| סרטון גדול מ-20MB | נדחה עם הסבר שמציע קישור. **20MB הם כ-10–15 שניות של וידאו מטלפון**, ולכן זה המסלול הרגיל ולא חריג |
| **תמונות** | עד 10 למתכון, הקטנה בדפדפן לפני העלאה (צלע ארוכה 1600px), תקרה קשה 5MB |
| תמונה ראשית | הראשונה כברירת מחדל, הכותב יכול לבחור אחרת |

סרטון שהועלה למתכון ציבורי נמשך מהשרת שלנו על ידי כל מי שצופה. זה מקובל, והוא
מוגבל משני כיוונים: 20MB לקובץ ו-200MB לחשבון.

## 4. קטלוג

**שלושה צירים סגורים ועוד אחד חופשי.** הצירים הסגורים הם מה שהסינון עובד עליו,
ולכן הם חייבים להיות אמינים.

| ציר | ערכים | כמה למתכון |
| --- | --- | --- |
| **נושא** | עוגות, עוגיות, מאפים, בצקים, מנה עיקרית, מנת פתיחה, מרקים, סלטים, תוספות, קינוחים, שתייה | כמה |
| **סוג** | אפייה, בישול, טיגון, ללא בישול, גריל, אידוי | כמה |
| **כשרות** | חלבי, בשרי, פרווה | אחד |
| **מתאים ל** | פסח, טבעוני, צמחוני, ללא גלוטן, ללא לקטוז | כמה |
| **מטבח** | מרוקאי, איטלקי, אסייתי, מזרחי, אשכנזי, אמריקאי | אחד |
| **תגים חופשיים** | כל טקסט — "של סבתא", "לשבת" | כמה, **פרטיים למשתמש** |

התגים החופשיים פרטיים בכוונה: "של סבתא" שלי אינו של אחרים, ובאתר פתוח
לאינטרנט תג משותף הוא גם מקום לזבל. **המנהל מנהל את הרשימות הסגורות מתוך
האפליקציה** — אחרת כל קטגוריה חדשה דורשת שינוי קוד ופריסה.

**קושי**: קל / בינוני / מאתגר, נקבע על ידי הכותב.
**זמן**: שני שדות בדקות — **זמן עבודה** ו**זמן המתנה**. "שעה וחצי" שהוא 10 דקות
עבודה ושעה ועשרים בתנור הוא מתכון קל, ומי שקורא "שעה וחצי" חושב אחרת.

## 5. חיפוש

תיבה אחת, מחזירה פרטיים וציבוריים ביחד עם סימון לכל תוצאה, ולצדה סינון לפי כל
צירי הקטלוג, קושי וזמן.

**מה נסרק, בסדר הדירוג:** שם המתכון → רכיבים → אופן ההכנה וטיפים.
**מה לא נסרק:** תגובות. תגובה שאומרת "לא הצליח לי" אינה תוצאת חיפוש.
**ולא צריך לומר, ולכן נאמר:** החיפוש אינו נוגע במתכונים הפרטיים של אחרים.

**עברית** — בשלב הראשון חיפוש תת־מחרוזת על עמודת טקסט מנורמלת (ניקוד וסימנים
מוסרים). זה מוצא "עוגיות" בתוך "עוגיות שוקולד", אבל **לא ימצא "עוגייה" כשחיפשת
"עוגיות"** — נטיות עבריות דורשות מנוע גזירה, וזה אינו בשלב הראשון. נאמר כאן
במפורש כדי שלא ייראה כתקלה.

## 6. מתכון ציבורי

**"שמור אצלי" = מועדף שמצביע על המקור**, לא העתק. הכותב משפר — מי ששמר רואה את
השיפור, ואין גרסאות סותרות במסד.

**עריכה לאחר פרסום מותרת**, ולצד המתכון מוצג "עודכן לאחרונה ב—". תגובה שנכתבה
לפני העדכון האחרון מסומנת **"נכתבה לפני עדכון המתכון"** — כי "יצא לי נוזלי מדי"
מבלבל קוראים אחרי שהכותב תיקן את הכמויות. הסימון פותר את זה בלי למחוק תגובות
ובלי לשמור גרסאות.

**שם הכותב (שם התצוגה) מוצג** במתכון ציבורי ובתגובות. לא אנונימי.

### כשמתכון ציבורי נעלם

| מה קרה | התגובות | המועדפים |
| --- | --- | --- |
| הפך לפרטי | נשמרות ומוסתרות; חזרה לציבורי מחזירה אותן | נשארים, מסומנים "המתכון אינו זמין כרגע" |
| נמחק | נמחקות איתו (`CASCADE`) | נשארים, מסומנים "הוסר על ידי הכותב", והמשתמש יכול להסיר |

המחיקה מבקשת אישור שאומר **כמה תגובות יימחקו**. מועדף שבור שנשאר עם הסבר עדיף
על שורה שנעלמה בשקט — המשתמש זוכר שהוא שמר משהו.

## 8. רשימת קניות ומצב בישול

### רשימת קניות

בוחרים כמה מתכונים ומקבלים רשימה אחת מאוחדת, נשמרת, עם סימון מה נקנה, ועם
אפשרות להוסיף שורות ידנית (שקיות אשפה וחלב אינם בשום מתכון).

**האיחוד נעשה על השכבה המחושבת** (3.2), ולכן 300 גרם ו-200 גרם משני מתכונים
מתחברים גם כשאחד נרשם "2 כוסות". מה שלא ניתן לחיבור — יחידות שונות של אותו
מוצר — מוצג בשתי שורות תחת אותו מוצר:

```
☐ קמח — 500 גרם          (מ-2 מתכונים)
☐ גבינה 5% — 750 גרם
☐ קינמון — 2 כפיות + קורט   ← לא אוחד, ובכוונה
```

**רשימה שמודה שהיא לא יודעת עדיפה על רשימה שטועה בביטחון.** טעות כאן שולחת
אותך לסופר עם מספר שגוי, ואתה מגלה במטבח.

### מצב בישול

שלב אחד גדול, הרכיבים של אותו שלב לצדו, סימון כבוצע, כפתורים בגודל אצבע
מלוכלכת, ומסך שלא נכבה (`Screen Wake Lock API` — דורש HTTPS, שיש לנו; בדפדפן
ישן המסך פשוט ייכבה כרגיל).

**רץ ברצף דרך כל החלקים**, ומלמעלה שורת חלקים שמאפשרת לקפוץ מיד למלית כשהבצק נח
במקרר. מתכון פשוט ומתכון מורכב מקבלים אותו מסך, בלי שלב בחירה בדרך.

### הדפסה

גיליון `@media print` — המתכון על נייר, בלי ניווט ובלי תגובות. זול לממש, ויש מי
שרוצה דף במטבח.

## 9. תשתית

| מה | הכרעה |
| --- | --- |
| מסד נתונים | **SQLite דרך PDO**, כמו `claude-tasks` שעובד בשרת הזה |
| הגדרות חיבור | `journal_mode = WAL`, `foreign_keys = ON`, `busy_timeout = 5000` |
| מיגרציות | `CREATE TABLE IF NOT EXISTS` ב-`lib/db.php`, לפי אותה תבנית |
| קובץ הנתונים | `recipes-app/data/recipes.sqlite` |
| מדיה | `recipes-app/data/media/` |

### השורות שחייבות להיכנס ל-`deploy.yml` לפני קוד שמירה

```
--exclude='recipes-app/data/*.sqlite*'
--exclude='recipes-app/data/media/'
```

**בלעדיהן כל פריסה תמחק את המתכונים ואת המדיה, ואין שחזור.** זו הנקודה היחידה
בפרויקט שנזקה בלתי הפיך.

## 10. אבטחה — מה שההרשמה החופשית מחייבת

אלה אינן שאלות. הן מה שייעשה, מפני שהמעלה הוא אלמוני:

- **בדיקת סוג אמיתית** ב-`finfo`, לא לפי סיומת. קובץ בשם `clip.mp4` יכול להיות
  קוד PHP.
- **שם קובץ שהשרת מחלל**, ולא השם שנשלח.
- **`.htaccess` שמונע הרצת קוד** בתיקיית המדיה, כמו ב-`claude-tasks/data/`.
- **מקצב 200MB לחשבון**, נבדק בצד השרת ולא רק בדפדפן, עם מדד נראה למשתמש
  והודעה ברורה כשנגמר. מחיקת מתכון משחררת נפח.
- **תקרת קובץ אינה תקרת חשבון**: אלף העלאות תקניות של 20MB הן 20GB, והדיסק
  משותף עם כל הכלים בריפו. המקצב הוא מה שסוגר את זה.
- **הכול דרך `prepare`** — אין הרכבת SQL ממחרוזות.
- **פלט בורח** — תגובה של זר מוצגת כטקסט, לא כ-HTML.

## 11. עובדות שחסרו לי

לא החלטות — נתונים שלא היה לי דרך להשיג מכאן. שניים מהם נענים עכשיו
במסך האבחון של המנהל (⚙), מהשרת עצמו:

1. **`upload_max_filesize` ו-`post_max_size` בשרת.** 20MB דורשים שהשרת ירשה
   זאת, ובאירוח משותף ברירת המחדל נעה בין 2M ל-64M. **האפליקציה תקרא את
   המגבלות בעצמה** (`ini_get`) ותציג את התקרה האמיתית במקום להבטיח 20MB
   ולהיכשל בשקט. אם התקרה נמוכה — זו הגדרה שמשנים ב-cPanel.
2. **נפח פנוי בשרת.** קובע כמה חשבונות של 200MB אפשר להחזיק.
