# הניתוח היומי של הטעם — הוראות לצ'אט עם השעון

את הקובץ הזה מריץ צ'אט של קלוד שנפתח לבד פעם ביום (Routine). הוא קורא את יומן השימוש של
הלקוחות, מבין מה כל אחד אוהב, ומחזיר לאפליקציה תקציר, משקלות ובחירות. מזה נבנה "✨ בשבילך".

**בלי קרדיט ובלי גיט.** הניתוח הוא שלך, הצ'אט — לא קריאה ל-API בתשלום. והתוצאה הולכת
**ישירות לשרת**, לא לריפו: הריפו ציבורי, וטעם של לקוח הוא מידע אישי. **אל תעשה commit לשום
נתון של לקוח, ואל תכתוב אותו לשום קובץ בריפו.** אין בעבודה הזאת שינוי קוד.

הקוד שמאחורי זה: `lib/taste_job.php` (יצוא ויבוא), `lib/foryou.php` (איך זה משפיע).

---

## 1. קריאה

הטוקן מגיע בהודעה שפתחה את הצ'אט (`TOKEN=...`).

```bash
B=https://mbe-plus.com/mini_projects/recipes-app
curl -sS -b 'humans_21909=1' "$B/logs.php?token=$TOKEN&view=taste" -o /tmp/taste-in.json
python3 -c "import json; d=json.load(open('/tmp/taste-in.json')); print(len(d['users']), 'לקוחות', '· הטוקן בתוקף עד', d['token_expires_at'])"
```

- `403` — הטוקן פג או בוטל. עצור, ודווח למשתמש בדיוק מה לעשות (סעיף 5).
- `users` ריק — אין מה לנתח היום (אף אחד לא עשה דבר מאז הניתוח הקודם). דווח ועצור.

## 2. מה יש ביצוא

לכל לקוח (`user_id` — מזהה בלבד, בלי שם ובלי דוא"ל):

| שדה | מה |
| --- | --- |
| `events` | יומן 90 הימים האחרונים, החדש ראשון. `kind`: `search` (חיפוש באפליקציה: `q`, `tags`, `n` = כמה נמצא), `web_search` (חיפוש ברשת), `open` (פתח מתכון), `web_open` (פתח מהרשת), `save` (`to` = לאיזה אוסף), `unsave`, `hide` ("הסר מהרשימה שלי"), `cook` (בישל עד הסוף), `shop` (הוסיף לקניות), `foryou_click`, `not_interested`, `less_topic` (`topic`). ברוב השורות — `recipe`: שם, תגים, `min` (זמן כולל), `d` (קושי), `ings` (רכיבים) |
| `saved` | מה ששמור אצלו עכשיו באוספים |
| `own` | מתכונים שהוא עצמו כתב |
| `declared` | מה שהצהיר ב"🎯 מה אני אוהב" — נושאים, ותזונה (תזונה **מסננת** בשרת; אל תסתור אותה) |
| `previous` | הניתוח הקודם שלך — לעדכן, לא להתחיל מאפס |
| `candidates` | מתכונים שאפשר לבחור מהם (`key` = `r:12` באפליקציה, `w:345` מהרשת) |

ו-`vocabulary` — שמות התגים המותרים (לפי ציר) והתכונות.

## 3. הניתוח — המכנה המשותף

לכל לקוח, חפש **מה חוזר** — לא מה קרה פעם אחת:

- **משקל לפעולה:** בישל / שמר / הוסיף לקניות — חזק. פתח — חלש. חיפש — בינוני, ו**חיפוש
  שלא מצא כלום (`n: 0`) הוא רצון שלא נענה** — מילה טובה ל-`keywords`. הסיר / הסתיר / "לא
  מעניין" / "פחות כאלה" — שלילי.
- **בשרי / חלבי / טבעוני:** מהתגים, ומהרכיבים (`ings`) כשאין תג.
- **קליל ומהיר מול מושקע:** `min` ו-`d` של מה ששמר ובישל. רוב מה שבחר עד חצי שעה וקל →
  `quick` חיובי. בישולים ארוכים ומורכבים → שלילי.
- **מיוחד מול ביתי:** מטבח זר, שילובים לא שגרתיים, מתכוני אירוח → `special` חיובי. קלאסיקות
  ביתיות → שלילי.
- **מעט נתונים** (פחות מ-5 פעולות) — ניתוח זהיר: משקלות קטנים, תקציר קצר, אולי בלי בחירות.
- **`previous` קיים** — עדכן בהדרגה. אל תהפוך כיוון בלי עדויות חדשות של ממש.

**אסור:** להסיק מידע רגיש — בריאות, דת (מעבר לתגי הכשרות שהוא עצמו משתמש בהם), מצב
משפחתי, מצב כלכלי. לא לציין לקוחות אחרים. לא לנחש מגדר — לנסח בלי פנייה מגדרית.

## 4. הפלט — והחזרה לשרת

קובץ אחד, `/tmp/taste-out.json` (**לא בריפו**):

```json
{
  "version": 1,
  "users": [
    {
      "user_id": 17,
      "summary": "בשר על האש ובישולים ארוכים; פחות מתכונים טבעוניים",
      "profile": {
        "tags": { "בשרי": 2.5, "מנה עיקרית": 1, "טבעוני": -1.5 },
        "quick": -0.4,
        "special": 0.6,
        "keywords": ["אסאדו", "צלעות", "על האש"],
        "avoid": ["סלמון"]
      },
      "picks": [
        { "key": "r:123", "reason": "כי שמרת סטייק וחיפשת אסאדו" },
        { "key": "w:4567", "reason": "בישול ארוך — כמו האסאדו שבישלת" }
      ]
    }
  ]
}
```

| שדה | כלל |
| --- | --- |
| `summary` | עד 160 תווים. **פנימי** — לך, לניתוח של מחר (`previous`). הלקוח לא רואה אותו |
| `tags` | **רק שמות מ-`vocabulary.tags`**, משקל -3 עד 3, עד 25. שם אחר — נדחה עם אזהרה |
| `quick`, `special` | -1 עד 1. לא בטוח — השמט |
| `keywords` | עד 12 מילים (2–30 תווים) שמופיעות בשמות של מתכונים שהוא אוהב. השרת מחפש לפיהן גם באינדקס של הרשת |
| `avoid` | עד 12 מילים — מה שהוא מסיר או לא נוגע בו |
| `picks` | עד 10, **רק מ-`candidates` שלו**. מוצגות ראשונות ב"בשבילך". `reason` עד 80 תווים — **פנימי**, לבקרה; הלקוח לא רואה למה |

שליחה, ובדיקת התשובה:

```bash
python3 -c "import json; json.load(open('/tmp/taste-out.json'))" && \
curl -sS -b 'humans_21909=1' -X POST -H 'Content-Type: application/json' \
  --data @/tmp/taste-out.json "$B/logs.php?token=$TOKEN&view=taste-import"
```

התשובה: `updated` (כמה נשמרו), `skipped` (מי לא — למשל כיבה התאמה אישית בינתיים — זה תקין),
`warnings` (תג לא מוכר, בחירה שאינה זמינה). **יש אזהרות — תקן ושלח שוב פעם אחת.**

## 5. הדיווח בסוף

הודעה אחת, בעברית, קצרה — ומסתיימת בסיכום (CLAUDE.md):

- כמה לקוחות נותחו, כמה נשמרו, אזהרות אם נשארו.
- **בלי פרטים של לקוחות** — לא תקצירים ולא מזהים. מספרים בלבד.
- **הטוקן פג בעוד פחות מ-14 יום** (`token_expires_at`), או קיבלת `403` — לכתוב למשתמש בדיוק:
  "באפליקציה: ☰ → יומן → שם: 'שעון יומי — טעם', תוקף: מותאם… → 90 ימים → צור טוקן → להעתיק
  את הטוקן ולשלוח לקלוד בצ'אט הראשי, כדי לעדכן את השעון."
