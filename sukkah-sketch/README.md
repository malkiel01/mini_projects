# שרטוט לסוכה

כלי לתכנון ולשרטוט של סוכה — דפנות, מידות וסכך — בתוך אוסף הכלים.

## מצב נוכחי — שלד בלבד

הכלי עצמו טרם נכתב. מה שקיים כאן הוא התשתית שהפרויקט ייכנס אליה:

| מה | איפה |
| --- | --- |
| דף הכלי | `index.html` |
| עיצוב | `assets/css/app.css` |
| קוד | `assets/js/app.js` |
| אייקון | `assets/icon.svg` |
| כרטיס בדף הראשי | `../index.html` |

הסוכה המסתובבת שבדף היא **מציין מקום**: ציור קווים על `<canvas>` בלי שום
ספרייה, שנועד להראות שהתיקייה חיה ושהנכסים נטענים מהשרת. שלושת הקבצים
`index.html`, `assets/css/app.css` ו-`assets/js/app.js` מיועדים להיות מוחלפים
בפרויקט האמיתי.

## כשתיכנס לכאן תיקיית הפרויקט

התיקייה שתועלה נכנסת אל `sukkah-sketch/` ומחליפה את מציין המקום. שלושה דברים
חייבים להיבדק בכניסה, מפני שהם מה שמבדיל בין "עובד אצלי" ל"עובד בשרת":

- **נקודת הכניסה** — חייב להישאר `sukkah-sketch/index.html`, כי לשם מצביע
  הכרטיס בדף הכלים.
- **נתיבים יחסיים** — נכסים נטענים ב-`./assets/...`. נתיב שמתחיל ב-`/` נשבר
  בשרת, מפני שהאתר יושב תחת `/mini_projects/` ולא בשורש הדומיין.
- **תיקיית נתונים** — אם הפרויקט כותב לדיסק בצד שרת, התיקייה שנכתבת חייבת
  `--exclude` משלה ב-`.github/workflows/deploy.yml`. בלעדיו כל פריסה תדרוס
  את מה שנשמר, כמו שכבר מוגדר ל-`renovation-punchlist` ול-`claude-tasks`.

## שערי בדיקה בפריסה

`deploy.yml` בודק תחביר של כל קובץ `.php` ושל כל קובץ `.js` לפני שהוא מעלה
משהו, ונעצר בשגיאה. קוד צד־שלישי מוקטן פטור מהבדיקה רק אם הוא יושב תחת
`vendor/`; ספרייה חיצונית שתיכנס לכאן בשם אחר — תיבדק, ועלולה להפיל פריסה.

## פריסה

התיקייה נפרסת אוטומטית עם שאר הריפו דרך `.github/workflows/deploy.yml`, ללא
הגדרה ייעודית. אין כאן כרגע קוד PHP ואין תיקיית נתונים.
