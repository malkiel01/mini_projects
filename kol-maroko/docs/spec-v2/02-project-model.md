## 1. הפרויקט בשורה אחת

**הפרויקט הוא עץ קבצים, והוא מקור האמת היחיד של העמוד** (D1). אין מודל נוסף, אין מסד שמחזיק "את העמוד", ואין מנוע
שמייצר ממנו HTML. מה שהגולש מקבל הוא הקבצים האלה (אחרי שלב הבנייה הגלוי של `07`), ומה שהעורך החזותי משנה הוא הטקסט שלהם.

שלושה סוגי קבצים, ורק שלושה:

| סוג | דוגמה | איפה הבייטים | נערך |
| --- | --- | --- | --- |
| **טקסט** | `index.html`, `css/page.css`, `js/page.js`, `kol.json` | במאגר הפרויקט | בעורך הקוד; HTML ו-CSS גם חזותית |
| **נתונים** | `data/words.json` | **בטבלת המילים** — הקובץ הוא הפנים השניות שלה (סעיף 8) | בטבלה, בקובץ, ועל הקנבס (V11) |
| **מדיה** | `media/hero.jpg`, `media/audio/6.mp3` | **בספריית המדיה** — הקובץ בפרויקט הוא הפניה (סעיף 4) | בספרייה (`05`); מוחלף גם מהקנבס |

בעל העמוד רואה את שלושתם באותו עץ, ואינו צריך לדעת איפה הבייטים.

## 2. פריסת ברירת המחדל

זה מה שההסבה (F3) יוצרת, ומה ש"פרויקט חדש" יוצר. **שום שם כאן אינו חובה** חוץ מקובץ הכניסה — וגם הוא הגדרה ב-`kol.json`.
בעל העמוד יכול לשנות שם, להעביר, לפצל ולמחוק כל קובץ; מה שנשבר בעקבות זה מוצג לו (`04`, "הפניות שבורות"), ולא נחסם.

```
index.html              קובץ הכניסה — כל ה-<head> וכל ה-<body> של העמוד
css/
  tokens.css            משתנים: צבעים, גופנים, מידות                 ← היעד של "גלובליים" (V9)
  base.css              סגנון לפי תגית: h1–h6, a, button, img         ← היעד של "ברירות מחדל" (V9)
  page.css              סגנון לפי מחלקה                               ← היעד הרגיל של העורך החזותי
js/
  kol-data.js           קובץ מערכת: רשימות, חיפוש, סינון, נגן (סעיף 6)
  page.js               ההתנהגות של העמוד עצמו
data/
  words.json            המילים והנושאים (סעיף 8)
media/                  תמונות, גופנים, הקלטות — הפניות לספרייה
components/<name>/      רכיבים (סעיף 7)
kol.json                הגדרות הפרויקט (סעיף 5)
```

בהסבה (F3) נוספים הקבצים שמקורם באתר, **כמו שהם**: `css/theme-style.css` (ה-`style.css` של ערכת הנושא), `css/lexicon.css`,
`js/lexicon.js` (`09`). הם קבצים רגילים של בעל העמוד מהרגע הראשון.

## 3. כללי הקבצים

**בתוכן אין שום איסור** (ע1): כל HTML, כל CSS, כל JavaScript, כל סוג קובץ. הכלי אינו מנקה, אינו ממקד ואינו משכתב את מה
שנכתב — לא בשמירה ולא בפרסום. קובץ עם סיומת של שרת (`x.php`) מותר, ונשאר טקסט דומם: שום שרת אינו מריץ אותו (G4).

**המגבלות היחידות הן טכניות, והן של בעל האתר** **[ש-5]**:

| מגבלה | ברירת מחדל | למה |
| --- | --- | --- |
| נתיב | עד 200 תווים; רכיבי נתיב בלי `/`, `\`, תו בקרה, `..`; לא מתחיל ב-`/`; עברית מותרת | נתיב הוא גם כתובת |
| רישיות | שני נתיבים שנבדלים רק באותיות גדולות / קטנות — נדחה ביצירה | השרתים אינם אחידים בזה |
| קובץ טקסט | עד 2MB | עורך הקוד והניתוח |
| מספר קבצים | עד 2,000 (לא כולל מדיה) | G5 |
| נפח המדיה | תקרת הדיסק של הכלי (היום 5GB) | G5 |

חריגה נדחית בהודעה שאומרת מה המגבלה ומי משנה אותה. המספרים — הגדרות של בעל האתר במסך המפתח, לא קבועים בקוד.

**שמות שמורים:** `kol.json` בשורש בלבד. אין אחרים.

**לכל קובץ:** נתיב · תוכן · `rev` (מספר עולה בכל שמירה) · sha256 · גודל · מי שינה ומתי. מחיקה היא העברה לסל (ע4).

**האחסון:** רשומות הקבצים — טבלאות חדשות במסד הקיים (`data/kol.sqlite`); התוכן — לפי sha256 תחת `data/files/_project/`.
שני המקומות כבר מוחרגים בפריסה, ולכן לא נדרש `--exclude` חדש (פרוסה F2, סעיף 4). ⚠️ מימוש שיבחר נתיב אחר תחת `data/`
מחייב `--exclude` ב-`deploy.yml` **לפני** שהקוד מתמזג (`CLAUDE.md`).

## 4. מדיה: קובץ בפרויקט שהוא הפניה לספרייה

- כל קובץ תחת כל תיקייה בפרויקט יכול להיות מדיה. **הבייטים נשמרים פעם אחת, בספריית המדיה**; בעץ הפרויקט יושבת הפניה
  (נתיב ← מזהה קובץ בספרייה). כך 1,494 הקלטות אינן מוכפלות, והספרייה (`05`) והעץ מראים את אותם קבצים.
- בקוד כותבים נתיב רגיל: `<img src="media/hero.jpg">`, `url(../media/bg.webp)`. אין כתובות מיוחדות ואין מזהים בקוד.
- **החלפת קובץ בספרייה** מחליפה אותו בכל מקום שמפנה לנתיב. **שינוי שם או העברה** — העורך מציע לעדכן את כל ההפניות
  בקבצי הטקסט, ומציג אותן לפני הביצוע.
- **הקלטה שעדיין "באתר"** (היום: כל 1,494 — עובדה מהבעלים, T5) מופיעה בעץ ובספרייה כהפניה חיצונית: נראית, מושמעת
  מהכתובת שלה, ומסומנת "טרם הובאה". אחרי ההבאה (A2) היא קובץ רגיל, באותו נתיב. הקוד של העמוד אינו משתנה.
- מדיה שאף קובץ טקסט אינו מפנה אליה נשארת בספרייה, מסומנת "לא בשימוש". אינה נמחקת לבד.
- תמונה נשמרת **כמו שהועלתה**. המרה והקטנה הן הצעה בזמן ההעלאה, לא כפייה (`01-gap` 12.3); SVG מותר (12.2).

## 5. `kol.json` — הגדרות הפרויקט

קובץ טקסט רגיל בשורש. נערך במסך "הגדרות הפרויקט" (טופס) וגם כקובץ; שניהם אותו קובץ. JSON לא תקין: העורך מסמן את השורה,
והסטודיו ממשיך לעבוד עם הגרסה התקינה האחרונה עד שמתוקן.

```json
{
  "version": 1,
  "entry": "index.html",
  "pages": "auto",
  "breakpoints": [
    { "id": "tablet", "label": "טאבלט", "max": 1024, "preview": 820 },
    { "id": "mobile", "label": "טלפון", "max": 767, "preview": 390 }
  ],
  "styles": { "tokens": "css/tokens.css", "base": "css/base.css", "page": "css/page.css" },
  "data": {
    "words": { "file": "data/words.json", "source": "words" }
  },
  "components": "components/",
  "system": { "js/kol-data.js": { "version": "1.0.0", "modified": false } }
}
```

| מפתח | משמעות |
| --- | --- |
| `entry` | הקובץ שמוגש בכתובת הבסיס |
| `pages` | `"auto"` — כל קובץ `.html` שאינו בתוך `components/` הוא עמוד **[ש-3]**. `about/index.html` ← `…/lexicon/about/`; `404.html` — עמוד השגיאה. או רשימה מפורשת |
| `breakpoints` | נקודות השבירה שהעורך מציג כמצבי מכשיר וכותב כ-`@media (max-width: …)`. אפשר להוסיף, לשנות ולמחוק. `preview` — רוחב הקנבס במצב הזה |
| `styles` | לאן העורך החזותי כותב **כברירת מחדל**. בעל העמוד יכול להפנות לקבצים אחרים, ולכל שינוי בודד לבחור יעד אחר (`03`, "כלל היעד") |
| `data` | מקורות הנתונים: שם ← קובץ ← טבלה (סעיף 8). רשימות נוספות נרשמות כאן **[ש-16]** |
| `system` | קובצי המערכת, הגרסה שלהם, והאם שונו (סעיף 6). מתעדכן בידי הכלי |

`kol.json` **אינו** מתפרסם לגולש כברירת מחדל (אין בו סוד; פשוט אין בו צורך). אפשר לשנות זאת במסך הפרסום.

## 6. קובצי המערכת (D7)

קובץ מערכת הוא קוד שהכלי מספק כדי שהעמוד יעבוד "מהקופסה" — בראשם `js/kol-data.js`, שמממש את קשירת הנתונים (סעיף 8).
**הוא קובץ בפרויקט ככל קובץ:** נפתח, נערך, נמחק. אין בו שום דבר שבעל העמוד אינו רואה.

- **לא שונה:** מתעדכן יחד עם הכלי. העדכון הוא שינוי קובץ רגיל — נרשם בהיסטוריה, נראה ב"מה ישתנה" לפני הפרסום הבא, והפיך.
- **שונה בידי בעל העמוד:** נשאר שלו. הכלי אינו דורס. כשיוצאת גרסה חדשה מוצג "יש גרסה חדשה — השוואה", עם שלוש פעולות:
  לקחת את החדשה, להשאיר את שלי, או לפתוח את שתיהן זו לצד זו.
- **נמחק:** מותר. מה שנשען עליו מפסיק לעבוד בתצוגה החיה, והעורך אומר זאת.

**הקנבס וקובץ מערכת שנערך** — נקודה שצריך לומר בגלוי: בקנבס העריכה סקריפטים אינם רצים (S2), ולכן את רשימות הנתונים
מציג שם המימוש של הכלי, לא `js/kol-data.js` של הפרויקט. כל עוד הקובץ לא שונה — זהים. אם בעל העמוד שינה אותו, הקנבס
מציג סרגל: "הרשימה מוצגת כאן לפי ברירת המחדל; קובץ המערכת שונה — האמת בתצוגה החיה". העריכה החזותית של התבנית ושל
הכרטיסים ממשיכה לעבוד.

## 7. רכיבים

**רכיב אינו קופסה סגורה.** הוא תיקייה עם HTML, CSS ו-JS רגילים, ועם קובץ שמתאר אילו הגדרות להציג בפאנל. כל חלק ברכיב
נבחר ונערך על הקנבס כמו כל אלמנט. בעל העמוד עורך רכיבים קיימים ויוצר רכיבים משלו (`01-gap` 7.14).

```
components/accordion/
  component.json        שם, אייקון, קטגוריה, וסכמת ההגדרות
  template.html         ה-HTML שמוכנס לעמוד
  style.css             נטען פעם אחת לעמוד שמשתמש ברכיב
  script.js             לא חובה
```

### 7.1 סכמת ההגדרות

כל שדה אומר מה מופיע בפאנל, **ולאן הוא כותב**. אין יעד נסתר: כל הגדרה היא שינוי טקסט שנראה בקובץ.

```json
{
  "name": "accordion", "label": "אקורדיון", "icon": "▤", "category": "content",
  "fields": [
    { "id": "title",  "label": "כותרת",       "control": "text",   "target": { "text": ".acc-title" } },
    { "id": "open",   "label": "פתוח בהתחלה", "control": "toggle", "target": { "attr": "open", "on": ".acc-item" } },
    { "id": "gap",    "label": "רווח",        "control": "size",   "target": { "var": "--acc-gap" } },
    { "id": "style",  "label": "סגנון",       "control": "select", "options": ["plain", "boxed"],
      "target": { "class": "acc--{value}" } },
    { "id": "items",  "label": "פריטים",      "control": "repeater", "target": { "children": ".acc-item" } }
  ]
}
```

| יעד | מה נכתב |
| --- | --- |
| `text` | תוכן הטקסט של האלמנט שהבורר מוצא בתוך המופע |
| `attr` | תכונת HTML |
| `class` | מחלקה מתוך קבוצה (אחת בכל רגע) |
| `var` | משתנה CSS בתכונת `style` של שורש המופע |
| `children` | רשימת ילדים שאפשר להוסיף, למחוק ולסדר (repeater) |
| `src` | קובץ מדיה (`src`, `href`, `poster`) |

סוגי השליטה (`control`) הם אותם סוגים של הפאנל הכללי (`03`): טקסט, טקסט עשיר, מספר, מידה עם יחידה, צבע, גופן, בחירה, מתג,
מדיה, קישור, repeater. **הפאנל הכללי** (מרווחים, טיפוגרפיה, רקע…) זמין לכל חלק ברכיב בלי שהסכמה תזכיר אותו.

### 7.2 מופע בעמוד

מופע הוא **ה-HTML המלא של הרכיב, כתוב בתוך קובץ העמוד**, עם סימון על השורש:

```html
<section class="acc acc--boxed" data-kol-component="accordion" style="--acc-gap:12px"> … </section>
```

אין שלב הרחבה בזמן ריצה: מי שפותח את `index.html` רואה את כל ה-HTML, והעמוד עובד גם בלי הכלי (ע2).

- **מקושר** (ברירת המחדל): כשמשנים את `template.html` או את הסכמה, העורך מעדכן את כל המופעים — תיקון טקסט בכל קובץ,
  עם תצוגה מקדימה של מה ישתנה, ושמירת ערכי ההגדרות של כל מופע. `style.css` ו-`script.js` משותפים ממילא.
- **שונה במקום:** מופע שבעל העמוד שינה בו מבנה ביד או על הקנבס מסומן "שונה מהרכיב". בעדכון הרכיב הוא בוחר לכל מופע
  כזה: לעדכן (ולאבד את השינוי המקומי, שמוצג לו), או לנתק.
- **מנותק:** הסימון מוסר, וזה HTML רגיל.
- **כותרת ותחתית משותפות בין עמודים** (`01-gap` 8.4) הן רכיב מקושר שמופיע בכמה קבצי `.html`.

### 7.3 ספריית הרכיבים המוכנים

הכלי מספק רכיבים מוכנים (V16; הרשימה ב-`01-gap` 4.7). הם **מועתקים לפרויקט** כשמשתמשים בהם בפעם הראשונה, ומאותו רגע
הם קבצים של בעל העמוד, לפי כללי קובצי המערכת (סעיף 6): לא שונה ← מתעדכן; שונה ← שלו.

## 8. נתונים וקשירת נתונים (D6)

### 8.1 המקור

טבלת המילים שבכלי נשארת מקור האמת (`00` §10). `data/words.json` הוא **אותם נתונים, כקובץ**: קריאת הקובץ מחזירה את
הטבלה; שמירת הקובץ מעדכנת את הטבלה, אחרי אימות, עם שגיאה שנוקבת בשורה. הפרטים — `06-data.md` (N1).

```json
{
  "topics": [ { "id": "food", "label": "אוכל" } ],
  "items": [
    { "id": 6, "word": "…", "meaning": "…", "topics": ["food"], "audio": "media/audio/6.mp3" }
  ]
}
```

**`id` הוא מזהה המילה, והוא המפתח של ההקלטה** — כך הבעלים תיאר את הקשר: "למילה עם איי די שש, אנחנו נפעיל את שמע מספר
שש" (T2). המזהה יציב ואינו משתנה בעריכה, במיון או בייבוא. הכתובת של ההקלטה באתר היא רק **מקור להבאה** (`05`), לא מפתח.
שדות מותאמים **[ש-16]** הם מפתחות נוספים באותו אובייקט (N2).

### 8.2 התכונות

קשירת נתונים נכתבת בתכונות HTML על אלמנטים רגילים. אין תחביר תבניות בתוך הטקסט, ולכן תבנית הכרטיס היא HTML רגיל שנערך
חזותית כמו כל אלמנט.

| תכונה | על מה | משמעות |
| --- | --- | --- |
| `data-kol-list="words"` | מכל | הרשימה מוצגת כאן. הילד `<template>` הוא תבנית הפריט |
| `data-kol-sort="word"` / `"manual"` / `"-id"` | המכל | מיון: לפי שדה, ידני (סדר הקובץ), או יורד |
| `data-kol-page="60"` | המכל | כמה פריטים בכל טעינה |
| `data-kol-text="meaning"` | בתוך התבנית | תוכן הטקסט ← השדה |
| `data-kol-html="meaning"` | בתוך התבנית | כמו `text`, אבל כ-HTML |
| `data-kol-attr-src="audio"` | בתוך התבנית | תכונה כלשהי ← השדה (`src`, `href`, `alt`, `title`…) |
| `data-kol-if="audio"` / `"!audio"` | בתוך התבנית | האלמנט מוצג רק אם לשדה יש / אין ערך |
| `data-kol-each="topics"` | בתוך התבנית | חזרה על האלמנט לכל ערך בשדה-רשימה |
| `data-kol-search="words"` | `<input>` | חיפוש חי ברשימה; `data-kol-search-fields="word meaning"` |
| `data-kol-filter="words:topics"` | מכל | כפתורי סינון לפי שדה; הילד `<template>` הוא תבנית הכפתור |
| `data-kol-count="words"` | כל אלמנט | "X מתוך Y" — התבנית בתכונה `data-kol-count-text`, נערכת |
| `data-kol-more="words"` | כפתור | "טען עוד" |
| `data-kol-empty="words"` | כל אלמנט | מוצג כשאין תוצאות |
| `data-kol-play` | כפתור בתוך התבנית | משמיע את ההקלטה של הפריט |

כל הטקסטים שהגולש רואה — כיתובי הכפתורים, המונה, הודעת הריק — הם תוכן של אלמנטים בקובץ, ולכן נבחרים ונערכים
(`01-gap` ע-6 עד ע-8). אין כיתוב שחי בתוך ה-JS.

### 8.3 מי מממש

אותה סמנטיקה, בשלושה מקומות, **מאותו קוד**:

| איפה | מה רץ | מתי |
| --- | --- | --- |
| אצל הגולש | `js/kol-data.js` של הפרויקט | חיפוש, סינון, "טען עוד", נגן |
| בבנייה לפרסום | אותו קובץ, במסגרת הבנייה המבודדת (D5) | כותב את הרשימה ל-HTML מראש, כדי שגוגל יראה את המילים בלי להריץ קוד (`00` §7.3) |
| בקנבס העריכה | המימוש של הכלי — אותו מקור, בהקשר מהימן (סעיף 6) | הצגת הכרטיסים כאלמנטים שנבחרים |

`kol-data.js` אינו נשען על אחסון בדפדפן (אין במקור אטום), וטוען את `data/words.json` ב-`fetch` יחסי (I4).

**בעל העמוד אינו חייב להשתמש בקשירה.** הוא יכול למחוק את `kol-data.js` ולכתוב את הרשימה בקוד משלו. אז היא נערכת
בקוד בלבד — זה הפער פ-1 שב-`01-gap` §6, והוא פתוח.

## 9. גרסאות, טיוטה ופרסום — ברמת המודל

- **טיוטה** = מצב הקבצים עכשיו. **גרסה מפורסמת** = צילום של כל העץ ברגע הפרסום (מניפסט: נתיב ← hash; `07`).
- **נקודת שחזור** = צילום של כל העץ + הנתונים, כמו היום, מורחב לקבצים. שחזור יוצר נקודה חדשה ואינו מוחק (ע4).
- **היסטוריה** = רצף השינויים בכל הקבצים, עם שמות ("גודל הכותרת הראשית", "גרירת כותרת") — `04`.
- הגרסאות ונקודות השחזור של המודל הישן נשארות לצפייה ולשחזור אל המודל הישן; אינן נמחקות (`09`).
