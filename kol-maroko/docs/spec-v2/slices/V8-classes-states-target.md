# פרוסה V8 — מחלקות משותפות, מצבים, כלל היעד המלא, "מאפיינים נוספים", תכונות

> **אפיון:** `03-visual-editor.md` §4.2 (כלל היעד), §4.4 ("מאפיינים נוספים"), §8.2 (מצבים ומחלקות). **תלות:** V3; V7 רצויה
> (מצב × מכשיר). **תלויה בבעלים:** לא.
> **מה קיים בקוד (V3):** בחירה מרובה (`canvas.picked()`, Shift + לחיצה) — כל שינוי נכתב **לכלל של כל אחד בנפרד**; כלל היעד
> מציע: המחלקה, הכלל שהערך בא ממנו, `style=""`, ומחלקה חדשה בשם קריא (`Styler.suggest`).
> **החלוקה:** כמו שביקשה הבקרה — הליבה היא "צור מחלקה משותפת". נשארים כאן גם המצבים, "מאפיינים נוספים" והתכונות, כפי
> שנקבע ב-`03` §15: שלושתם הם **אותו כלל יעד**, ופיצול שלהם היה כותב את בורר היעד פעמיים.

## 1. מה בונים

אחרי V8 בעל העמוד **מעצב כמה אלמנטים יחד ובמקום אחד**, מעצב ריחוף ולחיצה, ו**אין מאפיין CSS ואין תכונת HTML שאינו
יכול לכתוב מהפאנל.**

1. **"צור מחלקה משותפת"** מבחירה מרובה; ניהול מחלקות (תגיות), שינוי שם בכל הפרויקט.
2. **מצבים:** רגיל / ריחוף / מיקוד / לחוץ / וכל פסאודו-מחלקה — והקנבס מציג את המצב.
3. **כלל היעד המלא:** מחלקה משותפת, תגית, בורר בהקלדה, מצב.
4. **"מאפיינים נוספים"** — כל הצהרה, וכל מאפיין.
5. **זהות:** `id`, מחלקות, וכל תכונת HTML.

## 2. קריטריוני קבלה

### מחלקה משותפת — הליבה

- [ ] בבחירה מרובה (2 ומעלה), בראש לשונית "עיצוב": **"משנה את: כל אחד בכלל שלו (3)"** (ההתנהגות של V3), ולצידו
      **"צור מחלקה משותפת"**. לחיצה: שם מוצע — **המחלקה המשותפת הקיימת**, אם יש (כל הנבחרים חולקים `kadisha-hero-title`;
      אז היא ברירת המחדל, "משפיע על 6"), אחרת שם נגזר מהמשותף (`hero-title`, מתגית + הקשר), ניתן לשינוי לפני האישור.
- [ ] **מה נכתב — עסקה אחת:** המחלקה מתווספת ל-`class` של כל אלמנט (בסוף, בלי לשנות את הקיימות; אלמנט בלי `class` — מקבל
      תכונה), וכלל ריק נוצר בקובץ `styles.page`. **הערכים אינם מועתקים לכלל** — המראה אינו משתנה ביצירה.
- [ ] **"העבר את המשותף למחלקה"** (אופציונלי, בתיבה בדיאלוג): הצהרות **זהות** בכל הכללים הנוכחיים של האלמנטים (אותו מאפיין,
      אותו ערך) מועברות לכלל החדש ונמחקות מהמקור — רק אם המקור הוא כלל **של אלמנט אחד** (מחלקה שלו בלבד). תצוגה מקדימה
      של ההצהרות; הבדיקה: המראה המחושב של כל אלמנט **זהה לפני ואחרי** (בדיקה אוטומטית בקנבס, ואם לא — הפעולה מבוטלת).
- [ ] מרגע שנוצרה, בורר היעד מציע אותה ראשונה לכל בחירה של אלמנטים שחולקים אותה; כל שינוי — פעם אחת, לכולם.
- [ ] **סדר הכלל:** הכלל החדש נכתב בסוף הקובץ, והעורך **אינו** מסדר מחדש כללים כדי שינצח. כשערך בו לא ייראה (כלל של
      מחלקה ספציפית דורס) — "נדרס" של V3, עם ההצעות.

### ניהול מחלקות

- [ ] לשונית "מתקדם" ← "זהות": המחלקות של האלמנט **כתגיות** — הוספה (השלמה מכל המחלקות בפרויקט: HTML ו-CSS), הסרה, גרירה
      לשינוי סדר. לכל תגית: כמה אלמנטים נושאים אותה, וכמה כללים משתמשים בה. ריחוף מסמן אותם בקנבס.
- [ ] **"שנה שם בכל הפרויקט":** מעדכן כל הופעה — `class=""` בכל עמוד ורכיב, בוררי CSS, ו**מחרוזות ב-JS** (מוצגות לבחירה
      ידנית, לא מוחלפות לבד, כי `'.hero'` ב-JS עשוי להיות משהו אחר). תצוגה מקדימה: diff לכל קובץ. עסקה אחת.
- [ ] מחלקה שאין לה כלל ואינה ב-JS — "לא משמשת לעיצוב". כלל שאין אלמנט שתואם לו — מסומן "לא חל על אף אלמנט" (גם בקוד).
- [ ] `id`: שדה; כפול בעמוד — מסומן; שינוי מעדכן `for` / `aria-*` / `href="#…"` בעמוד ובוררי `#id`, עם תצוגה מקדימה.

### מצבים

- [ ] בורר מצב בראש לשונית "עיצוב": **רגיל · ריחוף · מיקוד · לחוץ · ביקור (קישור) · מושבת · ראשון / אחרון**, ושדה להקלדת כל
      פסאודו-מחלקה (`:focus-visible`, `:nth-child(2n)`, `:has(img)`, `:checked`…) — מה ש-`CSS.supports('selector(…)')` מקבל.
- [ ] **הקנבס מציג את האלמנט במצב שנבחר**, בלי עכבר: העורך מעתיק את הכללים של המצב לכלל זמני שמכוון לאלמנט (בקנבס
      בלבד, לא בקובץ). ריחוף אמיתי בקנבס לא נשבר.
- [ ] **מה נכתב:** כלל `<יעד>:<מצב>` **מיד אחרי** כלל היעד (`03` §4.2), באותו קובץ; עם מכשיר (V7) — בתוך ה-`@media`. כלל קיים
      שמכסה את אותו מצב (`.btn:hover, .btn:focus`) — נערך במקומו, ונאמר שהוא משותף לשני מצבים.
- [ ] בפאנל, במצב שאינו רגיל: כל ערך מראה "נכתב במצב הזה" / "עובר מרגיל"; איפוס במצב מוחק רק את ההצהרה של המצב.
- [ ] **מעבר (transition)** בין רגיל למצב — שליטה בקבוצת "תנועה" הבסיסית: מאפיין (או "הכול"), משך, השהיה, עקומה.
      (שאר "תנועה" — V10.)
- [ ] **מצב של הורה** ("כשמרחפים על הכרטיס — הכותרת משנה צבע"): בורר "מצב של: האלמנט / `<הורה>`" — נכתב `.card:hover .title`.

### כלל היעד המלא

- [ ] הבורר מציע, בנוסף על V3: **מחלקה משותפת** (כל מחלקה של האלמנט, עם "משפיע על N") · **התגית** (`h2` ← `styles.base`) ·
      **בורר בהקלדה** (כל בורר; העורך מראה על כמה ועל אילו אלמנטים הוא חל, ומזהיר אם אינו חל על הנבחר) · **מצב** (למעלה).
- [ ] **ספציפיות גלויה:** לכל יעד ברשימה — האם ינצח את מה שנראה היום, לפני הבחירה (✓ / "נדרס ע"י …").
- [ ] **המפל — הסגירה של ⚠️ מ-V3:** `@layer`, `@scope` ו-`:where()` / `:is()` מקוננים מחושבים לפי הכללים, לא בקירוב. הבדיקה:
      200 מקרים אקראיים שבהם "מי מנצח" של הפאנל = `getComputedStyle` של הקנבס.

### "מאפיינים נוספים" (`03` §4.4)

- [ ] בתחתית כל לשונית, ובלשונית "מתקדם": **כל ההצהרות שחלות על האלמנט ואין להן שליטה ייעודית** — שם, ערך, מקור, מכשיר,
      מצב, `!important`, איפוס. נערכות במקום (שם וערך), עם השלמה של **כל** מאפייני ה-CSS (מהדפדפן: `CSS.supports` על הרשימה
      של `getComputedStyle`), כולל מאפיינים מותאמים (`--x`).
- [ ] "＋ מאפיין": שם (השלמה) וערך — נכתב לכלל היעד, במכשיר ובמצב הנוכחיים. **הבדיקה של המבחן:** מאפיין שאין לו שליטה בשום
      פרוסה (`mix-blend-mode`, `clip-path`, `writing-mode`, `scroll-snap-type`) — נכתב, נראה בקנבס, ונמחק.
- [ ] "צפה כ-CSS": כל הצהרות כלל היעד כטקסט, נערכות כגוש (עם `checkValue` של V3 על כל ערך) — למי שמעדיף להקליד.

### תכונות HTML

- [ ] "מתקדם" ← "זהות" ← **תכונות:** כל התכונות של האלמנט, נערכות; "＋ תכונה" — שם וערך. השלמה לתכונות המוכרות של התגית
      ול-`aria-*`, `data-*`, `role`, `title`, `lang`, `dir`, `tabindex`.
- [ ] תכונות `data-kol-*` מוצגות בקבוצה "נתונים" עם הסבר בעברית (`02` §8.2); עריכתן החזותית — V11, וכאן הן נערכות כטקסט.
- [ ] **אסור — ונאמר:** `on*` (`onclick`…) ו-`href="javascript:…"` אינם נכתבים מהפאנל ("קוד נכתב בקובץ JS — פתח בקוד"),
      כמו `<` בערך CSS ב-V3. זו אינה נעילה של העמוד — זו הגנה על **מי שפותח את העורך** (הקנבס אינו מריץ קוד, אבל מסך אחר
      עלול להציג). בקוד הם נכתבים, ורצים בתצוגה החיה ואצל הגולש.
- [ ] ערכים עם מרכאות, `&`, `<` — נכתבים כישויות (כמו `escAttr` של V3). בדיקת K2 לתכונה חדשה, שינוי, מחיקה, ושם עם `:`.

### כללי

- [ ] כל פעולה: עסקה עם שם; ביטול מחזיר קבצים זהים; נראית מיד בעורך הקוד.
- [ ] הרתמה — K2 לכל סוג כתיבה חדש: מחלקה לכמה אלמנטים + כלל (n+1 טווחים, שני קבצים) · העברת הצהרות בין כללים · כלל מצב
      אחרי היעד · כלל מצב בתוך `@media` · שינוי שם בכל הפרויקט · תכונה חדשה / מחיקה. **שקילות המודל** אחרי כל אחת.
- [ ] **איפה הנתונים:** קובצי הפרויקט בלבד. אין נתיב חדש.
- [ ] `v8.cjs`: שש הכותרות ← "צור מחלקה משותפת" ← צבע ← כולן משתנות, קובץ אחד השתנה בשורה אחת · ריחוף ← צבע ← הקנבס מציג,
      והכלל `:hover` אחרי הבסיס · `clip-path` מ"מאפיינים נוספים" · ביטול עד ההתחלה — קבצים זהים.

## 3. בדיקת הבעלים (מטלה)

על העמוד האמיתי: לבחור את שש הכותרות (Shift) ← "צור מחלקה משותפת" ← לשנות גופן וצבע פעם אחת · לבחור כפתור נושא ←
"ריחוף" ← צבע אחר, ולראות בקנבס בלי עכבר · להוסיף מ"מאפיינים נוספים" `letter-spacing` שלילי ו-`text-shadow` · לשנות שם
של מחלקה ולראות את ה-diff · Ctrl+Z עד ההתחלה.

## 4. מה לא כלול

גלובליים (משתנים, ברירות מחדל לתגיות, גופנים) — V9 · שאר "תנועה" (אנימציה, transform, גלילה) — V10 · מצבים של רשימת
הנתונים ("אין תוצאות") — V11 · העתק / הדבק סגנון — V13.

## 5. השורה שעונה על המבחן

V8 סוגרת את **הרשת שמתחת לכל השליטות**: אחריה **אין מאפיין CSS ואין תכונת HTML שבעל העמוד רואה את תוצאתם ואינו יכול
לכתוב מהפאנל** (`03` §1.4). ו-`01-gap` 3.11, 4.7–4.9, 6.6, 6.8, 6.9; **ע-19** בחלק הריחוף.

**מה נשאר:** `on*` ו-`javascript:` — בקוד בלבד, בכוונה ובגלוי (למעלה). אנימציות — V10. פסאודו-אלמנטים (`::before`) נבחרים
מ-V5 ונערכים כאן כיעד ("`::before` של `.kadisha-hero`") — כולל `content`.
