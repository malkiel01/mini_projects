# פרוסה N3 — רשימות נוספות ("פתגמים"): טבלה, קובץ, שדות ואקסל לכל רשימה

> **אפיון:** `06-data.md` §2.5 (המילון הוא פשוט הרשימה הראשונה), §2.6, §4; `02-project-model.md` §5 (`data` ב-`kol.json`), §8.
> **תלות:** **N2 מוזגה** (שדות לפי סוג, "מתפרסם", מנוע האימות והשינויים) · N1 ✔. **V11** — רק לחלק "גרור רשימה לקנבס"; בלעדיה N3
> מוסיפה את הרשימה לעמוד דרך קובץ (§2.5), ולכן **אינה מחכה ל-V11**. **תלויה בבעלים:** **[ש-16]** — ברירת המחדל "א" (רשימות בעצמו).
> **מה קיים אחרי N2:** מנוע אחד למילים (`words_json`, `words_file_items`, `words_plan`, `words_apply`, `words_csv*`) שקשור לטבלאות `words` / `topics`;
> `word_fields`; הקובץ הווירטואלי `data/words.json` (`pf_words_path`, `PF_WORDS_ID = -1`). **`kol-data.js` כבר כללי:** כל `data-kol-list="<שם>"`
> טוען `data/<שם>.json`, כל מפתח-רשימה בראש הקובץ (`[{id,label}]`) הוא טבלת תוויות לסינון, וכל שדה נקשר בשמו — **אין בו שינוי ב-N3.**

## 1. מה בונים

בעל העמוד לוחץ "➕ רשימה חדשה", קורא לה "פתגמים", מוסיף לה שדות (פתגם, פירוש, הקלטה, מקור) — ומקבל את כל מה שיש למילים:
טבלה, קובץ `data/proverbs.json` בעץ, אקסל, שדות "מתפרסם", הקלטות, סדר בגרירה, סל — **ובלחיצה אחת גם קטע בעמוד** שמציג אותה עם
חיפוש וסינון. המילון אינו מקרה מיוחד בממשק; הוא הרשימה הראשונה.

## 2. קריטריוני קבלה

### 2.1 המודל — הוספה בלבד

- [ ] `lists` — `key` (PK, `^[a-z][a-z0-9_]{0,29}$`, לא `words`, לא שם של קובץ מערכת), `label` ("פתגמים"), `item_label` ("פתגם"), `sort_order`,
      `created_at`, `created_by`. **המילים אינן שורה בטבלה הזו** — הן נשארות בטבלאות שלהן; המנוע רואה אותן כרשימה בשם `words`.
- [ ] `list_items` — `list`, `id` (מספר שלם, **לכל רשימה בנפרד**, מ-1, לא חוזר אחרי מחיקה), `data` (JSON לפי השדות), `sort_order`, `updated_at`,
      `updated_by`; `PRIMARY KEY (list, id)`. `list_trash` — כמו `words_trash` (+ `list`).
- [ ] `list_fields` — אותו מבנה כמו `word_fields` של N2 + `list`; `PRIMARY KEY (list, key)`. **לא משנים את `word_fields`** (מיגרציה מוסיפה בלבד).
      רשימה חדשה נפתחת עם שדה אחד, `title` (טקסט קצר, חובה, מתפרסם) — ניתן לשינוי שם ומפתח כמו כל שדה.
- [ ] **מיגרציה אחת** — המספר: **max(main)+1 ברגע ההגשה "מוכן"** (אין מספרים שמורים). `snap_state()` כולל את שלוש הטבלאות.
- [ ] **איפה הנתונים:** `data/kol.sqlite` (מוחרג). אין קובץ חדש בשרת, אין `--exclude` חדש.

### 2.2 מנוע אחד, שני מתאמים

- [ ] `lib/lists.php` (חדש): הפעולות של N1/N2 — בנייה לקובץ, ניתוח ואימות עם שורה ועמודה, תצוגת שינויים לפי `id`, החלה בעסקה, CSV, סל,
      נקודת שחזור, סדר — **פעם אחת**, מעל מתאם: `list_adapter('words')` (הטבלאות של היום) ו-`list_adapter('<key>')` (`list_items`).
- [ ] **המילים עוברות דרך המנוע בלי שינוי התנהגות:** בדיקה — `data/words.json` (עורך, תצוגה, חבילה) **זהה בבייטים** לפני ואחרי N3; כל
      הבדיקות של N1 ו-N2 עוברות כמו שהן.
- [ ] `words_*` ב-`lib/lexicon.php` נשארות כשמות (נקראות מ-`build.php`, `project.php`, `preview.php`) ומעבירות למנוע — כך אף קובץ אחר
      אינו משתנה.
- [ ] **בחירה בקובץ:** לכל שדה `choice` — בראש הקובץ מפתח בשם השדה עם `[{"id": value, "label"}]` (מה ש-`kol-data.js` כבר קורא כטבלת
      תוויות), כך ש-`data-kol-filter="proverbs:source"` בונה כפתורים עם השמות. חל גם על שדות `choice` של המילים (N2), **רק כשיש כאלה**
      — בלי שדה כזה הקובץ של המילים לא משתנה.

### 2.3 בממשק

- [ ] **📚 מילים ← "📚 נתונים"**: בראש הלשונית — בורר רשימה ("מילים · פתגמים · ➕ רשימה חדשה"); הטבלה, "🧩 מבנה" (N2), החיפוש,
      הסינון, הגרירה והאקסל — אותו רכיב לכל רשימה, לפי השדות שלה. הנושאים (N2) — רק במילים.
- [ ] **➕ רשימה חדשה:** שם, שם לפריט, מפתח (נגזר, ניתן לשינוי), נתיב הקובץ (ברירת מחדל `data/<key>.json`). נוצרת ← נרשמת ב-`kol.json`
      (`"data": {"proverbs": {"file": "data/proverbs.json", "source": "list:proverbs"}}`) — **שמירה של `kol.json` דרך מנוע הקבצים של F2**
      (גרסה בהיסטוריה), והקובץ מופיע בעץ עם סמל "מקושר לטבלה".
- [ ] **ייבוא מאקסל כרשימה חדשה:** "➕ רשימה חדשה ← מאקסל": השורה הראשונה היא הכותרות ← שדה לכל עמודה (סוג מנוחש, כמו ההצעה ב-N2),
      תצוגה מקדימה של השדות ו-5 השורות הראשונות, ואז יצירה + ייבוא באותה עסקה.
- [ ] **שינוי שם / מפתח של רשימה:** המפתח הוא שם הקובץ ושם הרשימה בקשירות — אותה תצוגת קשירות של N2 §3.3 (`data-kol-list`, `-search`,
      `-filter`, `-count`, `-more`, `-empty`, `data-kol-src`), עסקה אחת. **מחיקת רשימה** — לסל, כולה (השורה, השדות, הפריטים), עם נקודת
      שחזור; הרישום ב-`kol.json` מוסר; האזהרה מונה את הקשירות שיישארו בלי נתונים. "שחזור" מחזיר הכול.

### 2.4 הקובץ, הבנייה, ההקלטות

- [ ] הקובץ הווירטואלי של N1 **לכל רשימה**: `pf_words_path` ← `pf_list_paths()` (מ-`kol.json`, כל `source: "list:*"` ו-`"words"`); קריאה, שמירה,
      `rev`, התנגשות, מחיקה (= הסרה מ-`kol.json`, הטבלה נשארת), שכפול (עותק סטטי + אזהרת "שדות פנימיים") — כמו במילים.
- [ ] **תצוגה חיה ובנייה:** כל רשימה רשומה נבנית לחבילה (`build_words` ← `build_lists`), רק השדות המתפרסמים, עם קובצי `image` / `audio`
      בנתיבים `media/audio/<list>-<id>-<key>.<ext>` / `media/images/…`. **כתיבה מראש לגוגל** (`data-kol-prerendered`, M1) — לכל `data-kol-list`,
      לא רק `words`.
- [ ] שדה `audio` ברשימה — נערך מהטבלה (`Media.pick`), נבנה לחבילה. בספריית ההקלטות (📼) — כמו "הקלטה שנייה" של N2: **N2b**, אחרי A3.
- [ ] בדיקה: רשימה עם 3 פריטים ← `data/proverbs.json` בתצוגה החיה ובחבילה, בסדר הנכון, בלי שדה פנימי.

### 2.5 "הוסף לעמוד" — בלי לחכות ל-V11

- [ ] ברשימה — "➕ הוסף לעמוד": בוחרים קובץ עמוד ומקום ("בסוף `<main>`" / "בסוף `<body>`" / "אחרי האלמנט עם `id`…"). נוסף **קטע HTML רגיל**:
      כותרת (`label` של הרשימה), תיבת חיפוש (`data-kol-search`), כפתורי סינון לשדה `choice` הראשון (אם יש), מונה, המכל (`data-kol-list`,
      `data-kol-sort="manual"`) עם `<template>` שבו אלמנט לכל שדה מתפרסם (`data-kol-text` / `-html` / `-attr-src` / `data-kol-play` לפי הסוג),
      "טען עוד", ו"אין תוצאות". **כל הכיתובים — טקסט באלמנטים** (כלל 1 של `kol-data.js`), בעברית, ניתנים לעריכה.
- [ ] וגם `css/page.css` מקבל בלוק קצר עם מחלקות הקטע (`.kol-list-<key> …`). שני הקבצים נשמרים **דרך מנוע הקבצים** (גרסה בהיסטוריה,
      "הוסף את הרשימה פתגמים"), כך שהעורך החזותי וה-Ctrl+Z שלו רואים אותם כשינוי רגיל.
- [ ] **אם V11 כבר מוזגה** — גם "גרור רשימה לקנבס" מהפאנל שלה (מה ש-V11 מגדירה); אם לא — הכפתור הזה בלבד, ו-V11 תוסיף את השאר.
- [ ] בדיקה (`tests/browser/n3.cjs`): רשימה חדשה ← שלושה פריטים ← "הוסף לעמוד" ← בתצוגה החיה: הכותרת, שלושת הפריטים, החיפוש מוצא אחד,
      הסינון עובד; Ctrl+Z בעורך מסיר את הקטע.

## 4. מה לא כלול

"גרור רשימה לקנבס" ובחירת שדות לכרטיס בפאנל — **V11** · קשר בין רשימות (פתגם ← מילה) — לא בשלב הזה; שדה `text` עם מזהה מספיק
לקישור בקוד · הקלטות של רשימה בספריית ההקלטות — **N2b** · רשימה שמקורה בכתובת חיצונית (`data-kol-src` חיצוני) — כבר נתמך ב-`kol-data.js`,
מחוץ לניהול של הכלי (**[ש-12]**).

## 6. השורה שעונה על המבחן

N3 סוגרת `01-gap` 9.6 ואת החצי השני של **[ש-16]**: בעל העמוד **פותח רשימה חדשה בעצמו**, והיא מקבלת כל מה שיש למילים — בלי
