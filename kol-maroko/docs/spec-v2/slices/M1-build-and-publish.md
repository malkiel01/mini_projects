# פרוסה M1 — בנייה ופרסום של פרויקט הקבצים (צד הכלי)

> **אפיון:** `07-publish-and-mount.md` §1–4, §9; `06-data.md` §4 (שדות "מתפרסם"); `09-migration.md` (סדר המעבר). **תלות:** F2a ✔,
> F3 ✔ (🧪 בשרת), F4 ✔ (המסגרת המבודדת); N1 — **לא חוסמת** (ראו §2, "נתונים"). M2 (התוסף v2) — **לא חוסמת את הבנייה**,
> וחוסמת רק את השליחה לאתר האמיתי. **תלויה בבעלים:** **[ש-7]** (מפרסם מיד — ברירת המחדל), **[ש-12]** (משאבים חיצוניים —
> מידע, לא חסימה). נכתב לפי ברירות המחדל.
> **נבנית במקביל ל-V4**, בצ'אט קוד נפרד. לכן §5 קובע בדיוק אילו קבצים מותר לה לגעת.

## 1. מה בונים

אחרי M1 מפרסם (`publisher`) לוחץ "🚀 פרסום" על **פרויקט הקבצים** (לא על הטיוטה הישנה), ומקבל: **בנייה** בדפדפן שלו,
**"מה ישתנה"** מול הגרסה הקודמת, ו**חבילה חתומה** — קבצים לפי sha256 ומניפסט — שנשמרת בכלי ונשלחת לאתר ברגע שהתוסף
יודע לקבל אותה (M2).

1. **הבנייה** (`07` §2) — במסגרת מבודדת, מאותו מנוע כמו התצוגה החיה.
2. **"מה ישתנה"** (`07` §3) — קבצים, נתונים, משאבים חיצוניים, אזהרות, ותצוגה של הגרסה הבנויה.
3. **המניפסט והחתימה** (`07` §4) — Ed25519 במפתח הקיים.
4. **שליחה לפי hash** — רק מה שהאתר עוד אינו מחזיק; המניפסט אחרון.
5. **הודעת פרסום** לבעל האתר **[ש-7]**.

**מה לא משתנה:** מסלול הפרסום של היום (טיוטה ← `html` + `css` ← תוסף 1.4) **ממשיך לעבוד כמו שהוא**, והוא זה שמגיש את
העמוד החי עד M3. M1 מוסיפה מסלול שני, ואינה נוגעת בראשון.

## 2. קריטריוני קבלה

### הבנייה (`07` §2)

- [ ] "🚀 פרסום" ← **"בנה גרסה מהפרויקט"**: הכלי מגיש את קובצי הפרויקט (F2, אותו `rev`) למסגרת מבודדת **בתוך הדפדפן של
      המפרסם** — אותה מסגרת ואותה מדיניות כמו התצוגה החיה (F4, `00` §7.1: מקור אטום, בלי גישה לעוגיות ולמסד). אין Node בשרת.
- [ ] **הבנייה מעתיקה כל קובץ כמו שהוא** — בייט בבייט. בדיקה: sha256 של כל קובץ בחבילה = sha256 שלו במאגר, **חוץ** מ:
      (א) קובצי `data/*.json` שנבנו מהטבלאות; (ב) עמודים עם כתיבה מראש. שום קובץ אחר אינו שונה, מאוחד, מקוצר או מקבל קוד של הכלי.
- [ ] **מה יוצא מהחבילה:** `kol.json` ו-`components/*/component.json` — לא נשלחים (הגדרה במסך: "פרסם גם אותם", כבוי).
      שום קובץ אחר אינו מוצא בשקט; קובץ שהמפרסם בחר להוציא (רשימה במסך) — מופיע ב"מה ישתנה".
- [ ] **נתונים:** `data/words.json` נבנה מטבלת המילים **באותה פונקציה שמגישה אותו לתצוגה החיה** (`pv_words`, `lib/preview.php`),
      כדי שהתצוגה והפרסום יראו אותו דבר. השדות: מה שהתצוגה מגישה היום (עד N1 / N2 — כל השדות; אחרי N2 — רק "מתפרסם", `06` §4).
      ההקלטות: כתובות **בתוך החבילה** (`media/audio/<id>.<ext>`) לכל הקלטה שכבר אצלנו (A2); הקלטה שעדיין "באתר" — נשארת
      כתובת, ומופיעה באזהרות (`07` §3).
- [ ] **כתיבה מראש** (`data-kol-prerender` על המכל; בלי — "הכול"): במסגרת הבנייה רץ `js/kol-data.js` **של הפרויקט** על כל
      עמוד שיש בו `data-kol-list`; ה-DOM שנוצר ברשימה נכתב לתוך ה-HTML **בתוך המכל בלבד** (סימון `data-kol-prerendered`
      על המכל, כדי ש-`kol-data.js` אצל הגולש ימשיך ממנו ולא יכפיל). שאר הקובץ — בייט בבייט מהמקור. `"N"` — N ראשונים; `"none"` — בלי.
- [ ] **כשהבנייה נכשלת** (שגיאת JS בכתיבה מראש, קובץ שהעמוד מפנה אליו ואינו קיים, זמן מעל 60 שניות): **אין גרסה**. המסך
      מציג את השגיאה עם קובץ ושורה, "פתח בקוד", ו**"בנה בלי כתיבה מראש"**. בלי `kol-data.js` — "אין כתיבה מראש" כהודעה, לא כשגיאה.
- [ ] **המניפסט** נבנה בדפדפן: `entry`, `files: { path: { sha256, size, type } }` — sha256 מחושב **בשרת** מחדש לכל קובץ שהועלה,
      ונדחה אם אינו תואם. נתיב: יחסי, בלי `..`, בלי `\`, בלי תווי בקרה, עד 255 תווים; סוג — לפי הסיומת, מרשימה סגורה בשרת.
- [ ] ביצועים: הפרויקט המוסב (כ-1,500 מילים, הקלטות כהפניות) נבנה בפחות מ-20 שניות במחשב; פס התקדמות לכל שלב.

### "מה ישתנה" (`07` §3)

- [ ] מול **הגרסה האחרונה של המסלול החדש** שנשלחה בהצלחה; אין כזו — "פרסום ראשון: כל הקבצים חדשים", ומתחתיו השוואה
      **חזותית** (לא קבצית) מול העמוד של היום: צילום של התצוגה הבנויה לצד התצוגה החיה של הטיוטה הישנה, ב-1280 וב-390.
- [ ] **קבצים:** נוספו / השתנו / נמחקו, עם diff לכל קובץ טקסט (אותו רכיב diff של היסטוריית F2) ותצוגה ממוזערת למדיה.
- [ ] **נתונים:** כמה מילים נוספו / השתנו / נמחקו, כמה הקלטות — מתוך השוואת `data/words.json`.
- [ ] **משאבים חיצוניים [ש-12]:** כל `http(s)://` שמחוץ לחבילה — מסריקת ה-HTML וה-CSS (כולל `url()` בתוך `var()`, `03` §4.1),
      ומה שהמסגרת המבודדת ביקשה בפועל בזמן הבנייה. לכל אחד: כתובת, סוג, קובץ ושורה. **מידע, לא חסימה.**
- [ ] **אזהרות:** הפניה פנימית שבורה (`src` / `href` / `url()` לקובץ שאינו בחבילה); הקלטה "באתר"; קובץ מעל 10MB; דבר שלא
      יעבוד בארגז החול (`localStorage`, `serviceWorker`, `<iframe>` של יוטיוב — `00` §7); גודל החבילה מול המכסה (`settings`).
      אזהרה **אינה חוסמת** פרסום, חוץ מחריגה מהמכסה.
- [ ] **"▶️ תצוגה של הגרסה הבנויה"** — החבילה עצמה, במסגרת המבודדת, מהקבצים הבנויים (לא מהמאגר).
- [ ] הבנייה נשמרת כ**גרסה מוכנה** (`built`), עם המניפסט, ה-diff והאזהרות — גם אם לא נשלחה. אפשר לבנות שוב; גרסה מוכנה
      ישנה מסומנת "נבנתה מ-rev N; הפרויקט השתנה מאז".

### המניפסט, החתימה והשליחה (`07` §4)

- [ ] המניפסט המלא: `site`, `page`, `version` (עולה בלבד, **מונה משותף** לשני המסלולים — כדי שהתוסף לא יקבל מספר שכבר ראה),
      `time`, `nonce`, `entry`, `published_by`, `files`. חתום ב-**Ed25519** במפתח הקיים (`pub_key`), על הבייטים כפי שנשלחו.
- [ ] **שליחה לפי hash:** לכל קובץ — שאלה לאתר "יש לך?" (`asset_has`, רשימה בבקשה אחת), ואז העלאה בחלקים של מה שחסר
      (`asset_put`, אותו מנגנון חלקים של `asset_send` היום). **המניפסט נשלח אחרון** (`manifest`). עד שהוא התקבל — דבר באתר
      לא השתנה, ובכלי הגרסה `sending`, לא `live`.
- [ ] **החתימה על כל בקשה** — כמו `site_post` היום (פעולה, אתר, עמוד, זמן ±5 דקות, nonce חד-פעמי). אין סוד בדפדפן: הקבצים
      הבנויים עולים לכלי, **והכלי** (השרת) הוא ששולח לאתר.
- [ ] **כשל באמצע** (רשת, תשובה שאבדה): אפשר "המשך שליחה" — מה שהאתר כבר אישר אינו נשלח שוב. תשובת `old_version` עם אותו
      מספר — נחשבת הצלחה (כמו `version_send` היום).
- [ ] **הבדיקה לפני השליחה:** `site_ping` מחזיר את גרסת הפרוטוקול של התוסף. **תוסף 1.x** ← הכפתור "שלח לאתר" מושבת, עם:
      "הגרסה מוכנה ונשמרה. התוסף באתר הוא 1.x — לשליחה נדרש 2.0 (M2, מטלה לבעלים)". **הבנייה וכל "מה ישתנה" עובדים בלי תוסף.**
- [ ] פרסום ששינה כותרת אחת שולח **קובץ אחד** ומניפסט (בדיקה מול המקבל המדומה, §3).
- [ ] הרשאות: בנייה — `editor` ומעלה (רואה, אינו שולח); שליחה — `publisher` (`require_role`, ברשימת פעולות הכתיבה, `pf_guard`).
      `audit` לכל בנייה, שליחה וכשל.

### הודעת פרסום [ש-7]

- [ ] אחרי פרסום שהצליח: שורה ביומן הפעולות, **והודעה בכלי לבעל האתר** (`owner`) — מי, מתי, גרסה, קישור ל"מה ישתנה" של
      אותה גרסה — מוצגת בכניסה הבאה שלו עד שנקראה. מייל — רק אם יתברר שיש שליחת מייל מהשרת (`06` §3.4); לא חלק מ-M1.

### כללי

- [ ] **המסלול הישן לא נשבר:** הבדיקות הקיימות של פרסום הטיוטה (`tests/run.php`, `fake-wp.php`) עוברות בלי שינוי; פרסום
      בטיוטה ממשיך לשלוח `html` + `css` לתוסף 1.4.
- [ ] **איפה הנתונים:** הגרסות — טבלה במסד הקיים (`data/kol.sqlite`, מיגרציה חדשה); קובצי החבילה — **לפי sha256 במאגר
      הקיים** (`pf_blob_put`, `data/files/_project/`), בלי עותק נוסף. שני המקומות כבר מוחרגים בפריסה — **אין `--exclude` חדש**.
      אם הקוד בוחר תיקייה אחרת תחת `data/` — `--exclude` לפניה, דרך הבקרה.
- [ ] `php -l`, `node --check`, `check-apps`, `sync --check`; כל הבדיקות של §3.

## 3. מה נבדק בלי האתר — ומה רק עם M2

התוסף v2 אינו קיים, ולכן **שום פרסום של M1 אינו מגיע לגולש**. מה שכן נבדק, מקצה לקצה, בלי האתר:

| בדיקה | איך |
| --- | --- |
| **מקבל מדומה v2** | `tests/fake-wp.php` מקבל את שלוש הפעולות החדשות (`asset_has`, `asset_put`, `manifest`) לפי `07` §5.1: מאמת חתימה, nonce, זמן, hash של כל גוש, ושכל קובץ שבמניפסט קיים — ורק אז "מחליף מצביע". זה **החוזה של M2**, כתוב כבדיקה |
| שליחה | פרסום ראשון שולח את כל הקבצים; שינוי כותרת ← קובץ אחד; כשל באמצע ← "המשך" אינו שולח שוב; מניפסט שקובץ בו חסר ← נדחה, ו"הגרסה שבאוויר" במקבל לא השתנתה |
| חתימה | מניפסט ששונה בבייט אחד אחרי החתימה ← נדחה; nonce חוזר ← נדחה; זמן מחוץ ל-±5 דקות ← נדחה |
| **החבילה נכונה** | `tests/browser/m1.cjs`: בונה את הפרויקט המוסב (`f3-seed.php`), **מגיש את החבילה מתיקייה סטטית** (שרת הבדיקה) ופותח אותה בדפדפן: המילים נראות **עם JS כבוי** (כתיבה מראש), החיפוש והסינון עובדים עם JS, ההקלטה מתנגנת, 0 בקשות שנכשלו, 0 שגיאות קונסול. זו ההוכחה ש"החבילה עומדת בפני עצמה" (R2) |
| בייט בבייט | sha256 של כל קובץ בחבילה מול המאגר — הכול שווה חוץ מ-`data/*.json` ומהמכלים שנכתבו מראש |
| כשל בנייה | `kol-data.js` שזורק שגיאה ← אין גרסה, השגיאה עם קובץ ושורה; "בלי כתיבה מראש" ← גרסה |
| הרשאות | `editor` בונה ואינו שולח; `publisher` שולח; אורח — 401 |
| תוסף 1.x | `site_ping` מחזיר 1.4 ← "שלח" מושבת, הגרסה נשמרת `built` |

**רק עם M2 (ולכן לא קריטריון של M1):** קבלה אטומית באתר האמיתי; הגשה לפי I1–I8; מטמון LiteSpeed / Cloudflare; `Range` לשמע;
ערכת ההתקפה. M1 **נמסרת** כשכל הטבלה למעלה ירוקה; היא **נסגרת** (`01-gap`) רק אחרי M2.

**בדיקת הבעלים (מטלה):** "🚀 פרסום" ← "בנה גרסה מהפרויקט" ← לעבור על "מה ישתנה" ← "▶️ תצוגה של הגרסה הבנויה" בטלפון
ובמחשב ← לראות "התוסף באתר הוא 1.x". ו"🐞" על כל דבר בתצוגה הבנויה שאינו כמו בתצוגה החיה.

## 4. מה לא כלול

התוסף v2 — קבלה, הגשה, מטמון, חזרה לגרסה באתר (M2) · המעבר באתר החי והשבתת המסלול הישן (M3) · אופני הצבה (M4) · תיבת
פניות למשוב (M5) · "חזרה לגרסה קודמת" באתר — M2 (בכלי: רשימת הגרסות של המסלול החדש, לקריאה ול"בנה שוב מ-rev") · מייל לבעל האתר.

## 6. השורה שעונה על המבחן

M1 אינה משנה דבר ממה שהגולש רואה היום — ובכוונה. היא סוגרת את **החצי של הכלי** בצעד "להגיע לגולש" של "קוד-כללי"
(`01-gap` §1) ואת 11.4: מה שבעל העמוד כתב בקבצים נבנה, נבדק, ונחתם **בלי סינון ובלי קיצור**, והוכח בדפדפן שהחבילה עומדת
בפני עצמה.

**מה עדיין לא נכון אחרי M1 — בגלוי:** שום שינוי בקבצים **אינו מגיע לגולש**. העמוד החי ממשיך להיות מוגש מהטיוטה הישנה,
עם הסינון שלה (`01-gap`, "היום בקוד"), עד M2 (התוסף) ו-M3 (המעבר). מי שאומר לבעלים "אפשר לפרסם מהקבצים" לפני M2 — טועה.
