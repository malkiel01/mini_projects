> **מה קיים בקוד:** טבלת `words` (`id`, `wp_id`, `word`, `meaning`, `topics` כ-JSON של **שמות**, `audio`, `external_id`, `updated_*`),
> `topics` (`slug`, `name`), `words_trash`; `pv_words()` (`lib/preview.php`) בונה את `data/words.json` מהטבלה **לתצוגה החיה ולבנייה
> (M1)** — אבל **הקובץ אינו בעץ הפרויקט**: אי אפשר לפתוח אותו, לערוך או לשמור (`reviews/F3.md` ❌). הסדר — `lex_sort`, קבוע.

## 1. מה בונים

אחרי N1 מי שכותב קוד **פותח את `data/words.json` במנהל הקבצים, עורך, ושומר — והטבלה מתעדכנת**; ומי שמזין תוכן **גורר מילה
בטבלה, והסדר בעמוד משתנה**. שתי הדלתות הן אותם נתונים, בלי עותק שמתיישן.

1. **קובץ וירטואלי** `data/words.json` בעץ הפרויקט — נוצר מהטבלה בקריאה, נכתב לטבלה בשמירה, אחרי אימות ותצוגת שינויים.
2. **סדר ידני** — עמודה `sort_order`, גרירה בטבלה, ו-`"manual"` ב-`data-kol-sort` מכבד אותו.
3. **אקסל / CSV לפי `id`** — תצוגה מקדימה של מה ישתנה; "החלף הכול" רק במפורש.
4. **פונקציה אחת** שבונה את הקובץ — לתצוגה החיה, לבנייה, ולעורך.

## 2. קריטריוני קבלה

### הקובץ בעץ

- [ ] `data/words.json` מופיע במנהל הקבצים בתיקייה `data/`, עם סמל "מקושר לטבלה" ותווית: "נבנה מטבלת המילים — שמירה מעדכנת את
      הטבלה". המיקום והשם נקבעים ב-`kol.json` (`data.words.file`, `02` §5); שינוי שם הקובץ שם — מזיז אותו בעץ.
- [ ] **קריאה** (פתיחה בעורך, הורדה, ZIP, תצוגה חיה, בנייה): התוכן נבנה **ברגע הקריאה** בפונקציה אחת, `words_json()` — זו
      ש-`pv_words()` קוראת לה היום (העברה, לא העתקה). מבנה: `{ "topics": [{id, label}], "items": [{id, word, meaning, topics:[slug],
      audio, …}] }`, בסדר התצוגה (`sort_order`, ואחריו `id`), `JSON_PRETTY_PRINT`, שני רווחים, UTF-8 בלי escape.
- [ ] **אין גוש שמור:** הקובץ אינו נכתב ל-`data/files/_project/` ואינו נכנס להיסטוריית הקבצים כגוש. ה-`rev` שלו = חותמת של הטבלה
      (`max(updated_at)` + מספר שורות + גרסת הנושאים), כך שעורך שנפתח לפני שינוי בטבלה **יודע** שהקובץ השתנה (התנגשות — כמו כל
      קובץ ב-F2: "השתנה מאז שפתחת — הצג הבדלים / טען מחדש").
- [ ] **מחיקה, העברה, שכפול** של הקובץ במנהל הקבצים — **אינם מוחקים מילים**. מחיקה: "זה הקובץ של טבלת המילים; למחוק אותו מהעמוד =
      להסיר את `data.words` מ-`kol.json`" — עם הפעולה הזו (הטבלה נשארת). שכפול — יוצר קובץ JSON **רגיל** (עותק סטטי), ונאמר.

### שמירה ← טבלה

- [ ] שמירה (Ctrl+S בעורך, העלאת קובץ באותו נתיב, ייבוא ZIP שמכיל אותו): הקובץ מנותח ומאומת **לפני** כל כתיבה. שגיאה — עם
      **שורה ועמודה**, בתוך העורך (סימון Monaco), והטבלה **אינה** משתנה. הבדיקות:
      JSON לא תקין · `items` חסר או אינו רשימה · `id` כפול · `id` שאינו מספר שלם חיובי · `word` ריק · שדה מסוג שגוי (`topics` שאינו
      רשימת מחרוזות) · נושא שאינו קיים — **מוצע** "צור נושא `<slug>`" (לא שגיאה, אם אושר) · `audio` שאינו קובץ בספרייה, נתיב בפרויקט,
      או כתובת `https://` של האתר המחובר — אזהרה, לא שגיאה · מפתח לא מוכר — נשמר? **לא ב-N1**: אזהרה "שדה לא מוכר `x` — יתווסף
      כשדה ב-N2", והשמירה נדחית עד שהוסר.
- [ ] **תצוגת השינויים — לפי `id`**, לפני הביצוע: "ישתנו 3 מילים · תתווסף 1 · יעברו לסל 0 · ישתנה הסדר של 12", עם רשימה מתקפלת
      (לכל מילה: לפני ← אחרי, לפי שדה). כפתור "החל" / "בטל". **פריט בלי `id`** = מילה חדשה, ומקבלת מזהה מהכלי (המספר הבא);
      הקובץ נשמר מחדש עם המזהה.
- [ ] **מחיקה** = מילה שאינה בקובץ ← **לסל** (`words_trash`), לא נמחקת; עם ההקלטה שלה **מקושרת** (אינה נמחקת מהספרייה).
      לפני מחיקה כלשהי, או שינוי של יותר מ-20 מילים — **נקודת שחזור** אוטומטית.
- [ ] **`id` אינו משתנה:** פריט ששינה `id` = מילה אחת נמחקה (לסל) ואחרת נוספה — וכך זה מוצג, עם אזהרה: "המזהה הוא המפתח של
      ההקלטה ושל קישורים למילה".
- [ ] **`topics`** בקובץ — **מפתחות** (`slug`); בטבלה היום — **שמות**. השמירה ממירה מפתח ← שם דרך `topics`; נושא חדש שאושר נוסף
      לטבלת הנושאים. (המרה של עמודת `topics` במסד למפתחות — **לא** ב-N1; N2 מחליטה.)
- [ ] השמירה היא **עסקה אחת במסד** (`BEGIN … COMMIT`); כשל באמצע — דבר לא השתנה. נכתבים `updated_at`, `updated_by`; ו-`audit`
      אחד: "words.json · 3 שונו, 1 נוספה". ההיסטוריה של הקובץ במנהל הקבצים מציגה את השמירה, עם ה-diff של הקובץ.
- [ ] הרשאות: קריאה — `editor`; שמירה — `editor` (כמו עריכה בטבלה היום); "החלף הכול" ומחיקה של יותר מ-20 — `publisher`.

### סדר ידני (`06` §2.2)

- [ ] עמודה חדשה `sort_order INTEGER` (מיגרציה אחת, הוספה בלבד). **המילוי הראשון משחזר את הסדר של היום בדיוק**: ערכי `lex_sort`
      הנוכחי, בקפיצות של 10. בדיקה: הרשימה בתצוגה החיה לפני ואחרי המיגרציה — זהה.
- [ ] בטבלת המילים (📚): ידית ⠿ לגרירת שורה, ו"העבר ל…" (מספר מקום); גרירה של בחירה מרובה. נכתב `sort_order` רק לשורות שזזו
      (מספור מחדש של טווח רק כשאין מקום). מילה חדשה — בסוף.
- [ ] `data-kol-sort="manual"` ב-`kol-data.js` = סדר הקובץ (שהוא `sort_order`). `"word"`, `"-id"` וכל שדה — כמו היום, עם
      `Intl.Collator` ושפה מ-`data-kol-sort-lang` (ברירת מחדל `he`).
- [ ] **הסדר בקובץ = הסדר בטבלה:** שינוי סדר הפריטים ב-`data/words.json` ושמירה — מעדכנים את `sort_order`, ומוצגים בתצוגת
      השינויים ("ישתנה הסדר של 12").

### אקסל / CSV (`06` §2.6)

- [ ] **ייצוא** (קיים, `words_csv`): עמודות `id`, `word`, `meaning`, `topics`, `audio`, `sort_order`, ו-`wp_id` / `external_id` אם יש.
- [ ] **ייבוא** (`words_csv_import`) עובר **לאותו מנוע של השמירה**: אותו אימות (עם מספר שורה בגיליון), אותה תצוגת שינויים לפי
      `id`, אותה עסקה ואותה נקודת שחזור. שורה בלי `id` = מילה חדשה. **ייבוא אינו מוחק** מילים שאינן בקובץ — אלא אם נבחר
      "החלף הכול" (`publisher`, נקודת שחזור, ואישור עם מספר המילים שיעברו לסל).
- [ ] קידוד: UTF-8 עם / בלי BOM, ו-Windows-1255 (אקסל עברי ישן) — מזוהה, ומוצג "זוהה קידוד …".

### כללי

- [ ] **שלוש הדלתות — אותם נתונים:** שינוי בטבלה ← הקובץ הפתוח בעורך מסומן "השתנה"; שמירת הקובץ ← הטבלה מתעדכנת; התצוגה החיה
      והבנייה (M1) קוראות את אותה `words_json()`. בדיקה אחת שעוברת על שלושתן.
- [ ] `M1`: הבנייה ממשיכה לקרוא דרך `pv_words` / `words_json` — **בלי שינוי בקבצי M1**. ("מתפרסם" לפי שדה — N2.)
- [ ] **איפה הנתונים:** טבלאות קיימות ב-`data/kol.sqlite` (מוחרג), עמודה אחת חדשה. אין קובץ חדש בשרת, אין `--exclude` חדש.
- [ ] בדיקות: `tests/cases/*-words-file.php` — כל שגיאת אימות (שורה ועמודה), תצוגת שינויים, מחיקה לסל, `id` חדש, נושא חדש, עסקה
      שנכשלת באמצע, התנגשות `rev`, סדר; `tests/browser/n1.cjs` — פתיחה בעורך, עריכה, שמירה, הטבלה, התצוגה החיה.

## 3. בדיקת הבעלים (מטלה)
