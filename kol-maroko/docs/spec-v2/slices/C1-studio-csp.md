# פרוסה C1 — CSP לסטודיו, ככותרת שרת

> **מקור:** `00-overview.md` S6 ("המעטפת קשיחה"); ממצא של צ'אט הקוד ב-A1: **ל-`index.html` של הסטודיו אין היום CSP בכלל.**
> **תלות:** F1 (היומן, לדוחות ההפרה). השלב השני — עם F4. **תלויה בתשובות הבעלים:** לא.
> **למה פרוסה משלה:** קריטריון ה-CSP של A1 נדחה (הכרעת הבקרה), כי `<meta>` CSP בדף הסטודיו חל גם על מסגרת התצוגה
> הישנה (`srcdoc`) ושובר אותה. הפתרון אינו שורה ב-A1 אלא מדיניות לכל מסך.

## 1. הבעיה

- הסטודיו רץ במקור של הפלטפורמה, ומציג תוכן שבעל העמוד ועוזריו כתבו. בלי CSP, כל טעות של הצגה כ-HTML היא הרצת קוד
  בסשן של מי שפתח את המסך — כולל בעל האתר.
- התצוגה של הסטודיו הישן היא `iframe srcdoc` (`audit` 3.1). מסמך `srcdoc` **יורש את ה-CSP של הדף שמכיל אותו**, ולכן
  מדיניות קשיחה על הדף חוסמת בתוכה תמונות, גופנים וסקריפטים של העמוד. **לאימות** (סעיף 5).
- מכאן: אי אפשר להקשיח את הסטודיו הישן עד הסוף בלי לשבור את התצוגה שלו. אפשר להקשיח את המסכים החדשים מהיום הראשון.

## 2. ההכרעה: מדיניות לכל מסמך, בשני שלבים

**תמיד ככותרת שרת, לא `<meta>`** — כותרת תומכת ב-`frame-ancestors`, ב-`sandbox` ובדיווח, ואינה תלויה בתוכן הדף. נקבעת
ב-`.htaccess` של `kol-maroko/` או בקוד שמגיש את הדף; הקוד מכריע.

### שלב א — מיד (אחרי F1)

על **כל** תשובה של האפליקציה (דפים ו-API):

| כותרת | ערך | למה בטוח כבר עכשיו |
| --- | --- | --- |
| `X-Content-Type-Options` | `nosniff` | אינו משפיע על תוכן תקין |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | |
| CSP — **נאכף** | `object-src 'none'; base-uri 'self'; form-action 'self'` | שלוש הנחיות שהתצוגה הישנה אינה צריכה |
| CSP — **דיווח בלבד** (`Content-Security-Policy-Report-Only`) | המדיניות המלאה של שלב ב | אינו חוסם דבר; כל הפרה נרשמת ביומן המפתח |

ולכל תשובה של `api.php`: `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'; sandbox` — תשובת JSON
לעולם אינה מסמך.

### שלב ב — עם F4, למסכים החדשים

המסכים החדשים (מנהל הקבצים, עורך הקוד, העורך החזותי, הספרייה) מוגשים כמסמך משלהם, והתצוגה שלהם היא מסגרת **מכתובת
מבודדת** (S3) — לא `srcdoc` — ולכן אינה יורשת דבר. עליהם נאכפת המדיניות המלאה:

| הנחיה | ערך | הערה |
| --- | --- | --- |
| `default-src` | `'none'` | |
| `script-src` | `'self'` | בלי `'unsafe-inline'`, בלי `'unsafe-eval'`. Monaco מאוחסן באפליקציה (F2a) |
| `worker-src` | `'self' blob:` | ה-workers של Monaco — **לאימות** |
| `style-src` | `'self' 'unsafe-inline'` | סגנון בתוך הדף נדרש לעורך; אינו מריץ קוד |
| `img-src`, `media-src` | `'self' blob: data:` + **הדומיין של האתר המחובר** | להשמעת הקלטות "באתר" (A1) ולתמונות שטרם הובאו. רק כמדיה |
| `font-src` | `'self' data:` | |
| `connect-src` | `'self'` | |
| `frame-src` | כתובת התצוגה המבודדת בלבד | |
| `frame-ancestors` | `'self'` | אם הפלטפורמה מטמיעה את האפליקציה במסגרת — **לבדיקה מול `platform/README.md`**; אחרת `'none'` |
| `base-uri`, `object-src`, `form-action` | כמו שלב א | |
| `report-to` / `report-uri` | נקודת הדיווח של F1 | |

**הקנבס הדומם** (S2): סקריפטים כבויים בו במסגרת בלי `allow-scripts`; את שאר המדיניות הוא **יורש** מ-`editor.php` (§2א).

### 2א. מה נבנה בפועל — והכרעת האפיון על הקנבס (2026-11-12, אחרי `team/reviews/V1b.md`)

`editor.php` מגיש את העורך עם המדיניות המלאה, בשני הבדלים מהטבלה שלמעלה — **שניהם מאושרים:**

| הנחיה | נבנה | למה מאושר |
| --- | --- | --- |
| `style-src` | + `https://fonts.googleapis.com` | העמוד האמיתי טוען את הגופנים שלו משם; בלעדיהם הקנבס אינו נאמן לעמוד, וכל מידה של טקסט בו שגויה |
| `font-src` | + `https://fonts.gstatic.com` | כנ"ל. קובצי גופן בלבד; אין שם קוד |
| `frame-src` | `live.php` ו-`preview/` בלבד | התצוגה החיה המבודדת (F4) |

**הקנבס הדומם הוא `srcdoc`, ולכן יורש את המדיניות הזו** — ולא "מדיניות משלו" כפי שנכתב למטה. **מאושר, ונשאר מחמיר:**
משאב חיצוני של העמוד שאינו Google Fonts או האתר המחובר **אינו נטען בקנבס**; הוא נטען בתצוגה החיה (מקור אטום, המדיניות
של `00` §7.1) ואצל הגולש. הנימוקים:

1. הקנבס רץ **בתוך הסשן של מי שעורך** — כולל בעל האתר. משאב חיצוני שעוזר הוסיף לעמוד היה נטען מהדפדפן של כל מי שפותח
   את העורך: כתובת ה-IP שלו, שעת הפתיחה, ומה שהשרת הזר בוחר להחזיר. בתצוגה החיה זה קורה במקור מבודד, ובלחיצה מודעת.
2. CSS של העמוד חל על הקנבס. עם `img-src` פתוח, כלל כמו `[value^="a"] { background: url(https://x/…) }` מדליף תוכן
   החוצה. היום הקנבס מכיל רק את העמוד — אבל ההגנה אינה צריכה להישען על כך.
3. המחיר נמוך, ואינו נעילה: שום דבר אינו נעשה **לא-עריך**; הוא רק אינו **מוצג** במסך אחד, ונאמר במפורש (`03` §2.1).

**מה נדרש כדי שזה לא יהפוך ל"דבר שרואים ואי אפשר לשנות"** — קריטריונים, למי שנוגע בקנבס הבא (V5 לכל המאוחר):

- [ ] הפס "N משאבים חיצוניים אינם מוצגים בעורך" נפתח ל**רשימה**: כתובת, סוג, קובץ ושורה, "בחר בעורך", "פתח בקוד",
      "▶️ הצג בתצוגה החיה". הספירה נעשית מניתוח הקבצים (HTML ו-CSS), לא מהפרות CSP בלבד.
- [ ] אלמנט שהמשאב שלו נחסם מוצג בקנבס בגודלו, מסומן, ונבחר; הכתובת נערכת ומוחלפת.
- [ ] **אין דיווח הפרות CSP על החסימות האלה** ליומן המפתח כשגיאה — הן צפויות; הן נספרות בנפרד.
- [ ] `connect-src 'self'` נשאר: שום קוד של העורך אינו פונה החוצה. הגופנים הם הבקשה היחידה שיוצאת מהעורך לצד שלישי —
      ו-V9 מציעה "הבא את הגופן לפרויקט", שאחריה גם היא נעלמת.

**פתוח לבעלים — [ש-27]:** האם לאפשר לבעל האתר לאשר שרת נוסף להצגה בעורך. ברירת המחדל: לא.

### הסטודיו הישן

נשאר בשלב א עד שהוא מוסר (אחרי M3). זה פער ידוע ומתועד: המסך הישן אינו מוקשח עד הסוף, והפיצוי — הסינון הקיים שלו,
שנשאר במקומו כל עוד המסך חי.

## 3. קריטריוני קבלה

### שלב א

- [ ] ארבע הכותרות נשלחות על כל דף ועל כל תשובת API. בדיקה אוטומטית שקוראת את הכותרות.
- [ ] **שום מסך קיים אינו משתנה.** בדיקה ידנית של: הסטודיו והתצוגה שלו, `</> קוד`, 📚 מילים (כולל השמעה מהאתר),
      🗂️ קבצים (כולל הספרייה של A1), 🚀 פרסום, ⚙️, עורך התמלילים המוטמע.
- [ ] הפרות של המדיניות "דיווח בלבד" נרשמות ביומן המפתח, מקובצות לפי הנחיה ומקור, עם מונה — לא שורה לכל הפרה.
- [ ] אחרי שבוע של שימוש: רשימת ההפרות מצורפת למטלה, ומשמשת לכיוון המדיניות של שלב ב.

### שלב ב

- [ ] המדיניות המלאה נאכפת על כל מסך חדש. בדיקה אוטומטית בדפדפן: סקריפט בתוך הדף, `eval`, ותמונה מדומיין זר — נחסמים.
- [ ] בדיקת התקפה: קובץ פרויקט בשם `<img src=x onerror=alert(1)>.html` ותוכן דומה בשם רכיב, בשם מחלקה ובהודעת שגיאה
      מהתצוגה החיה — אינם מריצים קוד, **גם אם** אחד המסכים הציג אותם בטעות כ-HTML.
- [ ] הקלטה "באתר" מתנגנת; תמונה "באתר" מוצגת; ושום בקשת `fetch` לדומיין של האתר אינה מצליחה מהסטודיו.
- [ ] התצוגה החיה של F4 עובדת במלואה (היא מסמך נפרד, במקור אטום, עם המדיניות של `00` §7.1 — לא של הסטודיו).

## 4. מה מתעדכן ב-A1

הקריטריון "ה-CSP של הסטודיו מתיר שמע ותמונות מהדומיין של האתר בלבד" **עובר לכאן** (שלב ב). ב-A1 נשאר מה שנאכף בקוד:
הספרייה מנגנת רק כתובת שהדומיין שלה הוא האתר המחובר.

## 5. לאימות לפני המימוש — בדיקה צרה אחת

1. שמסמך `srcdoc` יורש את ה-CSP של ההורה גם כשהוא מגיע בכותרת (לא רק ב-`<meta>`), ומה קורה כשלמסגרת יש `sandbox`.
2. ש-`Header set` ב-`.htaccess` פועל ב-LiteSpeed של השרת, ושאינו מתנגש עם כותרות שהשער של הפלטפורמה מוסיף.
3. מה Monaco דורש ב-`worker-src` וב-`style-src`.

## 6. השורה שעונה על המבחן

C1 אינה משנה דבר ממה שבעל העמוד רואה או עורך. היא סוגרת את **S6** ואת **G8** (`00` §5, §8): בלעדיה "קיר ולא מסננת" נכון
רק בצד של האתר, ובצד של הכלי כל טעות הצגה היא פרצה.
