# פרוסה N2 — שדות מותאמים למילה, ונושאים מורחבים

> **אפיון:** `06-data.md` §2.3 (שדות מותאמים), §2.4 (נושאים), §2.6 (אקסל), §4 (מה מגיע לגולש). **תלות:** N1 ✔ (`words_json`, מנוע
> השמירה `words_plan` / `words_apply`, `sort_order`, מיגרציה 17). **תלויה בבעלים:** **[ש-16]** — ברירת המחדל "א: הוא מוסיף שדות
> בעצמו" נבנית; אם יענה "ב" — הפרוסה נעצרת לפני המיזוג, דבר לא נשבר (הכול הוספה).
> **מה קיים בקוד:** `words` (`id`, `word`, `meaning` — HTML, `topics` — JSON של **שמות**, `audio`, `external_id`, `wp_id`, `sort_order`);
> `topics` (`slug` PK, `name` UNIQUE); `topic_op` (שינוי שם / הסרה, עם `topic_trash`); `WJ_ITEM_KEYS` — רשימה סגורה, ומפתח לא מוכר
> בקובץ = שגיאה "יתווסף כשדה ב-N2". **פגם קיים:** שינוי שם של נושא יוצר שורה חדשה ב-`topics` — ה-`slug` משתנה, ובעמוד כפתור
> הסינון, הקישור וה-CSS לפי המפתח נשברים.

## 1. מה בונים

אחרי N2 בעל העמוד **מוסיף לכל מילה שדה משלו** — "תעתיק לטיני", "דוגמה במשפט", "הקלטה שנייה" — במסך אחד, והשדה מופיע מיד בכל
שלוש הדלתות: עמודה בטבלה, מפתח ב-`data/words.json`, עמודה באקסל; ובבנייה ובתצוגה החיה — אם סומן "מתפרסם". ו**הנושאים הופכים
לרשימה שלו**: סדר, צבע, תמונה, מוסתר, מיזוג — ושינוי שם אינו שובר דבר בעמוד.

1. **"מבנה המילה"** — רשימת השדות (כולל ארבעת הקיימים), הוספה, עריכה, שינוי מפתח עם עדכון הקשירות, מחיקה לסל.
2. **ערכים** — עמודה אחת חדשה `words.extra` (JSON), ואימות לפי סוג בכל דלת (אותו מנוע של N1).
3. **"מתפרסם"** — `words_json()` מסננת לתצוגה החיה ולבנייה; העורך רואה הכול.
4. **נושאים מורחבים** — עמודות ב-`topics`, מסך נושאים, מיזוג, ושינוי שם שה-`slug` שלו קבוע.

## 2. המודל

### 2.1 טבלת השדות — `word_fields`

| עמודה | מה |
| --- | --- |
| `key` TEXT PK | המפתח בקובץ ובקשירה. `^[a-z][a-z0-9_]{0,39}$`. שמורים: `id`, `topics_*`, `sort_order`, `wp_id`, `external_id`, `count`, `shown`, `total`, `label` |
| `label` TEXT | השם בממשק (עברית) |
| `type` TEXT | `text` · `longtext` · `rich` · `number` · `bool` · `choice` · `date` · `url` · `image` · `audio` · `list` |
| `col` TEXT NULL | לשדה מובנה — העמודה במסד (`word`, `meaning`, `topics`, `audio`); לשדה מותאם — `NULL` (הערך ב-`extra`) |
| `required` INT · `def` TEXT · `help` TEXT | חובה / ברירת מחדל (JSON) / עזרה למזין |
| `options` TEXT | ל-`choice`: JSON `[{"value","label"}]` |
| `published` INT | 1 — נכנס ל-`words.json` של העמוד; 0 — הערה פנימית |
| `dir` TEXT | `auto` · `rtl` · `ltr` |
| `sort_order` INT | סדר העמודות בטבלה ובקובץ |

**המילוי הראשון** (באותה מיגרציה): ארבע שורות מובנות — `word` (מילה, `text`, חובה), `meaning` (פירוש, `rich`), `topics` (נושאים, מיוחד),
`audio` (הקלטה, `audio`) — כולן `published=1`. **אחרי המיגרציה `words.json` זהה בבייטים למה שהיה לפניה** (בדיקה).

**שדות מובנים** (`col` אינו `NULL`): משנים להם שם, מפתח, עזרה, כיוון ו"מתפרסם". סוג — רק בתוך משפחה: `word` — `text`; `meaning` — `text` /
`longtext` / `rich` (מעבר ל-`text` מוריד HTML — עם תצוגת שינויים); `topics`, `audio` — קבועים. אי אפשר למחוק `word`. `id` אינו שדה
ברשימה ואינו נערך (N1). **[הכרעה טכנית — ל-`decisions.md`: 06 §2.3 אומר "אפשר לשנות להם שם וסוג"; הסוג מוגבל כי `word` הוא
המפתח של כל חיפוש וקישור, ו-`topics`/`audio` מחוברים לטבלאות.]**

### 2.2 הערכים — `words.extra`

עמודה `extra TEXT NOT NULL DEFAULT '{}'`: אובייקט `{key: value}` לשדות המותאמים בלבד. ערך ריק = המפתח חסר. בצורה קנונית לפי סוג:

| סוג | במסד / בקובץ | אימות (שגיאה עם שורה ועמודה) |
| --- | --- | --- |
| `text` | מחרוזת, עד 500, בלי ירידת שורה | אורך |
| `longtext` | מחרוזת, עד 20,000 | אורך |
| `rich` | HTML, דרך `sanitize_rich` (כמו `meaning`) | — (מנוקה; אם השתנה בניקוי — אזהרה) |
| `number` | מספר JSON | לא מספר; ב-CSV — `.` או `,` עשרוני |
| `bool` | `true` / `false` | ב-CSV: `1/0`, `כן/לא`, `true/false` |
| `choice` | `value` מתוך `options` | ערך שאינו ברשימה — **מוצע** "הוסף אפשרות" (כמו נושא חדש ב-N1) |
| `date` | `YYYY-MM-DD` | תאריך לא קיים |
| `url` | `https://` או `http://` בלבד | scheme אחר — שגיאה |
| `image` | מזהה קובץ (`kind=image`) במסד; בקובץ — `media/images/<id>.<ext>` | קובץ שאינו בספרייה — אזהרה, כמו `audio` ב-N1 |
| `audio` | מזהה קובץ (`kind=audio`); בקובץ — `media/audio/<id>-<key>.<ext>` (`06` §2.3) | כמו `audio` ב-N1 |
| `list` | מערך מחרוזות, עד 50 × 200; ב-CSV — מופרד ב-`; ` (כמו `topics`) | איבר שאינו מחרוזת |

`required` נבדק בשמירה מכל דלת (שגיאה); `def` ממלא מילה **חדשה** בלבד — הוספת שדה עם ברירת מחדל אינה כותבת ל-1,500 מילים.

### 2.3 נושאים — `topics` מורחבת

עמודות חדשות: `sort_order INT`, `color TEXT` (`#rrggbb` או ריק), `image TEXT` (מזהה קובץ או ריק), `hidden INT DEFAULT 0`. **המילוי הראשון
משחזר את הסדר של היום** (`lex_sort` לפי שם, בקפיצות של 10), ו**כל שם נושא שבמילים ואין לו שורה** מקבל שורה עם ה-`slug` שהוא
מקבל היום (`kt-<md5>`), כדי שאף מפתח בעמוד לא ישתנה.

- **הקשר מילה ← נושא נשאר לפי שם במסד** (`words.topics`), ו**ה-`slug` הוא הזהות**: שינוי שם = `UPDATE topics SET name` + שכתוב השם
  במילים, **באותה עסקה, וה-`slug` לא זז**. **[הכרעה טכנית: המרת `words.topics` למפתחות נדחית — `library.php`, `code.php`,
  `migrate.php` קוראים שמות; ההמרה אינה נותנת לבעל העמוד דבר שהוא לא מקבל כך.]**
- **שינוי `slug`** — מותר, עם אותה תצוגת קשירות של שינוי מפתח שדה (§3.3): `data-kol-filter-value="<slug>"` וכל הופעה בקבצי הפרויקט.
- **מיזוג** א ← ב: כל מילה עם א מקבלת ב (בלי כפילות), שורת א עוברת ל-`topic_trash` (`op='merge'`, עם הנושאים של כל מילה לפני),
  והקשירות ל-`slug` של א מוצגות לעדכון ל-ב.
- **בקובץ:** `"topics": [{"id", "label", "color"?, "image"?, "hidden"?}]` — מפתחות ריקים נשמטים, **כך שבלי צבע/תמונה הקובץ זהה ל-N1**.
  ברשימה — כל הנושאים שיש להם מילה, לפי `sort_order`. נושא `hidden`: בקובץ של העורך — עם `"hidden": true`; **בקובץ המתפרסם — לא
  ברשימה** (אין כפתור), ונשאר על המילים. תמונה — `media/images/<id>.<ext>`, ונכנסת לחבילה.
- בקובץ, `label` / `color` / `image` / `hidden` / הסדר של נושא **קיים** — **נשמרים** משמירת הקובץ (מה שהיה ב-N1 אזהרה "נעשה במסך הנושאים"
  נהיה עדכון), ומוצגים בתצוגת השינויים: "ישתנה נושא אחד".

## 3. קריטריוני קבלה

### 3.1 מסך "מבנה המילה"

- [ ] בטבלת המילים (📚) — כפתור "🧩 מבנה המילה" (בלי לשונית חדשה ב-`studio.html`). רשימת השדות לפי `sort_order`, עם גרירה; לכל שדה:
      שם, מפתח, סוג, "מתפרסם", חובה, ומספר המילים שיש להן ערך.
- [ ] **הוספת שדה:** שם → מפתח נגזר (תעתיק לטיני פשוט; אם ריק — `field_<n>`), ניתן לשינוי, נבדק מול התבנית והשמורים והקיימים. סוג,
      חובה, ברירת מחדל, עזרה, "מתפרסם" (ברירת מחדל: **כן**), כיוון. נשמר → העמודה מופיעה בטבלה **בלי רענון**, והקובץ הפתוח בעורך מסומן
      "השתנה" (`words_rev` כולל את המבנה).
- [ ] **שינוי סוג** של שדה מותאם: מחושבת המרה לכל ערך קיים (`number` ← `text`: "12" ✓, "שתים" ✗). תצוגה: "יומרו 340, ייכשלו 3" עם
      רשימת הנכשלים. ערך שנכשל **אינו נמחק בשקט**: ההמרה נעצרת עד שהנכשלים תוקנו, או שנבחר במפורש "רוקן את 3 הנכשלים"
      (נקודת שחזור לפני).
- [ ] **מחיקת שדה** — לסל: השדה וכל הערכים שלו (`{id: value}`) נשמרים בשורה ב-`field_trash`; "שחזור" בסל (`lib/restore.php`, `restore.js`) מחזיר
      את השדה והערכים כמו שהיו. לפני מחיקה — נקודת שחזור, והאזהרה מונה את הקשירות בקבצי הפרויקט שיישארו בלי ערך.
- [ ] `editor` — ערכים. **מבנה** (הוספה, מחיקה, שינוי סוג או מפתח, "מתפרסם") — `publisher`; **[לבדיקה מול R1: אם `08` נותן את זה
      לתפקיד אחר — לפי `08`.]**

### 3.2 שלוש הדלתות

- [ ] **טבלה:** עמודה לכל שדה, לפי סוגו: עריכה בתא (text/number/date/url), תיבה (bool), בחירה (choice), עורך טקסט עשיר כמו `meaning`
      (rich/longtext — בחלון), בחירת קובץ דרך `Media.pick({kind})` (image/audio — כמו ההקלטה היום), תגיות (list). `help` כטקסט עזרה, `dir`
      על התא. "הצג עמודות" — בחירה אילו עמודות מוצגות (נזכר לכל משתמש, בשרת או ב-`localStorage` של הסטודיו; לא ב-`kol-data.js`).
      סינון לפי שדה: "יש ערך / אין ערך", ולבחירה — לפי ערך.
- [ ] **קובץ:** `words_json(null)` (העורך) — כל השדות, בסדר `sort_order`, אחרי המובנים; `WJ_ITEM_KEYS` נהיה דינמי (`id`, `wp_id`, `external_id`
      + מפתחות השדות). שמירת הקובץ מאמתת לפי סוג (§2.2) עם שורה ועמודה, ותצוגת השינויים מונה גם שדות: "ישתנה `translit` ב-40 מילים".
      **מפתח לא מוכר** — לא עוד שגיאה סגורה: **מוצע** "צור שדה `x` (סוג מנוחש מהערכים: מספרים → `number`, true/false → `bool`, אחרת `text`)"
      — ההצעה דורשת `publisher`; בלי אישור — שגיאה כמו היום.
- [ ] **אקסל / CSV:** ייצוא — עמודה לכל שדה (הכותרת: ה-`label`), אחרי העמודות של N1. ייבוא — התאמת עמודה לפי `label` **או** `key`; עמודה
      שאינה מוכרת — מוצגת בתצוגה המקדימה "לא תיובא" עם הצעה ליצור שדה (`publisher`). אותו מנוע, אותה עסקה (N1).
- [ ] **כולן אותם נתונים:** בדיקה אחת — שדה נוסף במסך ← עמודה בטבלה ← מפתח בקובץ ← עמודה ב-CSV ← ערך מהקובץ נראה בטבלה.

### 3.3 שינוי מפתח — עדכון הקשירות

- [ ] שינוי `key` של שדה (וגם `slug` של נושא) סורק את קבצי הפרויקט (`pf_files`, כל קובץ טקסט; לא `media/`) ומוצא: ערכים של `data-kol-text`,
      `-html`, `-attr-*`, `-value`, `-if`, `-class-*`, `-each`, `-sort`, `-search-fields`, `-filter` (החלק שאחרי `:`), `-filter-value`, ו-`{key}` בתוך
      תבניות; ובקבצי JS — `item.key` / `['key']` **מוצגים כ"לבדיקה ידנית" ולא מוחלפים**. התצוגה: קובץ · שורה · לפני ← אחרי, עם סימון
      לכל שורה (ברירת מחדל: כולן מסומנות חוץ מ"לבדיקה ידנית").
- [ ] "החל": שינוי המבנה, שכתוב `extra` בכל המילים, וכתיבת הקבצים — **עסקה אחת**; כל קובץ נשמר כגרסה בהיסטוריה של F2 עם הסיבה
      "שינוי מפתח `a` → `b`". התנגשות `rev` בקובץ שנפתח בינתיים — כמו כל שמירה ב-F2.
- [ ] שדה מובנה: שינוי מפתח `meaning` → `definition` משנה את המפתח **בקובץ ובקשירה בלבד**; העמודה במסד נשארת (`col`).

### 3.4 "מתפרסם" — מה מגיע לגולש (`06` §4)

- [ ] `words_json($app)` (תצוגה חיה) ו-`build_words` (M1) — **רק שדות `published=1`**; `wp_id` / `external_id` כמו היום. בדיקה: שדה פנימי
      עם ערך — אינו מופיע בבייטים של החבילה **ולא** בתגובה של `/preview/…/data/words.json`.
- [ ] **הקובץ בעורך מציג הכול**, ובראשו (בתווית של מנהל הקבצים, לא בתוך ה-JSON) — "שדות פנימיים: `notes` — לא מתפרסמים". **שכפול** הקובץ
      (עותק סטטי, N1) **כן מכיל** שדות פנימיים — ולכן אזהרה בשכפול: "העותק כולל 2 שדות פנימיים, והוא יתפרסם כקובץ רגיל".
- [ ] `image` / `audio` מותאמים שמתפרסמים — הקבצים נכנסים לחבילה (`build_words` מכליל את מה שהוא עושה היום ל-`audio` לכל שדה מסוג
      קובץ), בנתיבים של §2.2. הקלטה שנייה **אינה** חלק מספריית ההקלטות (📼) ב-N2 — ראו §4.

### 3.5 נושאים

- [ ] **מסך הנושאים** (בתוך 📚, ליד "מבנה המילה"): כל הנושאים, גם בלי מילים (עם 0); גרירה לסדר; שם, מפתח, צבע (בורר), תמונה (`Media.pick`),
      מוסתר; "מזג אל…"; הסרה (כמו `topic_op delete` היום, לסל).
- [ ] שינוי שם: ה-`slug` **אינו משתנה** (בדיקה: לפני ואחרי — אותו `id` בקובץ, ואותם `data-kol-filter-value` בתצוגה החיה). זה מתקן את
      הפגם שבראש הפרוסה.
- [ ] מיזוג ושינוי `slug` — עם תצוגת הקשירות (§3.3); מיזוג — לסל, ו"שחזור" מחזיר את שני הנושאים והשיוכים.
- [ ] שמירת הקובץ עם שינוי ב-`label` / `color` / `hidden` / סדר של נושא קיים — מעדכנת את `topics`, ומוצגת בתצוגת השינויים.

### 3.6 כללי

- [ ] **מיגרציה אחת** (המספר: **max(main)+1 ברגע שהפרוסה מוגשת "מוכן"** — אין מספרים שמורים; ב-`main` היום 17): `CREATE TABLE word_fields`,
      `CREATE TABLE field_trash`, `ALTER TABLE words ADD COLUMN extra`, `ALTER TABLE topics ADD COLUMN` × 4. **הוספה בלבד.** המילוי (שדות
      מובנים, `sort_order` של נושאים, שורות לנושאים חסרים) — ב-PHP, אידמפוטנטי, כמו `words_order_fill` של N1.
- [ ] **נקודת שחזור** (`lib/restore.php`): `snap_state()` כולל את `word_fields` ואת העמודות החדשות (`SELECT *` של `words` ו-`topics` כבר
      תופס אותן; `word_fields` — מפתח חדש), ו"שחזור" מחזיר גם את המבנה. בדיקה: הוסף שדה ← נקודה ← מחק ← שחזר.
- [ ] `audit` לכל שינוי מבנה: `field_add` / `field_edit` / `field_key` / `field_delete` / `topic_merge` / `topic_slug`.
