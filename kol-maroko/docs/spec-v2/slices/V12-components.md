# פרוסה V12 — רכיבים: הוספה, הגדרות מהסכמה, עריכה, יצירה, קישור בין מופעים ועמודים

> **אפיון:** `03-visual-editor.md` §10; `02-project-model.md` §7 (המבנה, הסכמה, המופע, מקושר / שונה / מנותק); `01-gap` 7.14, 7.15, 8.1 (רכיב),
> 8.4. **תלות:** V1–V4 (בחירה, Navigator, תוכן, מבנה וגרירה), V8 (מחלקות, משתנים — יעדי `class` / `var`), F2 ✔ (קבצים, diff). **תלויה בבעלים:** לא.
> **שני הכללים לכל פרוסת V:** במחשב — על כל המסך; כל שליטה גם בגרירה.
> **מה קיים:** `components/` מוגדרת ב-`kol.json` (`02` §5); `build.php` מוציא `components/*/component.json` מהחבילה; אין שום ממשק לרכיבים.

## 1. מה בונים

רכיב הוא **תיקייה של קבצים רגילים** ומופע הוא **HTML מלא בעמוד** (`02` §7). אחרי V12 בעל העמוד גורר רכיב לקנבס, משנה לו הגדרות בפאנל,
עורך את הרכיב עצמו — וכל המופעים מתעדכנים — ו**יוצר רכיב משלו** מכל אלמנט, עם פאנל הגדרות שהוא בונה בהצבעה, בלי לכתוב JSON.

## 2. קריטריוני קבלה

### 2.1 הספרייה וההוספה

- [ ] בספריית ההוספה (V4) — לשונית "רכיבים": כל `components/*/component.json` של הפרויקט (שם, סמל, קטגוריה), ולאחר V16 — גם המוכנים של הכלי
      (מסומנים "יועתק לפרויקט").
- [ ] **גרירה לקנבס** (או לחיצה ← "הוסף אחרי הנבחר"): נכתב ה-HTML של `template.html` במקום, עם `data-kol-component="<שם>"` על השורש, וערכי ברירת
      המחדל של ההגדרות. **פעם אחת לכל עמוד:** `<link rel="stylesheet" href="components/<שם>/style.css">` ל-`<head>` (אם יש), ו-`<script defer src="…/script.js">`
      (אם יש). שתי הכתיבות — פעולה אחת ב-Ctrl+Z.
- [ ] `script.js` של רכיב **אינו רץ בקנבס** (בלי סקריפטים); הקנבס מראה את המצב הסטטי, ותווית "יש לרכיב קוד — ראו ▶️ תצוגה חיה".

### 2.2 הגדרות מהסכמה (`02` §7.1)

- [ ] בבחירת שורש מופע — "תוכן" מציג את `fields` של הרכיב, בסדר שלהם, עם אותן שליטות של הפאנל הכללי (`control`: טקסט, טקסט עשיר, מספר, מידה, צבע,
      גופן, בחירה, מתג, מדיה, קישור, repeater). **הערך הנוכחי נקרא מהמופע עצמו** (מה-`target`), לא משמור צדדי.
- [ ] כל יעד כותב **בדיוק** את מה ש-`02` §7.1 אומר: `text` (תוכן האלמנט שהבורר מוצא בתוך המופע) · `attr` · `class` (אחת מהקבוצה — הקודמת מוסרת) · `var`
      (ב-`style` של השורש) · `children` (repeater: הוסף / מחק / שכפל / גרור לסדר — **וגם בגרירה בקנבס**, V4) · `src`. יעד שהבורר שלו אינו נמצא במופע —
      השדה מוצג מושבת עם "החלק `.acc-title` חסר במופע הזה".
- [ ] **הפאנל הכללי** (עיצוב, מתקדם) — זמין לכל חלק במופע, כרגיל; כתיבה לפי כלל היעד (`03` §4.2). שינוי עיצוב שכותב ל-`style.css` של הרכיב
      (יעד "המחלקה של האלמנט", כשהכלל שם) — **משפיע על כל המופעים**, והפאנל אומר זאת ("ישנה את כל 4 המופעים — או כתוב לעמוד הזה בלבד").

### 2.3 מקושר / שונה במקום / מנותק (`02` §7.2)

- [ ] **המצב מחושב, לא נשמר:** מציירים את `template.html` עם ערכי ההגדרות של המופע (קוראים אותם מהמופע); אם התוצאה (מנורמלת: רווחים, סדר
      תכונות) זהה למופע — **מקושר**; אחרת — **שונה במקום**, עם "הצג את ההבדלים". בלי `data-kol-component` — **מנותק** (HTML רגיל).
- [ ] התג על שורש המופע (בקנבס וב-Navigator): ◆ מקושר · ◇ שונה · (בלי) מנותק. "נתק" — מסיר את הסימון; "חזור לרכיב" — מחליף את המופע בציור
      מחדש (עם ה-diff לפני).

### 2.4 עריכת הרכיב עצמו

- [ ] **"✏️ ערוך את הרכיב"** — פותח את `components/<שם>/template.html` בקנבס (עם `style.css` שלו), באותו עורך: בחירה, גרירה, עיצוב, הוספה. ההגדרות
      נערכות בלוח "הגדרות הרכיב" (§2.5).
- [ ] **"שמור ועדכן מופעים":** רשימה של כל המופעים בכל קובצי ה-HTML — לכל אחד ה-diff. המקושרים — מסומנים לעדכון (ערכי ההגדרות שלהם נשמרים);
      השונים — לכל אחד "עדכן (השינוי המקומי יאבד — מוצג)" / "נתק" / "דלג". "החל" — כתיבה של כל הקבצים **בפעולה אחת** בהיסטוריה (F2), ו-Ctrl+Z
      אחד מחזיר הכול.
- [ ] **כותרת ותחתית משותפות** (`01-gap` 8.4): אותו רכיב בכמה עמודים — העדכון חוצה קבצים; ב"עמודים" (V15) — "הוסף לכל העמודים".

### 2.5 יצירת רכיב (`01-gap` 7.14)

- [ ] אלמנט נבחר ← **"שמור כרכיב"**: שם (באנגלית, kebab-case, נגזר), שם לתצוגה, סמל, קטגוריה. נוצרים `template.html` (ה-HTML של האלמנט), `component.json`,
      ו-`style.css` — **הצעה** אילו כללי CSS מהעמוד חלים רק על האלמנט ועל צאצאיו (לפי המחלקות): "העבר / העתק / השאר בעמוד", לכל כלל. האלמנט
      בעמוד הופך למופע מקושר הראשון.
- [ ] **"➕ הוסף הגדרה"** — מצביעים על חלק ברכיב (בקנבס או ב-Navigator) ובוחרים מה נחשף: הטקסט שלו · תכונה (רשימה של התכונות שלו) · מחלקה מתוך
      קבוצה (מקלידים את האפשרויות) · משתנה CSS (בוחרים מאפיין, והעורך הופך את הערך ל-`var(--x)` עם ברירת מחדל) · קובץ · "הילדים — רשימה". שם
      להגדרה ← שורה ב-`fields`. הבורר נגזר (מחלקה קיימת; אם אין — מחלקה חדשה בשם קריא, `03` §4.2).
- [ ] `component.json` — **קובץ רגיל**, פתוח לעריכה ב-📁; עריכה שם ← הפאנל מתעדכן; JSON לא תקין ← הפאנל מציג את השגיאה עם שורה (כמו `kol.json`).
- [ ] **מחיקת רכיב** — רק אם אין מופעים מקושרים (אחרת: "נתק את 3 המופעים קודם?"); לסל של F2.

### 2.6 כללי

- [ ] **במחשב — על כל המסך** (1920×1080, 1366×768); לוח "הגדרות הרכיב" ולשונית הרכיבים — בלי רוחב קבוע שמשאיר ריק.
- [ ] הבנייה (M1): `components/*/component.json` ממשיך לצאת מהחבילה; `template.html` — גם הוא (הוא מקור לעורך, לא לגולש), אלא אם בעל העמוד סימן
      אחרת; `style.css` / `script.js` — נכנסים כשמופע מפנה אליהם. **שורה אחת ב-`build.php`** (הכלל של `template.html`) — בתיאום עם הבקרה.
- [ ] בדיקות: `tests/browser/v12.cjs` — הוספה (HTML + `<link>` פעם אחת), כל יעד בסכמה, repeater בגרירה, מקושר ← שונה (עריכה ביד) ← "חזור לרכיב",
      עריכת רכיב ← 3 מופעים בשני קבצים ← Ctrl+Z אחד, "שמור כרכיב" + "הוסף הגדרה" ← `component.json` נכון; `tests/editor/component-state.mjs` — חישוב
      המצב על 20 מקרים.

## 3. בדיקת הבעלים (מטלה)

במחשב, על כל המסך: לבחור את שורת החיפוש והנושאים ← "שמור כרכיב" ← "הוסף הגדרה": הכיתוב של הכפתור · להוסיף את הרכיב לעמוד שני · לשנות
את הכיתוב במופע אחד · "ערוך את הרכיב": להגדיל את הגופן ← לראות ששני המופעים התעדכנו והכיתוב השונה נשמר · Ctrl+Z · לפתוח את
`component.json` ולקרוא. "🐞" על כל חלק ברכיב שלא נבחר.

## 4. מה לא כלול

הספרייה המוכנה (אקורדיון, לשוניות, קרוסלה…) — **V16** · תבניות של מקטע / עמוד ("שמור כתבנית", ייצוא וייבוא) — **V13** · רכיב בתוך רכיב —
נתמך כ-HTML, ועדכון מקונן — רמה אחת בלבד בשלב הזה (מוצג).
