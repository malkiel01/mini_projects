# קול מרוקו — האפיון

סטודיו עריכה חזותי לעמוד **אחד**: https://maghreb.co.il/lexicon/ (וורדפרס, בלוהוסט, מאחורי Cloudflare).

> מצב: **אפיון שאושר** (2026-10-25). ההכרעות — פרק 12.

---

## 1. חוק הברזל

לכלי **אין שום גישה לאתר**: לא סיסמת וורדפרס, לא מסד, לא SSH, לא FTP. הדבר היחיד שהוא יודע לעשות מול
האתר הוא לשלוח **"גרסה חדשה של עמוד קול מרוקו"**, חתומה במפתח פרטי שנמצא רק אצלו. האתר מחזיק רק את
המפתח **הציבורי**, ותוסף קטן בו מקבל את הגרסה הזו ותו לא.

מה זה אומר בפועל:

- דליפה מהכלי (גם של המפתח הפרטי) = אפשר להחליף את **העמוד הזה** בלבד. לא משתמשים, לא עמודים אחרים, לא
  קבצי האתר.
- דליפה מהאתר = כלום. המפתח הציבורי אינו סוד.
- התוסף לא כותב שום דבר מעבר לאחסון שלו (אפשרות `kol_maroko_*` ותיקייה ב-uploads).

## 3. מודל העמוד

העמוד הוא **מסמך JSON** אחד. HTML נגזר ממנו בשרת (PHP), גם לתצוגה המקדימה וגם לפרסום — מקור אחד, בלי
שני מנועי רינדור שמתפצלים.

```
page
 ├─ settings   {title, width:"boxed|full", max_width:1140, colors:{…}, fonts:{…}, direction:"rtl"}
 └─ sections[]                          פס רוחבי (רקע, ריפוד)
      └─ columns[] (1–4, רוחב באחוזים, נערמים בטלפון)
           └─ widgets[]
```

כל רכיב: `{id, type, props, style}`. `id` — 8 תווים אקראיים, יציב (ה-AI וההיסטוריה מפנים אליו).

| `type` | `props` | הערות |
| --- | --- | --- |
| `heading` | `text, level:1–4` | טקסט עשיר מוגבל (מודגש, נטוי, קישור) |
| `text` | `html` | טקסט עשיר קצר; מסונן ב-allowlist (פרק 10) |
| `longtext` | `doc, html, css` | **עורך התמלילים**: `doc` — המזהה אצלו; `html/css` — העותק האחרון (`doc_export`) |
| `image` | `file, alt, caption, link?` | `alt` חובה לפרסום |
| `gallery` | `files[], columns` | |
| `audio` | `file, title, transcript?` | הקלטה / קובץ שמע, עד 50MB |
| `video` | `file` או `embed:{provider:"youtube\|vimeo", id}` | קובץ — עד 50MB |
| `file` | `file, label` | קובץ להורדה (PDF וכו') |
| `button` | `label, href, style` | |
| `code` | `html, height` | קטע קוד מוטמע — תמיד במסגרת מבודדת (פרק 10) |
| `divider`, `spacer` | `height` | |

`style` לכל רכיב — שדות קבועים ולא CSS חופשי: יישור, צבע טקסט/רקע, ריפוד, שוליים, גודל גופן, הסתרה
בטלפון/במחשב. כך אין הזרקת CSS, והרכיבים נשארים עקביים.

**ה-CSS שנגזר עטוף ב-`.kol-page`** (כל בורר מתחיל בו), כדי שלא ידרוס את ערכת הנושא של האתר ולהפך.

## 4. טיוטה, גרסה ופרסום

```
טיוטה (אחת, משותפת) ──שמירה──▶ revisions (היסטוריית שמירות)
        │
        └──"פרסום" (מפרסם בלבד)──▶ versions (מספר עולה, קפוא) ──חתום──▶ האתר
```

- **טיוטה אחת משותפת** לעמוד. שמירה אוטומטית (2 שניות אחרי שינוי) עם `rev`: שמירה על `rev` ישן → 409,
  ו"מישהו אחר שינה — לרענן". **נעילת עריכה** כמו בעורך התמלילים: הראשון עורך, השני רואה "בעריכה אצל X"
  (פגה אחרי 2 דקות בלי דופק).
- **היסטוריית שמירות** — מאוחדת לנקודה אחת לכל משתמש בכל 10 דקות, עד 200. שחזור = טעינה לטיוטה.
- **גרסה** נוצרת רק בפרסום: עותק קפוא של ה-JSON, ה-HTML וה-CSS שנגזרו, רשימת הקבצים, מי ומתי, ותשובת
  האתר. לא נמחקת.
- **חזרה לגרסה קודמת** = פרסום שלה מחדש **כגרסה חדשה** (מספר עולה). האתר לעולם לא מקבל מספר ישן.
- **"מה ישתנה"** לפני פרסום: רשימת הרכיבים שנוספו / השתנו / נמחקו מאז הגרסה החיה.
- **בדיקות לפני פרסום** (חוסמות): תמונה בלי `alt`, קישור לא https, קובץ חסר, גודל חבילה מעל התקרה.

## 5. תפקידים — מסך "חברים"

טבלה `members(sub, role, name, email, added_by, added_at)`. הזהות מ-`$_SERVER['PLATFORM_USER']`.

| תפקיד | עריכה ושמירת טיוטה | פרסום | AI | ניהול חברים, מפתחות, מכסות, הגדרות |
| --- | --- | --- | --- | --- |
| **עורך** | ✓ | — | ✓ (במכסה) | — |
| **מפרסם** | ✓ | ✓ | ✓ (במכסה) | — |
| **בעלים** | ✓ | ✓ | ✓ | ✓ |

- **בעלים** = `platform_admin: true`. אוטומטי, לא נשמר בטבלה ולא ניתן להסרה מתוך הכלי.
- **משתמש פלטפורמה שעבר את השער ואינו בטבלה** → מסך "אין לך תפקיד בכלי — בקש מבעל המערכת". השער
  (`restricted`) הוא הסינון הראשון; הטבלה היא השני. שניהם חייבים לאשר.
- הבעלים מוסיף חבר לפי מייל או לפי מי שכבר ניסה להיכנס (רשימת "ביקשו גישה" — `sub` שנרשם בניסיון
  הכניסה), ובוחר תפקיד.
- **יומן פעולות** (`audit`): כניסה, שמירה, פרסום, שחזור, שינוי חבר/תפקיד, קריאת AI, החלפת מפתח.

## 6. פרסום וחתימה

### 6.1 המפתח

- `sodium_crypto_sign_keypair()` בהפעלה הראשונה, נשמר **במסד הכלי** (טבלה `keys(kid, public, secret,
  created_at, retired_at)`), מוחרג בפריסה. `kid` = `YYYY-MM` + 4 תווים.
- הבעלים רואה את **המפתח הציבורי** במסך ההגדרות, עם כפתור העתקה — ומדביק אותו בהגדרות התוסף בוורדפרס,
  פעם אחת.
- **החלפת מפתח:** הבעלים יוצר מפתח חדש; עד שהוא מודבק בתוסף, הפרסום חותם בישן. התוסף מחזיק עד 2 מפתחות.

### 6.2 החבילה

```
POST https://maghreb.co.il/wp-json/kol-maroko/v1/publish
Content-Type: application/json
X-Kol-Kid:       2026-10-a1b2
X-Kol-Signature: <base64 של חתימת Ed25519 על הגוף בדיוק כפי שנשלח>

{
  "site": "maghreb.co.il",
  "page": "lexicon",
  "version": 17,                       מספר עולה, תמיד
  "time": 1761400000,                  ±300 שניות משעון האתר
  "nonce": "<32 hex>",
  "html": "<div class=\"kol-page\">…</div>",
  "css":  ".kol-page …",
  "assets": [{"name":"a8f3….webp","sha256":"…","size":123456,"type":"image/webp"}],
  "published_by": "שם המפרסם"
}
```

- החתימה על **הגוף כולו** (כולל `site`, `page`, `version`, `time`, `nonce`) — אי אפשר להעביר חבילה לאתר
  אחר או לעמוד אחר.
- **האתר דוחה** (תשובה `{"ok":false,"code":…}`): `bad_signature`, `wrong_site`, `stale` (זמן), `replay`
  (nonce שנראה), `old_version` (`version` ≤ האחרונה שהתקבלה), `asset_missing`, `too_large`.
- **הצלחה:** `{"ok":true,"version":17,"url":"https://maghreb.co.il/lexicon/"}`. הכלי שומר את התשובה
  בגרסה.
- **כשל רשת** — הגרסה נשמרת "לא נשלחה", וכפתור "שליחה שוב" שולח **אותה גרסה** (מספר זהה, זמן ו-nonce
  חדשים, חתימה חדשה). אם הקודמת דווקא הגיעה — האתר עונה `old_version` עם המספר שאצלו, והכלי מסמן
  "נשלחה".

### 6.3 הקבצים

**נשלחים בפרסום** (הכרעה 3). לפני הגרסה, כל קובץ שהאתר עוד לא קיבל נשלח בבקשה חתומה משלו:
`POST /wp-json/kol-maroko/v1/asset`, בחלקים של 4MB (`{sha256, part, parts, data(base64)}` — החתימה כמו ב-6.2).
האתר שומר בשם ה-sha256, ובודק את ה-hash בסיום. הגרסה עצמה מפנה לקבצים בשמם, והאתר דוחה (`asset_missing`)
גרסה שחסר לה קובץ. כך האתר עצמאי לגמרי — נפילה של השרת שלנו לא שוברת אותו.

### 6.4 Cloudflare

ההוראות המדויקות נכתבות לבעל המערכת כשמגיעים לשלב הפרסום (כלל WAF ← Custom rule ← Skip לנתיב
`/wp-json/kol-maroko/v1/publish`, `POST` בלבד). **לבדוק אז:** Bot Fight Mode בתוכנית החינמית לא ניתן
לעקיפה בכלל Skip — אם הוא דלוק, ייתכן שצריך כלל IP Access (Allow) לכתובת השרת שלנו במקום. ייתכן גם
ש-ModSecurity של בלוהוסט חוסם — נבדק בשליחת ניסיון.

## 7. תוסף הוורדפרס

`kol-maroko/wordpress-plugin/kol-maroko/` — קובץ PHP אחד וקריאה (`readme.txt`), בלי תלות.

- **מסך הגדרות** (`הגדרות ← קול מרוקו`, `manage_options` בלבד): המפתח הציבורי (הדבקה), איזה עמוד
  (ברירת מחדל — העמוד בכתובת `/lexicon/`), מתג "פעיל", הגרסה החיה, 10 הגרסאות האחרונות שהתקבלו, ו**"חזרה
  לתוכן המקורי"** (מכבה את ההחלפה בלי למחוק).
- **נקודת קבלה אחת:** `POST /wp-json/kol-maroko/v1/publish`, `permission_callback` ציבורי — ההגנה היא
  החתימה. בודק לפי הסדר: גודל, חתימה, `site`/`page`, זמן, nonce (טבלה קטנה ב-option, 10 דקות), גרסה.
- **אחסון:** כל גרסה ב-option (`kol_maroko_v_<n>`, נשמרות 10), הקבצים ב-`wp-content/uploads/kol-maroko/`.
  `post_content` של העמוד **לא נדרס** — כך "חזרה למקור" תמיד אפשרית.
- **תצוגה:** **תבנית של התוסף לעמוד הזה בלבד** (הכרעה 1, `template_include`): `get_header()`, התוכן שלנו,
  `get_footer()`. עובד גם אם העמוד בנוי היום באלמנטור. מתג "פעיל" כבוי → העמוד המקורי.
- **אין בתוסף:** שום נקודה שמחזירה מידע, שום עריכה, שום קריאה החוצה.
- **מטמון:** אחרי החלפה — ניקוי מטמון העמוד (`clean_post_cache`, ו-purge של תוסף מטמון אם קיים —
  LiteSpeed/WP Rocket/W3TC, בלי תלות). Cloudflare: לבדוק בשלב 6 אם צריך כלל "Bypass cache" לעמוד, או purge ידני.

## 8. עוזר בינה מלאכותית

- **ספק:** Claude API (Anthropic), על בסיס `recipes-app/lib/ai.php` ו-`lib/secrets.php` — **מועתק**,
  לא `require`. המפתח ב-`data/secrets.json` (מוחרג, `0600`), לעולם לא חוזר לדפדפן (רק "מוגדר · ‎…a1b2").
- **מה הוא עושה:** מקבל בקשה בעברית ("תוסיף מתחת לכותרת פסקה שמסבירה…", "תקצר את הפתיחה", "תתרגם
  לצרפתית את הכיתוב של התמונות") ואת ה-JSON של העמוד (או של הרכיבים שנבחרו), ומחזיר **רשימת פעולות**
  במבנה קבוע (`add / update / move / remove` לפי `id`), בפלט מובנה לפי סכימה.
- **לא מוחל לבד:** התוצאה מוצגת כתצוגה מקדימה ("מה ישתנה"), והמשתמש מאשר / דוחה. אושר → נכנס לטיוטה
  כשמירה רגילה (עם נקודה בהיסטוריה — אפשר לבטל).
- **הוא לא נוגע:** בקבצים, בקטעי קוד ובהגדרות הפרסום. פעולה על רכיב `code` נדחית בשרת.
- **מכסה:** טוקנים לחודש לכל חבר — ברירת מחדל 300K (⚙️ הגדרות), ומכסה אישית במסך החברים; בעלים בלי מכסה. המודל: `claude-opus-5-5`, effort `medium`, `fallbacks: "default"`. לפני קריאה —
  בדיקת יתרה; אחרי — רישום השימוש בפועל מהתשובה.
- **`ai_usage(request_id, sub, at, model, input_tokens, output_tokens, status, reported_at)`** —
  `request_id` = UUID v4 שנוצר **לפני** הקריאה ונשמר גם בכשל. `reported_at` ריק עד הדיווח לתוסף
  התשלומים (`payments/`, באפיון) — כך כל קריאה מדווחת פעם אחת בדיוק.

## 9. קבצים והקלטות

- **העלאה:** תמונה, שמע, וידאו, PDF ומסמכים. **הקלטה מהדפדפן** (`MediaRecorder`): ‎`audio/mp4` כשנתמך
  (ספארי), אחרת ‎`audio/webm;codecs=opus`. **אין ffmpeg בשרת** — הקובץ נשמר כפי שהוקלט, ולכן מוצגת
  אזהרה כשקובץ webm עלול לא להתנגן באייפון ישן, עם הצעה להעלות m4a/mp3.
- **עד 50MB לקובץ**, בחלקים של 8MB (`upload_init / upload_chunk / upload_done`) — כך לא נוגעים ב-64M
  של השרת, ושגיאת 413 מטופלת (מוצג הגבול שנמדד ב-`ini_get` בזמן ריצה).
- **בדיקה בשרת:** `finfo` (לא הסיומת), רשימת סוגים מותרת, `getimagesize` לתמונות. תמונות — `imagick`/`gd`:
  הסרת EXIF (מיקום!), הקטנה לרוחב 2400 ו-WebP + המקור. SVG — **אסור** (סקריפט בתוך תמונה).
- **אחסון:** `data/files/<2 תווים>/<32 hex>.<ext>`, שם אקראי. מוגש רק דרך `api.php?action=file`, אחרי בדיקת
  חבר. טבלה `files(id, name, type, size, sha256, w, h, duration, by, at)`.
- **תקרה פנימית:** 5GB לכל הכלי (ברירת מחדל, הבעלים משנה), מוצגת במסך הקבצים עם מד. מעליה — העלאה
  נחסמת.
- **ספריית מדיה** בסטודיו: כל הקבצים, חיפוש, "בשימוש ב…", מחיקה של קובץ שאינו בשימוש בטיוטה או בגרסה.

## 10. אבטחה

- **השער:** `"gate": true`, `"restricted": true`. `public` — רק `api.php?action=embed_key` (בשביל עורך
  התמלילים). שום דבר אחר.
- **בקשות משנות:** JSON בלבד, `X-Kol` + CSRF (אסימון מקושר ל-`sub`), כמו בשאר האפליקציות.
- **טקסט עשיר** (`heading`, `text`, וה-HTML מעורך התמלילים): מסונן בשרת ב-`DOMDocument` מול allowlist
  (תגיות: `p br strong em u s a ul ol li h2–h4 blockquote span`; תכונות: `href` https/mailto/tel, `dir`,
  `class` מרשימה). בכל שמירה **ובכל פרסום** מחדש — לא סומכים על מה שבמסד.
- **קטעי קוד** — לעולם לא רצים בדומיין שלנו: בסטודיו הם מוצגים ב-`<iframe sandbox="allow-scripts"
  srcdoc>` (בלי `allow-same-origin`), כך שאין להם גישה לעוגיות, ל-API או ל-DOM של הסטודיו. באתר — **גם במסגרת מבודדת** (הכרעה 4): `<iframe sandbox="allow-scripts allow-popups allow-forms" srcdoc>`, בגובה
  שנקבע ברכיב. קוד לא יכול לשנות את שאר העמוד או לקרוא עוגיות של האתר.
- **CSP לסטודיו:** `default-src 'self'; frame-src 'self' https://mbe-plus.com https://www.youtube-nocookie.com
  https://player.vimeo.com; object-src 'none'; base-uri 'none'`.
- **הדפים בעמוד שפורסם** — ה-HTML נבנה מהמודל (פרק 3), לא מטקסט חופשי. הדבר היחיד שעובר "כמו שהוא"
  הוא קטע קוד, לפי ההכרעה.

## 15. ייבוא העמוד הקיים (`lib/import.php`, `lib/legacy.php`)

- **ההמרה שומרת את העיצוב:** סביב כל פס, עמודה ורכיב נשמרות העטיפות המקוריות (המחלקות של אלמנטור / וורדפרס), כמבנה
  מסונן ולא כטקסט. ה-CSS של העמוד נשמר (`imported_css`) ונשלח בכל פרסום. התוסף טוען באתר את הסגנונות הבסיסיים של

## 16. המילון (`lib/lexicon.php`, `assets/js/words.js`) — הכרעות 2026-10-25

הייבוא הראשון מהאתר הראה שהעמוד אינו אלמנטור: הוא תבנית PHP של ערכת הנושא (`page-kadisha-lexicon.php`) שמציגה
1,496 רשומות `kadisha_word` — חיפוש, נושאים, השמעה, מבוא ומשוב. הכרעות בעל המערכת:

1. **"להחליף את העמוד כולו, הכל הכל — רק תשמור אופציה תמיד לחזור, בתוך המערכת, למצב שלפני כל השינויים."**
2. **המילים מנוהלות רק בכלי.** מה שבוורדפרס נשאר כמו שהוא, ולא משפיע על העמוד כשהגרסה מהכלי מוצגת.

איך:

- **הייצוא** (תוסף 1.2): `data/lexicon.json` — ההגדרות (`kadisha_lexicon_get`), המבוא, המילים (מילה, פירוש,
  נושאים, כתובת ההקלטה, מספר מהאקסל) והנושאים. ההקלטות לא נכנסות לקובץ — נשארות באתר. ה-CSS וה-JS של התבנית —
  לתצוגה בסטודיו בלבד.
- **הרכיב "המילון"**: מרנדר את **אותו HTML** כמו התבנית — אותן מחלקות ואותם מזהים. באתר התבנית עדיין משויכת לעמוד,
  ולכן ערכת הנושא ממשיכה לטעון לו את `lexicon.css` ו-`lexicon.js` — והמראה וההתנהגות זהים. בסטודיו אותו JS רץ בתוך
  התצוגה המבודדת (80 המילים הראשונות; באתר — כולן). מילון אחד לעמוד.
- **המילים** בטבלה `words`; נושא חדש מקבל slug קבוע לפי השם. **הקלטה**: כתובת באתר (מה שיובא), או קובץ שלנו —
  הקלטה חדשה שנשלחת בפרסום כמו כל קובץ. כתובת מאתר אחר — נדחית.
- **כל גרסה שומרת עותק של המילים** (`versions.words`). "פרסום מחדש" של גרסה ישנה מחזיר גם את המילים שהיו בה;
  "מה ישתנה" מראה כמה מילים נוספו / השתנו / נמחקו.
- **חזרה לעמוד המקורי — מהכלי:** פעולה חתומה `switch` בתוסף (כמו כל פעולה: חתימה, זמן, nonce). כיבוי — האתר מציג
  את התבנית ואת המילים שבוורדפרס; הפעלה — את הגרסה האחרונה. במסך 🚀 פרסום (מפרסם ובעלים).
- **משוב על מילה** נשלח דרך האתר לפי מספר הרשומה בוורדפרס — ולכן רק למילים שהגיעו משם.
- **ההקלטות — עותק בכלי** (הכרעה 2026-10-25): תוסף 1.3 מייצא אותן בכמה ZIP (עד 300MB כל אחד, `audio.json` + הקבצים).
  בייבוא כל הקלטה נכנסת לספרייה עם `files.origin` = הכתובת שלה באתר, ונקשרת לכל מילה שהצביעה עליה. בפרסום — הקלטה
  עם origin מוצגת מהכתובת שבאתר ולא נשלחת שוב; הקלטה שהוחלפה בכלי — נשלחת כקובץ חדש.
- **עריכה — טבלה** (הכרעה 2026-10-25): המילה והנושאים נערכים בתא (נשמר ביציאה), הפירוש וההקלטה — בכרטיס. סינון לפי
  נושא והקלטה; ניהול נושאים (שינוי שם / איחוד / הסרה); ייצוא לאקסל (CSV עם BOM) וחזרה ממנו — שורה עם מזהה מעדכנת,
  בלי מזהה מוסיפה; פירוש שלא השתנה שומר את העיצוב; מחיקה והקלטות — לא מהקובץ.

## 17. קבצי הקוד ועבודה מצ'אט (`lib/code.php`, `lib/agent.php`, `agent.php`) — הכרעות 2026-10-25

**קבצי הקוד** — "כל הקוד ניתן לעריכה, כמו ב-VS Code"; JS — כל עורך.
- `lexicon.html` (תבנית Mustache: `{{x}}`, `{{{html}}}`, `{{#list}}…{{/list}}`, `{{^x}}…{{/x}}`), `lexicon.css` (גם תבנית —
  הגדלים מהפאנל), `lexicon.js`. התבנית אינה קוד שרת — רק נתונים: ההגדרות מהפאנל, המבוא, הנושאים והמילים.
- בלי קבצים — התבנית המובנית (אותו HTML כמו ערכת הנושא) והקבצים של ערכת הנושא באתר. "📝 יצירת הקבצים" — מהעמוד
  כמו שהוא; "↩️" — חזרה למובנית (הקבצים נשמרים בהיסטוריה).
- **קוד מהכלי לא רץ בדף של האתר** (תיקון 2026-10-25, לפי צ'אט האפיון ובאישור בעל האתר — מחליף את "JS רץ בעמוד"):
  - HTML מהתבנית — מנוקה בשרת (`tpl_clean_html`): בלי script / iframe / object / base / meta / link / style, בלי `on*`,
    בלי `javascript:` / `data:` (חוץ מתמונה), טופס בלי `action`, ובלי `<` `>` בערכי `data-*` (ה-JS של ערכת הנושא מכניס
    אותם ב-innerHTML). גם "קרא עוד" / "הסתר" בפאנל — טקסט בלבד.
  - CSS — ממוקד במכל (`css_scope`): כל בורר מתחיל ב-`.kadisha-lexicon-page`; `html` / `body` / `:root` הופכים למכל;
    `@import` נופל; `url()` רק https.
  - JS כמו של ערכת הנושא → היא מריצה את שלה; הגרסה מסומנת `data-kol-css` והתוסף מחליף רק את ה-CSS.
  - JS שנערך → המילון כולו ב-`iframe sandbox="allow-scripts allow-popups allow-forms"` (srcdoc, **בלי allow-same-origin** —
    מקור אטום: בלי עוגיות, בלי parent/top, בלי wp-admin ובלי AJAX של האתר). מסומן `data-kol-frame`. הגשר היחיד —
    קוד קבוע של התוסף (1.5): גובה המסגרת, מיקום החלונות הקופצים, ושליחת משוב על מילה בשדות קבועים
    (`kadisha_lex_send_feedback`; word_id, name, email, message, website). המחיר: גוגל סורק פחות טוב תוכן במסגרת.
  - קו הגנה שני בתוסף (`kol_maroko_clean_html`): כל גרסה שמתקבלת — בלי script, `on*`, `javascript:`, ו-iframe רק
    מבודד או נגן יוטיוב / וימאו. גם גרסה חתומה מכלי שהשתלטו עליו לא מריצה קוד בדף.
- שמירה: תבנית שבורה נדחית עם מספר השורה; `rev` מונע דריסה; 50 שמירות לכל קובץ בהיסטוריה; עותק בכל גרסה.
- העורך: Monaco (העורך של VS Code) מ-jsDelivr; אם לא נטען — תיבת טקסט. תצוגה חיה של הטיוטה עם ה-JS.

**עבודה מצ'אט** — "סקיל עם שם משתמש וסיסמה, לעריכת האתר הזה בלבד"; "רק טיוטה".
- כל עורך יוצר לעצמו כניסה (✨ ← 🤖 עבודה מצ'אט) ומקבל סקיל להעתקה (או SKILL.md). הסיסמה מוצגת פעם אחת; בשרת — גיבוב.
- `agent.php` ציבורי בשער (`app.json`), עם כניסה משלו: `X-Kol-User` + `X-Kol-Password` (או Basic). רק: טיוטה, תצוגה,
  מילים, נושאים, קבצי קוד, הקבצים (קריאה), "מה ישתנה". אין פרסום, חברים, הגדרות, מפתחות, ייבוא, החלפה באתר.
