# אבחון כשלים בפריסה

כל תקלה כאן **קרתה בפועל** והתבררה בלוג. הטבלה ממפה סימפטום → סיבה, כדי שלא תנחש.

הכלל שמעליהן: **מצא את החתימה המדויקת בלוג לפני שאתה מנסח תיאוריה.** הודעות שגיאה של ssh ו‑rsync נראות דומות במקרים שונים לגמרי, וניחוש מוביל לתיקון של בעיה שלא קיימת.

## טבלת אבחון

| מה מופיע בלוג | הסיבה | התיקון |
| --- | --- | --- |
| `Permission denied, please try again.` ואחריו `Too many authentication failures` | אימות המפתח נכשל, ו‑ssh נפל לאימות סיסמה. ההודעה על ריבוי נסיונות **מטעה** — היא תוצאה, לא סיבה | בדוק את תוכן `DEPLOY_SSH_KEY` |
| `Permission denied (publickey,...)` | אותה סיבה, אבל ההודעה מדויקת | אותו דבר |
| `deploy_key is not a key file` | הסוד אינו מפתח קריא: נעול בסיסמה, נחתך, או שהודבק לשם משהו אחר | ראה "מפתח נעול" למטה |
| `identity file ... type -1` | ssh לא זיהה את סוג המפתח — אותה משפחת תקלות | אותו דבר |
| `Will attempt key: ... explicit` **בלי** סוג וטביעת אצבע, ובלי `Offering public key` אחריו | ssh לא הצליח לגזור מפתח ציבורי מהקובץ. הבעיה בתוכן, **לא** בהרשאה בשרת | אותו דבר |
| `jailshell: line N: ...: command not found` × עשרות, ואז `remote command could not be run (code 126)` | אחד מסודות היעד רב־שורתי. היעד נשלח כמחרוזת אחת וה‑shell המרוחק מריץ כל שורה | בדוק ש‑`DEPLOY_PATH`, `DEPLOY_USER`, `DEPLOY_HOST` הם שורה אחת |
| השורה האחרונה בשגיאות היא `/: Is a directory` | מאשר שהתוכן הרב־שורתי הוא **`DEPLOY_PATH`** — הסלאש שה‑workflow מוסיף אחריו | תקן את `DEPLOY_PATH` |
| `DEPLOY_PASS:` ריק ב‑env של השלב | הסוד `DEPLOY_SSH_PASSPHRASE` לא הוגדר | הגדר אותו, או השתמש במפתח בלי סיסמה |
| הכול ירוק אבל האתר לא השתנה | הענף שמוזג אינו הענף שממנו האתר מוגש | בדוק את `branches:` מול ענף ההגשה בפועל |

## מפתח נעול בסיסמה

**החתימה:** שתי השורות הראשונות אחרי `BEGIN` הן

```
Proc-Type: 4,ENCRYPTED
DEK-Info: AES-128-CBC,...
```

ואחריהן שורה ריקה. `ssh` **לא יכול** לפתוח מנעול בלי אדם שמקליד, ולכן מפתח כזה לא יעבוד ישירות.

**שים לב:** אם תשאל את המשתמש "מה בשורה הראשונה", התשובה תהיה `BEGIN` וזה לא יגלה כלום — הכותרת יושבת בשורות 2–3. שאל על שורות 2 ו‑3 במפורש.

שלוש דרכים, וכולן תקפות:

| דרך | מה היא דורשת |
| --- | --- |
| מפתח בלי סיסמה | ליצור מפתח חדש ב‑cPanel עם שדה סיסמה **ריק**, ולאשר אותו (Authorize) |
| להסיר את המנעול מעותק | `cp ~/.ssh/<key> /tmp/k && ssh-keygen -p -f /tmp/k -N ""` — המקור נשאר נעול |
| להשאיר נעול ולתת את הסיסמה | סוד `DEPLOY_SSH_PASSPHRASE`, וה‑workflow פותח דרך `ssh-agent` |

הבחירה היא של המשתמש. **אל תכפה יצירת מפתח חדש** אם הוא מעדיף אחרת — `assets/deploy.yml` תומך בשני המצבים והשלב מדלג על עצמו כשאין סיסמה.

הערה על אבטחה, אם נשאלת: סיסמה שיושבת בכספת גיטהאב ליד המפתח אינה מוסיפה הגנה מעשית — מי שקורא את האחד קורא את השני. סיסמה נועדה להגן על מפתח שיושב במחשב אישי. זו הסיבה שהמוסכמה בפריסות היא מפתח ייעודי בלי סיסמה. אמור זאת פעם אחת ואל תחזור עליה.

## אבחון תוכן של סוד בלי לחשוף אותו

גיטהאב מצנזר בלוג כל מחרוזת שמקורה בסוד. **הדפסת שורות מהמפתח תחזיר `***` ולא תלמד דבר.** מספרים נגזרים עוברים:

```bash
body=$(sed '1d;$d' ~/.ssh/deploy_key)
echo "שורות:        $(wc -l < ~/.ssh/deploy_key)"
echo "BEGIN:        $(head -n1 ~/.ssh/deploy_key | grep -cE '^-----BEGIN [A-Z ]*PRIVATE KEY-----$')"
echo "END:          $(tail -n1 ~/.ssh/deploy_key | grep -cE '^-----END [A-Z ]*PRIVATE KEY-----$')"
echo "לא-base64:    $(printf '%s\n' "$body" | grep -cvE '^[A-Za-z0-9+/=]*$')"
echo "אורך מינ/מקס: $(printf '%s\n' "$body" | awk '{print length}' | sort -n | head -1) / $(printf '%s\n' "$body" | awk '{print length}' | sort -n | tail -1)"
```

החתימות, כפי שנמדדו:

| מצב | שורות | END | לא‑base64 | מינ׳/מקס׳ |
| --- | --- | --- | --- | --- |
| **תקין** (RSA‑2048 פתוח) | 27 | 1 | 0 | ~40 / 64 |
| **נעול בסיסמה** | 30 | 1 | **2** | **0 / 64** |
| טקסט מהדף נכנס להעתקה | 31 | 0 | >0 | משתנה |
| גלישת שורות בנייד | 53 | 1 | 0 | **20 / 44** |
| העתקה חלקית | 18 | 0 | 0 | **64 / 64** |

## למה נכשלנו שוב ושוב בפעם הראשונה

התקלה נקבעה כבר בהרצה הראשונה. מה שעלה חמש הרצות מיותרות:

1. **תיאוריה במקום השוואה.** היה ריפו אחר שנפרס לאותו שרת בהצלחה מאות פעמים. השוואה אליו הייתה חושפת מיד שה‑workflow זהה ורק הסודות שונים. במקום זה נוסו שלוש תיאוריות על הקוד — `ssh-rsa`, `ssh-agent`, דגלים — וכולן הופרכו.
2. **הכרזת הצלחה מוקדמת.** הרצה שעדיין רצה אחרי 3 שניות אינה הצלחה. רק `conclusion: success`.
3. **שאלת אבחון גרועה.** "מה בשורה הראשונה" כשהמידע בשורות 2–3.
4. **בקשת מידע שהמערכת מסתירה.** הדפסת שורות מסוד מחזירה `***`.

הכלל המעשי: **כשיש מערכת דומה שעובדת, השוואה אליה היא הצעד הראשון — לא האחרון.**
