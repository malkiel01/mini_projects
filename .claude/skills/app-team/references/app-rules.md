# מה כל אפליקציה חייבת — ואיך בודקים

זו גם רשימת הסקר לאפליקציה קיימת (`<app>/dev/audit.md`): לכל סעיף — ✅ / חלקי / ❌, עם `קובץ:שורה`, ומה חסר.

| # | הכלל | איך בודקים |
| --- | --- | --- |
| 1 | **רישום בפלטפורמה** — `app.json` עם `id` = שם התיקייה, `"gate": true`; בפיתוח גם `"restricted": true` | `php platform/check-apps.php` |
| 2 | **התחברות דרך הפלטפורמה, עם אפשרות ניתוק** — לפי `platform/docs/auth.md` ו-`sso.md` | `"sso"` ב-`app.json`; כניסה בלי מסך נוסף כשמחוברת; כניסה משלה כשמנותקת |
| 3 | **עצמאית** — משתמשים, מסד ועוגייה משלה; בלי `require` מחוץ לתיקייה; בלי קישור "חזרה לכלים" | `grep -rn "require.*\.\./\.\." <app>`; `grep -rn '\.\./index.html' <app>` |
| 4 | **חשבון מפתח — DevLoop** | רשומה ב-`devloop/apps.json` וב-`.devloop.json`; 🐞 בכותרת למפתח; `php devloop/tools/sync.php --check` |
| 5 | **חשבון מפתח — יומן ובדיקות** — יומן בקשות ושגיאות, יומן פעולות, בדיקות תקינות | מסך מפתח באפליקציה |
| 6 | **חשבון מפתח — משתמשים והרשאות** | ניהול משתמשים ומתן הרשאות; מהמודול המשותף כשהוא קיים |
| 7 | **מפת דרכים** — `dev/open-items.json` | נקרא בדשבורד הפיתוח (`platform/devboard.php?app=<id>`) |
| 8 | **ענן MBE ותוספים — לפי צורך** | האפיון עונה מה נשמר בענן ואילו תוספים; חיבור דרך `mbe-cloud/drives` ובקשות חתומות — לא `require` |
| 9 | **נתונים מוגנים** — כל נתיב נתונים מוחרג ב-`deploy.yml`, ו-`data/.htaccess` חוסם | `grep -n '<app>' .github/workflows/deploy.yml` מול כל מקום שהקוד כותב אליו |
| 10 | **בדיקות שעוצרות פריסה** | צעד ב-`deploy.yml` שמריץ את הבדיקות של האפליקציה |
| 11 | **כתובות ציבוריות** — כל כתובת שנפתחת בלי התחברות ב-`"public"` | לעבור על נקודות הכניסה (פורטל, webhook, API לאפליקציה) |
| 12 | **עיצוב** — עברית, RTL, טלפון קודם | הסקיל `phone-first-design` |

סעיפים 4–6 הם "חשבון המפתח". סעיף 8 תלוי באפיון; "לא צריך" היא תשובה תקינה, אם נכתבה.
