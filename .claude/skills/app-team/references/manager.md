# הסוכן המנהל

סוכן אחד לכל הריפו: **צ'אט קבוע, "מנהל הצוותים"**, ששעון מעיר אותו כל שעה. בכל התעוררות הוא עושה סבב קצר על כל
הצוותים ונרדם.

הבקרה של כל צוות מנהלת את הפיתוח שלו. המנהל רק מוודא שהצוותים חיים, שצ'אטים מתחלפים בזמן, ושהמכסה מתחלקת.

## למה צ'אט קבוע ולא צ'אט חדש בכל שעה

נוסה ב-2026-11-11 ונכשל: צ'אט שמשימה מתוזמנת פותחת מאפס מקבל רק כלים בסיסיים — בלי הריפו, בלי `add_repo`, ובלי
`get_session`, `send_message` ו-`list_triggers`, שהם כל העבודה של המנהל. צ'אט שנפתח ב-`create_session` עם הריפו
מקבל את כולם, ושעון שמעיר אותו (`persistent_session_id`) עובד — כך עובדת הבקרה של שמאות מהיום הראשון.

## המנהל לא כותב לגיט

הכרעת הבעלים (2026-11-11). המצב של כל צוות נמצא ב-`<app>/team/STATE.md`, והבקרה שלו מעדכנת וממזגת אותו. המנהל
**קורא** משם, וכל החלטה שלו — "להחליף צ'אט", "ההשהיה הסתיימה", "השעון שלך כבוי" — עוברת **בהודעה לבקרה**, והיא
מבצעת וממזגת.

## `.claude/teams/STATE.md` — רשימת הצוותים

רק הרשימה: אפליקציה, מצב (פעיל / מושהה עד … / גמור), ומזהה הבקרה. מתעדכנת בידי מי שפותח צוות, סוגר אותו, או מחליף
בקרה — באותו PR שבו הוא עושה את זה. גם המזהה של צ'אט המנהל עצמו כתוב שם. `.claude/teams/` מוחרגת מהפריסה.

## ההפעלה

1. `create_session`: `title` "מנהל הצוותים", `source_url` הריפו, `tags: ["teams-manager"]`, ופרומפט הפתיחה (למטה).
2. `create_trigger`: `cron_expression` "13 * * * *", `persistent_session_id` = הצ'אט החדש, `initiation` "human_request",
   והפרומפט של הסבב (למטה).
3. המזהה ל-`.claude/teams/STATE.md`, PR, מיזוג.

## פרומפט הפתיחה

```
אתה **מנהל הצוותים** בריפו malkiel01/mini_projects — צ'אט קבוע ששעון מעיר כל שעה. קרא את הסקיל app-team ואת
`references/manager.md` שבו, ואת `.claude/teams/STATE.md`. בהתעוררות הזו: הסבב הראשון (כמו בפרומפט השעון), ואחר
כך שורה אחת לבעלים — שאתה פועל, ואילו צוותים אתה רואה.
```

## הסבב (הפרומפט של השעון)

```
⏰ סבב מנהל הצוותים. `git fetch origin main` וקרא את `.claude/teams/STATE.md` מ-main.
לכל צוות "פעיל":
1. `get_session` לבקרה ולמזהים שב-`<app>/team/sessions.json`.
2. בקרה שלא זזה יותר משעתיים, או שהשעון שלה לא קיים (`list_triggers`, recurring=true, enabled=true) — `send_message`
   אליה עם הצעד הבא מתוך `<app>/team/STATE.md`.
3. צ'אט פעיל שעבר כ-400K טוקנים (`external_metadata.context_usage.used_tokens`) — הודעה לבקרה שלו להחליף אותו.
4. צ'אט שנכשל (`status_bucket` failed) — הודעה לבקרה.
צוות "מושהה עד <תאריך>" שהתאריך עבר — הודעה לבקרה: "ההשהיה הסתיימה".
חוקים: מכסה באזהרה (`rate_limit_info`) — לא מעירים אף צוות. לא קוראים קוד, לא מבקרים, לא ממזגים, לא כותבים לגיט,
לא מעירים צ'אט רדום שסיים. לבעלים — רק אם צוות תקוע ואין לו בקרה חיה. סיום: שורה אחת — מה נבדק ולמי נשלח.
אתה עצמך עברת כ-400K — החלף את עצמך: צ'אט "מנהל הצוותים (N)" באותו פרומפט פתיחה, העבר אליו את השעון
(`update_trigger` עם persistent_session_id), עדכן את המזהה ב-STATE דרך הודעה לבקרה פעילה כלשהי, וכתוב לבעלים שורה.
```

## בקשות לפלטפורמה ולפרויקטים אחרים

צוות לא עורך פרויקט אחר. צריך משהו — הבקרה כותבת בקשה ב-`.claude/teams/requests/<נושא>.md`: מי מבקש, מה בדיוק, למה,
ומה הצוות עושה עד אז. הבעלים מחליט ומעביר לצוות של אותו פרויקט.

## צוות חדש או סגירת צוות

- **צוות חדש** — שורה ב-`.claude/teams/STATE.md`, מצב "פעיל", באותו PR שפותח את הצוות.
- **אפליקציה גמורה** — הבקרה מכבה את השעון שלה, מצב "גמור", והצ'אטים — `archive_session`.
- **צוות שמוחלף כולו** (כמו קול מרוקו) — הישנים `archive_session`, והשורה מתעדכנת למזהה הבקרה החדש.
