# עבודה על תור המטלות

הלוח נמצא ב‑`claude-tasks/`. אדם זורק לשם בקשות תוך כדי מחשבה; אתה עובר עליהן אחת‑אחת, עונה, ומתקדם.

**העיקרון שמפריד את זה מצ׳אט:** שאלה שלך לא עוצרת את הריצה. אתה רושם אותה על המטלה, משחרר אותה, וממשיך למטלה הבאה שאינה קשורה. כשהאדם עונה — היא חוזרת לתור מעצמה וקופצת לראש. כך אף בקשה לא נשכחת, ואף שאלה לא מבזבזת את שאר הלילה.

## חיבור

צריך שני דברים, ושניהם מגיעים מהמשתמש:

| | |
| --- | --- |
| כתובת | `https://<דומיין>/claude-tasks/api.php` |
| אסימון | הגדרות בלוח ← "חיבור Claude" ← הצגה (מנהל בלבד) |

כל בקשה: `POST`, גוף JSON, ושתי כותרות — `X-Worker-Token` ו‑`X-Worker-Name`. תן לעצמך שם יציב (למשל `claude-night`), כדי שיהיה ברור בלוח מי מחזיק במטלה.

שמור את האסימון בקובץ מקומי שאינו בגיט, או בקש אותו בכל הרצה. **אל תכתוב אותו לתוך הריפו.**

## המחזור

חזור על הלולאה עד שאין מטלות, או עד שנגמר התקציב שהוקצב להרצה.

### 1. משוך מטלה

```
POST ?action=claim     {"topic_id": 3}        # השמט topic_id כדי לקחת מכל הנושאים
```

מחזיר `task` ו‑`notes`, או `task: null` כשהתור ריק. **קרא את `notes` לפני שאתה מתחיל** — אם המטלה כבר עברה סבב, התשובה של האדם נמצאת שם, וזו בדיוק הסיבה שהיא חזרה אליך.

המשיכה נועלת את המטלה ל‑30 דקות. אין צורך לשחרר ידנית אם נפלת — הנעילה פגה מעצמה.

### 2. עשה את העבודה

לפי `kind`:

- **`code`** — המטלה נושאת `repo` ו‑`branch`. עבוד כרגיל: ענף, בדיקות, PR. אם הריפו אינו בסשן, צרף אותו.
- **`question` / `research`** — התשובה עצמה היא התוצר. כתוב אותה כתוצאה, לא כקובץ.

**מטלה ארוכה:** אם עברו יותר מ‑20 דקות, שלח `POST ?action=heartbeat {"id": N}` כדי להאריך את הנעילה. אחרת מטלה שאתה באמצעה תשוחרר וייתכן שעובד אחר ייקח אותה.

### 3. סיים, או שאל והמשך

```
POST ?action=complete  {"id": N, "result": "מה נעשה, וקישור ל-PR אם יש"}
POST ?action=block     {"id": N, "question": "מה בדיוק חסר לך כדי להמשיך"}
```

**מתי `block`:** רק כשבאמת אי אפשר להתקדם בלי הכרעה של אדם — שתי אפשרויות סבירות שההבדל ביניהן משנה, החלטת מוצר, או גישה שאין לך. **לא** בשביל לאשר משהו שאתה כבר בטוח בו.

נסח את השאלה כך שאפשר לענות עליה במשפט. "A4 או Letter?" טובה מ‑"איך לגשת לייצוא?".

**אחרי `block` — אל תעצור. חזור מיד לשלב 1.** זו כל הנקודה: מטלה תקועה לא צריכה להשבית את השאר.

### 4. אם התור ריק

`task: null` פירושו שסיימת. סכם לאדם מה נעשה ומה ממתין לו, ואל תמציא עבודה שלא ביקשו.

## עבודה לאורך הלילה

כדי שהלוח יתקדם בלי אדם נוכח, קבע Routine שמפעיל סשן על הלולאה הזו. כשהוא נורה — הרץ מטלות עד שהתור ריק, ואז סיים.

שני דברים שכדאי לזכור כשאין מי שיעצור אותך:

- **מטלה שנכשלת שוב ושוב** — אל תנסה אותה בלולאה. `block` עם מה שנתקע, ועבור הלאה.
- **פעולה הרסנית או בלתי הפיכה** שלא נתבקשה במפורש — `block` ושאל. הימצאות בתור אינה אישור.

## הסדר שאתה מקבל אינו מקרי

המטלות בנושא מסודרות מראש — תשתית לפני מה שנשען עליה, דחוף מוקדם, ומטלה שכתוב בה `#12` תמיד אחרי מטלה 12. `claim` מחזיר את הראשונה בסדר הזה, ולכן **קח את מה שנתנו לך** ואל תדלג קדימה כי משהו נראה לך קל יותר.

כשאתה פותח מטלת המשך שתלויה במטלה שעבדת עליה, כתוב בכותרת שלה `#<מזהה>` — זה מה שמונע מהתור להגיש אותה לפני שהבסיס קיים.

הנושא של מטלה נקבע לעתים אוטומטית. אם מטלה נחתה בנושא שברור שאינו שלה, זו הערה שווה ל‑`add-note` — ומילות המפתח של הנושא (`update-topic`) הן התיקון האמיתי, לא שינוי הנושא של המטלה הבודדת.

## מה שהלוח מבטיח, ומה לא

הלוח מונע כפילות: המשיכה רצה בטרנזקציה, ושני עובדים לעולם לא יקבלו את אותה מטלה. נבדק ב‑12 משיכות במקביל.

מה שהוא **לא** עושה: אינו מוודא שהעבודה נכונה. `complete` הוא הצהרה שלך. אל תסגור מטלה על סמך "אמור לעבוד" — אותה משמעת שנדרשת בכל מקום אחר נדרשת גם כאן, ובעצם יותר, כי אין אדם שקורא מעבר לכתף.
