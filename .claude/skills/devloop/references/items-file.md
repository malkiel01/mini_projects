# קובץ המטלות בקוד (`items_file` ב-`.devloop.json`, בדרך כלל `<app>/dev/open-items.json`)

```json
{
  "updated": "2026-10-14",
  "repo": "OWNER/REPO",
  "note": "הסבר קצר שמוצג בראש המסך",
  "items": [
    {
      "code": "PM-018", "area": "DevLoop",
      "status": "verify", "status_at": "2026-10-14T13:40:00Z",
      "kind": "feature", "priority": "normal", "opened": "2026-10-14",
      "title": "…", "detail": "…",
      "acceptance": "משפט אחד — איך יודעים שזה עובד",
      "steps": ["צעד במסך", "…", "מה אמור לקרות"],
      "questions": [],
      "pr": 295, "closed": "2026-10-14"
    }
  ]
}
```

- **קוד חדש** — רק `next_code` מהפיד. מטלות שנפתחות במסך, מ-🐞 ומשגיאות ביומן מקבלות קודים בייצור, ואתה לא רואה
  אותן בלי הפיד; קוד מנוחש עלול להתנגש (מטלה בקובץ מסתירה מטלה מהמסך עם אותו קוד). בלי גישה לפיד — אל תפתח קוד חדש
  בקובץ; עדכן מטלה קיימת, או בקש מהמפתח לפתוח מהמסך.
- **`status_at`** — מתי הקובץ קבע את המצב (UTC, לא בעתיד). מצב שנקבע מבחוץ (✅ / ↩️ של המפתח, `devapi-comment`,
  הפריסה) גובר על הקובץ עד שהקובץ מתעדכן עם `status_at` חדש יותר. אל תדרוס ✅ שלו בלי סיבה בשיח.
- `closed` + `pr` כשנסגרה (אחרי ✅ שלו). מטלה מהמסך (`source: user`) חיה בטבלה — מעדכנים אותה ב-`devapi-comment`.

## איך כותבים מטלה — שהמפתח יבין בלי לשאול

המטלה נקראת על ידי מי שלא כתב את הקוד, בטלפון. `title` — מה השתנה, במילים שלו (לא שמות קבצים / פונקציות).
`detail` — בחלקים, כל חלק בכותרת בשורה משלו ושורה ריקה ביניהם (המסך שומר את השורות):

```
❓ מה הבעיה            (באג; או "❓ מה ביקשת — ולמה" לבקשה)
משפט או שניים: מה קרה / מה היה חסר, עם דוגמה אמיתית (שם, סכום, מסך).

🛠️ מה עשיתי           (או "🛠️ מה אני מציע לעשות" — למטלה שעוד לא התחילה)
• מה רואים עכשיו במסך — איפה ומה לוחצים, לא איך זה ממומש
• …

💡 הצעות לשיפור — להחלטתך   (לא חובה)
• מה עוד אפשר, או מה בכוונה לא נעשה — ושאלה פתוחה אם יש
```

- **שפה פשוטה, משפטים מלאים.** בלי ראשי תיבות ובלי מונחים פנימיים (`pm_…`, "endpoint", "migration").
- **דוגמה עם מספרים** כשמדובר בכסף: "אבן דרך של 162,840 — 146,556 בגמר ו-16,284 במסירה".
- **`acceptance`** — משפט אחד שהמפתח יכול לבדוק בעיניים. **`steps`** — צעדים במסך, מהכניסה ועד מה שאמור לקרות.
- מטלה טכנית שלא משנה כלום אצלו — לכתוב את זה במפורש ("אצלך לא אמור להשתנות דבר").
