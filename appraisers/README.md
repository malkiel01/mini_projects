# שמאות מקרקעין

פלטפורמה לניהול תיקי שמאות מקרקעין ולהפקת דוחות: פתיחת תיק וזיהוי הנכס,
איסוף מסמכים, בקשות לגורמים חיצוניים, מידע מרשויות, ביקור בנכס, עסקאות
השוואה, ועריכת הדוח.

**מצב: בפיתוח — גרסה 0.1, התשתית** (אפיון `docs/spec/01-foundation.md`): כניסה דרך השער של הפלטפורמה, משרדים, צוות
והזמנות, ניהול המערכת, ומסך המפתח. תיקים — בפרוסות הבאות.

## הכללים שהקוד נשען עליהם

- **הזהות — רק מהשער.** `PLATFORM_USER` → חשבון משלה (מקושר ב-`platform_sub`) → session משלה. אין מסך כניסה, אין
  סיסמה, אין יציאה. מנותקת או שהמעטפת לא עונה → 503, נכשל סגור.
- **המשרד נקבע בשרת.** המשרד של הבקשה הוא המשרד הפעיל שב-session (`apr_office_id($ctx)`), ולעולם לא מזהה שהדפדפן
  שלח. בקשה יכולה לשאת `office` (pid) — הוא חייב להיות המשרד הפעיל. משרד זר ומשרד שלא קיים: אותה תשובה, 404.
- **`id` לא יוצא מהשרת.** בכתובות וב-API — רק `pid`.
- **כל פעולה משנה** רצה ב-`apr_tx()` אחד עם `apr_audit()` שלה. היומן רק מתמלא (טריגרים במסד חוסמים עדכון ומחיקה),
  ואין בו תוכן — מזהים ומצבים בלבד.
- **היומן הטכני בלי תוכן:** פעולה, מצב, משך, מי. גוף הבקשה לא נרשם; שגיאת משימת רקע נרשמת בלי הודעת החריגה.
- **פעולה חדשה ב-API** = שורה ב-`APR_ACCESS` (`lib/access.php`) + מימוש בנתב. בדיקה סטטית עוצרת אחד בלי השני.
  כתובת ציבורית חדשה — גם ב-`"public"` שב-`app.json`, באותו PR.
- **מיגרציה שנכנסה ל-`main` לא משתנה.** שינוי במסד = קובץ חדש עם המספר הבא.
- **פרוסה חדשה מוסיפה:** בדיקת תקינות (`apr_health_register`), שירות רקע (`apr_job_register`), ובדיקת בידוד —
  משתמש ממשרד ב׳ מנסה כל פעולה שלה על נתוני משרד א׳.

## פיתוח מקומי

```
php appraisers/tests/run.php          # כל הבדיקות: SQLite בזיכרון, ובדיקת HTTP מול שרת הפיתוח של PHP
APR_DATA_DIR=/tmp/apr php -S 127.0.0.1:8765 -d auto_prepend_file=$PWD/appraisers/tests/dev-prepend.php -t appraisers
```

`tests/dev-prepend.php` מדמה את השער: העוגייה `dev_as` = `owner` (ברירת המחדל), `none`, `detached`, או `sub:שם:מייל`.

## מי בונה

ארבעה צ'אטים — אפיון, קוד, בקרה ומטלות — לפי `team/PROTOCOL.md`. הבעלים מדבר
רק עם הבקרה (הכרעות) ועם המטלות (דברים לבדוק ולעשות).

## מה טרם הוכרע

השאלות לבעלים — ב-`docs/open-questions.md`; הקוד בנוי לפי ברירות המחדל שם. מה שסטה מהאפיון של הפרוסה, ולמה:

- **מיגרציות ב-`.sql`** ולא ב-`.php`, וגרסת הסכימה ב-`PRAGMA user_version` (ולא ב-`meta`): טרנזקציה אחת פשוטה
  לכל קובץ. האפיון מסמן את מבנה הקבצים כהמלצה.
- **"העתקת קישור" להזמנה קיימת מנפיקה אסימון חדש** (והקודם מפסיק לעבוד): במסד נשמר רק ה-hash, לפי האפיון.
- **מייל ייחודי:** חשבון שני במעטפת עם אותו מייל (לא מאומת) נפתח כאן בלי מייל.
- **`office` בבקשה שאינו המשרד הפעיל:** משרד אחר שלי → 409 "המשרד הפעיל הוחלף" (לשונית ישנה); זר או לא קיים → 404.
- **מצב `cancelled` למשימת רקע**, נוסף על הרשימה שבאפיון — בשביל "ביטול" במסך המפתח.
- **service worker** — לא נבנה בפרוסה הזו (יש `manifest.webmanifest`); שייך לפרוסה 14.
- **מיגרציה 002 מוחקת את הטבלאות של 001 ויוצרת את המבנה של האפיון.** 001 נפרסה לפני שהאפיון נכתב, ולכן לא משתנה.
  002 נבדקת משני המצבים: מסד ריק, ומסד שכבר ב-`user_version = 1`. לא היו בטבלאות נתונים אמיתיים.
