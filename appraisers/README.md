# שמאות מקרקעין

פלטפורמה לניהול תיקי שמאות מקרקעין ולהפקת דוחות: פתיחת תיק וזיהוי הנכס,
איסוף מסמכים, בקשות לגורמים חיצוניים, מידע מרשויות, ביקור בנכס, עסקאות
השוואה, ועריכת הדוח.

**מצב: בפיתוח — גרסה 0.1, התשתית.** כניסה דרך השער של הפלטפורמה, משרדים וצוות, ומסך המפתח. תיקים — בפרוסות הבאות.

## איך זה בנוי

- **הזהות — רק מהשער.** האפליקציה מחוברת (`"gate": true`): השער כותב את `PLATFORM_USER`, והאפליקציה פותחת לפיו
  חשבון משלה (`users`, מקושר ב-`platform_sub`), עם session משלה (העוגייה `apr_session`) ו-CSRF. אין מסך כניסה,
  אין סיסמה ואין יציאה. חשבון שהוזמן במייל מתקשר בכניסה הראשונה — רק כשהמייל אומת בפלטפורמה.
- **המשרד נקבע בשרת.** המשרד של כל בקשה נגזר מה-session ומהחברות של המשתמש (`apr_office_id($ctx)`), ולעולם לא
  ממזהה שהדפדפן שלח. מי שחבר בכמה משרדים בוחר במפורש; אין ניחוש.
- **תפקידים במשרד:** מנהל משרד, שמאי, שמאי שותף / מתמחה, עובד משרד. לפחות מנהל משרד פעיל אחד תמיד.
- **מנהל הפלטפורמה** (= `platform_admin` מהשער, הבעלים) פותח ומשעה משרדים וממנה מנהל ראשון — ואינו רואה תוכן של
  משרד, אלא אם צורף אליו כחבר (מתועד ביומן הפעולות).
- **המפתח** (אותו אדם) — 🛠️ בכותרת: 📋 מטלות (DevLoop), 📜 יומן בקשות ושגיאות (שרת ודפדפן, עם מזהה בקשה),
  🧾 יומן פעולות, 🩺 בדיקות תקינות. 🐞 בכותרת מדווח מכל מסך. שגיאה בשרת מחזירה למשתמש את מזהה הבקשה.
- **מיגרציה שנכנסה ל-`main` לא משתנה.** שינוי במסד = קובץ חדש עם המספר הבא.
- **חיבור חיצוני או שירות רקע חדש** נרשם בבדיקות התקינות: חיבור — `apr_connections()`; שירות — קורא ל-
  `apr_service_beat()` בכל ריצה (`lib/health.php`).

## פיתוח מקומי

```
php appraisers/tests/run.php          # כל הבדיקות — SQLite בזיכרון, בלי שרת
APR_DATA_DIR=/tmp/apr php -S 127.0.0.1:8765 -d auto_prepend_file=$PWD/appraisers/tests/dev-prepend.php -t appraisers
```

`tests/dev-prepend.php` מדמה את השער: העוגייה `dev_as` = `owner` (ברירת המחדל), `none`, או `sub:שם:מייל`.

## מי בונה

ארבעה צ'אטים — אפיון, קוד, בקרה ומטלות — לפי `team/PROTOCOL.md`. הבעלים מדבר
רק עם הבקרה (הכרעות) ועם המטלות (דברים לבדוק ולעשות).

## מה טרם הוכרע

בתשתית (ברירות המחדל שלפיהן נבנה; ההכרעה — בצ'אט האפיון ובבקרה):

- **מי פותח משרד** — כרגע רק מנהל הפלטפורמה. הרשמה עצמית של משרד — לא נבנתה.
- **הרשאה בפלטפורמה למוזמן** — מי שהוזמן למשרד צריך גם הרשאה לאפליקציה בכלים הדיגיטליים, והיא ניתנת שם ביד.
  אפשר שההזמנה תיתן אותה לבד (`provision.php`, `platform/docs/sso.md` §6) — דורש מפתח חתימה והצהרה ב-`app.json`.
- **איחוד לפי מייל לא מאומת** — לא מתאחד (חשבון חדש בלי משרד). משתמש ותיק בפלטפורמה שהמייל שלו לא אומת יצטרך
  צירוף מחדש אחרי הכניסה הראשונה.
- **מייל למפתח** על מטלה שממתינה לו — עוד אין לאפליקציה שליחת מייל.

הכול מלבד מה שהאפיון מסמן "נקבע". ההחלטות הפתוחות מפרק 21 של האפיון עוברות
ל-`docs/open-questions.md`, כל אחת עם המלצה וברירת מחדל.
