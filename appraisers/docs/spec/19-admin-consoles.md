# 19 — מסכי ניהול: משרד ומערכת, ומדדים

**תלויה ב-08 וב-11** (ומרכזת מסכים שנבנו בפרוסות קודמות). האפיון: 16.2, 18.3,
25.6; דרישות 02, 03, 25; ש-29.

עד כאן כל פרוסה הוסיפה מסך ניהול משלה. הפרוסה הזו **מאחדת** אותם לשני מרכזים
מסודרים, ומוסיפה מדדים והתרעות.

## 1. מה בונים

1. **ניהול המשרד** — מרכז אחד למנהל משרד.
2. **ניהול המערכת** — מרכז אחד למנהל המערכת.
3. מדדים: למשרד — מפורטים; למערכת — **מצרפיים בלבד**.
4. התרעות תפעוליות: כשלי שליחה, חיבורים שנפלו, שימוש חריג בבינה.
5. התראות למשתמש (פעמון), עם אכיפת הרשאות.

## 2. מה לא

- גישה של מנהל המערכת לתוכן — נשארת רק דרך גישת תמיכה (פרוסה 05).
- חיוב, חבילות ותמחור — לא (2.2).

## 3. מודל הנתונים

```
notifications                            התראה למשתמש
  id, pid, user_id, office_id NULL
  kind              TEXT                 'doc.received', 'msg.failed', 'conflict.open' …
  case_id NULL, link_type, link_pid NULL
  params            JSON                 מזהים ומספרים בלבד — הנוסח נבנה בהצגה
  created_at, read_at

notification_prefs
  user_id, kind, in_app INT, email INT

metrics_daily                            צבירה יומית — מחושבת בשירות רקע
  day, office_id NULL (NULL = כל המערכת)
  key               TEXT                 'cases.open', 'ai.cost_est', 'files.bytes' …
  value             NUMERIC
  UNIQUE(day, office_id, key)

ops_alerts                               התרעה תפעולית
  id, pid
  scope             system | office
  office_id NULL
  kind              channel.failed | ai.spike | cron.stale | disk.low | jobs.failed | source.incident
  severity          info | warn | error
  params            JSON
  status            open | acked | resolved
  first_at, last_at, count
  acked_by, acked_at
```

**`notifications.params` אינו מכיל תוכן** — רק מזהים. הנוסח ("התקבל מסמך בתיק
2026-0014") נבנה **בזמן ההצגה, אחרי `can()`**: אם ההרשאה בוטלה בינתיים, ההתראה
מציגה "הפריט אינו זמין עוד" — בלי מספר תיק ובלי שם.

## 6. מדדים (ש-29)

מחושבים בשירות רקע יומי (`metrics.daily`) אל `metrics_daily`; המסכים קוראים משם.

### 6.1 למנהל משרד

| מדד | פירוט |
| --- | --- |
| תיקים פתוחים | לפי מצב; לפי אחראי |
| תיקים שנפתחו / נסגרו | לפי שבוע וחודש |
| זמן טיפול | חציון ימים מפתיחה לאישור הדוח — **רק כשיש 5 תיקים ומעלה** בתקופה |
| דרישות פתוחות | סך הכול; דרישות חובה; ממתינות לבדיקה |
| עומס | תיקים פתוחים ומשימות פתוחות לכל חבר |
| ביקורים | מתוכננים, הושלמו |
| בינה | עלות משוערת לפי משתמש ולפי חודש; חסימות |
| הודעות | נשלחו, נכשלו, לא ידוע |

"לפי אחראי" ו"עומס" מציגים **ספירות**. מנהל שאינו משתתף בתיק אינו מקבל מהמדדים
יותר ממה ששורת הניהול נותנת לו (ש-35).

### 6.2 למנהל המערכת — מצרפי בלבד

| מדד | רמת הפירוט |
| --- | --- |
| משרדים, משתמשים פעילים | סך הכול; חדשים לפי שבוע |
| תיקים | **ספירה לכל משרד** — בלי מצב, בלי אחראי |
| נפח אחסון | לכל משרד; סך הכול; מקום פנוי |
| בינה | עלות משוערת ומדווחת לפי משרד, משתמש, מודל ויום |
| הודעות | לפי ערוץ וחיבור: נשלחו, נכשלו |
| שירותי רקע | משימות לפי סוג ומצב; זמן ריצה |
| שגיאות | מספר שגיאות שרת ודפדפן ליום (מהיומן הטכני) |

**סף פרטיות** 🟡: מדד לפי משתמש מוצג למנהל המערכת רק לבינה (שם יש לו אחריות על
המכסה). שאר המדדים — לפי משרד, לכל היותר.

## 7. התרעות תפעוליות (האפיון 18.3)

שירות רקע (`ops.watch`, כל 15 דקות) בודק ויוצר או מעדכן `ops_alerts`:

| התרעה | תנאי | למי |
| --- | --- | --- |
| `channel.failed` | חיבור עבר ל-`failed`; או מעל 20% כשלים בשעה | בעל החיבור (מנהל משרד / מנהל המערכת) |
| `ai.spike` | שימוש של משתמש ביום האחרון פי 5 מהממוצע השבועי שלו 🟡; או 90% ממכסה | מנהל המשרד; ובמסלול המנוהל — גם מנהל המערכת |
| `ai.key_invalid` | חיבור בינה עבר ל-`invalid` | בעל החיבור |
| `cron.stale` | המתזמן לא רץ 30 דקות | מפתח |
| `jobs.failed` | משימה ב-`failed` / `needs_action` | מפתח; ואם היא של משרד — מנהל המשרד, **בלי פרטים טכניים** |
| `disk.low` | מתחת ל-500MB | מפתח, מנהל המערכת |
| `source.incident` | מנהל המערכת רשם תקלה במקור | כל מי שיש לו בדיקה פתוחה מולו |

- אותה התרעה שחוזרת **מעדכנת** `last_at` ו-`count` — לא נוצרת שורה חדשה.
- התרעה נסגרת לבד כשהתנאי חלף, או ב"טיפלתי".
- התרעות `error` — גם במייל, לפי העדפות המשתמש.

## 8. התראות למשתמש

פעמון בכותרת, עם מונה. סוגים — כל פרוסה מוסיפה את שלה:

| אירוע | למי |
| --- | --- |
| מסמך התקבל (06, 07) | בעלי `review_docs` בתיק |
| הודעה נכשלה / לא ידוע (07, 08) | השולח |
| נמען ענה "אין ברשותי" (07) | השולח, האחראי |
| משימה הוקצתה לי; משימה באיחור (04) | המוקצה |
| הוזמנתי לתיק / למשרד (01, 05) | המוזמן |
| סתירה נפתחה (10) | האחראי |
| טיוטת דוח נוצרה; הצעת עדכון (17) | האחראי |
| דוח הועבר לבדיקה (17) | בעלי `approve_report` |
| קישור מסירה נפתח (18) | המוסר |
| גישה / שיתוף עומדים לפוג (05) | המשתף |
| בקשת הגדלת מכסה (11) | מי שרשאי להגדיל |

- **התראה נוצרת רק למי שיש לו הרשאה לפריט ברגע היצירה**, ונבדקת שוב בהצגה (סעיף 3).
- מייל על התראה — **בלי תוכן**: "יש לך עדכון במערכת שמאות מקרקעין", וקישור. בלי
  מספר תיק, בלי שם לקוח, בלי שם קובץ (3.3: "אין לחשוף … דרך … התראות").
- העדפות: לכל סוג — באפליקציה / במייל / כבוי. ברירת המחדל: באפליקציה דלוק, במייל
  רק "הוקצתה לי משימה" ו"הוזמנתי".
- התראות Push — לא בפרוסה הזו 🟡.

## 10. מקרי קצה

1. **משרד עם תיק אחד.** "זמן טיפול" אינו מוצג (פחות מ-5).
2. **מדד ליום שהשירות לא רץ בו.** מוצג חסר ("אין נתון") — לא 0.
3. **התראה על תיק שההרשאה אליו בוטלה.** "הפריט אינו זמין עוד".
4. **התראה על פריט שנמחק.** כנ"ל.
5. **משתמש בשני משרדים.** הפעמון מציג התראות מכל המשרדים, מסומנות בשם המשרד;
   לחיצה מחליפה משרד פעיל **אחרי אישור** ("לעבור למשרד X?").
6. **מנהל המערכת שהוא גם חבר במשרד.** במסכי המערכת — מצרפי; במשרד שלו — כחבר רגיל.
   אין מסך שמערבב.
7. **1,000 התראות שלא נקראו.** המונה מציג "99+"; רשימה בעמודים; "סימון הכול כנקרא".
8. **התרעת `ai.spike` למשתמש חדש** (אין ממוצע). אינה נבדקת בשבוע הראשון.
9. **שינוי הגדרת משרד באמצע פעולה** (למשל תוקף קישור). חל על פעולות חדשות בלבד.
10. **השעיית מנהל המערכת האחרון.** נחסם (פרוסה 01).

## 11. קריטריוני קבלה

- **19-A1** 🤖 כל פעולת `#/system/*` ← 404 למי שאינו מנהל המערכת; כל פעולת ניהול
  משרד ← נדחית למי שאינו מנהל במשרד הפעיל.
- **19-A2** 🤖 **תשובות המדדים של המערכת אינן מכילות**: `pid` של תיק, מספר תיק,
  כותרת, כתובת, שם גורם, שם קובץ. (בדיקה על כל מפתח וערך בתשובה.) *(29)*
- **19-A3** 🤖 מדדי משרד א׳ אינם מוחזרים למנהל משרד ב׳.
- **19-A4** 🤖 "זמן טיפול" עם פחות מ-5 תיקים ← `null`.
- **19-A5** 🤖 יום בלי צבירה ← `null`, לא 0.
- **19-B1** 🤖 התראה אינה נוצרת למשתמש שאין לו הרשאה לפריט.
- **19-B2** 🤖 התראה קיימת, וההרשאה בוטלה ← התשובה אינה כוללת מספר תיק או שם; רק
  "אינו זמין עוד".
- **19-B3** 🤖 גוף מייל ההתראה אינו מכיל מספר תיק, שם קובץ או שם גורם.
- **19-B4** 🤖 `notifications.params` מכיל מזהים ומספרים בלבד (בדיקת סכימה).
- **19-C1** 🤖 חיבור שעבר ל-`failed` ← `ops_alerts` אחת; כשל חוזר מעדכן `count`
  ואינו יוצר שורה שנייה.
- **19-C2** 🤖 התנאי חלף ← ההתרעה `resolved`.
- **19-C3** 🤖 התרעת `jobs.failed` למנהל משרד אינה כוללת `last_error`.
- **19-D1** 🤖 שינוי הגדרת משרד נרשם ביומן עם הערך הקודם והחדש.
- **19-D2** 🤖 חבר שאינו מנהל אינו יכול לשנות הגדרת משרד.
- **19-E1** 👁 ניהול המשרד וניהול המערכת — כל הלשוניות נפתחות בטלפון בלי גלילה אופקית.
- **19-E2** 👁 מסך המדדים של המשרד מציג תיקים לפי מצב ולפי אחראי.
- **19-E3** 👁 מסך המדדים של המערכת — אין בו שום פרט שמזהה תיק או לקוח.
- **19-E4** 👁 הפעמון: התראה על מסמך שהתקבל מובילה לקובץ.
