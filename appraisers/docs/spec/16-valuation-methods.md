# 16 — חלופות שווי וגישות שומה נוספות

**תלויה ב-15.** האפיון: 4.3, 6.2, 24.2–24.4, 27.3, 27.4; דרישה 24.

המערכת מיועדת לכל תחום המקרקעין, ולא רק לממוצע עסקאות לדירות. הפרוסה בונה
**מסגרת** שבה השמאי מתעד כל גישה — קלטים, מקורות, נוסחה, הנחות ונימוק — בלי
שהמערכת מתיימרת לדעת את הנוסחה הנכונה.

## 1. מה בונים

1. **חלופות שווי** בתיק: לכל אחת מועד קובע, מצב נכס מונח, והנחות.
2. **גישות** בתוך חלופה: השוואה (פרוסה 15), הכנסה, עלות, אחרת.
3. **גיליון חישוב גלוי** — שורות עם מקור ויחידה, ופעולות חשבון פשוטות.
4. רכישה ושיפוץ: הנתונים שאסור לערבב (27.4).
5. מסקנת שווי לכל חלופה — של השמאי.

## 2. מה לא 🟢

- **אין מחשבון מוכן לגישת ההכנסה או לגישת העלות.** האפיון (27.3): "הגדרות מפורטות
  של תזרימים, שיעורי היוון, עלויות והפחתות אינן מאושרות… לפני יצירת מחשבונים ייבנו
  דוגמאות מבוקרות עם שמאי." לכן נבנה גיליון כללי, והשמאי כותב את השורות.
- אין הצעת שיעור היוון, אין ערכי ברירת מחדל מקצועיים, אין "שווי מוצע".

## 4. חלופות שווי (האפיון 6.2, ש-11, ש-20)

- לתיק יכולות להיות כמה חלופות. **לכל אחת מועד קובע והנחות משלה, נשמרים בנפרד.**
- בפתיחת תיק נוצרת חלופה אחת, "מצב קיים", עם המועד הקובע של התיק.
- פרופיל עם הדגל "שיפוץ מתוכנן" יוצר שתיים: **"מצב קיים"** ו-**"בהנחת השלמת
  השיפוץ"** (`after_works`).
- חלופה `after_works` **חייבת** הנחות שמפרטות: לאיזו תוכנית עבודות היא מתייחסת
  (מסמך), ומה מצב האישור שלה. בלי זה — היא מסומנת "חסרות הנחות", ומופיעה בבקרת
  הדוח.
- **השוואת עסקאות "לפני" ו"אחרי" שיפוץ** — רק בקבוצות נפרדות, ורק כשלעסקאות יש
  `condition` ידוע. עסקה שמצבה לא ידוע אינה יכולה להיכנס לקבוצה של "אחרי שיפוץ"
  בלי נימוק מפורש של השמאי (27.4).

## 5. גיליון חישוב ⚙️

לגישת הכנסה, עלות או כל שיטה אחרת. **השמאי בונה אותו; המערכת רק מחשבת.**

- **שורת קלט** (`input`): תיאור, ערך, יחידה, יחידת זמן, **מקור** (נתון מהתיק /
  מסמך / טקסט), ו-**`origin`**: סופק (בחוזה, במסמך) · הוערך · הנחת השמאי. כך נשמרת
  ההפרדה שהאפיון דורש (24.3) בין נתון שסופק לבין הערכה.
- **שורת חישוב** (`calc`): נוסחה על שורות קודמות בלבד.
- **שורת הערה** (`note`).

**הנוסחה** — מבנה, לא טקסט חופשי:

```json
{ "op": "mul", "args": ["r1", 12] }
{ "op": "sub", "args": ["r3", "r4"] }
{ "op": "div", "args": ["r5", { "pct": "r6" }] }
```

פעולות: `add` · `sub` · `mul` · `div` · `sum` (טווח שורות) · `pct` (המרת אחוז
לשבר). **אין פונקציות אחרות, אין `eval`, אין הפניה קדימה** (שורה מפנה רק לשורות
שמעליה — ולכן אין מעגלים).

- אותו חשבון מדויק של פרוסה 15: בלי נקודה צפה; עיגול פעם אחת, בתוצאה.
- **כל שורת חישוב מציגה את הנוסחה במילים ובמספרים**: "הכנסה שנתית = דמי שכירות
  חודשיים × 12 = 8,500 × 12 = 102,000".
- חלוקה באפס, או שורה שמפנה לקלט ריק ← **אין תוצאה**; מוצג "לא ניתן לחשב: <שורה>
  חסרה". קלט ריק **אינו** אפס.
- **יחידות זמן:** שורה עם `month` ושורה עם `year` באותה פעולת חיבור או חיסור ←
  אזהרה: "יחידות זמן שונות". אין המרה אוטומטית.
- שורת קלט שמקושרת ל-`fact` ← רושמת `fact_uses`; הנתון השתנה ← הגיליון `stale`.

**תבניות גיליון** — אין בזריעה. השמאי יכול לשמור גיליון כתבנית אישית או משרדית,
ולהשתמש בה בתיק אחר (בלי הערכים — רק המבנה והתיאורים). תבניות מומלצות יתווספו
כשיאושרו מקצועית (ש-04).

## 6. גישות ומסקנה (האפיון 27.3)

- בחלופה אפשר גישה אחת או כמה. לכל גישה: סוג, **נימוק** (למה היא מתאימה), ותוצאה:
  - `comparison` ← המסקנה של קבוצת ההשוואה (פרוסה 15), `computed`;
  - `income` / `cost` / `other` ← השורה האחרונה של הגיליון (`computed`), או ערך
    שהשמאי מקליד (`entered`), עם נימוק.
- כמה גישות ← השמאי קובע משקל לכל אחת, והמערכת מציגה את הממוצע המשוקלל **כחישוב
  עזר**.
- **מסקנת החלופה** (`conclusion_value`) — מקליד השמאי, עם נימוק. אינה מתמלאת לבד.
- **כשאין נתונים מספיקים** — השמאי מתעד את המגבלה (`assumptions` מסוג `limitation`),
  והמסקנה נשארת ריקה. **המערכת אינה מייצרת שווי** 🟢.

## 7. רכישה ושיפוץ — נתונים שאין לערבב (האפיון 4.3, 27.4)

שבעה דברים, שבעה מקומות:

| מה | איפה נשמר |
| --- | --- |
| מחיר חוזי | `renovation_items.contract_price` (ו-`fact` מקושר) |
| תאריך העסקה | `item_date` של אותה שורה |
| שווי מוערך למועד הקובע | `alternatives.conclusion_value` |
| תקציב שיפוץ מוצהר | `declared_budget` |
| הצעת מחיר | `quote` — כמה, ולכל אחת גרסאות (`supersedes_id`) |
| עלות שאומתה | `verified_cost` |
| מצב נוכחי / הנחת מצב לאחר עבודות | `alternatives.state_kind` + `assumptions` |

כללים:

- **תקציב השיפוץ אינו מתווסף לשווי** — בשום חישוב אוטומטי. אין שורה, כפתור או
  תבנית שמחברים "שווי קיים + עלות = שווי אחרי". שמאי שרוצה לבטא תוספת ערך — כותב
  שורה בגיליון, עם נימוק, והיא שלו.
- כל ערך מקושר למסמך או למשתמש שהזין אותו.
- **המערכת אינה מעריכה השלמת עבודות או היתכנות תכנונית מתוך הצעת מחיר** (24.2).
- **עבודות שהשתנו אחרי הביקור** (הצעת מחיר חדשה שמחליפה קודמת, או שינוי בדגל
  השיפוץ) ← נוצרת **משימת סקירה מחדש** של ההנחות והחישובים בחלופת `after_works`,
  והיא מסומנת `stale`.

## 8. מסכים

| נתיב | מסך |
| --- | --- |
| כרטיס תיק ← **עסקאות וחישובים** | בראש: החלופות. בכל חלופה: מועד קובע, מצב מונח, הנחות, גישות, מסקנה |
| ← חלופה ← גישה | קבוצת ההשוואה (פרוסה 15), או הגיליון |
| ← גיליון | טבלה: תיאור · ערך · יחידה · מקור · סוג (סופק / הוערך / הנחה) · נוסחה. הוספת שורה, גרירה |
| ← **רכישה ושיפוץ** (מוצג כשהדגל דלוק) | הטבלה מסעיף 7; הצעות מחיר וגרסאותיהן |
| סקירה | מסקנות החלופות זו לצד זו — **כל אחת עם שמה ועם המועד הקובע שלה** |

שתי מסקנות לעולם אינן מוצגות בלי התווית של החלופה: "מצב קיים: … · בהנחת השלמת
השיפוץ: …".

## 10. מקרי קצה

1. **מחיקת חלופה שדוח נשען עליה.** מחיקה רכה; הדוח המאושר אינו משתנה; טיוטה
   מסומנת `stale`.
2. **חלופה בלי מועד קובע.** מותר; מוצג "מועד קובע: לא ידוע", ומופיע בבקרת הדוח.
3. **שתי חלופות עם אותו שם.** נחסם.
4. **אין חלופה ראשית.** תמיד יש בדיוק אחת; מחיקתה מעבירה את הסימון לראשונה.
5. **נוסחה שמפנה לשורה שנמחקה.** השורה מסומנת "נוסחה שבורה"; אין תוצאה; הגיליון
   אינו נותן תוצאה סופית.
6. **גרירת שורת חישוב מעל הקלט שלה.** נחסם ("שורה אינה יכולה להפנות לשורה שמתחתיה").
7. **הצעת מחיר בלי סכום** (רק מסמך). נשמרת; `amount = NULL`; "סכום: לא ידוע".
8. **שתי הצעות מחיר מאותו קבלן.** שתי שורות, או גרסה חדשה של אותה הצעה — לבחירת
   המשתמש. הגרסה הקודמת נשארת.
9. **שורת אחוז עם 15 במקום 0.15.** היחידה `%` קובעת; `pct` ממיר. ערך מעל 100 ביחידת
   `%` ← אזהרה, לא חסימה.
10. **תבנית גיליון נשמרת עם ערכים.** נחסם בקוד — רק מבנה ותיאורים.
11. **משקולות לגישות, ולאחת אין תוצאה.** הממוצע המשוקלל אינו מוצג; "לגישה <שם> אין
    תוצאה".

## 11. קריטריוני קבלה

- **16-A1** 🤖 לכל חלופה `key_date` ו-`assumptions` משלה; שינוי באחת אינו משנה אחרת.
- **16-A2** 🤖 תיק עם דגל שיפוץ נפתח עם שתי חלופות: `existing` ו-`after_works`.
- **16-A3** 🤖 חלופת `after_works` בלי הנחה שמקושרת למסמך עבודות ← מוחזרת עם הסימון
  "חסרות הנחות".
- **16-A4** 🤖 `conclusion_value` של חלופה ושל גישה אינו מתמלא אוטומטית; שמירה בלי
  נימוק ← נדחית.
- **16-B1** 🤖 גיליון: `r1 = 8500` (₪ לחודש), `r2 = r1 × 12`, `r3 = 12000`,
  `r4 = r2 − r3`, `r5 = 6` (%), `r6 = r4 ÷ pct(r5)` ← `r2 = 102,000`, `r4 = 90,000`,
  `r6 = 1,500,000` — בדיוק.
- **16-B2** 🤖 קלט ריק ← השורות התלויות בו מחזירות `null` עם סיבה — לא 0.
- **16-B3** 🤖 חלוקה באפס ← `null` עם סיבה.
- **16-B4** 🤖 נוסחה שמפנה לשורה שמתחתיה, לשורה שאינה קיימת, או עם `op` לא מוכר ←
  נדחית בשמירה.
- **16-B5** 🤖 אין `eval` ואין `float` במנוע הגיליון (בדיקה סטטית).
- **16-B6** 🤖 שמירת גיליון כתבנית אינה שומרת אף `value`.
- **16-C1** 🤖 אין בקוד פעולה, שורה מובנית או תבנית שמחברת `declared_budget`,
  `quote` או `verified_cost` למסקנת שווי. (בדיקה: יצירת כל פריטי השיפוץ אינה משנה
  שום `conclusion_value` ושום תוצאת גישה.)
- **16-C2** 🤖 הצעת מחיר חדשה שמחליפה קודמת ← נוצרת משימת סקירה, וחלופת
  `after_works` מסומנת `stale`; הקודמת עדיין קיימת.
- **16-C3** 🤖 ארבעת סוגי `renovation_items` נשמרים ומוחזרים בנפרד; אין שדה מאוחד.
- **16-C4** 🤖 `fact` שמקושר לשורת קלט השתנה ← הגיליון `stale`.
- **16-C5** 🤖 **בידוד:** חלופות, גיליונות ופריטי שיפוץ של תיק ממשרד אחר ← 404.
- **16-D1** 👁 התרחיש שבאפיון 4.3: שתי חלופות, כל אחת עם מסקנה ונימוק, מוצגות זו
  לצד זו עם התוויות.
- **16-D2** 👁 בגיליון, כל שורת חישוב מציגה את הנוסחה במילים ובמספרים.
- **16-D3** 👁 שורת קלט מציגה אם הערך סופק, הוערך, או הנחת השמאי.
