# 13 — ביקור: טופס מהפרופיל, תמונות, וכמה ביקורים

**תלויה ב-04 וב-03.** האפיון: 12.1, 26.1, 26.2; דרישה 21 (החלק המקוון).

הפרוסה בונה את הביקור **כשיש רשת** — בטלפון ובמחשב. עבודה בלי קליטה וסנכרון —
פרוסה 14, שנשענת על המודל שכאן. לכן **כל שדה כאן כבר נושא מספר גרסה**.

## 1. מה בונים

1. מקטע **"ביקור"** בפרופיל: בונה טפסים — קבוצות, שדות, חובה, תנאי הצגה.
2. ביקורים בתיק: כמה ביקורים, לכל אחד מבקר, מועד ומצב.
3. מילוי הטופס עם שמירה הדרגתית.
4. מדידות ושטחים עם יחידה, דרך קבלה, ואומדן.
5. תמונות: צילום, תיאור, מיקום בנכס, "לדוח", והרשאת שימוש.
6. סימון השלמה, דחייה, או "לא הייתה גישה".
7. העברת תשובות הביקור לנתוני התיק — כהצעות.

## 4. מקטע "ביקור" בפרופיל

```json
"visit": {
  "groups": [
    { "key": "ident", "title": "זיהוי וביקור", "sort": 1, "repeat": false, "when": null },
    { "key": "rooms", "title": "חדרים", "sort": 4, "repeat": true, "when": null }
  ],
  "fields": [
    { "key": "access", "group": "ident", "label": "דרך הגישה לנכס",
      "type": "text", "required": false, "when": null, "sort": 1 },
    { "key": "area_measured", "group": "areas", "label": "שטח שנמדד",
      "type": "area", "required": false, "maps_to": "area", "sort": 2 },
    { "key": "front_photo", "group": "photos", "label": "חזית הבניין",
      "type": "photo", "required": true, "min": 1, "sort": 1 }
  ],
  "completion": { "block_on_required": true }
}
```

**סוגי שדה:** `text` · `longtext` · `number` · `area` (ערך + יחידה + סוג שטח) ·
`length` · `choice` · `multichoice` · `yesno` · `date` · `photo` (תמונה אחת או יותר).

- **`when`** — אותו מבנה תנאים של פרוסה 03, עם שני מקורות נוספים: `answer.<field_key>`
  (תשובה אחרת בטופס) ו-`property_type`. כך "מספר מעלית" מופיע רק אם "יש מעלית" = כן.
- **`repeat`** — קבוצה חוזרת (חדר, יחידה, קומה): המבקר מוסיף שורות.
- **`maps_to`** — מאפיין בקטלוג (פרוסה 10) שהתשובה תוצע אליו.
- **`required`** — חובה **לסימון השלמה**, לא לשמירה.

**טופס ברירת המחדל** (נזרע בפרופילים המומלצים, מסומן "דוגמה") — שש הקבוצות
שבאפיון 26.2:

| קבוצה | שדות לדוגמה | כלל |
| --- | --- | --- |
| זיהוי וביקור | תאריך, שעה, מבקר, נוכחים, כתובת, זיהוי הגישה | לכל שדה: נצפה / נמסר / לא אומת |
| סביבה ובניין | שימושי הסביבה, דרכי גישה, סוג הבניין ומצבו | תיאור עובדתי; הערכה מקצועית — בשדה נפרד |
| פנים הנכס | חלוקה, קומה, מצב תחזוקה, שימוש בפועל; חדרים (חוזר) | לפי סוג הנכס |
| שטחים והצמדות | מדידה או שטח שנמסר; חניה, מחסן, מרפסת | יחידה, סוג שטח, מקור, נמדד / הוערך |
| ממצאים ומגבלות | חלקים שלא נבדקו; אי התאמה אפשרית למסמכים; הערות | **בלי** שדה "עבירה" / "חוקי" |
| תצלומים | חזית, כניסה, חדרים, נוף, ליקויים | תיאור, מיקום, הרשאת שימוש |

בדיקות הפרסום (פרוסה 03, סעיף 8) מתרחבות: שני שדות עם אותו `key` ❌; `when` שמפנה
לשדה שלא קיים או שמופיע אחריו ❌; `maps_to` למאפיין לא קיים ❌; שדה `area` בלי
`maps_to` ⚠️.

## 5. ביקור בתיק (האפיון 26.1)

1. **תיאום:** מבקר (משתתף בתיק עם `visit`), מועד, איש קשר לגישה, והערת גישה.
   נוצרת משימה למבקר.
2. **פתיחה:** "התחלת ביקור" ← `in_progress`; **הטופס מצולם** ל-`form_snapshot`.
   שינוי מאוחר בפרופיל אינו משנה ביקור שנפתח.
3. **מילוי** — סעיף 6.
4. **סיום** — אחד משלושה:

| תוצאה | מתי | מה נדרש |
| --- | --- | --- |
| `completed` הושלם | הביקור בוצע | כל שדות החובה הגלויים מלאים (אם `block_on_required`); אחרת — רשימת החסרים, ואישור מנומק |
| `postponed` נדחה | לא התקיים | סיבה; אפשר לקבוע מועד חדש — **באותה רשומה** |
| `no_access` לא הייתה גישה | הגיעו ולא נכנסו | תיאור; מה שכן נצפה (חזית, סביבה) נשמר |

**`postponed` ו-`no_access` לעולם אינם מוצגים כביקור שהושלם** 🟢 — לא בתיק, לא
בדוח, ולא כטריגר לטיוטה (פרוסה 17).

5. **ביקור נוסף** = רשומה חדשה (`seq` הבא), עם מבקר, מועד ומצב משלה. הביקור הקודם
   **אינו נדרס** ונשאר לצפייה. הטופס החדש מתחיל ריק; "העתקת תשובות מביקור <N>" —
   פעולה מפורשת, ומה שהועתק מסומן "הועתק מביקור N — לאמת".
6. **פתיחה מחדש** של ביקור שהושלם — המבקר או השמאי האחראי, עם נימוק. אם הביקור
   כבר שימש בדוח — הפריטים התלויים מסומנים (פרוסה 10, סעיף 7).

## 6. מילוי הטופס (האפיון 12.1, 16.1, 25.5)

### 6.1 המסך — לתנאי שטח

- שדה אחד בשורה; יעדי מגע גדולים; מקלדת מספרית לשדות מספר.
- **התקדמות לפי קבוצות**: "זיהוי 4/5 · שטחים 0/3 · תצלומים 2 (חסרה חזית)".
- **שמירה הדרגתית**: כל שדה נשמר כשעוזבים אותו. ליד כל שדה חיווי: נשמר ✓ · שומר…
  · **לא נשמר — נסו שוב**. אין כפתור "שמירה" כללי, ואין אובדן בסגירת הדף.
- כפתור מצלמה קבוע בתחתית.
- הנתונים שהוכנו מהתיק (מזהים, נתוני נכס, מסמכים מותרים) — בלשונית צד, לקריאה.

### 6.2 כל תשובה נושאת

- הערך; ולמדידה — **יחידה**; ולשטח — **סוג שטח** (כולל "לא ידוע").
- **`obtained`** — איך התקבל: נצפה · נמסר (וממי) · נמדד · הוערך · לא אומת.
  ברירת המחדל לפי סוג השדה, והמבקר משנה.
- הערה חופשית.

**שדה ריק נשמר ריק** — לא 0, לא "לא". "אין" הוא תשובה שהמבקר בוחר.

### 6.3 מיקום גיאוגרפי (ש-21)

כבוי. הגדרת משרד "לצרף מיקום לתמונות" — כשדלוקה, **המבקר מתבקש להסכים במכשיר שלו**
בכל ביקור, ורואה חיווי כשהמיקום נרשם. מיקום אינו נלקח מנתוני התמונה (EXIF):
**נתוני EXIF מוסרים מכל תמונה בקליטה** (מלבד כיוון התמונה), כדי שקובץ שנמסר ללקוח
לא יחשוף מיקום או מכשיר.

## 7. תמונות

- צילום ישיר, או בחירה מהגלריה; כמה בבת אחת.
- כל תמונה עוברת את צינור הקליטה (פרוסה 06) — נשמרת ב-`files`, עם `channel = visit`.
- בצד המכשיר: הקטנה ל-2,560 פיקסלים בצלע הארוכה 🟡 לפני ההעלאה; המקור אינו נשמר.
- לכל תמונה: **תיאור**, **מיקום בתוך הנכס** (מרשימה + חופשי), סדר, ו**"לדוח"**.

**הרשאת שימוש** (`usage`) — האפיון 15.2, 26.2:

| ערך | מי רואה | לדוח? |
| --- | --- | --- |
| `private` (ברירת המחדל) | המבקר והשמאי האחראי | לא |
| `case` | כל מי שיש לו `view` בתיק | לא |
| `report` | כנ"ל | **כן** — המבקר מאשר: "צולמה בידי / יש לי רשות להשתמש בה בדוח" |

- **תמונה אינה משותפת לגורם חיצוני מעצם קיומה.** נמען בפורטל לעולם אינו רואה
  תמונות ביקור.
- "לדוח" בלי `usage = report` ← נחסם, עם הסבר.
- **צילום אינו מאמת מידע תכנוני** (12.1) — אין שדה שמסיק מתמונה משהו על היתר.

## 8. מהביקור לנתוני התיק

כשביקור מסומן `completed`, לכל תשובה עם `maps_to`:

- נוצר `fact` (פרוסה 10) עם `source_kind = visit`, `source_ref_pid` = הביקור,
  `source_date` = תאריך הביקור, `estimated` לפי `obtained`.
- המצב: **`manual`** — לא `verified`. השמאי מאמת כרגיל.
- `obtained = reported` ← `note`: "נמסר בביקור מ-<מי>".
- סותר נתון קיים ← נפתחת סתירה (פרוסה 10). למשל: שטח שנמדד מול שטח בהסכם.
- **אי התאמה אפשרית** — השדה "אי התאמה אפשרית למסמכים" יוצר **משימת בדיקה** עם
  הטקסט והתמונות, מקושרת ל"מקורות ותכנון". **לא נקבעת עבירה** 🟢.
- פתיחה מחדש ועריכה ← ה-`facts` מהביקור מתעדכנים; מה שכבר אומת חוזר ל-`manual`
  ומסומן `stale` לצרכניו.

## 11. מקרי קצה

1. **שני אנשים ממלאים את אותו ביקור** (שמאי ומתמחה). כל שמירה שולחת את ה-`rev`
   שקראה; אם השדה השתנה בינתיים ← **שתי הגרסאות מוצגות להכרעה**. אין דריסה.
   (המסך המלא של ההכרעה — פרוסה 14; כאן: חלון פשוט "הערך שלך / הערך של <שם>".)
2. **הטופס השתנה בפרופיל באמצע ביקור.** הביקור ממשיך עם `form_snapshot`.
3. **שדה חובה מוסתר בתנאי.** אינו נדרש להשלמה.
4. **תנאי השתנה אחרי שהשדה מולא** ("יש מעלית" חזר ל"לא"). התשובה נשמרת, מוסתרת,
   ואינה עוברת לנתונים.
5. **הרשת נפלה באמצע שמירה** (בפרוסה הזו, בלי מצב לא-מקוון). השדה מסומן "לא נשמר";
   ניסיון חוזר אוטומטי כשהרשת חוזרת, כל עוד הדף פתוח. **אזהרה בסגירת הדף** אם יש
   שדות שלא נשמרו.
6. **תמונה של 40MB.** מוקטנת במכשיר לפני ההעלאה; אם עדיין מעל המגבלה — נדחית עם הסבר.
7. **המבקר הוסר מהתיק באמצע.** השמירה הבאה נדחית; מה שנשמר — נשאר.
8. **ביקור שהושלם בלי אף תמונה.** מותר, אלא אם שדה תמונה סומן חובה.
9. **שני ביקורים פתוחים באותו תיק.** מותר (שני מבקרים, שני מועדים).
10. **מחיקת תמונה שכבר בדוח.** מחיקה רכה; הפרק מסומן `stale`.
11. **`no_access` ואז ביקור מוצלח.** שתי רשומות; רק השנייה `completed`.
12. **קבוצה חוזרת עם 0 שורות**, כשיש בה שדה חובה. אין שורות ← אין חובה; אם הקבוצה
    עצמה נדרשת — `min_rows` בהגדרת הקבוצה.

## 12. קריטריוני קבלה

- **13-A1** 🤖 פתיחת ביקור מצלמת את הטופס; פרסום גרסת פרופיל חדשה אינו משנה את
  `form_snapshot`.
- **13-A2** 🤖 שמירת שדה מעלה את ה-`rev` שלו; שמירה עם `rev` ישן ← 409, עם שני הערכים.
- **13-A3** 🤖 שדה שלא מולא אינו יוצר שורה, ואינו מוחזר כ-0 או כ-`false`.
- **13-A4** 🤖 תשובת שטח בלי יחידה או בלי סוג שטח ← נדחית (`unknown` מותר).
- **13-A5** 🤖 סימון `completed` עם שדה חובה גלוי ריק ← נדחה, עם רשימת החסרים. שדה
  חובה שמוסתר בתנאי אינו חוסם.
- **13-A6** 🤖 `postponed` ו-`no_access` אינם מוחזרים בשום שאילתה של "ביקורים
  שהושלמו", ואינם יוצרים `facts`.
- **13-A7** 🤖 ביקור שני אינו משנה אף שורה של הראשון.
- **13-B1** 🤖 `completed` ← לכל תשובה עם `maps_to` נוצר `fact` במצב `manual`,
  `source_kind = visit`. **אף אחד אינו `verified`.**
- **13-B2** 🤖 שטח שנמדד בביקור ושונה משטח קיים מאותו סוג ← נפתחת סתירה.
- **13-B3** 🤖 "אי התאמה אפשרית" יוצרת משימה; אין שום שדה בוליאני של עבירה.
- **13-C1** 🤖 תמונה `private` ← 404 למשתתף שאינו המבקר או האחראי.
- **13-C2** 🤖 `for_report` עם `usage` שאינו `report` ← נדחה.
- **13-C3** 🤖 אף פעולת `portal-*` אינה מחזירה תמונת ביקור.
