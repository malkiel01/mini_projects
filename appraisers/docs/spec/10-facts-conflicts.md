# 10 — נתונים, מקור לכל נתון, וסתירות

**תלויה ב-06.** האפיון: 6.1, 11, 17.1, 23.2; דרישה 20; בדיקת קבלה 15.

כל נתון שמשמש לשומה — שטח, קומה, תמורה, תאריך — נשמר עם **מקור, יחידה ומצב בדיקה**.
הפרוסה בונה את המודל ואת ההזנה הידנית; ההצעה האוטומטית מתוך מסמך — פרוסה 12.

## 1. מה בונים

1. קטלוג מאפיינים (מה אפשר לדעת על נכס ועל עסקה).
2. **נתונים** (`facts`): כמה ערכים לאותו מאפיין, כל אחד עם מקור ומצב.
3. הזנה ידנית, תיקון ששומר את ערך המקור, ואימות.
4. זיהוי **סתירה**, משימת בירור, והכרעה מנומקת — **לכל מטרה בנפרד**.
5. מעקב תלויות: נתון שהשתנה מסמן את מה שנשען עליו.
6. מסך סקירה: המסמך לצד הנתון.

## 2. מודל הנתונים

```
attributes                               הקטלוג — של המערכת
  key               'area', 'floor', 'rooms', 'contract_price' …
  label, group      זיהוי | מאפיינים | עסקה | שיפוץ | זכויות | שכירות
  value_type        number | money | date | text | choice | bool
  unit_kind         area | length | money | count | none
  has_area_kind     INT                  האם נדרש "סוג שטח"
  choices           JSON NULL
  multi             INT                  האם טבעי שיהיו כמה ערכים (הצמדות, צדדים)
  domain            'real_estate'
  status            active | hidden

facts
  id, pid, office_id, case_id
  attribute_key
  value_num         NUMERIC NULL         מספר; כסף — באגורות
  value_text        TEXT NULL
  value_date        DATE NULL
  unit              TEXT NULL            'sqm', 'ILS' …
  area_kind         registered | built | gross | net | primary | other | unknown    NULL כשלא רלוונטי
  estimated         INT                  אומדן, לא מדידה
  state             proposed | manual | needs_clarification | verified | rejected
  source_kind       document | visit | source_check | user | ai
  source_file_id, source_page, source_locator     העמוד והסימון במסמך, ככל שיש
  source_ref_pid    TEXT NULL            ביקור / בדיקת מקור / עסקה
  source_date       DATE NULL            תאריך המקור
  method            manual | ai | ocr | import
  original_num, original_text, original_date      הערך כפי שהגיע — לפני תיקון
  corrected_by, corrected_at, correction_note
  entered_by, entered_at
  verified_by, verified_at
  rejected_reason
  note
  rev               INT                  לנעילה אופטימית
  deleted_at

conflicts
  id, pid, office_id, case_id
  attribute_key
  status            open | resolved | dismissed
  task_id           → tasks
  created_at

conflict_facts
  conflict_id, fact_id

conflict_resolutions                     הכרעה — אחת לכל מטרה
  id, conflict_id
  purpose           TEXT                 "לחישוב מחיר למ"ר", "לתיאור הנכס בדוח" …
  chosen_fact_id    → facts
  reasoning         TEXT
  resolved_by, resolved_at

fact_uses                                מי נשען על הנתון
  fact_id
  used_in_type      calc | comp | report_section | alternative
  used_in_pid
  stale             INT                  הנתון השתנה מאז השימוש
```

**"לא קיים"** אינו שורה: מאפיין בלי שום `fact` מוצג "לא ידוע". **אין שורת ברירת
מחדל, ואין אפס** 🟢 (6.1).

**"חסר / לא ברור"** כשכן רוצים לתעד שחיפשו ולא מצאו: שורה ב-`state =
needs_clarification`, כל שדות הערך `NULL`, ו-`note` שמסביר.

## 3. הקטלוג — זריעה 🟡

לפי הדוגמאות שבאפיון 6.1, 11.1, 24, 27.4. מסומן "דוגמה" עד אישור שמאי:

| קבוצה | מאפיינים |
| --- | --- |
| מאפיינים | סוג נכס, שימוש בפועל, **שטח** (עם סוג שטח), קומה, קומות בבניין, חדרים, מצב בנייה, מצב תחזוקה, שנת בנייה, **הצמדות** (רב-ערכי: חניה, מחסן, מרפסת, גג — כל אחת עם שטח) |
| זכויות | סוג הזכות, בעלים רשומים (רב-ערכי), הערות ושעבודים (רב-ערכי) |
| עסקה | **מחיר חוזי**, תאריך החוזה, צדדים (רב-ערכי), תנאי תשלום |
| שיפוץ | **תקציב מוצהר**, **הצעת מחיר** (רב-ערכי), **עלות שאומתה**, תיאור העבודות, שלב ביצוע |
| שכירות | דמי שכירות, תקופה, תפוסה, הוצאות (לנכס מניב) |

`area_kind` הוא **חובה** לכל נתון שטח: רשום · בנוי · ברוטו · נטו · עיקרי · אחר ·
**לא ידוע**. "לא ידוע" הוא ערך חוקי ונפוץ — עדיף על ניחוש.

מנהל המערכת מוסיף ועורך מאפיינים; מאפיין בשימוש אינו נמחק.

## 4. מצבי נתון (האפיון 23.2)

| מצב | משמעות |
| --- | --- |
| *(אין שורה)* | לא קיים |
| `proposed` | הוצע מחילוץ (פרוסה 12) — **ממתין לבדיקה** |
| `manual` | הוזן ידנית, עוד לא אומת |
| `needs_clarification` | דורש בירור |
| `verified` | אומת בידי משתמש מורשה |
| `rejected` | נדחה (נשאר להיסטוריה; אינו משמש לדבר) |

- **רק `verified` נחשב "נתון מאומת".** `manual` ו-`proposed` משמשים בחישוב ובדוח
  **עם סימון "לא אומת"**, ומופיעים בבקרת הדוח (פרוסה 17).
- מצב הנתון ומצב המסמך — **שני מסלולים נפרדים** 🟢: מסמך יכול להיות `approved`
  והשטח שממנו `needs_clarification`; ולהפך — אימות שדה אינו מאשר את המסמך.
- נתון שמקורו `ai` **אינו יכול להיות `verified` בלי פעולת אדם**, ואינו יכול להגיע
  ל-`verified` בלי `source_file_id` (או מקור אחר שאפשר לפתוח).

## 5. תיקון ואימות

- **תיקון** ערך: הערך כפי שהגיע נשמר ב-`original_*` (פעם אחת — בתיקון הראשון);
  נרשמים המתקן, הזמן והערה. **ערך המקור אינו אובד לעולם** (17.1).
- **אימות:** `verified`, עם מי ומתי.
- **דחייה:** `rejected`, עם סיבה.
- כל שינוי בודק `rev` — שני עורכים בו בזמן ← השני מקבל "הנתון עודכן בידי <שם>",
  עם שני הערכים. אין דריסה שקטה.

## 6. סתירות (האפיון 11.2, בדיקת קבלה 15)

### 6.1 מתי נפתחת סתירה

לאותו מאפיין (שאינו `multi`) יש שני נתונים פעילים (לא `rejected`) ש**ערכם שונה**,
**ואפשר להשוות ביניהם**:

- אותה יחידה (או שאפשר להמיר במדויק);
- **לשטח: אותו `area_kind`.** שטח רשום 78 מ"ר ושטח ברוטו 92 מ"ר **אינם סתירה** —
  אלה שני נתונים שונים, ומוצגים זה לצד זה. אם לאחד מהם `area_kind = unknown` ←
  נפתחת סתירה מסוג "אי אפשר להשוות — סוג השטח אינו ידוע", כדי שהשמאי יברר.
- מספרים: שונים מעבר לסף עיגול של היחידה (0.01 למ"ר; אגורה לכסף).
  תאריכים וטקסט: שונים.

**אין השוואה אוטומטית בין סוגי שטח שאינם שקולים** 🟢.

### 6.2 מה קורה

1. נוצרת `conflicts` במצב `open`, עם כל הנתונים המעורבים.
2. נוצרת **משימת בירור**, מקושרת לסתירה.
3. הנתונים עצמם **אינם משתנים** — שניהם נשמרים, עם מקורותיהם.
4. התיק מסומן "יש סתירה פתוחה" בלוח הראשי.

### 6.3 הכרעה

השמאי פותח את הסתירה: הערכים זה לצד זה, כל אחד עם המקור (ולחיצה פותחת את המסמך
בעמוד). הוא בוחר:

- **ערך למטרה מסוימת, עם נימוק** — למשל "לחישוב מחיר למ"ר: השטח מהתוכנית, כי …".
  אפשר כמה הכרעות, למטרות שונות.
- **"אין סתירה"** (`dismissed`) — עם נימוק: למשל, שני סוגי שטח שסומנו בטעות כזהים.
  אפשר לתקן `area_kind` באותה פעולה.
- **דחיית אחד הנתונים** — הוא עובר ל-`rejected`, עם סיבה.

הסתירה `resolved` כשיש הכרעה אחת לפחות. **אף ערך אינו נמחק ואינו נדרס.**

נתון שלישי שמגיע אחרי הכרעה, ושונה ← הסתירה נפתחת מחדש, וההכרעות הקודמות נשארות
בהיסטוריה.

## 7. תלויות (האפיון 11.2)

כל מקום שמשתמש בנתון — חישוב, עסקה, חלופת שווי, פרק דוח — רושם `fact_uses`.

כשנתון **משתנה** (ערך, יחידה, סוג שטח, מצב ל-`rejected`), או כשסתירה שהוא חלק
ממנה **נפתחת**:

- כל `fact_uses` שלו ← `stale = 1`;
- הפריטים התלויים מציגים "נתון ששימש כאן השתנה — לבדיקה מחדש";
- **גרסת דוח שכבר אושרה או נמסרה אינה משתנה** 🟢; היא מסומנת "נתונים השתנו אחרי
  האישור", והשמאי מחליט אם נדרשת גרסה חדשה (פרוסה 17).

הפרוסה הזו בונה את המנגנון ואת ה-API שלו; הצרכנים מתחברים בפרוסות 15–17.

## 8. מסכים (האפיון 11.2, 25.4)

| נתיב | מסך |
| --- | --- |
| כרטיס תיק ← סקירה ← **נתוני הנכס** | לכל קבוצה: מאפיין, ערך (או ערכים), יחידה, מקור, מצב. "לא ידוע" למאפיין בלי נתון. סימון לסתירה |
| ← מאפיין | כל הערכים שנרשמו לו, כולל שנדחו; "הוספת ערך" |
| ← קובץ ← **נתונים** (בפרוסה 06: מסך הקובץ) | המסמך משמאל, הנתונים שמקורם בו מימין; לחיצה על נתון מדפדפת לעמוד. "הוספת נתון מהעמוד הזה" |
| ← **סתירות** | רשימה; מסך הכרעה — סעיף 6.3 |
| `#/system/attributes` | הקטלוג (מנהל המערכת) |

**הזנה:** ערך, יחידה, סוג שטח (כשנדרש), מקור (מסמך ועמוד · ביקור · בדיקת מקור ·
"נמסר בעל פה מ-…"), תאריך המקור, אומדן כן / לא, הערה.

**הצגת ערך** תמיד עם יחידה, ולשטח — עם סוג השטח: "78 מ"ר (רשום)". ערך בלי יחידה
ידועה אינו מוצג כמספר חשוף.

## 9. הרשאות

| פעולה | הרשאה בתיק |
| --- | --- |
| צפייה בנתונים ובמקורותיהם | `view` (וגישה לקובץ המקור — לפי הקובץ) |
| הזנה, תיקון, "דורש בירור" | `edit` או `documents` |
| אימות, דחייה, הכרעה בסתירה | `review_docs` + תפקיד שמאי בתיק |
| ניהול הקטלוג | מנהל המערכת |

מי שרואה נתון אבל אין לו גישה לקובץ המקור (שיתוף `items`) רואה "מקור: מסמך" בלי
שם ובלי קישור.

## 10. מקרי קצה

1. **שטח בהסכם 80, שטח בתוכנית 86, שניהם `built`.** סתירה; משימה; שניהם נשמרים. *(15)*
2. **שטח בנסח 78 (`registered`), שטח בתוכנית 86 (`built`).** אין סתירה — מוצגים
   שניהם, כל אחד עם סוגו.
3. **שטח בלי סוג** (`unknown`) מול שטח `built`. סתירה מסוג "אי אפשר להשוות".
4. **אותו ערך משני מקורות.** אין סתירה; שני נתונים, שתומכים זה בזה.
5. **מחיר 0.** מספר חוקי — אבל ההזנה שואלת "אפס, או לא ידוע?". `NULL` אינו 0.
6. **הקובץ שהנתון נשען עליו נמחק.** הנתון נשאר, עם "מסמך המקור נמחק", וחוזר ל-
   `needs_clarification` אם היה `verified`.
7. **המסמך הוחזר להשלמה.** הנתונים שממנו נשארים, מסומנים "המסמך הוחזר להשלמה".
8. **הכרעה, ואז הנתון שנבחר נדחה.** ההכרעה מסומנת לא תקפה; הסתירה נפתחת מחדש.
9. **מאפיין `multi`** (שתי חניות). שני נתונים — לא סתירה.
10. **יחידות שונות** (דונם ומ"ר). ההמרה מדויקת (1 דונם = 1,000 מ"ר) ← משווים.
    יחידה לא מוכרת ← סתירה "אי אפשר להשוות".
11. **נתון ששימש בדוח מאושר השתנה.** סעיף 7: הדוח אינו משתנה, רק מסומן.
12. **מחיקת נתון.** רכה; מי שנשען עליו מסומן `stale`.

## 11. קריטריוני קבלה

- **10-A1** 🤖 מאפיין בלי נתון מוחזר כ"לא ידוע" (`null`) — לא 0, לא מחרוזת ריקה. *(15)*
- **10-A2** 🤖 שני נתוני שטח, אותו `area_kind`, ערכים שונים ← נוצרות סתירה ומשימת
  בירור; שני הנתונים והמקורות שלהם ללא שינוי. *(15)*
- **10-A3** 🤖 שני נתוני שטח עם `area_kind` שונה ← **אין** סתירה.
- **10-A4** 🤖 אחד מהם `unknown` ← סתירה מסוג "אי אפשר להשוות".
- **10-A5** 🤖 אותו ערך משני מקורות ← אין סתירה.
- **10-A6** 🤖 הכרעה בלי נימוק, או בלי מטרה ← נדחית.
- **10-A7** 🤖 אחרי הכרעה — אף נתון לא נמחק ולא שונה; אפשר הכרעה שנייה למטרה אחרת.
- **10-A8** 🤖 נתון שלישי שונה אחרי הכרעה ← הסתירה `open` שוב; ההכרעה הקודמת קיימת.
- **10-B1** 🤖 תיקון ערך שומר את המקורי ב-`original_*`; תיקון שני אינו דורס אותו.
- **10-B2** 🤖 עדכון עם `rev` ישן ← 409, והנתון בשרת לא השתנה.
- **10-B3** 🤖 נתון שטח בלי `area_kind` ← נדחה (אפשר `unknown`, אי אפשר ריק).
- **10-B4** 🤖 נתון עם `source_kind = ai` ובלי מקור שאפשר לפתוח אינו יכול לעבור
  ל-`verified`.
- **10-B5** 🤖 אימות בידי מי שאינו שמאי בתיק ← נדחה.
- **10-C1** 🤖 שינוי נתון ← כל `fact_uses` שלו `stale`.
- **10-C2** 🤖 אישור המסמך אינו משנה מצב של אף נתון; אימות נתון אינו משנה את מצב
  המסמך.
- **10-C3** 🤖 **בידוד:** נתונים וסתירות של תיק ממשרד אחר ← 404.
- **10-C4** 🤖 שותף בלי גישה לקובץ המקור מקבל את הנתון בלי `source_file_id` ובלי
  שם הקובץ.
- **10-D1** 👁 מסך הקובץ: לחיצה על נתון מדפדפת לעמוד שבו הוא מופיע.
- **10-D2** 👁 מסך ההכרעה מציג את שני הערכים, סוגי השטח והמקורות זה לצד זה.
- **10-D3** 👁 שטח מוצג תמיד עם סוגו; "לא ידוע" מוצג במילים.
