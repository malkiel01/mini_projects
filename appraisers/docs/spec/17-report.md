# 17 — דוח: פרקים, טיוטה אוטומטית, בקרה ואישור

**תלויה ב-11, 13, 15** (ונעזרת ב-09, 10, 16). האפיון: פרק 15, 22.6, 23.3, 25.5;
דרישות 28, 29; בדיקות קבלה 22, 27, 28.

הדוח נבנה מתוך התיק, נשאר ניתן לעריכה, ועובר בדיקה ואישור של השמאי. **אין דוח
"מאושר" רק מפני שנוצר קובץ.**

## 1. מה בונים

1. מקטע **"דוח"** בפרופיל: תבנית פרקים, טריגר, ומה הבינה רשאית לנסח.
2. הדוח כ**תוכן ונתונים בתוך התיק** — פרקים, עם קישור לממצאים ולמקורות.
3. **טיוטה אוטומטית** לפי הטריגר; או ביוזמת השמאי.
4. עורך פרקים, עם הגנה מפני **דריסה שקטה** של עריכה ידנית.
5. ניסוח פרקים בבינה — מסומן, מקושר למקורות, וממתין לסקירה.
6. **מסך בקרה**: חסרים, סתירות, מה לא אומת, ומה חוסם.
7. גרסאות: טיוטה · בבדיקה · מאושר · נמסר · הוחלף.
8. אישור — של שמאי מורשה, על גרסה מוגדרת, עם צילום הנתונים.

## 2. מה לא

- קובצי Word ו-PDF, ומסירה — פרוסה 18.
- חתימה — לא נבנית. הדוח **לעולם אינו מוצג כ"חתום"** 🟢.
- תבנית דוח סופית — האפיון: "זו אינה תבנית סופית"; ממתין לדוגמאות מהבעלים.

## 4. מקטע "דוח" בפרופיל

```json
"report": {
  "trigger": "visit_completed",
  "sections": [
    { "key": "purpose",   "title": "מטרת ההזמנה והמועד הקובע", "mandatory": true,  "build": "data", "ai": false },
    { "key": "property",  "title": "זיהוי הנכס והזכויות",       "mandatory": true,  "build": "data", "ai": true  },
    { "key": "area_desc", "title": "סביבת הנכס ותיאורו",        "mandatory": true,  "build": "data", "ai": true  },
    { "key": "visit",     "title": "הביקור",                    "mandatory": true,  "build": "data", "ai": true  },
    { "key": "planning",  "title": "המצב הרישומי והתכנוני",     "mandatory": true,  "build": "data", "ai": true  },
    { "key": "documents", "title": "מסמכים והיתרים",            "mandatory": false, "build": "data", "ai": false },
    { "key": "methods",   "title": "שיטות השומה",               "mandatory": true,  "build": "data", "ai": false },
    { "key": "comps",     "title": "עסקאות, התאמות וחישובים",   "mandatory": true,  "build": "data", "ai": false },
    { "key": "assume",    "title": "הנחות ומגבלות",             "mandatory": true,  "build": "data", "ai": false },
    { "key": "conclusion","title": "מסקנת השמאי",               "mandatory": true,  "build": "manual","ai": false },
    { "key": "appendix",  "title": "נספחים",                    "mandatory": false, "build": "data", "ai": false }
  ],
  "findings": { "…": "block | warn" },
  "include_excluded_comps": false,
  "include_unverified": "marked"
}
```

- **`trigger`**: `visit_completed` (ברירת המחדל 🟢🟡) · `manual` ("ביוזמת השמאי").
  שינוי בפרופיל משפיע על **תיקים חדשים** (בדיקת קבלה 27).
- **`build`**: `data` — הפרק נבנה מנתוני התיק; `manual` — נשאר ריק לכתיבת השמאי.
- **`ai`**: האם מותר לבינה לנסח את הפרק. **`methods`, `comps`, `assume` ו-`conclusion`
  — תמיד `false`, ואי אפשר להדליק** (ש-23): הם נבנים מהנתונים, והמסקנה נכתבת בידי
  השמאי.
- אלה אחד-עשר הפרקים המוצעים באפיון 15.1, מסומנים "דוגמה". השמאי מוסיף, מסיר,
  משנה סדר וכותרות.

## 5. תוכן פרק

`content` הוא רשימת **בלוקים** — לא HTML חופשי:

| בלוק | מה |
| --- | --- |
| `p` | פסקה; טקסט עם הדגשה בלבד |
| `h` | כותרת משנה |
| `list` | רשימה |
| `table` | טבלה שהמשתמש כתב |
| `data_table` | טבלה ש**נבנית מהתיק** בזמן ההצגה והיצוא: עסקאות, התאמות, מזהים, מסמכים, בדיקות מקור |
| `fact` | ערך של נתון מהתיק, משובץ בטקסט — עם יחידה וסוג שטח |
| `image` | תמונה מהביקור (`usage = report` בלבד) |
| `note_missing` | "לא ידוע: <מה>" — חוסר מסומן |

- **`fact` ו-`data_table` הם הפניות, לא העתקים** — בטיוטה הם מציגים את הערך העדכני.
  באישור הם **מצולמים** (סעיף 8).
- כל בלוק יכול לשאת `src`: הפניה למקור (נתון, קובץ ועמוד, בדיקת מקור, ביקור,
  עסקה). **"מקור לכל טענה מהותית"** (25.5): בלוק `p` שנוצר אוטומטית או בבינה נושא
  `src`; פסקה שהשמאי כתב — יכול להוסיף.
- טקסט מוצג ומיוצא כטקסט נקי; אין הזרקת HTML.

## 6. יצירת טיוטה (האפיון 15.1, 22.6, בדיקת קבלה 27)

### 6.1 מתי

- `trigger = visit_completed`: ביקור שסומן **הושלם, והשרת אישר את כל הסנכרון שלו**
  (פרוסה 14, 7.3). `postponed` ו-`no_access` **אינם** מפעילים.
- `trigger = manual`: כפתור "יצירת טיוטה".
- בשני המקרים — רק אם **אין עדיין גרסה** לדוח. ביקור שני אינו יוצר טיוטה שנייה;
  הוא מייצר **הצעות עדכון** (סעיף 7).

### 6.2 איך

משימת רקע `report.draft`:

1. יוצרת `report_versions` מספר 1, `draft`, `origin = auto`, עם צילום התבנית.
2. לכל פרק `build = data` — **בונה את התוכן מהנתונים, בקוד** (לא בבינה): טבלאות,
   ערכים, רשימות. מה שחסר נכנס כ-`note_missing` — **חוסר אינו מעכב את היצירה** 🟢.
3. לכל פרק `ai = true`, **אם הבינה זמינה** (פרוסה 11: מדיניות, מסלול, מכסה, התיק
   אינו "בלי בינה") — `ai_run` עם `purpose = report.draft`, ו**רק** עם הנתונים של
   הפרק הזה. התוצאה: `origin = ai`, `ai_reviewed = 0`.
4. פרק `build = manual` — נשאר `empty`.

**מה נכנס לטיוטה** — רק מידע שמותר להשתמש בו: נתונים שאינם `rejected`; קבצים שלא
נדחו; תמונות `usage = report`; עסקאות `selected` (ו-`excluded` רק אם הפרופיל
ביקש). נתון שאינו `verified` נכנס **מסומן "לא אומת"** (או לא נכנס, לפי
`include_unverified`).

### 6.3 כשהבינה אינה זמינה

הטיוטה **נוצרת בכל זאת**, מהנתונים. הפרקים שהיו אמורים להיות מנוסחים בבינה נשארים
עם התוכן שנבנה מהנתונים, ועליהם פס: **"ניסוח בבינה ממתין: <הסיבה>"** (אין חיבור ·
מכסה · בינה כבויה למשרד · תיק "בלי בינה"), עם "ניסוח עכשיו" למי שרשאי.
**אין נפילה למסלול אחר.**

אם אין רשת או שהמשימה נכשלה — המשימה במצב `failed` / `needs_action`, והתיק מציג
"יצירת הטיוטה מתעכבת: <סיבה>".

### 6.4 ההנחיה לבינה

- נשלחים: כותרת הפרק, והנתונים שלו כמבנה (ערכים, יחידות, מקורות). **לא** מסמכים
  שלמים, לא פרקים אחרים, לא שמות לקוחות מעבר למה שהפרק צריך.
- המודל מתבקש לנסח **רק על בסיס מה שקיבל**; על כל נתון חסר — לכתוב "לא ידוע", ולא
  להשלים. הוא מחזיר בלוקים, כל אחד עם `src` שמפנה לנתון שקיבל.
- השרת מאמת: `src` קיים ברשימת הנתונים שנשלחו; **מספר שמופיע בטקסט ואינו אחד
  מהערכים שנשלחו ← הבלוק מסומן "מספר שלא נמצא בנתונים"** ומופיע בבקרה.
- **אין בפלט שווי, מסקנה או המלצה** — ההנחיה אוסרת, והפרקים הרלוונטיים אינם
  נשלחים לבינה כלל.

## 7. עריכה, ואיסור הדריסה השקטה (בדיקת קבלה 28) 🟢

- העורך: רשימת הפרקים משמאל (עם מצב כל אחד), הפרק באמצע, **המקורות שלו** מימין.
- שמירה אוטומטית, עם `rev`. עריכה ראשונה של אדם ← `user_edited = 1`.
- **שני עורכים באותו פרק** ← השני מקבל "הפרק עודכן בידי <שם>", עם שתי הגרסאות.

**כשמגיע מידע חדש** (מסמך, נתון שאומת, ביקור נוסף, עסקה, שינוי בקבוצה):

| מצב הפרק | מה קורה |
| --- | --- |
| `user_edited = 0` (לא נגעו בו) | בלוקי `fact` / `data_table` מתעדכנים לבד (הם הפניות). טקסט אוטומטי נבנה מחדש, והפרק מציג "עודכן: <מה השתנה>" |
| `user_edited = 1` | **התוכן אינו משתנה.** נוצרת `section_proposals`, והפרק מציג "יש הצעת עדכון" |

**הצעת עדכון** נפתחת בתצוגת הבדלים: התוכן שלי מול המוצע. אפשרויות: **קבלה** (מחליף)
· **דחייה** · **מיזוג** (עריכה ידנית, עם ההצעה לצד). ההחלטה נרשמת.

גם בפרק שנערך, בלוקי `fact` ו-`data_table` ממשיכים להציג ערך עדכני — **אבל** אם
הערך השתנה מאז העריכה, הבלוק מסומן "הערך השתנה: היה X", כדי שהשמאי יבדוק שהטקסט
סביבו עדיין נכון.

**"יצירה מחדש"** של פרק או של כל הטיוטה — פעולה מפורשת, עם אזהרה ורשימת הפרקים
שנערכו ידנית; ברירת המחדל: **לא לגעת בהם**.

## 8. גרסאות ואישור (האפיון 15.2, 23.3)

```
draft ──"העברה לבדיקה"──▶ in_review ──"אישור"──▶ approved ──(מסירה, פרוסה 18)──▶ delivered
  ▲                          │                       │
  └────"החזרה לעריכה"────────┘                       └──"גרסה חדשה"──▶ draft (מספר הבא); הקודמת ← superseded כשהחדשה מאושרת
```

### 8.1 אישור

- **מי:** רק בעל `approve_report` בתיק (ברירת המחדל: השמאי האחראי בלבד — ש-09).
  פעולה רגישה (פרוסה 02).
- **על מה:** גרסה מוגדרת, במצב `in_review`.
- **מה קורה באישור:**
  1. רצה הבקרה (סעיף 9). ממצא חוסם ← אין אישור.
  2. לכל אזהרה — נדרש נימוק (`report_findings_ack`).
  3. **`snapshot`** — צילום מלא: כל בלוק `fact` ו-`data_table` עם הערך של אותו רגע;
     הנתונים, העסקאות, ההתאמות, החישובים, החלופות וההנחות שהדוח נשען עליהם; רשימת
     המקורות; התבנית; מי ומתי.
  4. `content_hash` מחושב על התוכן והצילום.
  5. `approved`. **מעכשיו הגרסה אינה ניתנת לשינוי — בשום פעולת API** 🟢.
  6. מצב התיק ← `approved`.

### 8.2 אחרי האישור

- שינוי בנתון, בעסקה או בחישוב שהגרסה נשענת עליו ← `stale_after_approval = 1`;
  הגרסה מציגה "נתונים השתנו אחרי האישור". **הגרסה עצמה אינה משתנה** — היא מוצגת
  ומיוצאת מה-`snapshot`.
- **"גרסה חדשה"** — יוצרת `draft` במספר הבא, כהעתק של המאושרת, **עם הערכים
  העדכניים**, ותצוגת הבדלים מול הקודמת. נדרש נימוק לפתיחתה; נרשם.
- הקודמת נשארת `approved` / `delivered` עד שהחדשה מאושרת — ואז `superseded`.
  **גרסה שנמסרה נשמרת לתמיד**, וניתנת לצפייה.
- אין "ביטול אישור". יש רק גרסה חדשה.

## 9. מסך הבקרה (האפיון 15.2, ש-22, בדיקת קבלה 22)

רשימה אחת של **ממצאים**, מחושבת מהתיק בזמן אמת. לכל ממצא: מה, איפה (עם קישור),
ורמה.

| ממצא | ברירת המחדל |
| --- | --- |
| אין שמאי מורשה לאשר בתיק | 🔴 חוסם |
| פרק חובה ריק | 🔴 חוסם |
| טקסט בינה שלא נסקר (`origin = ai`, `ai_reviewed = 0`) | 🔴 חוסם |
| תמונה בדוח בלי `usage = report` | 🔴 חוסם |
| בלוק בינה עם "מספר שלא נמצא בנתונים" | 🔴 חוסם |
| הצעת עדכון שלא הוכרעה | 🔴 חוסם |
| דרישת חובה שאינה `approved` / `not_relevant` | 🟡 אזהרה |
| סתירה פתוחה | 🟡 אזהרה |
| נתון בדוח שאינו `verified` | 🟡 אזהרה |
| מקור מהפרופיל שלא נבדק, או `unavailable` / `not_found` | 🟡 אזהרה |
| משימה פתוחה בתיק | 🟡 אזהרה |
| מדגם קטן; עסקה נבחרת עם נתונים חסרים | 🟡 אזהרה |
| חלופה בלי מועד קובע, או `after_works` בלי הנחות | 🟡 אזהרה |
| `note_missing` בפרק | 🟡 אזהרה |
| חלופה בלי מסקנה | 🟡 אזהרה |
| בלוק `fact` שערכו השתנה מאז עריכת הפרק | 🟡 אזהרה |
| מסמך שהנתון נשען עליו הוחזר להשלמה / נמחק | 🟡 אזהרה |

- **🔴 חוסם** — אי אפשר לאשר עד שמתוקן.
- **🟡 אזהרה** — אפשר לאשר, **עם נימוק לכל ממצא**. הנימוקים נשמרים עם הגרסה.
- הסיווג הוא הגדרה בפרופיל (`findings`). **ארבעת הראשונים אינם ניתנים להורדה
  מ"חוסם".**
- הבקרה זמינה תמיד — לא רק לפני אישור — ומוצגת גם בסקירת התיק.

## 10. מסכים (האפיון 25.5)

| נתיב | מסך |
| --- | --- |
| כרטיס תיק ← **דוח וגרסאות** | רשימת הגרסאות: מספר, מצב, מי ומתי. "יצירת טיוטה" / "גרסה חדשה" |
| `#/cases/<pid>/report/<גרסה>` | **העורך** — סעיף 7. גרסה מאושרת: קריאה בלבד, מה-`snapshot` |
| ← **בקרה** | סעיף 9 |
| ← **תצוגה מקדימה** | הדוח כפי שייראה, עם פס "טיוטה — לא מאושר" |
| ← **השוואת גרסאות** | מה נוסף, הוסר והשתנה — בטקסט ובנתונים |
| ← הערות | הערות לבודק, לפי פרק |
| עורך פרופיל ← **דוח** | סעיף 4 |

כפתורי "העברה לבדיקה", "אישור" ו"גרסה חדשה" **מוצגים רק למורשים** — והשרת בודק
בכל מקרה.

## 11. הרשאות

| פעולה | הרשאה בתיק |
| --- | --- |
| צפייה בגרסה מאושרת | `view` |
| צפייה בטיוטה | `view` למשתתף פנימי; שותף חיצוני — רק עם `see_draft` |
| עריכה, הצעות עדכון, הערות, "ניסוח בבינה" | `edit` |
| סימון "נסקר" על טקסט בינה | `edit` + תפקיד שמאי בתיק |
| העברה לבדיקה, החזרה לעריכה | `edit` + תפקיד שמאי |
| **אישור** | `approve_report` |
| גרסה חדשה אחרי אישור | `approve_report`, בנימוק |

## 12. מקרי קצה

1. **ביקור הושלם, ואין אף נתון.** נוצרת טיוטה שכולה `note_missing`. *(27)*
2. **הטריגר הופעל פעמיים** (ניסיון חוזר של המשימה). `dedupe_key` לפי התיק; טיוטה אחת.
3. **השמאי ערך פרק, ואז הגיע מסמך חדש.** הצעת עדכון; התוכן שלו ללא שינוי. *(28)*
4. **הפרופיל שונה ל-`manual` אחרי שהתיק נפתח.** התיק ממשיך לפי הגרסה שלו (אוטומטי).
   תיק חדש — ידני. *(27)*
5. **אישור, ושנייה אחר כך משתנה נתון.** הגרסה `approved` מה-`snapshot`; מסומנת `stale`.
6. **שני אנשים לוחצים "אישור" יחד.** `rev`; השני מקבל "הגרסה כבר אושרה".
7. **השמאי האחראי הוחלף אחרי האישור.** האישור נשאר על שם המאשר.
8. **תמונה שבדוח נמחקה.** בטיוטה — הבלוק מציג "התמונה הוסרה", וממצא חוסם. בגרסה
   מאושרת — התמונה נשמרת (קובץ שגרסה מאושרת מפנה אליו **אינו נמחק פיזית**).
9. **המכסה נגמרה באמצע ניסוח הפרקים.** מה שנוסח — נשאר; השאר "ממתין: מכסה".
10. **הבינה החזירה טקסט עם שווי.** ההנחיה אוסרת; בנוסף, מספר שאינו בנתונים ← ממצא
    חוסם.
11. **פרק חובה שהשמאי מחק מהתבנית בתיק.** מותר — התבנית של הגרסה היא שלו; נרשם ביומן.
12. **טיוטה נמחקת.** רק גרסה `draft` שלא אושרה מעולם, ורק בידי `approve_report`,
    בנימוק. מחיקה רכה.
13. **תיק בלי ביקור כלל** (שומת משרד). הטריגר לא יופעל; "יצירת טיוטה" ידנית זמינה,
    ופרק הביקור מסומן `note_missing`.
14. **`snapshot` גדול** (מאות עסקאות). נשמר דחוס; אין מגבלה מעשית.

## 13. קריטריוני קבלה

- **17-A1** 🤖 ביקור `completed` עם סנכרון מלא, בפרופיל `visit_completed` ← נוצרת
  גרסה 1, `draft`, `origin = auto`. *(27)*
- **17-A2** 🤖 `postponed` / `no_access` / `completed` עם התנגשות פתוחה ← לא נוצרת.
- **17-A3** 🤖 פרופיל `manual` ← לא נוצרת לבד; נוצרת בלחיצה. שינוי הפרופיל אינו
  משנה את ההתנהגות בתיק קיים. *(27)*
- **17-A4** 🤖 תיק בלי נתונים ← הטיוטה נוצרת, ופרקי הנתונים מכילים `note_missing`;
  **אין בשום בלוק 0 במקום ערך חסר**. *(22, 27)*
- **17-A5** 🤖 בינה לא זמינה (ארבע הסיבות, כל אחת) ← הטיוטה נוצרת; הפרקים מסומנים
  "ממתין" עם הסיבה; **אפס** קריאות למתאם במסלול אחר.
- **17-A6** 🤖 הטריגר פעמיים ← גרסה אחת.
- **17-A7** 🤖 הפרקים `methods`, `comps`, `assume`, `conclusion` אינם נשלחים למתאם
  בשום תצורת פרופיל.
- **17-B1** 🤖 פרק עם `user_edited = 1` + נתון חדש ← `content` **זהה בית-בבית**;
  נוצרה `section_proposals`. *(28)*
- **17-B2** 🤖 פרק עם `user_edited = 0` + נתון חדש ← מתעדכן, ואין הצעה.
- **17-B3** 🤖 "יצירה מחדש" בברירת המחדל אינה משנה פרקים שנערכו ידנית.
- **17-B4** 🤖 שמירת פרק עם `rev` ישן ← 409.
- **17-C1** 🤖 אישור בידי משתמש בלי `approve_report` ← נדחה — **גם שמאי, גם מנהל
  משרד, גם מנהל המערכת**. *(22)*
- **17-C2** 🤖 כל אחד מששת הממצאים החוסמים — כשהוא קיים, האישור נדחה (שש בדיקות).
- **17-C3** 🤖 אזהרה בלי נימוק ← האישור נדחה; עם נימוק לכל אזהרה ← מאושר, והנימוקים
  שמורים. *(22)*
- **17-C4** 🤖 נתון חסר שבדוח מופיע ברשימת הממצאים לפני האישור. *(22)*
- **17-C5** 🤖 אחרי אישור: כל פעולת עדכון על הגרסה, על פרקיה ועל ה-`snapshot` ←
  נדחית. ה-`content_hash` אינו משתנה.
- **17-C6** 🤖 אחרי אישור, שינוי `fact` שבדוח ← `stale_after_approval = 1`; קריאת
  הגרסה מחזירה את **הערך הישן** (מה-`snapshot`).
- **17-C7** 🤖 "גרסה חדשה" ← `draft` במספר הבא, עם הערך **החדש**; הקודמת עדיין
  `approved`. אישור החדשה ← הקודמת `superseded`, וקריאתה עדיין מחזירה את תוכנה.
- **17-C8** 🤖 אין פעולת API שיוצרת גרסה `approved` שלא דרך האישור (יצוא, למשל,
  אינו משנה מצב). *(22)*
- **17-D1** 🤖 תשובת בינה עם `src` שלא נשלח ← הבלוק נזרק; עם מספר שאינו בנתונים ←
  ממצא חוסם.
- **17-D2** 🤖 הבקשה למתאם לפרק מכילה רק את נתוני אותו פרק.
- **17-D3** 🤖 **בידוד:** דוח, גרסאות ופרקים של תיק ממשרד אחר ← 404; שותף בלי
  `see_draft` אינו מקבל טיוטה.
- **17-E1** 👁 העורך: לחיצה על מקור בפרק פותחת את המסמך בעמוד.
- **17-E2** 👁 הצעת עדכון מוצגת כהבדלים, עם קבלה / דחייה / מיזוג.
- **17-E3** 👁 מסך הבקרה: כל ממצא מקשר למקום שמתקנים בו.
- **17-E4** 👁 גרסה מאושרת מוצגת "מאושרת", ולעולם לא "חתומה".
- **17-E5** 👁 עם מפתח אמיתי: פרק "סביבת הנכס ותיאורו" מנוסח, מסומן "נכתב בבינה —
  לא נסקר", ואינו כולל שווי.
