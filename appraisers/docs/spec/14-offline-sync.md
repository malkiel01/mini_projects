# 14 — אפליקציה מותקנת, עבודה בלי קליטה, וסנכרון

**תלויה ב-13.** האפיון: 12.2, 12.3, 23.3, 26.3; דרישות 21, 22; בדיקות קבלה
16, 17, 30.

השמאי מכין תיק למכשיר, יוצא לשטח, ממלא ומצלם בלי רשת, וכשהרשת חוזרת — הכול
מסתנכרן, בלי כפילויות ובלי דריסה שקטה.

## 1. מה בונים

1. **אפליקציה מותקנת:** `manifest.webmanifest`, service worker, אייקונים. Android —
   גם אפליקציה עטופה (TWA). iPhone — התקנה מ-Safari (ש-05).
2. **"הכנה למכשיר":** הורדת תיק לביקור, עם דוח מה ירד ומה לא.
3. אחסון מקומי של הטופס, התשובות והתמונות.
4. **תור סנכרון** עם מצב לכל פריט, וניסיון חוזר.
5. **פתרון התנגשויות** — שתי הגרסאות להכרעה.
6. רישום מכשירים, תפוגה ומחיקה של תוכן מקומי, ונוהל אובדן מכשיר.

## 2. מה עובד בלי רשת, ומה לא 🟢

| עובד בלי רשת | **אינו** עובד בלי רשת — ואינו מוצג כאילו בוצע |
| --- | --- |
| פתיחת תיק שהוכן | פתיחת תיק שלא הוכן |
| מילוי טופס הביקור | חיפוש מידע חי, מקורות, מפה |
| צילום תמונות | שליחת הודעה או בקשה |
| צפייה בפרטים ובמסמכים שהוכנו | כל פעולת בינה |
| סימון הביקור "הושלם" (נכנס לתור) | אישור מסמך, אישור דוח, שיתוף |

כפתור של פעולה שדורשת רשת מוצג **כבוי, עם "דורש חיבור"** — לא נעלם, ולא "ממתין".

## 3. מודל הנתונים

### 3.1 בשרת

```
devices
  id, pid, user_id
  label             TEXT                 "אייפון של דנה" — המשתמש נותן שם
  ua_short          TEXT
  key_hash          TEXT UNIQUE          hash של מפתח המכשיר
  status            active | revoked
  last_seen_at, created_at, revoked_at, revoked_by

device_packs                             מה הוכן לאיזה מכשיר
  id, pid, device_id, case_id, visit_id
  prepared_at
  manifest          JSON                 מה נכלל; מה לא ולמה
  expires_at
  status            active | expired | revoked | wiped

sync_ops                                 כל פעולה שהגיעה ממכשיר
  op_id             TEXT PRIMARY KEY     נוצר במכשיר
  device_id, user_id, case_id, visit_id
  kind              answer.set | answer.clear | photo.add | photo.meta | photo.delete | visit.status
  base_rev          INT NULL             הגרסה שהמכשיר ראה
  received_at
  result            applied | duplicate | conflict | rejected
  reject_reason     TEXT NULL
  server_rev        INT NULL

sync_conflicts
  id, pid, case_id, visit_id
  field_key, row_no
  server_value      JSON                 הערך בשרת, מי ומתי
  device_value      JSON                 הערך מהמכשיר, מי ומתי (לפי שעון המכשיר — מידע בלבד)
  op_id
  status            open | resolved
  chosen            server | device | custom
  resolved_by, resolved_at
```

### 3.2 במכשיר (IndexedDB) ⚙️

`packs` (התיק שהוכן: טופס, פרטים, רשימת קבצים) · `blobs` (קבצים ותמונות) ·
`answers` (הערכים המקומיים, עם `base_rev`) · `outbox` (תור הפעולות) · `meta`
(מפתח המכשיר, המשתמש, מועדי תפוגה).

**בסיס המסד המקומי נושא את מזהה המשתמש.** משתמש אחר שנכנס באותו מכשיר אינו רואה
את הנתונים של הקודם — ורואה הצעה למחוק אותם.

## 4. האפליקציה המותקנת (האפיון 2.1, ש-05)

- `manifest.webmanifest`: שם, אייקונים, `display: standalone`, `dir: rtl`,
  `lang: he`, `start_url` ו-`scope` — **תיקיית האפליקציה בלבד**.
- **service worker** משלה, בתיקייה שלה: שומר את מעטפת הממשק (HTML, JS, CSS,
  אייקונים), כדי שהאפליקציה תיפתח בלי רשת. **אינו שומר תשובות API** — הנתונים
  במסד המקומי, לא במטמון.
- **כל כתובת מחוץ לתיקיית האפליקציה נפתחת בחוץ** (CLAUDE.md) — כולל אתרי המקורות.
- **עדכון גרסה:** גרסה חדשה מותקנת ברקע; מוצג "יש גרסה חדשה — רענון". **אין רענון
  אוטומטי באמצע ביקור**, ואין רענון כל עוד יש פריטים בתור.
- **Android (TWA):** לפי התבנית `recipes-app/android` — מעתיקים, לא משנים את המקור.
  `"install": {"release": "appraisers-store"}`.
- **iPhone:** מסך הסבר להתקנה מ-Safari ("שיתוף ← הוספה למסך הבית").
- ה-`manifest` וה-service worker ב-`public` של `app.json`.

**מגבלה שהמסך אומר במפורש** (26.3): "המכשיר עלול למחוק נתונים מקומיים של אפליקציה
שלא נפתחה זמן רב, או כשנגמר המקום. סנכרנו בהקדם." באייפון מוצג הסבר חד יותר.

## 5. הכנה למכשיר (האפיון 12.2, 26.1)

בכרטיס הביקור: **"הכנה למכשיר הזה"** — דורש רשת, משתמש מחובר, והרשאת `visit`.

**מה יורד:** הטופס (`form_snapshot`); התשובות הקיימות עם ה-`rev` שלהן; פרטי התיק
הנחוצים לביקור (מספר, כותרת, מזהים, נתוני נכס, איש קשר לגישה); ומסמכים **שהמשתמש
בחר** מתוך אלה שיש לו בהם `view`.

**מה לא יורד, ומוצג עם הסיבה:**

| פריט | סיבה שמוצגת |
| --- | --- |
| קובץ מעל 15MB 🟡 | "קובץ גדול — לא ירד" (אפשר לבחור במפורש) |
| קובץ שאין בו הרשאה | אינו מוצג כלל |
| קובץ ממקור ש-`license.offline` שלו `no` או `unknown` | "רישיון המקור אינו מתיר שמירה במכשיר" |
| מפות ותצלומי אוויר | "לא נשמרים במכשיר" |
| הערות פנימיות, עסקאות, דוח | אינם חלק מחבילת הביקור |

**מסך ההכנה** מציג: מצב (מוריד · מוכן · נכשל), מועד העדכון האחרון, מה ירד, מה לא
ולמה, כמה מקום תפוס, ומתי התוכן יפוג.

**"מוכן ללא קליטה" מוצג רק כשכל הפריטים החיוניים ירדו ואומתו** — הטופס, פרטי
התיק, וכל קובץ שנבחר (hash תואם). אחרת: "ההכנה לא הושלמה", עם מה שחסר.

## 6. עבודה במכשיר

- **המסך הוא אותו מסך ביקור** של פרוסה 13. ההבדל: כל שמירה נכתבת קודם למסד המקומי,
  ונכנסת ל-`outbox`.
- **לכל פריט — מצב גלוי** (23.3):

| מצב | פירוש |
| --- | --- |
| 💾 שמור במכשיר | נכתב למסד המקומי |
| ⏳ ממתין לסנכרון | בתור |
| 🔄 מסתנכרן | נשלח עכשיו |
| ✅ סונכרן | **השרת אישר קבלה** — לא "יש רשת" |
| ⚠️ נכשל | עם סיבה, ו"נסו שוב" |
| ⚖️ דורש הכרעה | התנגשות |

- **פס מצב קבוע** בראש המסך: "אין חיבור · 12 פריטים ממתינים" / "מסנכרן 3 מתוך 12"
  / "הכול סונכרן ✓".
- **"שמירה מקומית אינה גיבוי"** — כל עוד יש פריטים שלא סונכרנו, מוצג פס: "הנתונים
  במכשיר בלבד עד לסנכרון."
- תמונה: נשמרת מקומית מיד (מוקטנת), עם תמונה ממוזערת; ההעלאה — בתור.

## 7. סנכרון (האפיון 12.3, בדיקות קבלה 16, 17)

### 7.1 הפעולה

כל שינוי במכשיר הוא **פעולה** עם: `op_id` (אקראי, נוצר במכשיר), סוג, השדה, הערך,
`base_rev` (הגרסה שהמכשיר ראה כשערך), וזמן המכשיר (למידע בלבד).

### 7.2 השרת, לכל פעולה

| בדיקה | תוצאה |
| --- | --- |
| `op_id` כבר ב-`sync_ops` | `duplicate` — מחזיר את התוצאה המקורית. **אין שינוי** |
| המכשיר `revoked`; המשתמש הושעה; אין `visit` בתיק | `rejected`, עם הסיבה |
| הביקור כבר `completed` בידי אחר, או נסגר | `rejected: visit_closed` |
| `base_rev` = הגרסה הנוכחית בשרת | `applied`; `rev` עולה |
| `base_rev` ≠ הנוכחית, **והערך בשרת זהה לערך שנשלח** | `applied` (אין מה להכריע) |
| `base_rev` ≠ הנוכחית, והערכים שונים | **`conflict`** — הערך בשרת **לא משתנה**; נוצרת `sync_conflicts` |

**ההכרעה אינה לפי שעון** 🟢 (23.3): שעון המכשיר נשמר ומוצג, אבל אינו קובע מי מנצח.
תמיד אדם מכריע.

### 7.3 התור

- נשלח לפי הסדר; שדות בקבוצות של עד 50 פעולות; תמונות אחת-אחת.
- כשל רשת ← ניסיון חוזר בהשהיה גדלה (5 שניות עד 5 דקות). כשל ב-`rejected` ← **אין
  ניסיון חוזר**; הפריט מסומן ⚠️ עם הסיבה.
- **תמונה:** `photo.add` נושא `op_id`; העלאה שנקטעה ונשלחה שוב ← השרת מזהה את
  ה-`op_id` (וגם את ה-`sha256`) ← **תמונה אחת**.
- מתחיל לבד כשהרשת חוזרת והאפליקציה פתוחה; וכפתור "סנכרון עכשיו".
- **`visit.status = completed` נשלח אחרון**, ורק אחרי שכל שאר הפעולות של הביקור
  הוחלו. יש התנגשות פתוחה או פריט שנכשל ← הביקור נשאר `in_progress`, והמסך מסביר.
  כך "ביקור שהושלם וסונכרן" — הטריגר לטיוטת הדוח — פירושו באמת שהכול בשרת.

### 7.4 פתרון התנגשות

מסך "דורש הכרעה" — במכשיר ובמחשב, לכל מי שיש לו `visit` בתיק:

- השדה; **הערך שלי** (ומתי, לפי המכשיר); **הערך שבשרת** (מי, ומתי).
- שלוש אפשרויות: שלי · שלהם · ערך אחר (להקליד).
- ההכרעה היא פעולה חדשה עם ה-`rev` העדכני, ונרשמת ביומן הפעולות עם שני הערכים.
- **עד ההכרעה — הערך בשרת הוא התקף**, והשדה מסומן ⚖️ אצל כולם.

## 8. הגנה, תפוגה ואובדן מכשיר (האפיון 12.3, 18.1)

- **מפתח מכשיר** נוצר בהכנה הראשונה; ה-hash שלו בשרת. כל בקשת סנכרון נושאת אותו.
- **תפוגה:** חבילה פגה 14 יום אחרי ההכנה 🟡, או 14 יום אחרי סנכרון מלא — המוקדם.
  אחריה התוכן המקומי נמחק בפתיחה הבאה. **פריטים שלא סונכרנו אינם נמחקים בתפוגה**
  — הם נשארים, עם אזהרה, עד שיסונכרנו או שהמשתמש ימחק אותם במפורש.
- **יציאה מהחשבון / משתמש אחר** ← הצעה למחוק; אם יש פריטים שלא סונכרנו — אזהרה
  מפורשת עם המספר.
- **ביטול הרשאה או השעיה** ← נאכף **בחיבור הבא**: הסנכרון נדחה, והשרת מחזיר הוראת
  מחיקה (`wipe`) שהאפליקציה מבצעת. **המסך בשרת אומר במפורש: "אי אפשר להבטיח מחיקה
  ממכשיר שאינו מחובר."**
- **אובדן מכשיר:** תפריט משתמש ← "המכשירים שלי" ← "ביטול מכשיר". גם מנהל משרד
  יכול לבטל מכשיר של חבר במשרדו. אחרי ביטול: הסנכרון נדחה, ונשלחת הוראת מחיקה
  בחיבור הבא. **פעולות שלא סונכרנו מהמכשיר הזה — אבדו**, והמסך אומר זאת, עם רשימת
  החבילות שהיו עליו.
- **הצפנה מקומית:** נשענים על הצפנת המכשיר. המערכת אינה מוסיפה הצפנה משלה למסד
  המקומי בגרסה הזו 🟡 — ונאמר כך במסך ההכנה: "הנתונים מוגנים בנעילת המכשיר. ודאו
  שהמכשיר נעול בקוד."

## 10. מקרי קצה (האפיון 26.3)

1. **החיבור נפל באמצע העלאת תמונה.** נשלחת שוב; תמונה אחת בשרת. *(16)*
2. **האפליקציה נסגרה באמצע מילוי.** מה שסומן 💾 קיים בפתיחה הבאה, גם בלי רשת. *(16)*
3. **נגמר המקום במכשיר.** השמירה המקומית נכשלת ← **השדה מסומן "לא נשמר"**, והצילום
   נחסם עם הסבר. שום דבר אינו "נשמר" בשקט.
4. **המערכת ניקתה את האחסון המקומי.** בפתיחה: "הנתונים המקומיים אינם זמינים". מה
   שסונכרן — בשרת. מה שלא — אבד, ומוצג כך.
5. **ה-session פג בזמן הניתוק.** האפליקציה ממשיכה לעבוד מקומית; בחיבור — כניסה
   מחדש דרך המעטפת, **ואז** הסנכרון. התור נשמר.
6. **מישהו ערך את אותו שדה בשרת.** התנגשות. *(17)*
7. **מישהו ערך שדה אחר באותו ביקור.** אין התנגשות — ההכרעה ברמת השדה.
8. **ההרשאה בוטלה בזמן הניתוק.** `rejected`; הנתונים במכשיר **נשארים גלויים למשתמש
   עד המחיקה**, עם "לא סונכרן — ההרשאה בוטלה", כדי שיוכל להעביר אותם ידנית לשמאי.
9. **הביקור הושלם בשרת בידי אחר.** `rejected: visit_closed`; כנ"ל.
10. **שני מכשירים של אותו משתמש.** כל אחד מכשיר נפרד; עריכת אותו שדה בשניהם ←
    התנגשות, כרגיל.
11. **שעון המכשיר שגוי בשנה.** אינו משפיע על ההכרעה; מוצג כפי שהוא, עם "לפי שעון
    המכשיר".
12. **גרסת אפליקציה ישנה מסנכרנת.** כל בקשה נושאת גרסת פרוטוקול; גרסה שאינה נתמכת
    ← "נדרש עדכון", **והתור נשמר** עד אחרי העדכון.
13. **הטופס השתנה בין ההכנה לסנכרון.** הביקור עובד עם `form_snapshot`; שדה שאינו
    בו ← `rejected: unknown_field`.
14. **מחיקת תמונה מקומית שעוד לא עלתה.** מוסרת מהתור; אינה נשלחת.
15. **סנכרון חלקי** (5 מתוך 12, ואז ניתוק). ה-5 מסומנים ✅; ה-7 ממתינים.

## 11. קריטריוני קבלה

- **14-A1** 🤖 אותה פעולה (`op_id`) נשלחת שלוש פעמים ← שינוי אחד בשרת; שלוש
  התשובות זהות. *(16)*
- **14-A2** 🤖 אותה תמונה נשלחת פעמיים (אותו `op_id`) ← קובץ אחד ושורת
  `visit_photos` אחת. *(16)*
- **14-A3** 🤖 פעולה עם `base_rev` ישן וערך שונה ← הערך בשרת **לא השתנה**; נוצרה
  `sync_conflicts`; התוצאה `conflict`. *(17)*
- **14-A4** 🤖 `base_rev` ישן וערך זהה ← `applied`, בלי התנגשות.
- **14-A5** 🤖 שתי פעולות על שדות שונים באותו ביקור, אחת מהן על בסיס ישן ← שתיהן
  מוחלות.
- **14-A6** 🤖 ההכרעה אינה תלויה בזמן המכשיר: פעולה עם זמן "עתידי" אינה גוברת.
