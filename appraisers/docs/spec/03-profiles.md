# 03 — פרופילים: ספרייה, גרסאות, כללים ושיתוף

**תלויה ב-01.** האפיון: פרק 5, 24, 25.3; דרישות 07–10; בדיקות קבלה 5, 7, 25.

פרופיל הוא תבנית כללים לשימוש חוזר. הפרוסה הזו בונה את **המעטפת** של הפרופיל —
ספרייה, גרסאות, שיתוף, כללים מותנים ותצוגת ניסיון — ואת שני המקטעים הראשונים:
**מסמכים** ו**משימות**. שאר המקטעים מצטרפים בפרוסות שלהם (08 קשר ותזכורות,
09 מקורות, 13 ביקור, 15 עסקאות, 17 דוח).

## 1. מה בונים

1. ספריית פרופילים בשלוש רמות: **מומלץ** (של המערכת), **משרדי**, **אישי**.
2. עורך פרופיל עם טיוטה וגרסאות מפורסמות.
3. מקטע מסמכים: קבוצות ודרישות, סדר, עדיפות, חובה, גורם אחראי, מועד יחסי, תנאי.
4. מקטע משימות.
5. כללים מותנים ("אם סומן שיפוץ — הוסף דרישה לפירוט עבודות").
6. תצוגת ניסיון: מה ייווצר לתיק לדוגמה — בלי ליצור תיק ובלי לשלוח דבר.
7. שכפול, ארכוב, שיתוף (צפייה / שכפול / עריכה), והיסטוריה.
8. ארבעה פרופילים מומלצים לדוגמה (ש-04).

## 2. מה לא

- החלת גרסה חדשה על תיק קיים, עם תצוגת הבדלים — פרוסה 04 (שם יש תיקים).
- "פרופיל משרדי מחייב" — ההגדרה נשמרת כאן; האכיפה בפתיחת תיק — פרוסה 04.

## 3. מודל הנתונים

```
profiles
  id, pid
  scope            recommended | office | personal
  office_id        INT NULL            NULL רק ל-recommended
  owner_user_id    → users             מי יצר; ב-personal — הבעלים
  domain           'real_estate'       הכנה לתחומים נוספים; ערך יחיד כרגע
  name, description
  purposes         JSON                מטרות שומה שהפרופיל מתאים להן
  property_types   JSON
  status           draft | active | archived
  current_version_id → profile_versions NULL     הגרסה המפורסמת האחרונה
  source_version_id  → profile_versions NULL     ממה שוכפל
  is_sample        INT                 "דוגמה — טעון אישור מקצועי"
  created_at, updated_at, deleted_at

profile_versions
  id, pid, profile_id
  number           INT                 1, 2, 3 … רק למפורסמות; הטיוטה = NULL
  state            draft | published
  content          JSON                סעיף 4
  change_note      TEXT NULL
  published_by, published_at
  created_at, updated_at
  UNIQUE(profile_id, number)

profile_shares
  id, pid, profile_id
  grantee_kind     user | office
  grantee_id       INT
  can              view | duplicate | edit
  granted_by, created_at
  revoked_at, revoked_by

office_settings  (מפתח ב-offices.settings)
  required_profile_id   pid NULL       "פרופיל משרדי מחייב" — כבוי כברירת מחדל
```

- **לכל פרופיל טיוטה אחת לכל היותר.** גרסה מפורסמת אינה נערכת לעולם; עריכה =
  טיוטה חדשה שמתחילה כהעתק של האחרונה.
- תיק מפנה ל-`profile_versions.id` (פרוסה 04), ולכן גרסה מפורסמת **אינה נמחקת**,
  גם כשהפרופיל בארכיון.

## 4. תוכן הגרסה (`content`)

מסמך JSON עם `schema` (מספר גרסת המבנה) ומקטעים. הפרוסה הזו מגדירה:

```json
{
  "schema": 1,
  "requirements": {
    "groups": [ { "key": "identity", "title": "זהות וזכויות", "sort": 1 } ],
    "items": [
      {
        "key": "contract",
        "group": "deal",
        "doc_type": "contract",
        "title": "הסכם מכר ונספחיו",
        "explain_recipient": "ההסכם החתום, כולל כל הנספחים",
        "explain_internal": "",
        "priority": "high",
        "mandatory": true,
        "party_kind": "lawyer",
        "due": { "mode": "relative", "days": 3 },
        "needs_review": true,
        "when": null,
        "sort": 1
      }
    ]
  },
  "tasks": {
    "items": [
      { "key": "check_rights", "title": "בדיקת מסמך הזכויות",
        "assignee": "responsible", "due": { "mode": "relative", "days": 5 },
        "when": null, "sort": 1 }
    ]
  },
  "rules": [
    {
      "key": "renovation_quote",
      "title": "שיפוץ מתוכנן — פירוט עבודות",
      "when": { "all": [ { "field": "flags.renovation_planned", "op": "is", "value": true } ] },
      "then": [ { "do": "add_requirement", "item": { "key": "works_quote", "…": "…" } } ]
    }
  ]
}
```

### 4.1 ערכים סגורים

| שדה | ערכים |
| --- | --- |
| `priority` | `high` · `normal` · `low` |
| `party_kind` | `client` · `lawyer` · `bank` · `architect` · `surveyor` · `office` (המשרד עצמו משיג) · `other` |
| `due.mode` | `relative` (ימים מפתיחת התיק) · `manual` (נקבע בתיק) · `none` |
| `assignee` (משימה) | `responsible` · `creator` · `unassigned` |
| `doc_type` | רשימה שמנהל המערכת מנהל (סעיף 4.3) |

### 4.2 תנאים — בלי קוד, בלי ביטויים חופשיים

תנאי הוא עץ של `all` / `any` שעליו עלים `{field, op, value}`. **אין `eval`**, אין
ביטוי טקסטואלי — רק המבנה הזה, והשרת מאמת אותו בשמירה.

| `field` | סוג | הערה |
| --- | --- | --- |
| `purpose` | רשימה | מטרת השומה של התיק |
| `property_type` | רשימה | סוג הנכס |
| `flags.<שם>` | כן / לא | דגלים שהפרופיל עצמו מגדיר (`content.flags`: מפתח, כותרת, שאלה למשתמש) ושמסומנים בפתיחת התיק |
| `party.<kind>` | כן / לא | האם יש בתיק גורם מהסוג הזה |

אופרטורים: `is` · `is_not` · `in` · `not_in`. עומק קינון עד 3.

פעולות ב-`then`: `add_requirement` · `add_task` · `alert` (התרעה לשמאי, עם טקסט).
"דרישת נימוק להחרגה" היא תכונה של הדרישה (`mandatory`), לא פעולת כלל.

### 4.3 סוגי מסמך

טבלת `doc_types` (מפתח, שם, תיאור), נזרעת עם הדוגמאות שבאפיון 7.1 ו-24: הסכם
ונספחים, מסמך זכויות (נסח / אישור זכויות), היתר בנייה, תוכניות, מסמך מדידה, מסמכי
רכישה, הצעת מחיר לשיפוץ, פירוט כמויות, חוזה שכירות, מסמכי מזמין, אחר. מנהל המערכת
מוסיף ועורך; סוג שנמצא בשימוש אינו נמחק — רק מוסתר.

## 5. שלוש הרמות

| רמה | מי רואה | מי עורך את המקור | מי משתמש בפתיחת תיק |
| --- | --- | --- | --- |
| **מומלץ** | כל המשתמשים | **רק מנהל המערכת** 🟢 | כולם |
| **משרדי** | חברי המשרד | מנהל משרד; שמאי שקיבל `edit` | חברי המשרד |
| **אישי** | הבעלים, ומי ששותף | הבעלים; מי שקיבל `edit` | הבעלים, ומי שקיבל `view` ומעלה |

- **שכפול** יוצר פרופיל חדש (אישי, או משרדי למנהל), עם `source_version_id`. העותק
  מנותק מהמקור: שינוי במקור **אינו** מגיע אליו (5.1 באפיון).
- שכפול מומלץ מותר לכל משתמש. שכפול אישי או משרדי — רק עם `duplicate` ומעלה.
- העותק מציג "שוכפל מ: <שם> גרסה N", ואם למקור יש גרסה חדשה יותר — "למקור יש
  גרסה חדשה" (מידע בלבד, בלי כפתור מיזוג).

## 6. שיתוף (האפיון 5.3)

- משתפים פרופיל אישי או משרדי עם **משתמש** (לפי מייל של משתמש קיים) או עם **משרד**.
- שלוש רמות, כל אחת כוללת את קודמותיה: `view` ← `duplicate` ← `edit`.
- לפני אישור — תצוגה מקדימה: מי הנמען, מה יוכל לעשות, ומה **לא** עובר: תיקים,
  לקוחות, מסמכים, סיסמאות, חשבונות הודעות, מפתחות בינה.
- **מה עובר בפועל:** רק `content` — מבנה, נוסחים וכללים. מקטע בפרופיל שמפנה
  לחיבור (ערוץ הודעות, פרוסה 08) עובר כ"סוג ערוץ" בלבד, בלי החיבור עצמו.
- ביטול שיתוף חוסם גישה עתידית; עותק שכבר שוכפל נשאר אצל המשכפל.
- פרופיל **מומלץ** אינו משותף — הוא גלוי לכולם ממילא.

## 7. מסכים (האפיון 25.3)

| נתיב | מסך |
| --- | --- |
| `#/profiles` | הספרייה: לשוניות מומלצים · של המשרד · שלי · שותפו איתי. לכל פרופיל: שם, תיאור, מטרות, סוגי נכס, בעלים, גרסה, מצב. חיפוש וסינון |
| `#/profiles/<pid>` | צפייה: הגרסה המפורסמת, לקריאה בלבד, עם כל המקטעים |
| `#/profiles/<pid>/edit` | העורך: לשוניות **פרטים · מסמכים · משימות · כללים · שיתוף · היסטוריה** (ובהמשך: תהליך ותזכורות, ביקור, מקורות, דוח) |
| `#/profiles/<pid>/try` | תצוגת ניסיון |
| `#/system/doc-types` | סוגי מסמך (מנהל המערכת) |

**העורך:**

- שמירה אוטומטית של הטיוטה; חיווי "נשמר" / "שומר…" / "השמירה נכשלה".
- מסמכים: גרירה לשינוי סדר (עובד במגע), הוספה, שכפול דרישה, מחיקה.
- **"פרסום גרסה"** — לפני הפרסום רצות בדיקות (סעיף 8), מוצג סיכום שינויים מול
  הגרסה הקודמת, ומבוקשת הערת שינוי.
- **היסטוריה:** כל גרסה — מספר, מי פרסם, מתי, הערה, וצפייה בה. השוואה בין שתי גרסאות.

**תצוגת ניסיון:** בוחרים מטרה, סוג נכס, מסמנים דגלים ואילו גורמים יש — ומוצגת
הרשימה שתיווצר: דרישות (עם מי אחראי ומתי), משימות והתרעות. ליד כל פריט שנוסף בכלל
— איזה כלל הוסיף אותו. **שום דבר לא נשמר ושום הודעה לא נשלחת.**

## 8. בדיקות לפני פרסום

חוסמות פרסום (❌) או מזהירות (⚠️):

| בדיקה | רמה |
| --- | --- |
| שני פריטים עם אותו `key` | ❌ |
| תנאי שמפנה לדגל שלא מוגדר, או ערך שאינו ברשימה | ❌ |
| כלל שמוסיף דרישה עם `key` שכבר קיים ברשימה הקבועה | ❌ |
| דרישה בלי כותרת | ❌ |
| דרישה שה-`party_kind` שלה `other` בלי הסבר לנמען | ⚠️ |
| דרישת חובה בלי מועד | ⚠️ |
| שני כללים עם אותו תנאי בדיוק | ⚠️ |
| פרופיל בלי אף דרישה ובלי אף משימה | ⚠️ |

## 9. הרשאות

| פעולה | מי |
| --- | --- |
| צפייה במומלץ | כל משתמש פעיל |
| יצירה, עריכה, פרסום, ארכוב של מומלץ | **מנהל המערכת בלבד** |
| יצירת פרופיל אישי | כל חבר משרד פעיל |
| יצירה ועריכה של פרופיל משרדי | מנהל משרד; חבר עם `edit` על הפרופיל |
| עריכה, פרסום, ארכוב, שיתוף של אישי | הבעלים; `edit` — עריכה ופרסום בלבד, לא שיתוף ולא ארכוב |
| שכפול | לפי סעיף 5 |
| קביעת "פרופיל משרדי מחייב" | מנהל משרד |
| ניהול `doc_types` | מנהל המערכת |

פרופיל אישי **שייך למשרד שבו נוצר** (`office_id`): כשהבעלים עוזב את המשרד, הפרופיל
נשאר במשרד כפרופיל משרדי בארכיון, ומנהל המשרד יכול להחזיר אותו לפעיל.

## 10. מקרי קצה

1. **שני אנשים עורכים את אותה טיוטה.** כל שמירה שולחת את `updated_at` שקראה; אם
   השתנה בינתיים ← "הטיוטה עודכנה בידי <שם>", עם "טעינה מחדש" או "שמירה כעותק".
   אין דריסה שקטה.
2. **ארכוב פרופיל שתיקים פתוחים משתמשים בו.** מותר; התיקים ממשיכים עם הגרסה שלהם.
   הפרופיל נעלם מבחירה בתיק חדש.
3. **מחיקת פרופיל.** רק טיוטה שלא פורסמה לעולם נמחקת באמת. כל השאר — ארכוב.
4. **המקור המומלץ נמחק או אורכב אחרי שכפול.** העותק לא מושפע; "שוכפל מ:" מציג את
   השם עם "(בארכיון)".
5. **שיתוף עם מייל שאין לו חשבון.** "לא נמצא משתמש בכתובת הזו" — הפרוסה אינה
   מזמינה משתמשים.
6. **`edit` שותף למישהו שעזב את המשרד שלו.** השיתוף הוא למשתמש, ולכן נשאר; בעל
   הפרופיל רואה אותו ברשימת השיתופים ויכול לבטל.
7. **ייבוא מבנה גדול מדי.** עד 300 דרישות, 100 משימות, 100 כללים לגרסה; מעבר לזה
   — שגיאה ברורה.
8. **`content` עם `schema` ישן** (אחרי שפרוסה מאוחרת הוסיפה מקטע). קורא ישן מתעלם
   ממקטע שאינו מכיר; מיגרציית תוכן רצה בקריאה ואינה משנה גרסאות מפורסמות.
9. **דגל נמחק מהפרופיל אבל כלל משתמש בו.** נחסם בבדיקות הפרסום.
10. **משתמש בשני משרדים.** הספרייה מציגה את הפרופילים של המשרד הפעיל בלבד (ואת
    המומלצים).

## 11. קריטריוני קבלה

- **03-A1** 🤖 מי שאינו מנהל המערכת אינו יכול ליצור, לערוך, לפרסם או לארכב פרופיל
  מומלץ (כל פעולה בנפרד). *(בדיקת קבלה 25)*
- **03-A2** 🤖 שכפול מומלץ יוצר פרופיל אישי עם `source_version_id`; עריכת העותק
  אינה משנה את המקור, ופרסום גרסה חדשה במקור אינו משנה את העותק. *(25)*
- **03-A3** 🤖 גרסה מפורסמת אינה ניתנת לעדכון בשום פעולת API.
- **03-A4** 🤖 פרסום יוצר `number` עוקב, ו-`current_version_id` מצביע עליו; נפתחת
  אפשרות לטיוטה חדשה שמתחילה כהעתק.
- **03-A5** 🤖 כל בדיקה מסעיף 8 שמסומנת ❌ אכן חוסמת פרסום (בדיקה לכל שורה).
- **03-A6** 🤖 תנאי עם מבנה לא מוכר, שדה לא מוכר, או עומק מעל 3 ← נדחה בשמירה.
- **03-B1** 🤖 תצוגת ניסיון: עם הדגל `renovation_planned` — הדרישה שהכלל מוסיף
  מופיעה, מסומנת בשם הכלל; בלי הדגל — לא מופיעה. אחרי הקריאה אין שום שורה חדשה
  בשום טבלה.
- **03-B2** 🤖 שני פרופילים עם רשימות שונות מחזירים בתצוגת ניסיון רשימות שונות
  לאותו קלט. *(5)*
- **03-C1** 🤖 משתמש עם `view` רואה ואינו יכול לשכפל או לערוך; עם `duplicate` —
  משכפל ואינו עורך את המקור; עם `edit` — עורך ומפרסם, ואינו יכול לשתף או לארכב. *(7)*
- **03-C2** 🤖 תשובת השיתוף והפרופיל המשוכפל אינם מכילים שום שדה מחוץ ל-`content`
  ולפרטי הפרופיל (בדיקה: אין מפתחות `office_id` זר, אין מזהי תיקים, אין חיבורים). *(7)*
- **03-C3** 🤖 אחרי ביטול שיתוף ← 404 לנמען; העותק שכבר שוכפל נשאר שלו.
- **03-C4** 🤖 **בידוד:** משתמש ממשרד ב׳ מבקש פרופיל משרדי או אישי של משרד א׳ שלא
  שותף איתו ← 404; הוא אינו מופיע בחיפוש שלו.
