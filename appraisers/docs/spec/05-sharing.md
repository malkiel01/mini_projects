# 05 — שיתוף: שמאי ממשרד אחר, גישת תמיכה, וביטול

**תלויה ב-04.** האפיון: 3.3, 18.1, 22.5; דרישות 02, 05, 06; בדיקות קבלה 2, 29.
(שיתוף עם לקוח ועורך דין בפורטל — פרוסה 07.)

## 1. מה בונים

1. הזמנת **שמאי ממשרד אחר** לתיק אחד — בלי לחשוף שום דבר אחר מהמשרד.
2. **גישת תמיכה** למנהל המערכת: רק בשיתוף יזום של הלקוח, מוגבלת בפריטים, בפעולות ובזמן.
3. שיתוף ברמת **כל התיק** או **פריטים נבחרים**.
4. תצוגה מקדימה לפני כל שיתוף; תוקף; ביטול; תיעוד.
5. אכיפה אחידה בכל נקודת גישה: רשימות, חיפוש, קבצים, תמונות ממוזערות, קישורים
   ישירים, התראות.

## 2. מודל הנתונים

```
case_members  (+)
  kind              internal | cross_office | support
  scope             all | items
  expires_at        NULL                חובה ל-support
  home_office_id    INT NULL            המשרד של השותף (ל-cross_office)
  invite_status     pending | active | declined
  reason            TEXT NULL           למה שותף (חובה ל-support)

case_member_items                        כש-scope = items
  member_id
  item_type         requirement | file | visit | source_check | comps | report
  item_pid          TEXT NULL           NULL = כל הפריטים מהסוג

share_previews                           מה הוצג למשתף רגע לפני האישור
  id, case_id, by_user_id, summary JSON, confirmed_at
```

`perms` נשאר כמו בפרוסה 04, עם שלוש תוספות: `download` (הורדת קבצים),
`see_internal` (הערות פנימיות ותחשיבים), `see_draft` (טיוטת דוח).
**שלושתן כבויות כברירת מחדל לכל מי שאינו `internal`** (3.3).

## 3. שמאי ממשרד אחר

1. בעל `members` בתיק מזין **מייל של משתמש קיים במערכת**. לא נמצא ← "לא נמצא
   משתמש בכתובת הזו. הוא צריך להירשם למערכת קודם." (בלי לחשוף אם הכתובת קיימת
   כחבר במשרד כלשהו — רק אם יש חשבון.)
2. בוחר היקף: **כל התיק** או **פריטים**; ופעולות. ברירת המחדל (ש-07): `view` בלבד.
3. בוחר תוקף: ללא הגבלה / 30 / 90 ימים 🟡.
4. **תצוגה מקדימה** — הנמען, המשרד שלו, מה יראה, מה יוכל לעשות, מה **לא** יראה
   (שאר תיקי המשרד, פרופילים, הערות פנימיות, טיוטת הדוח — אלא אם סומנו), ומתי פג.
5. אישור ← `invite_status = pending`. השותף רואה בלוח שלו "הוזמנת לתיק <מספר>
   ממשרד <שם>" ומאשר או דוחה. עד האישור — אין לו גישה.

**מה השותף רואה אחרי אישור:**

- התיק מופיע אצלו בלשונית נפרדת, "תיקים ששותפו איתי", **בכל משרד פעיל שלו** —
  מסומן בשם המשרד הבעלים. הוא אינו מתערבב בתיקי המשרד שלו.
- הוא פועל בתיק לפי `perms` בלבד. `members`, `approve_report` ו-`export` **אינם
  ניתנים להענקה** לשותף ממשרד אחר בפרוסה הזו 🟡 (22.5: "יכולת אישור דוח אינה
  נגזרת אוטומטית").
- שום API של המשרד הבעלים (צוות, פרופילים, ספר כתובות, תיקים אחרים) אינו נגיש לו.
- התיק **שייך למשרד שפתח אותו**; השיתוף אינו מעביר בעלות.

## 4. גישת תמיכה למנהל המערכת 🟢

מנהל המערכת **אינו יכול לבקש, ליצור או להרחיב** גישה. רק הלקוח יוזם:

1. בכרטיס התיק, "🛟 שיתוף עם התמיכה" — זמין לבעל `members` (השמאי האחראי).
2. בוחר: אילו פריטים (ברירת מחדל: **שום פריט** — חייבים לבחור), אילו פעולות
   (ברירת מחדל: `view` בלבד; `download` ניתן לסימון; **עריכה אינה ניתנת**), תוקף
   (יום / 7 / 30 ימים — **אין "ללא הגבלה"**), ונימוק קצר.
3. תצוגה מקדימה, ואישור חוזר (פעולה רגישה, פרוסה 02).
4. מנהל המערכת רואה ב-`#/system/support` את התיקים ששותפו איתו, עם ההיקף והתוקף.

- **אי אפשר להעניק יותר ממה שלמשתף עצמו יש.** משתף בלי `download` אינו יכול לתת
  `download`.
- הגישה פגה לבד; אפשר לבטל בכל רגע; אפשר להאריך — בפעולה חדשה, עם תצוגה מקדימה.
- כל צפייה של מנהל המערכת בפריט משותף נרשמת ביומן הפעולות של המשרד
  (`support.view`), והלקוח רואה "מי צפה ומתי".
- כשאין שיתוף פעיל — מנהל המערכת מקבל על כל תיק את אותו 404 כמו כל זר.

## 5. ביטול ותפוגה

- ביטול בידי בעל `members`; תפוגה — אוטומטית, נבדקת **בכל בקשה** (לא מחכים
  לשירות רקע). שירות רקע רק מסמן ומתריע.
- אחרי ביטול: כל בקשה ← 404. התיק נעלם מהרשימות ומהחיפוש של השותף.
- **המסך אומר במפורש** בזמן הביטול: "הביטול חוסם גישה מעתה. קבצים שכבר הורדו, או
  מידע שנשמר במכשיר מנותק, אינם נמחקים מרחוק." (3.3)
- 3 ימים לפני תפוגה — התראה למשתף.

## 6. אכיפה — רשימת הנקודות

פונקציה אחת מכריעה: `can(user, case, action, item?)`. היא נקראת בכל אחת מהנקודות,
ובכל פרוסה שמוסיפה נקודת גישה:

| נקודה | מה נבדק |
| --- | --- |
| רשימת תיקים, לוח ראשי, "המשימות שלי" | רק תיקים עם שורת חבר פעילה שלא פגה |
| חיפוש | כנ"ל; ובשיתוף `items` — רק בפריטים ששותפו |
| כרטיס תיק | לשונית מוצגת רק אם יש בה פריט מותר |
| קובץ, תמונה ממוזערת, תצוגה מקדימה, הורדה | `can` על הקובץ עצמו; `download` להורדה |
| קישור ישיר לפריט | כמו פתיחה רגילה — אין "קישור שיודעים אותו" |
| התראות ומיילים | לא נשלחת התראה על פריט שהנמען אינו רשאי לראות; הנוסח אינו כולל שם קובץ או שם גורם |
| הודעות שגיאה | זהות לאסור ולחסר |
| פעולת בינה (פרוסה 11) | רק על פריטים שלמפעיל יש בהם `view`; שותף חיצוני אינו מפעיל בינה על חשבון המשרד הבעלים |

## 7. מסכים

| נתיב | מסך |
| --- | --- |
| כרטיס תיק ← **גורמים והרשאות** | משתתפים פנימיים · שותפים ממשרדים אחרים · תמיכה — לכל אחד: היקף, פעולות, תוקף, מי הוסיף, "עריכה", "ביטול" |
| חלון "שיתוף" | נמען ← היקף ← פעולות ← תוקף ← **תצוגה מקדימה** ← אישור |
| `#/cases?tab=shared` | תיקים ששותפו איתי |
| `#/system/support` | גישות התמיכה הפעילות (מנהל המערכת) |
| כרטיס תיק ← פעילות | כל שיתוף, שינוי, ביטול וצפיית תמיכה |

## 8. מקרי קצה

1. **השותף עזב את המשרד שלו.** השיתוף הוא לאדם, ולכן נשאר; `home_office_id`
   מתעדכן להצגה. המשתף רואה "אינו עוד במשרד <שם>" ויכול לבטל.
2. **השותף הושעה במערכת.** אין גישה (ההשעיה גוברת).
3. **המשרד הבעלים הושעה.** אין גישה לאף אחד, כולל שותפים.
4. **המשתף איבד את `members`.** שיתופים שיצר נשארים; האחראי החדש רואה אותם.
5. **שיתוף פריט שנמחק אחר כך.** השורה ב-`case_member_items` נשארת ואינה מחזירה דבר.
6. **שיתוף `items` עם סוג שלם** (כל הקבצים). קבצים שיתווספו **אחרי** השיתוף —
   נכללים; התצוגה המקדימה אומרת זאת.
7. **אותו אדם מוזמן פעמיים.** שורה פעילה אחת; הזמנה שנייה מעדכנת, עם תצוגה מקדימה.
8. **שותף ממשרד אחר הוא גם מנהל המערכת.** שתי שורות נפרדות אינן נוצרות; הוא שותף
   רגיל (`cross_office`), וכללי התמיכה אינם חלים.
9. **תפוגה באמצע עבודה.** הבקשה הבאה ← 404; מה שלא נשמר אבד, והמסך מפנה ללוח.
10. **ניסיון להעניק `edit` לתמיכה** דרך ה-API ← נדחה, גם אם הממשק לא מציע.

## 9. קריטריוני קבלה

- **05-A1** 🤖 שותף ממשרד ב׳ עם `view` על תיק אחד: רואה אותו; **כל** פעולה אחרת של
  משרד א׳ (תיקים אחרים, צוות, פרופילים, ספר כתובות, חיפוש) ← 404 או ריק. *(2)*
- **05-A2** 🤖 עד שהשותף מאשר את ההזמנה — אין לו גישה.
- **05-A3** 🤖 שיתוף `items` עם קובץ אחד: הקובץ נגיש; קובץ אחר באותו תיק ← 404, גם
  בתמונה ממוזערת וגם בהורדה ישירה לפי `pid`.
- **05-A4** 🤖 שותף בלי `download` ← הורדה נדחית; בלי `see_internal` ← הערות פנימיות
  אינן בתשובה; בלי `see_draft` ← טיוטת הדוח אינה בתשובה.
- **05-A5** 🤖 `members`, `approve_report`, `export` אינם ניתנים להענקה ל-`cross_office`.
- **05-B1** 🤖 מנהל המערכת בלי שיתוף ← 404 על כל תיק ועל כל קובץ. *(29)*
- **05-B2** 🤖 אין שום פעולת API שבה מנהל המערכת יוצר או מרחיב שיתוף לעצמו. *(29)*
- **05-B3** 🤖 שיתוף תמיכה: בלי תוקף ← נדחה; בלי פריטים ← נדחה; עם `edit` ← נדחה;
  בלי נימוק ← נדחה.
- **05-B4** 🤖 המשתף אינו יכול להעניק הרשאה שאין לו.
- **05-B5** 🤖 צפיית תמיכה בפריט כותבת `support.view` ביומן של המשרד. *(29)*
- **05-B6** 🤖 אחרי `expires_at` ← 404, **בלי** שרץ שירות רקע.
- **05-C1** 🤖 אחרי ביטול ← 404 בכל נקודה מסעיף 6, והביטול ביומן. *(4, 29)*
- **05-C2** 🤖 התראה על קובץ חדש אינה נשלחת לשותף שהקובץ אינו בהיקף שלו.
- **05-C3** 🤖 החיפוש של שותף `items` אינו מחזיר התאמה מפריט שלא שותף.
- **05-D1** 👁 התצוגה המקדימה מציגה נמען, היקף, פעולות ותוקף, ואת מה שלא ייחשף.
- **05-D2** 👁 בזמן ביטול מוצגת האזהרה על עותקים שכבר הורדו.
- **05-D3** 👁 הלקוח רואה בלשונית הפעילות מי מהתמיכה צפה, במה ומתי.
