# 09 — מקורות מידע, בדיקות, תכנון והיתרים (המסלול הידני)

**תלויה ב-04.** האפיון: פרקים 9, 10.1, 28; מחקר הרשויות: כולו; דרישות 17, 18, 19;
בדיקות קבלה 13, 14, 26.

הפרוסה בונה את **המסגרת** לכל מקור חיצוני, ואת **המסלול הידני** שעובד תמיד: לפתוח
את האתר, לבדוק, לרשום מה נמצא, ולצרף. חיבור אוטומטי ומפה — פרוסה 20, ורק אחרי
בדיקת היתכנות.

## 1. מה בונים

1. **קטלוג מקורות** — כרטיס לכל מקור, בניהול מנהל המערכת.
2. **בדיקות בתיק** — לכל מקור רלוונטי: מה נבדק, מתי, בידי מי, ומה התוצאה.
3. מצבי בדיקה שמבחינים בין "לא נמצא" ל"לא קיים".
4. **רשימת תכנון והיתרים** — תוכנית, בקשה, החלטה והיתר כפריטים נפרדים.
5. מקטע **"מקורות"** בפרופיל: אוטומטי / ביוזמת השמאי, לכל מקור.
6. רישום הוצאה על מקור בתשלום (המערכת אינה משלמת).

## 2. מה לא

- שום קריאה אוטומטית לשום אתר חיצוני. גם "אוטומטי" בפרופיל פירושו כאן: **נוצרת
  משימה לבד**.
- מפה, גאוקודינג, שכבות — פרוסה 20.
- עסקאות השוואה — פרוסה 15 (המקור "רשות המסים" רשום כאן בקטלוג).

## 4. הקטלוג (האפיון 9.1, 28.1; מחקר הרשויות 2, 13.2)

## 5. מצבי בדיקה (האפיון 9.3; מחקר הרשויות 12)

| מצב | מתי | מוצג כ- |
| --- | --- | --- |
| `not_checked` | ברירת המחדל | לא נבדק |
| `planned` | נוצרה משימה | מתוכנן |
| `awaiting_identification` | אין מזהה נכס מספיק | ממתין לזיהוי |
| `needs_approval` | נדרש אישור או תשלום לפני פעולה | נדרש אישור |
| `in_progress` | המשתמש התחיל | בתהליך |
| `found` | נמצאה תוצאה | אותר |
| `partial` | נבדק חלקית | הושלם חלקית |
| `not_found` | אין תוצאה **בבדיקה ובמקור האלה** | לא אותר במקור שנבדק |
| `unavailable` | המקור לא היה זמין | מקור לא זמין |
| `needs_login` | המשתמש לא הצליח להזדהות | דורש הזדהות |
| `needs_clarification` | התוצאה לא ברורה | דורש בירור |
| `failed` | תקלה | נכשל |
| `verified` | גורם מורשה אימת | נבדק ואומת |

### הכלל שאסור לשבור 🟢

**`not_found` ו-`unavailable` אינם תוצאה שלילית.** בכל מקום שהם מוצגים — במסך,
בחיפוש, ובדוח — מופיע לצידם, **תמיד וללא אפשרות הסתרה**:

- `not_found`: "לא נמצאה תוצאה בבדיקה הזו, במקור הזה. אין בכך הוכחה שאין זכות,
  תוכנית, היתר או עבירה."
- `unavailable`: "המקור לא היה זמין. לא נבדק."

אין בקוד שום מיפוי של אחד מהמצבים האלה לערך בוליאני "אין".

**כללים נוספים:**

- `not_found` דורש `coverage_note` — מה בדיוק חיפשו.
- `unavailable`, `needs_login`, `failed` ← נוצרת **משימת השלמה ידנית** (בדיקת קבלה 13).
- `verified` — רק בעל `sources` שהוא שמאי (האחראי או שותף); נרשם מי ומתי.
- בדיקה אינה נמחקת — בדיקה חדשה לאותו מקור היא שורה חדשה; ההיסטוריה נשמרת.

## 6. המסלול הידני (האפיון 9.1, 28.2)

בלשונית "מקורות ותכנון" השמאי רואה את המקורות הרלוונטיים לתיק — הארציים, ואלה של
הרשות לפי היישוב שבמזהי הנכס — ולכל אחד את הבדיקה האחרונה.

1. **"פתיחת המקור"** — נפתח האתר הרשמי בלשונית חדשה; במערכת מוצגות ההוראות
   (`how_to`), המזהים של התיק להעתקה, ומה צריך להזדהות או לשלם.
2. המשתמש בודק **בעצמו, באתר המקור**. המערכת אינה מבקשת, אינה שומרת ואינה מעבירה
   סיסמה, קוד חד-פעמי או פרטי תשלום — **אין שדה כזה בשום מסך** 🟢.
3. **"רישום התוצאה"** — מצב, מה נבדק (אילו מזהים), טווח הכיסוי, סיכום, קישור,
   קובץ מצורף, ומגבלה.
4. קובץ מצורף עובר את צינור הקליטה (פרוסה 06), ואפשר לשייכו לדרישה.

**מקור בתשלום** (28.3): הכרטיס אומר שהגישה בתשלום ומי משלם (המשתמש, באתר המקור).
פתיחת הדף **אינה** פעולה מחייבת. אחרי הבדיקה אפשר לרשום את ההוצאה (`cost_amount`)
לצורכי התיק. אם הפרופיל דורש אישור להוצאה ← המצב `needs_approval` עד שהשמאי
האחראי מאשר.

**שמירת קישור או קובץ** — רק כש-`license.store` אינו `no`. כשהוא `no`: נשמר רק
הקישור ("הפניה בלבד"). כשהוא `unknown`: מותר, עם אזהרה: "תנאי השימוש של המקור לא
נבדקו. ודאו שמותר לכם לשמור את המסמך."

## 7. תכנון והיתרים (האפיון 10.1, דרישה 19, בדיקת קבלה 14)

רשימה אחת בתיק, שבה **כל סוג הוא סוג**:

| `kind` | מוצג כ- |
| --- | --- |
| `plan` | תוכנית |
| `application` | **בקשה להיתר** |
| `decision` | החלטה |
| `permit` | **היתר שהונפק** |
| `building_doc` | מסמך מתיק הבניין |
| `enforcement` | רישום פיקוח |

- **בקשה אינה היתר.** אין פעולה שהופכת `application` ל-`permit`; היתר הוא פריט
  חדש, ואפשר לקשר ביניהם.
- `status_reported` הוא טקסט **כפי שהמקור דיווח** — המערכת אינה מתרגמת אותו למצב
  משלה.
- **תחולה** (`applicability`) — מתחילה `unknown`, ורק שמאי קובע אותה, עם הערה.
- **רשימה ריקה** מציגה: "לא נרשמו פריטים. רשימה ריקה אינה מעידה שאין תוכנית, היתר
  או הליך — ראו אילו מקורות נבדקו." עם קישור לבדיקות.
- **אין שדה "עבירת בנייה" ואין שדה "חוקי".** אפשר לרשום `enforcement` (מה נמצא
  במקור), ואפשר לפתוח משימת "אי התאמה אפשרית" — לא יותר מזה. היעדר רישום פיקוח
  אינו מוצג כ"אין עבירה".

## 8. מקטע "מקורות" בפרופיל (מחקר הרשויות 12, בדיקת קבלה 26)

```json
"sources": {
  "items": [
    { "source": "xplan",               "mode": "auto",   "when": null },
    { "source": "tax_authority_deals", "mode": "manual", "when": null },
    { "source": "tabu_extract",        "mode": "ask",    "when": null }
  ],
  "spend_needs_approval": true
}
```

| `mode` | מה קורה בפתיחת תיק |
| --- | --- |
| `auto` | אם למקור חיבור מאושר (פרוסה 20) — רץ. **אחרת — נוצרת משימה לבדיקה ידנית.** הבדיקה `planned` |
| `manual` | המקור מופיע בתיק כ"לא נבדק"; אין משימה |
| `ask` | נוצרת משימה, והבדיקה `needs_approval` עד שהשמאי מאשר |

**הגדרה אינה יוצרת חיבור.** מקור שדרך הגישה שלו `guided` או `manual` לעולם אינו
מוצג כ"מחובר" בגלל ש-`mode` הוא `auto`.

לפני כל הפעלה: יש מזהה נכס מספיק (אחרת `awaiting_identification`); המקור `active`;
למשתמש `sources`.

## 9. מסכים (האפיון 25.5)

## 11. מקרי קצה

1. **התיק בלי יישוב.** מוצגים רק המקורות הארציים, ו"הוסיפו יישוב כדי לראות את
   מקורות הרשות המקומית".
2. **יישוב שאין לו כרטיס.** הכרטיס הכללי "רשות מקומית אחרת".
3. **נכס על שתי חלקות.** `query` מחזיק את שתיהן; הבודק מסמן אילו נבדקו. בדיקה שכיסתה
   רק אחת ← `partial`.
4. **מזהים השתנו אחרי בדיקה.** הבדיקה נשארת עם ה-`query` המקורי, ומסומנת "נעשתה
   לפני שינוי המזהים".
5. **מקור הוסתר בקטלוג.** בדיקות קיימות נשארות ומוצגות; אי אפשר לפתוח חדשה.
6. **אותו מסמך לשתי בדיקות.** מותר.
7. **משתמש מסמן `found` בלי קישור ובלי קובץ.** מותר, עם סיכום חובה; מוצג "בלי
   אסמכתא מצורפת".
8. **רישום כפול של אותו היתר.** אותו `kind` ואותו `ref_number` בתיק ← התרעה
   ("קיים כבר"), בלי חסימה.
9. **הוצאה של 0.** `cost_amount = 0` פירושו "ללא עלות"; `NULL` פירושו "לא נרשם".
10. **פרופיל מפנה למקור שהוסר מהקטלוג.** מתעלמים בפתיחת התיק, ומתריעים בעורך הפרופיל.

## 12. קריטריוני קבלה

- **09-A1** 🤖 רישום `unavailable` ← נוצרת משימת השלמה ידנית; **אין** בשום תשובה של
  התיק שדה שמסיק "אין היתר". *(13)*
- **09-A2** 🤖 כל תשובת API שמחזירה בדיקה במצב `not_found` או `unavailable` כוללת את
  נוסח ההסתייגות. *(13, 14)*
- **09-A3** 🤖 `not_found` בלי `coverage_note` ← נדחה.
- **09-A4** 🤖 אין פעולת API שמשנה `kind` של פריט תכנון מ-`application` ל-`permit`. *(14)*
- **09-A5** 🤖 רשימת פריטים שיש בה רק `application` — בתשובה אין אף פריט `permit`,
  ובסיכום "היתרים: 0 נרשמו" מופיע עם ההסתייגות. *(14)*
- **09-A6** 🤖 בסכימה אין עמודה בוליאנית של "עבירה" / "חוקי" / "אין היתר" (בדיקה
  על מבנה הטבלאות).
- **09-A7** 🤖 בדיקה חדשה לאותו מקור אינה מעדכנת את הקודמת.
- **09-B1** 🤖 פרופיל עם `auto` למקור שדרך הגישה שלו `guided` ← נוצרת משימה; הבדיקה
