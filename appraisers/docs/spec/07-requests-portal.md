# 07 — בקשות ופורטל לנמען

**תלויה ב-06.** האפיון: 8.1, 22.3, 25.4; דרישה 13; בדיקות קבלה 3, 4.

השמאי שולח לגורם חיצוני בקשה למסמכים; הנמען נכנס בקישור אישי לפורטל מוגבל, רואה
רק את מה שהוקצה לו, ומעלה. **לנמען אין חשבון** — לא כאן ולא במעטפת (`auth.md` §1).

## 1. מה בונים

1. הרכבת בקשה: נמען, דרישות, פעולות מותרות, תוקף, נוסח — ותצוגה מקדימה.
2. שליחה במייל, או קישור להעתקה (לשליחה ידנית בכל ערוץ).
3. הפורטל: דף ציבורי נפרד, בלי ניווט למערכת.
4. הזדהות לפי רגישות: קישור, ובנוסף קוד חד-פעמי למייל.
5. בפורטל: העלאה, הערה, "אין ברשותי", ומצב קבלה.
6. ביטול, תפוגה, שליחה מחדש.
7. יומן הודעות יוצאות, עם מצב אמיתי לכל אחת.

## 2. מה לא

- תזכורות אוטומטיות, מסרון, WhatsApp, קליטה נכנסת — פרוסה 08.
- הפורטל **אינו** מציג את התיק, גורמים אחרים, או את הדוח.

## 3. מודל הנתונים

```
requests
  id, pid, office_id, case_id
  party_id           → case_parties
  perms              JSON  { upload, view_own, download_own, reply }
  subject, body      TEXT              הנוסח כפי שנשלח
  expires_at
  status             draft | active | revoked | expired | completed
  created_by, created_at, revoked_at, revoked_by

request_items
  request_id, requirement_id

portal_links                            אסימון הגישה
  id, request_id
  token_hash         TEXT UNIQUE        רק ה-hash
  created_at, expires_at, revoked_at
  last_used_at, use_count

portal_devices                          מכשיר שעבר קוד חד-פעמי
  id, link_id
  device_hash        TEXT               hash של עוגיית המכשיר
  verified_at, expires_at

portal_otps
  id, link_id, code_hash
  attempts, expires_at, used_at

messages                                כל הודעה יוצאת (ובפרוסה 08 — גם נכנסת)
  id, pid, office_id, case_id
  request_id NULL, party_id NULL
  direction          out
  channel            email | link_copy
  to_hash            TEXT               hash של היעד; היעד עצמו נקרא מאיש הקשר
  status             planned | sent | delivered | failed | unknown
  provider_ref, error
  idempotency_key    TEXT UNIQUE
  created_by, created_at, sent_at

requirement_responses                   מה הנמען ענה
  id, pid, requirement_id, party_id, request_id
  kind               no_document | comment
  text
  created_at
```

## 4. הרכבת בקשה ושליחה (האפיון 8.1, 22.3)

1. **נמען** — גורם מהתיק, או חדש. מוצגים פרטי הקשר שלו, והמשתמש **מאשר אותם**
   (תיבת סימון: "הכתובת נכונה"). בלי מייל — רק "קישור להעתקה".
2. **דרישות** — מסמנים מתוך דרישות התיק. ברירת המחדל: אלה שמוקצות לגורם הזה.
3. **פעולות** — `upload` (דלוק) · `reply` (דלוק) · `view_own` — לראות מה שהוא עצמו
   העלה (דלוק) · `download_own` (כבוי).
4. **תוקף** — 30 יום (אפשר לשנות: 7 / 14 / 30 / 90).
5. **נוסח** — נושא וגוף, מתבנית של המערכת; ניתן לעריכה. (תבניות בפרופיל — פרוסה 08.)
6. **תצוגה מקדימה** 🟢 — בדיוק מה שיישלח: השולח כפי שיופיע (ש-36), הנמען, הנוסח,
   רשימת הדרישות עם ההסבר לנמען, מה יוכל לעשות, ועד מתי. **אין שליחה בלי המסך הזה.**
7. **שליחה** ← נוצרים `requests`, `portal_links` ו-`messages`; הדרישות עוברות
   ל-`requested`.

**המייל:** שם המשרד, הנוסח, וקישור אחד. **בלי** קבצים מצורפים, בלי פרטי הנכס מעבר
למה שהשמאי כתב בנוסח, ובלי שמות גורמים אחרים.

**"קישור להעתקה":** הקישור מוצג למשתמש פעם אחת, להדבקה היכן שירצה. נרשמת הודעה
בערוץ `link_copy` במצב `unknown` — **המערכת אינה יודעת אם נמסר**, והמסך אומר זאת.

**מצבי הודעה:** `sent` = `mail()` קיבל את ההודעה. **זו אינה מסירה** — המסך כותב
"נשלח", לא "התקבל". `failed` מוצג באדום בתיק ובלוח הראשי. `delivered` שמור לספק
שמדווח (פרוסה 08).

## 5. הפורטל

דף נפרד: `portal/index.html`, עם JavaScript ו-CSS משלו. **אינו טוען את קוד המערכת**,
ואין בו שום קישור אליה. כתובת: `…/appraisers/portal/#<אסימון>` — האסימון אחרי `#`,
כדי שלא יירשם ביומני השרת; הדף שולח אותו בגוף הבקשה.

### 5.1 הזדהות (ש-10)

| מה הנמען רוצה | מה נדרש |
| --- | --- |
| לראות את רשימת הדרישות ולהעלות קובץ | הקישור בלבד |
| לראות או להוריד קובץ שכבר הועלה (`view_own` / `download_own`) | הקישור **+ קוד חד-פעמי** למייל שלו, פעם אחת לכל מכשיר |

- הקוד: 6 ספרות, 10 דקות, 5 ניסיונות; אחריהם הקישור נחסם לרבע שעה.
- מכשיר שאומת נזכר 30 יום (עוגייה `apr_portal`, נתיב הפורטל בלבד).
- לנמען בלי מייל (קישור להעתקה בלבד) — `view_own` ו-`download_own` **אינם זמינים**.
- הגדרת משרד: "תמיד לדרוש קוד" — כבויה כברירת מחדל.

### 5.2 מה הנמען רואה (האפיון 25.4)

- כותרת: שם המשרד, ושם השמאי השולח.
- ההסבר שנכתב בבקשה.
- לכל דרישה: כותרת, **ההסבר לנמען**, יעד, מצב במילים פשוטות, ופעולה:
  - **"העלאת קובץ"** — אחד או יותר; מצלמה בטלפון.
  - **"אין ברשותי את המסמך"** — עם שדה הסבר.
  - **"הערה"**.
- אחרי העלאה: **"הקובץ התקבל. המשרד יבדוק אותו."** — אישור קבלה טכני בלבד, ונאמר
  במפורש שזו אינה בדיקה.
- דרישה שהוחזרה: סיבת ההחזרה שהבודק כתב לנמען, ואפשרות להעלות שוב.

**מצבים בעיני הנמען** (מיפוי, לא חשיפה של המצב הפנימי):

| פנימי | בפורטל |
| --- | --- |
| `requested` | "ממתין למסמך" |
| `received` | "התקבל — בבדיקה" |
| `returned` | "נדרשת השלמה", עם הסיבה |
| `approved` | "התקבל" |
| `not_relevant` | הדרישה נעלמת מהרשימה |

### 5.3 מה הנמען **אינו** רואה, אף פעם

מספר התיק, כתובת הנכס, גורמים אחרים, דרישות של אחרים, קבצים שאחרים העלו, הערות
פנימיות, נתונים שחולצו, מקורות, עסקאות, דוח. ה-API של הפורטל מחזיר **רק** את
הדרישות שב-`request_items`, ורק את הקבצים שהועלו **דרך הבקשה הזו**.

### 5.4 קישור שאינו עובד

פג, בוטל, או לא קיים ← **אותו מסך בדיוק**: "הקישור אינו בתוקף. לקבלת קישור חדש,
פנו למשרד ששלח אותו." בלי שם המשרד, בלי פרטי קשר — מי שיש לו את המייל המקורי
יודע למי לפנות.

### 5.5 העלאה בפורטל

אותו צינור קליטה של פרוסה 06 (סעיף 4), עם `uploader_kind = recipient`,
`channel = portal`. הדרישה עוברת ל-`received`. השמאי רואה **מי העלה, מתי, ובאיזה
ערוץ** (22.3).

## 6. מה קורה אצל המשרד

- **"אין ברשותי"** ← נרשמת תשובה, ונוצרת **משימת המשך** לשמאי ("הלקוח הודיע שאין
  ברשותו <מסמך>"). **הדרישה אינה נסגרת** ואינה הופכת ל-`not_relevant` — זו החלטה
  של השמאי (22.3).
- **הערה** ← מופיעה בדרישה, ומשימה אם סומן בפרופיל.
- **קובץ** ← "מסמכים שהתקבלו" בלוח הראשי.
- **הודעה שנכשלה** ← מוצגת בתיק ובלוח, עם: "עדכון פרטי קשר", "שליחה מחדש", "העתקת
  קישור", "ביטול הגישה". **הודעה שנכשלה אינה מקדמת שום דרישה** — הדרישות שהיו
  `required` חוזרות ל-`required`.
- כל הדרישות של הבקשה אושרו או סומנו לא רלוונטי ← הבקשה `completed`; הקישור נשאר
  תקף עד התפוגה, לצפייה במצב.

## 7. ביטול, תפוגה, שליחה מחדש (בדיקת קבלה 4)

- **ביטול** — מיידי; נבדק בכל בקשה של הפורטל. נרשם ביומן. המסך מזכיר: "עותקים
  שכבר הורדו אינם נמחקים".
- **תפוגה** — נבדקת בכל בקשה.
- **שליחה מחדש** — יוצרת קישור חדש **ומבטלת את הקודם**. מכשירים שאומתו — נשכחים.
- **שינוי המייל של הנמען** ← כל הקישורים הפעילים שלו מבוטלים, ונדרשת שליחה מחדש.
- הסרת גורם מהתיק ← כל הבקשות שלו מבוטלות.

## 8. `app.json` — כתובות ציבוריות

```
"portal/", "portal/**",
"api.php?action=…|portal-open|portal-otp-send|portal-otp-verify|portal-upload|portal-respond|portal-file|portal-client-error"
```

**לבדוק בחלון גלישה בסתר**, ולעבור על כל `fetch` שבדף הפורטל מול הרשימה —
פעולה שחסרה נחסמת בשקט ב-401, ומי שבודק כשהוא מחובר למעטפת לא רואה את התקלה.

כל פעולת `portal-*` מאמתת את האסימון בעצמה, ואינה קוראת את `PLATFORM_USER` ואת
`apr_session` בכלל — גם אם הם קיימים בדפדפן.

## 9. הגנות על הפורטל

- האסימון: 32 בתים אקראיים. במסד — רק ה-hash.
- הגבלת קצב לפי IP ולפי קישור: 60 בקשות לדקה; 20 העלאות לשעה לקישור.
- העלאה: אותה רשימת סוגים ואותה מגבלת גודל.
- דף הפורטל: `Referrer-Policy: no-referrer`, `Cache-Control: no-store`,
  `X-Robots-Tag: noindex`, ו-CSP שאינו מתיר סקריפט חיצוני.
- שגיאות דפדפן מהפורטל נרשמות (`portal-client-error`) — בלי האסימון ובלי תוכן.

## 11. הרשאות

| פעולה | הרשאה בתיק |
| --- | --- |
| צפייה בבקשות ובהודעות | `view` |
| יצירה, שליחה, שליחה מחדש, ביטול | `contact` |
| כל `portal-*` | מחזיק אסימון תקף, בגבולות `perms` של הבקשה |

## 12. מקרי קצה

1. **שני גורמים באותו תיק** (לקוח ועורך דין). שתי בקשות, שני קישורים; אף אחד אינו
   רואה את של השני — גם אם ניחש `pid` של קובץ.
2. **אותו אדם בשני תיקים.** שני קישורים נפרדים; הפורטל מציג רק את של הקישור שנפתח.
3. **הנמען מעביר את הקישור למישהו אחר.** מי שמחזיק בקישור יכול להעלות. לצפייה
   בקבצים נדרש הקוד למייל המקורי. התצוגה המקדימה מזכירה לשמאי: "כל מי שמחזיק
   בקישור יכול להעלות".
4. **הנמען פותח קישור ישן אחרי "שליחה מחדש".** "הקישור אינו בתוקף".
5. **דרישה נמחקה או סומנה לא רלוונטית אחרי השליחה.** נעלמת מהפורטל.
6. **דרישה נוספה לגורם אחרי השליחה.** אינה מצטרפת לבקשה הקיימת; "הוספה לבקשה"
   היא פעולה מפורשת, עם תצוגה מקדימה, ואינה שולחת מייל אלא אם סומן.
7. **הנמען מעלה קובץ שנדחה** (סוג, גודל, תוכן פעיל). רואה סיבה פשוטה; הדרישה אינה
   משנה מצב; המשרד אינו מקבל התראה על "מסמך שהתקבל".
8. **הנמען לוחץ פעמיים על "העלאה".** מזהה פעולה; קובץ אחד.
9. **`mail()` מחזיר הצלחה והמייל לא הגיע.** המערכת אינה יכולה לדעת; לכן "נשלח"
   ולא "התקבל", ו"שימוש אחרון בקישור: מעולם" מוצג ליד הבקשה.
10. **משתמש המערכת פותח קישור פורטל כשהוא מחובר.** רואה את הפורטל בדיוק כמו נמען;
    ה-session שלו אינו נגוע ואינו מעניק דבר.
11. **התיק נסגר.** הקישורים הפעילים מציגים "הבקשה נסגרה. תודה."; העלאה חסומה.
12. **המשרד הושעה.** כל הקישורים: "הקישור אינו בתוקף".

## 13. קריטריוני קבלה

- **07-A1** 🤖 אין נתיב ב-API ששולח בקשה בלי שהוצגה תצוגה מקדימה (השליחה דורשת
  מזהה תצוגה מקדימה תקף של אותו תוכן).
- **07-A2** 🤖 שליחה ← הדרישות `requested`, נוצרת `messages` אחת. שליחה חוזרת עם
  אותו מזהה פעולה ← אין הודעה שנייה.
- **07-A3** 🤖 `mail()` נכשל ← `failed`; הדרישות חוזרות ל-`required`; הבקשה מופיעה
  ב"הודעות שנכשלו".
- **07-B1** 🤖 `portal-open` באסימון של לקוח מחזיר רק את הדרישות שלו. **אין בתשובה**
  מספר תיק, כתובת, שמות גורמים אחרים, או דרישות שאינן ב-`request_items`. *(3)*
- **07-B2** 🤖 אסימון של לקוח + `pid` של קובץ שעורך הדין העלה ← 404. *(3)*
- **07-B3** 🤖 אסימון של לקוח + `pid` של דרישה של עורך הדין ← העלאה נדחית. *(3)*
- **07-B4** 🤖 `portal-file` בלי מכשיר מאומת ← נדחה, גם עם `view_own`.
- **07-B5** 🤖 6 ניסיונות קוד שגויים ← הקישור נחסם לרבע שעה.
- **07-B6** 🤖 אסימון שפג, שבוטל, ושאינו קיים ← אותה תשובה בדיוק. *(4)*
- **07-B7** 🤖 אחרי ביטול ← כל `portal-*` נדחה, והביטול ביומן הפעולות. *(4)*
- **07-B8** 🤖 "שליחה מחדש" ← האסימון הישן אינו עובד.
- **07-B9** 🤖 פעולות `portal-*` מתעלמות מ-`PLATFORM_USER` ומ-`apr_session`: בקשה
  עם זהות של שמאי ואסימון שגוי ← נדחית.
- **07-C1** 🤖 העלאה בפורטל ← `received`, `uploader_kind = recipient`; **לא**
  `approved`. *(8)*
- **07-C2** 🤖 "אין ברשותי" ← נוצרת משימת המשך; הדרישה נשארת `requested`.
- **07-C3** 🤖 קובץ שנדחה בפורטל ← הדרישה לא שינתה מצב.
- **07-C4** 🤖 במסד אין אסימון פורטל ואין קוד חד-פעמי בטקסט גלוי.
- **07-D1** 👁 חלון גלישה בסתר: הקישור נפתח, והעלאה מהטלפון עובדת — **בלי** מסך
  הכניסה של המעטפת.
- **07-D2** 👁 בפורטל אין שום קישור למערכת, לכלים, או לתיק.
- **07-D3** 👁 אחרי העלאה מוצג "התקבל — המשרד יבדוק", ולא "אושר".
