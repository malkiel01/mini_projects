# 06 — מסמכים: דרישות, העלאה, גרסאות, בדיקה ואישור

**תלויה ב-04.** האפיון: פרק 7, 22.4, 23.1, 25.4; דרישות 11, 12; בדיקות קבלה 8, 9.

רשימת הדרישות היא תוכנית העבודה של התיק. הפרוסה הזו בונה את הטיפול בה מבפנים —
צוות המשרד מעלה, בודק ומאשר. (העלאה בידי נמען — פרוסה 07.)

## 1. מה בונים

1. ניהול רשימת הדרישות: הוספה, סדר, פיצול לגורמים, "לא רלוונטי" בנימוק, בקשה שוב.
2. אחסון קבצים מאובטח, עם זיהוי סוג לפי תוכן.
3. העלאה פנימית — קובץ אחד או רבים, ושיוך לדרישה.
4. גרסאות וקבצים נלווים; היסטוריה.
5. זיהוי כפילות — התרעה בלבד.
6. בדיקה ואישור: קריא / שלם / מתאים; אישור, החזרה להשלמה, דחייה.
7. מכונת המצבים של דרישה (23.1).
8. מציג קבצים, תמונות ממוזערות, סינון וחיפוש.

## 4. אחסון וקליטה ⚙️

**כל קובץ שנכנס עובר את אותו צינור**, מכל ערוץ:

1. **גודל** — עד 25MB (הגדרה; ש-14). חריגה ← נדחה, עם הגודל המותר.
2. **זיהוי סוג לפי התוכן** (`finfo`, ובדיקת חתימה). הסיומת והסוג שמסר המעלה אינם
   קובעים דבר.
3. **רשימה מותרת:** PDF · JPEG · PNG · WEBP · HEIC/HEIF · DOCX · XLSX · ZIP.
   כל השאר נדחה: "סוג הקובץ אינו נתמך".
4. **תוכן פעיל:** PDF עם JavaScript או קובץ מוטמע; מסמך Office עם מאקרו; קובץ
   שהתוכן שלו אינו תואם לסוג שזוהה ← **נדחה** (`scan_state = rejected`, נשמרת רק
   שורת יומן עם ה-hash — לא הקובץ).
5. **סורק** — אם `clamscan` זמין בשרת, רץ; נמצא איום ← נדחה. אם אינו זמין:
   `scan_state = not_scanned`, והמסך **אינו** כותב "נסרק" (ש-33).
6. **שמירה:** `data/files/<2 תווים>/<מפתח אקראי>`, בלי סיומת. ה-hash מחושב.
7. **רק אחרי כל אלה** נוצרת שורה ב-`files`, והדרישה עוברת מצב.

- ZIP נשמר **כמו שהוא ואינו נפתח** בשרת (למשל חבילת היתר דיגיטלי עם קובץ חתימה —
  מחקר הרשויות 7.2). מוצג כ"חבילה", להורדה בלבד.
- **הגשה:** תמיד דרך `api.php`, אחרי `can()`. כותרות: `Content-Disposition:
  attachment` (חוץ מתצוגה מקדימה של PDF ותמונה, שמוגשות `inline` עם
  `Content-Security-Policy: sandbox`), `X-Content-Type-Options: nosniff`.
- תמונות ממוזערות: נוצרות בשרת לתמונות (GD / Imagick). ל-PDF — אם אין יכולת המרה
  בשרת, אייקון סוג; הדפדפן מציג את העמוד הראשון בתצוגה המקדימה.
- כשל בכל שלב ← **הקובץ אינו מסומן כהתקבל**, והמעלה רואה סיבה (7.2 שלב 2).

## 5. מצבי דרישה (האפיון 23.1)

| מצב | משמעות | מעברים |
| --- | --- | --- |
| `required` נדרשת | הוגדרה, לא נקלט מסמך | ← `requested` (נשלחה בקשה, פרוסה 07) · ← `received` (קובץ) · ← `not_relevant` (נימוק) |
| `requested` נשלחה בקשה | יש ניסיון שליחה מתועד | ← `received` · ← `not_relevant` · ← `required` (הבקשה בוטלה) |
| `received` התקבל וממתין לבדיקה | קובץ נקלט והבדיקה הטכנית עברה | ← `approved` · ← `returned` |
| `returned` הוחזר להשלמה | הבודק רשם בעיה | ← `received` (קובץ חדש) · ← `not_relevant` |
| `approved` אושר | בודק מורשה קבע שמתאים | ← `received` (קובץ חדש, או "פתיחה לבדיקה מחדש" בנימוק) |
| `not_relevant` לא רלוונטי | משתמש מוסמך קבע שאינה חלה | ← `required` (ביטול הסימון, בנימוק) |

כללים 🟢:

- **העלאה לעולם אינה מאשרת.** קובץ חדש ← `received`, תמיד. גם כשהמעלה הוא השמאי
  האחראי — האישור הוא פעולה נפרדת.
- **"התקבלה הודעה", "התקבל קובץ" ו"אושרה הדרישה" — שלושה אירועים.**
- `not_relevant` — רק בעל `review_docs`, ותמיד עם נימוק.
- מצב הדרישה נגזר מהקובץ האחרון שלה: אישור הגרסה האחרונה ← `approved`; החזרה ← `returned`.
- **אישור מסמך אינו אישור של הנתונים שבו** (22.4) — אלה מצבים נפרדים (פרוסה 10).

## 6. בדיקה ואישור

בודק (`review_docs`) פותח קובץ: המסמך משמאל, פרטיו מימין. מסמן:

- ☐ קריא · ☐ שלם (כל העמודים) · ☐ מתאים לדרישה
- תאריך המסמך (אם ידוע), והערה פנימית.

ואז אחת משלוש:

| פעולה | תנאי | תוצאה |
| --- | --- | --- |
| **אישור** | שלוש התיבות מסומנות | `approved`; נרשמים הבודק והזמן |
| **החזרה להשלמה** | סיבה מרשימה (חסרים עמודים · לא קריא · מסמך ישן · מסמך אחר · אחר) + הסבר לנמען | `returned`; הקובץ **נשאר בהיסטוריה**; נפתחת אפשרות להעלות קובץ נוסף |
| **דחייה** | נימוק | הקובץ מסומן `rejected` ומנותק מהדרישה (נשאר ב"קבצים שלא שויכו"); הדרישה חוזרת למצב שלפניו |

קובץ חדש לדרישה ← המעלה בוחר: **גרסה חדשה** (מחליפה את הקודמת כ"נוכחית") או
**קובץ נלווה** (מצטרף אליה). הגרסאות הקודמות נשארות, לפי הרשאות.

## 7. ניהול הרשימה

- **הוספת דרישה** — מסוג מסמך, או חופשית. `origin = manual`.
- **שינוי סדר** — גרירה, בתוך קבוצה ובין קבוצות.
- **פיצול לגורמים** — דרישה אחת הופכת לשתיים או יותר, כל אחת עם גורם משלה
  (`split_from_id`). המקורית נסגרת כ"פוצלה" ואינה נספרת.
- **בקשה שוב** — מחזירה `returned` / `approved` ל-`required`, עם נימוק.
- **שינוי אחראי, עדיפות, חובה, מועד** — חופשי לבעל `documents`; הורדת `mandatory`
  — רק לבעל `review_docs`, עם נימוק.

## 8. כפילות (בדיקת קבלה 9)

- **אותו `sha256` באותו תיק** ← התרעה בזמן ההעלאה: "הקובץ הזה כבר קיים בתיק
  (<הדרישה>, <התאריך>)". המעלה בוחר: "להעלות בכל זאת" או "ביטול".
- **אין מחיקה אוטומטית ואין איחוד אוטומטי.**
- הבדיקה היא בתוך התיק בלבד. **לעולם לא בין תיקים ולא בין משרדים** — אחרת
  ההתרעה עצמה הייתה חושפת שהקובץ קיים במקום אחר.

## 9. מסכים (האפיון 7.3, 25.4)

| נתיב | מסך |
| --- | --- |
| כרטיס תיק ← **דרישות וקבצים** | הרשימה, בקבוצות. שורה: כותרת, גורם, עדיפות, חובה, יעד, מצב, מספר קבצים. סינון: חסר · הועלה · בבדיקה · אושר · לא רלוונטי; לפי גורם, סוג, עדיפות |
| ← דרישה | פרטים, קבצים וגרסאות, היסטוריה, פעולות |
| ← קובץ | המציג + פרטים + בדיקה (ובהמשך: נתונים שחולצו) |
| ← "העלאה" | בחירה או גרירה של כמה קבצים; צילום מהטלפון; שיוך לכל קובץ |
| ← "קבצים שלא שויכו" | קבצים בלי דרישה; "שיוך" |

לכל קובץ מוצגים: שם, תאריך קבלה, תאריך המסמך, מקור (ערוץ והצהרה), מי העלה, סוג,
גרסה, הדרישה, ומצב הבדיקה. **שלושת התאריכים נפרדים** (23.4).

בלוח הראשי מתווסף: "מסמכים שהתקבלו וממתינים לבדיקה" — בתיקים שיש לי בהם `review_docs`.

חיפוש בפרוסה הזו: שם קובץ, כותרת דרישה, תגית — **רק בפריטים מורשים**.

## 11. מקרי קצה

1. **החיבור נפל באמצע העלאה.** אין שורה ב-`files`; קובץ זמני נמחק בניקוי. העלאה
   חוזרת עם אותו מזהה פעולה אינה יוצרת כפילות.
2. **קובץ של 0 בתים, או קובץ פגום שאינו נפתח.** נדחה בזיהוי הסוג.
3. **סיומת `.pdf`, תוכן של קובץ הרצה.** נדחה לפי התוכן.
4. **תמונת HEIC מאייפון.** נשמרת כמקור; לתצוגה נוצרת גרסת JPEG. אם השרת אינו יכול
   להמיר — מוצג אייקון, והקובץ זמין להורדה.
5. **קובץ מוצפן בסיסמה.** נשמר; הבודק רואה "מוגן בסיסמה", ומחזיר להשלמה.
6. **שני בודקים באותו קובץ.** השני מקבל "כבר נבדק בידי <שם>", עם התוצאה.
7. **קובץ אושר ואז הועלתה גרסה חדשה.** הדרישה חוזרת ל-`received`; האישור הקודם
   נשאר בהיסטוריה, משויך לגרסה שלו.
8. **מחיקת הקובץ היחיד של דרישה מאושרת.** הדרישה חוזרת ל-`required`; נרשם.
9. **אותו קובץ משויך לשתי דרישות** (נסח שמשמש גם לזהות וגם לזכויות). מותר: שתי
   שורות `requirement_files` לאותו `file_id`, כל אחת עם בדיקה משלה.
10. **אין מקום בדיסק.** ההעלאה נכשלת עם הודעה ברורה; בדיקת התקינות מתריעה מראש.
11. **שם קובץ עם תווים בעייתיים** (`../`, תווי בקרה, 300 תווים). נשמר להצגה אחרי
    ניקוי; אינו משפיע על האחסון.
12. **ZIP של 25MB שמתפרס ל-10GB.** לא רלוונטי — לא פותחים.
13. **תיק סגור.** אפשר לצפות ולהוריד; העלאה ובדיקה — רק אחרי פתיחה מחדש.

## 12. קריטריוני קבלה

- **06-A1** 🤖 העלאה לדרישה ← `received`, והקובץ `pending`. **גם כשהמעלה הוא השמאי
  האחראי.** *(8)*
- **06-A2** 🤖 אישור בלי שלוש התיבות ← נדחה; עם שלושתן ← `approved`, עם בודק וזמן.
- **06-A3** 🤖 החזרה להשלמה ← `returned`; הקובץ עדיין נגיש בהיסטוריה; קובץ חדש ←
  `received`, כגרסה 2. *(8)*
- **06-A4** 🤖 `not_relevant` בלי נימוק ← נדחה. משתמש בלי `review_docs` ← נדחה.
- **06-A5** 🤖 כל מעבר מהטבלה שבסעיף 5 מותר; מעבר שאינו בטבלה (למשל `required` ←
  `approved`) ← נדחה.
- **06-B1** 🤖 קובץ עם סיומת `.pdf` ותוכן שאינו PDF ← נדחה; אין שורה ב-`files`,
  והדרישה לא שינתה מצב. *(9)*
- **06-B2** 🤖 PDF עם JavaScript, ו-DOCX עם מאקרו ← נדחים. *(9)*
- **06-B3** 🤖 קובץ מעל המגבלה ← נדחה לפני שנשמר.
- **06-B4** 🤖 אותו קובץ פעמיים באותו תיק ← התשובה מסמנת `duplicate` ומחכה להחלטה;
  שום קובץ לא נמחק. *(9)*
- **06-B5** 🤖 אותו קובץ בשני תיקים שונים ← **אין** התרעה.
- **06-B6** 🤖 העלאה חוזרת עם אותו מזהה פעולה ← שורה אחת.
- **06-B7** 🤖 `storage_key` אינו נגזר מהשם המקורי; שם עם `../` אינו יוצר קובץ מחוץ
  ל-`data/files/`.
- **06-C1** 🤖 **בידוד:** הורדה, תצוגה מקדימה ותמונה ממוזערת לפי `pid` של קובץ
  ממשרד אחר, או מתיק שאיני משתתף בו ← 404.
- **06-C2** 🤖 בקשת HTTP ישירה לנתיב תחת `data/files/` ← אינה מחזירה את הקובץ.
- **06-C3** 🤖 תשובת הגשת קובץ נושאת `nosniff` ו-`Content-Disposition`; תצוגה
  מקדימה נושאת `sandbox`.
- **06-C4** 🤖 החיפוש אינו מחזיר קובץ מתיק שאינו מורשה.
- **06-D1** 🤖 פיצול דרישה לשני גורמים ← שתי דרישות חדשות, והמקורית אינה נספרת
  כפתוחה.
- **06-D2** 🤖 אותו קובץ בשתי דרישות ← שתי בדיקות נפרדות; אישור באחת אינו מאשר בשנייה.
- **06-D3** 🤖 `doc_date` שלא הוזן מוחזר `null`.
- **06-E1** 👁 צילום מסמך מהטלפון והעלאתו לדרישה, בלי לצאת מהמסך.
- **06-E2** 👁 גרירת חמישה קבצים במחשב, ושיוך כל אחד לדרישה.
- **06-E3** 👁 מסך הבדיקה: המסמך והתיבות זה לצד זה במחשב, זה מעל זה בטלפון.
- **06-E4** 👁 כשאין סורק בשרת — שום מסך אינו כותב "נסרק".
