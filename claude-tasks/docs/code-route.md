## שלוש דרכים

### א. הצ'אט לא מאזין — הוא מופעל

האפליקציה מפעילה ריצת Claude Code חדשה לכל הודעה (`claude -p` ב-GitHub Actions), עם ההיסטוריה מהיומן שלנו.

- **בעד:** אין שום דבר שצריך להישאר ער. אפס פניות ואפס טוקנים בהמתנה. לא תלוי במכונה של בעל הלוח.
- **נגד:** כל הודעה מחכה להפעלת הריצה [הסקה: בסדר גודל של דקה; לא נמדד]. אין זיכרון בין ריצות חוץ ממה שאנחנו
  מעבירים. ריצות על המנוי נספרות במכסה שלו [מחקר].
- **מה חסר לבנייה:** workflow שמקבל הודעה ומחזיר תשובה לאפליקציה; חבילת הקשר (סיכום + הודעות אחרונות + ענף);
  אסימון של Claude Code בסודות הריפו.

### ב. משיכה בתחילת תור

hook בצ'אט חי מושך הודעות ממתינות כשבעל הלוח כותב בו משהו.

- **בעד:** פשוט, אפס פניות לפי שעון, עובד גם בצ'אט בענן.
- **נגד:** הודעה מגיעה רק כשמישהו כבר נמצא בצ'אט. זו לא "האזנה" — זו תוספת, לא פתרון.

### ג. Channels — דחיפה לתוך סשן רץ

יכולת רשמית של Claude Code: שרת MCP שדוחף אירועים לתוך סשן רץ, כך ש-Claude מגיב גם כשאף אחד לא ליד המסוף.

מה שהתיעוד אומר [תיעוד]:
- ערוץ הוא שרת MCP שרץ **מקומית**, ליד התהליך של Claude Code, ומופעל לכל סשן בדגל `--channels`.
- אירועים מגיעים **רק בזמן שהסשן רץ**. סשן שנסגר — האירועים לא מחכים לו.
- כשהסשן נתקל בבקשת הרשאה ואף אחד לא שם, הוא נעצר עד שעונים. ערוץ יכול להעביר את הבקשה הלאה ("permission relay").
- לכל ערוץ רשימת שולחים מורשים; מי שלא ברשימה — נזרק בשקט.
- בארגוני Team ו-Enterprise בעלים צריך להפעיל; עם מפתח API מה-Console — מותר כברירת מחדל.
- היכולת מסומנת כתצוגה מקדימה למחקר [מקורות משניים, עקביים זה עם זה]: התחביר והפרוטוקול עשויים להשתנות, וערוץ
  שבונים לבד דורש דגל פיתוח.

המשמעות אצלנו [הסקה]:
- **זו הדרך היחידה שבה צ'אט Code באמת "מאזין"**, ובלי שהמודל בודק בעצמו. אבל היא דורשת תהליך `claude` שרץ כל הזמן
  על מכונה דלוקה — של בעל הלוח, או שרת קטן.
- הערוץ שלנו היה צריך לקבל הודעות מהאפליקציה. האחסון המשותף לא יכול לדחוף אל מכונה ביתית, ולכן הערוץ היה פותח
  חיבור יוצא אל האפליקציה — ובאחסון הנוכחי חיבור פתוח הוא בדיוק מה שהפיל את השרת ב-2.11 [מחקר]. נדרש שירות ביניים.
- **בצ'אטים בענן (claude.ai/code) — [לא נבדק] אם `--channels` זמין בכלל.** הצוותים של בעל הלוח רצים שם.

## המלצה

**אם מחזירים את מסלול Code — דרך א'.** היא היחידה שלא תלויה במכונה דלוקה, לא ביכולת ניסיונית ולא בחיבור פתוח, והיא
נשענת על אותו יומן שיחה שכבר בנוי בסטודיו. דרך ב' אפשר להוסיף עליה כמעט בחינם. דרך ג' שווה בדיקה רק אם יהיה שרת
שדולק תמיד, ואחרי שהיכולת תצא מתצוגה מקדימה.

כל עוד הסטודיו על Platform עונה על הצורך — אין סיבה לבנות אף אחת מהן.
