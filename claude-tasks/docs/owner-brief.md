# מטלות לקלוד — מה הבעלים צריך

המסמך המחייב של הצוות. מי שמשנה אותו: רק הבקרה, ורק לפי מה שהבעלים אמר.

## 1. במילים של הבעלים

> "אני רוצה לאפיין מחדש את אפליקציית מטלות לקלוד. בעצם הייתה לי בקשה מאוד פשוטה לבנות איזה שהוא צ'אט שינוהל בשיח
> ישיר מול הצ'אט של קלוד אבל בפלטפורמה שלי. כמובן שהפלטפורמה שלי תדע לקחת את זה גם מצ'ט קלוד וגם מצ'אט פלטפורמה.
> היה לנו בעייתיות מאוד מאוד גדולה איך אנחנו יוצרים תקשורת מהירה וישירה מהאפליקציה שלנו לצ'אט קלוד. אבל אני חשבתי
> על זה במחשבה שניה — למה שלא נחבר את זה באופן ישיר לתוך ה-cli של קלוד." (24.11.2026)

> "אוקיי אז אנחנו נתחיל מהמחשב שלי." (24.11.2026 — אחרי ההסבר שהגשר יכול לרוץ על המחשב שלו, על השרת, או על VPS)

> "אני רוצה לפתח לעצמי צ'אט ממש כמו צ'אט של קלוד, אפילו ממש דומה, שיהיו בו תוספים שמותאמים לי. אבל הוא מחובר ל-CLI של
> קלוד, כך שכל מה שניתן לעשות בקלוד — הרצת פקודות, התקנת סקילים, חיבור תוספים, כל עדכון שמתקבל בקלוד — יהיה גם אצלי.
> [...] זה משתמש בתוך החשבון פרו / מקס, או שהשימוש יהיה באמצעות טוקנים של קלוד פלטפורמה — את ההחלטה הזאת אנחנו מחליטים
> בהגדרות, וניתן לשינוי בכל רגע." (24.11.2026 — תיקון: "לא ממש הבנת אותי")

## 2. מה נגזר מזה

1. **צ'אט בפלטפורמה** (`claude-tasks/`), שבו הבעלים כותב ו-Claude Code עונה — שיח ישיר, תשובה תוך שניות, בלי לחכות
   לסבב או לשעון.
2. **החיבור הוא ל-Claude Code עצמו** (`claude -p` / Claude Agent SDK), לא ל-Messages API בלי כלים: Claude שעונה יכול
   לעבוד בריפו, להריץ פקודות ולזכור את השיחה (`--resume`).
3. **שלב ראשון: הגשר רץ על המחשב של הבעלים.** תהליך קטן שפונה **החוצה** לפלטפורמה (בלי לפתוח פורטים), לוקח הודעות,
   מעביר ל-Claude Code ומחזיר תשובות. עובד כשהמחשב דלוק. **שלב שני:** אותו גשר על שרת שזמין תמיד (Bluehost אם
   החבילה מאפשרת, אחרת VPS) — לא בשלב הזה.
4. **"גם מצ'אט קלוד וגם מצ'אט פלטפורמה":** שיחה אחת שאפשר להמשיך גם מהפלטפורמה וגם מ-Claude Code עצמו — מה שנכתב
   בצד אחד נראה בצד השני. (לאפיין: איך, ובאיזה היקף — שאלה לבעלים.)
5. **ברירות מחדל עד הכרעה** (שאלות לבעלים דרך הבקרה):
   - חשבון: **מפתח API** (לפי תיעוד Agent SDK — מנוי claude.ai לא מותר במוצר צד שלישי). מנוי — רק אם הבעלים מכריע.
   - הרשאות של Claude שרץ מהגשר: מוגדרות מראש ומוגבלות; ברירת מחדל — עבודה בריפו בלי דחיפה ופריסה.
   - מי רשאי לכתוב לצ'אט: רק הבעלים (כניסה דרך השער).
6. **מה למדנו (מחקר 2026-11-08, `docs/research-2026-11/`) — אילוצים, לא המלצה מחייבת:**
   - אין long-poll על ה-PHP המשותף (תקרית 429, 2.11: 13 צ'אטים תפסו תהליכי PHP).
   - מבצע אחד לכל הודעה — הודעה לא נענית פעמיים (F-03).
   - Remote Control לא מתאים כערוץ; האזנה לסשן מקומי דורשת תהליך חי אצל הבעלים.
7. הקוד הקיים (`bridge/`, `agent/run.mjs`, ערוצים, שער) — **רקע, לא אילוץ**. מה שמתאים — ממחזרים; השאר לא מחייב.

8. **תיקון הבעלים (24.11): הכוונה היא לממשק, לא רק לגשר.** ממשק שנראה ומתנהג כמו הצ'אט של Claude, עם תוספות אישיות,
   שמאחוריו ה-CLI האמיתי של Claude Code — לא מימוש חלקי. כל מה שה-CLI יודע (פקודות, סקילים, תוספים, MCP, עדכונים)
   זמין בממשק, והעדכונים של Claude מגיעים אליו לבד. **החשבון (מנוי Pro/Max או מפתח API) הוא הגדרה, ניתנת לשינוי בכל רגע.**

## 3. המבחן

הבעלים כותב הודעה בצ'אט בפלטפורמה, ותוך שניות מקבל תשובה מ-Claude Code שרץ על המחשב שלו — שזוכר את השיחה, ושיכול
להמשיך אותה גם מתוך Claude Code עצמו.
