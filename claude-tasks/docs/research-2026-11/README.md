## 1. ממצאים מרכזיים

1. **האפליקציה מושהית רק בעץ העבודה של הריפו** [מאומת]: אין `hooks` ב-`.claude/settings.json` (#1285, נמרג 2026-11-08), `bridge/hook.sh` יוצא מיד בלי `CLAUDE_TASKS_BRIDGE=on`. ה-API עדיין נפרס (deploy.yml) וה-allow ל-`create_trigger`/`send_later` נשאר גלובלי. מצב הייצור: [לא ידוע].
2. **סיבת ההשהיה המתועדת היא חיכוך תפעולי**, לא עומס: השער חסם `merge-own-pr` בצ'אט לא רשום (#1285). תקרית ה-429 ב-2026-11-02 (#1148, 13 צ'אטים עם long-poll של 20 ש' ששכבו על תהליכי PHP) מתועדת בנפרד; הקשר ביניהם הוא [הסקה].
3. **"Platform" בקוד אינו Managed Agents** [מאומת, grep על `/v1/agents`, `/v1/sessions`, agent-sdk: אפס]. יש ארבעה דברים שונים: (א) מסלול ☁️ = `curl` מ-PHP ל-Messages API/OpenAI/Gemini בלי כלים (`lib/answers.php`, `lib/ai.php`); (ב) Claude Code CLI בתוך GitHub Actions (`agent/claude-code.yml`); (ג) `agent/run.mjs` — לולאת Node ביתית; (ד) `lib/platform.php` — SSO של "הכלים הדיגיטליים", לא קשור ל-AI.
4. **אין "שיחה" אחת**: לערוץ >10 עמודות מצב מקבילות, ו"תקוע" משמעותו ארבעה דברים (F-01). אין ישות שמייצגת "שיחה לוגית + סשנים מקומיים של כל backend" — וזה בדיוק מה שהמוצר הרצוי דורש.
5. **מנגנון "שתיקה" ו-`ack` שבירים**: הודעה ללא ack חוזרת כהוראה וניתנת ל-☁️ פעם נוספת (F-03, F-02) — סיכון להרצה כפולה ולעלות.
6. **ה-WAKE הוא לולאת מודל** (F-22) ו-`dispatch_requests` ב-`sent` לא פג (F-05): בדיוק ההפך מ"האזנה בלי טוקנים".
7. **הרשאות** (ר' נספח d): F-7 — בריצת Claude Code ב-Actions ה-env מחזיק `ANTHROPIC_API_KEY`+`BOARD_TOKEN`+`GH_TOKEN` עם Bash מותר, והשער הוא regex; F-1 — מדיניות של תת-פרויקט עוקפת "אף פעם" של האב; F-5 — `owner_only` לא נאכף על עובדים.
8. **מצד Anthropic** [מאומת, ר' נספח c]: אי אפשר להחליף מודל בסשן Managed Agents קיים; Managed Agents דורש מפתח API (לא מנוי); Remote Control דורש תהליך `claude` חי + התחברות מנוי מלאה ואין לו API ציבורי; "Connected" אינו הוכחת זמינות; webhook נושא רק `type`+`id`.
9. **המסקנה הארכיטקטונית:** המוצר הרצוי ניתן לבנייה, אך לא כ"סשן משותף אחד" ולא על PHP משותף כמקור האזנה. נדרש (א) **שכבת שיחה לוגית** עם סשנים נטיביים מקושרים, (ב) **שירות אירועים/עובדים נפרד** מהאחסון המשותף, (ג) **שער מבצע יחיד** לכל בקשה. מומלצת אפשרות **B** (ר' §9).
10. **לא כל דרישה אפשרית:** Remote Control כ-transport לא ניתן לשילוב; האזנה חיה של סשן Claude Code **מקומי** מחייבת תהליך חי אצל המשתמש; תהליך רקע ב-sandbox של MA אינו מובטח לשרוד idle.

### 5.2 חוויית משתמש לכל הודעה
- שורת קלט: **[מסלול ▾] [מודל ▾] [💬 שלח]**. ברירת מחדל: הודעה קודמת → ברירת מחדל של שיחה → של פרויקט → של משתמש. רשימת המודלים מסוננת לפי המסלול שנבחר ולפי היכולת (שרת מחזיר `models` לכל מסלול; לא רשימה קשיחה בקוד כמו `PRICES`).
- **שינוי לגבי ההודעה הבאה** ≠ **הפסקת ריצה**: בזמן ריצה, בחירה חדשה מתייגת "הבא בתור"; כפתור נפרד "⏹ עצור והחלף" שולח `Interrupt` ל-executor הנוכחי ומחכה לאישור עצירה לפני התחלת הבא.
- כל בועת תשובה מציגה תג **מה רץ בפועל**: `Code · <מודל> · סשן #ns` / `Platform(MA) · …` / `Platform(API ישיר) · …`, אורך, וכן שימוש ($ או "מכסת מנוי — לא נמדד בדולרים").
- **מודל לא זמין / מכסה/קרדיט נגמרו / rate limit:** ברירת מחדל — **עצירה והצגת בחירה** ("Platform נגמר האשראי: להמשיך ב-Code? [כן] [רק הפעם] [לא]"). fallback אוטומטי רק אם המשתמש הגדיר מראש `fallback_policy` מפורש לפרויקט, ותמיד עם תיוג. 429 → backoff מעריכי עם jitter, תקרת ניסיונות, ללא retry-storm; 402/`enforced_spend_limit_reached` — לא ניסיון חוזר.

### 5.3 רציפות בלי סשן משותף
**אין סשן נטיבי משותף בין המוצרים** [מאומת בתיעוד: מוצרים נפרדים, אין מנגנון]. הפתרון: ה-Conversation הוא מקור האמת; כל Run מקבל **Handoff Packet**:
- `summary` מתגלגל (נוצר על ידי הרצה זולה, פעם אחת בכל החלפה ולא בכל הודעה) + `decisions[]` + `pending[]` + `open_questions[]`;
- **אחרון N תורות גולמיות** בלבד (N קטן וקבוע) — לא תמלול מלא, כדי שלא לשלוח תמלול גדל;
- מצב קוד: `repo`, `branch`, `head_sha`, `dirty=false` (חובה commit/stash לפני מסירה), קישורי PR, רשימת קבצים שהשתנו;
- הפניות ל-artifacts (קבצים ב-resource/ריפו), לא תוכן.
אי-אפשר להעביר: tool call רץ, מצב זיכרון פנימי, תהליכי רקע, tool-results גולמיים מעבר למה שהוצג; הממשק אומר זאת כשמחליפים באמצע ריצה.
**שינוי מודל ב-MA = `NativeSession` חדש** (אותה Conversation); ב-Claude Code אפשר `/model` בסשן קיים או סשן חדש לפי יכולת הספק.
**מניעת כתיבה ע"י executor ישן:** `Run` נושא `fence_token` (מספר עולה לכל Conversation); כל כתיבה/commit/PR/הודעה של executor חייבת לצרף אותו ל-controller; כתיבה עם token ישן נדחית (409). ב-git: ענף לכל Run או **שני Runs לא כותבים לאותו ענף בו-זמנית**; ה-Handoff חייב `head_sha` והצד הבא מתחיל מ-fetch.

## 6. האזנה וסנכרון בזמן אמת

### 6.1 הגדרה טכנית
"מאזין" = **רכיב דטרמיניסטי (קוד, לא מודל)** שמחזיק מנוי לזרם אירועים ומעדכן אחסון/ממשק. הוא לא "משתתף חושב". ארבע רמות נפרדות, ולכל אחת עלות שונה:
| פעולה | מי | טוקנים? |
|---|---|---|
| צפייה/סנכרון אירועים | Relay (קוד) + דפדפן/מכשירים | **אפס** |
| קבלת משימה | Dispatcher (קוד) ← Run ב-`queued` | אפס |
| ביצוע | executor אחד שנבחר | **כן** — רק כאן |
| קריאה למודל | תוצאה של ביצוע | כן |
**משתתף Claude Code וה-Platform "מחוברים לשיחה"** = רשומים כ-`Participant` במצב `observer` (מקבלים אירועי שיחה מהמתווך) ורק אחד מהם הוא `executor` של בקשה. התצפית אינה מעירה מודל. מה שמעיר מודל הוא רק `Run` שנוצר מ-**אירוע בקשה מפורש** (`origin=human` או `agent_request` מורשה).

### 6.2 איפה הקוד רץ ומה אפשרי לכל backend
| backend | איך מקבלים אירועים | איפה רץ הקוד | idle |
|---|---|---|---|
| MA | SSE `stream` לסשן (API) + webhook כטריגר + `events.list` ל-replay | Relay/worker נפרד (לא PHP משותף) | אין חיבור נדרש כשהסשן idle; webhook/poll חסום-תדירות מעיר את ה-Relay; אפס טוקנים |
| Claude Code ענן | `--cloud` שליחה; מעקב מצב ב-claude.ai/GitHub | worker | [לא אומת] מה זמין כסטרים תכנותי |
| Claude Code מקומי | hooks (Stop/UserPromptSubmit) → HTTP hook לשירות שלנו; **תהליך `claude` חי** אצל המשתמש | מכונת המשתמש | הסשן ער רק כש-`claude` רץ; Remote Control לא ניתן להטמעה |
| Claude Code ב-Actions | ריצה מוגבלת בזמן, תוצאה חוזרת ל-controller | GitHub runner | אין "האזנה" — ריצה חד-פעמית |
**הכרעה:** "האזנה ללא טוקנים" אפשרית **מלאה** עבור צד ה-UI וצד ה-MA (SSE/webhook לקוד שלנו). עבור Claude Code **מקומי** היא אפשרית רק כל עוד תהליך חי, ואין דרך מתועדת לדחוף לתוכו הודעה בלי שהמודל יעבד אותה (כל הודעה נכנסת = תור מודל). לכן: משימות ל-Code מקומי נמסרות **כשהמשתמש/התהליך מושך** (hook/`pull` בתחילת תור), או ל-Code בענן/Actions כ-Run חדש.

### 6.3 טכנולוגיות העברה (בלי להניח שהן "בחינם")
| | משקל על השרת | הערה |
|---|---|---|
| Polling קצר | N×בקשה/תדירות; על PHP משותף = בקשות כולל migrate() | ≤ הכרחי; מרווח ≥30 ש' + jitter + `If-None-Match`/`since_seq` |
| Long-poll | **תופס worker** לכל המתנה (הסיבה לתקרית) | **לא** באירוח הנוכחי |
| SSE | חיבור פתוח לכל לשונית/מכשיר: זיכרון, worker (ב-PHP-FPM), heartbeat (~15–25 ש'), proxy buffering/timeouts | רק בשירות שתוכנן לחיבורים פתוחים (Node/Go/ענן), לא ב-PHP משותף |
| WebSocket | כנ"ל + upgrade/proxy | מיותר אם SSE+POST מספיק (UI ← שרת הוא בעיקר קריאה) |
| Broker/Relay | תהליך אחד, חיבורי backend אחד-לשיחה (לא לכל לשונית) | הצעה |
| Webhook | נכנס בלבד, ללא חיבור פתוח | `type`+`id`, אימות חתימה, dedupe |

### 6.4 פרוטוקול אירועים (הצעה)
- כל אירוע: `event_id` (ULID), `conv_id`, `seq` (מונוטוני בשיחה, שרת מקצה), `origin`, `kind`, `payload`, `causation_id`, `idempotency_key`.
- **אחסון עמיד לפני שידור** (append-only); שידור הוא תצוגה של הלוג.
- לקוח שומר `last_seq`; reconnect = `GET /events?since=last_seq` ואז הצטרפות לסטרים; שרת מחזיר חורים = שליחה חוזרת, לא "נראה לי". כפילויות — לפי `event_id`.
- ack לכל **מכשיר** לתצוגה (`delivered_seq`), נפרד מ-ack של **executor** (`run.accepted`/`run.completed`).
- ריבוי לשוניות/מכשירים: כל אחד `Participant(kind=view)` עם lease (למשל 60 ש', חידוש heartbeat); מקור יחיד לתפיסת מנוי backend לשיחה.
- **נגד הד (reflection):** אירוע נושא `origin` מובנה; אירועי `agent`/`system` אינם יכולים ליצור `Run` אלא אם `kind=agent_request` ממושמע (שולח מורשה, `parent_run_id`, תקציב עומק/כמות). אין פרשנות טקסט (F-07).
- **executor יחיד:** `Run` נוצר ב-INSERT ייחודי על `(conv_id, request_id)`; `claim` בעסקה מותנית (כמו `claimNextTask` הקיים — מודל טוב לשימור) + `fence_token`.
- **Backpressure/storm:** backoff מעריכי+jitter, תקרת חיבורים לשיחה ולמשתמש, circuit breaker לפי backend, לעולם לא retry בלולאה על 429/402.

### 6.5 מה עולה ומה אפס
- **אפס טוקנים בהמתנה:** Relay, SSE, webhook→GET, heartbeat, סנכרון בין מכשירים, תצוגה.
- **עדיין עולה תשתית/רשת:** חיבורים פתוחים, אחסון אירועים, בקשות read ל-MA (1,200/דק'/ארגון — נספר), שירות Relay.
- **בהכרח inference:** כל `Run` (כולל תשובת סיכום ל-Handoff, והקשר שנקרא מחדש בסשן חדש).
- **לא אפשרי באירוח הנוכחי:** SSE/WS/long-poll ו-worker קבוע. **אפשרי באירוח הנוכחי:** רק polling דליל, ללא ערבות זמן אמת.

## 7. Remote Control כמקור השראה
**לאמץ (עקרונות UX):** לוג עמיד בצד שרת + לקוחות כ"חלון"; הצטרפות/ניתוק לא משנה את הריצה; הודעות מטלפון כ"הפניות"; push רק על אירוע שדורש אדם; permission prompts פתוחים עד תשובה.
**ציבורי:** CLI ו-claude.ai/code והאפליקציה בלבד. **לא זמין לצד שלישי:** API/פרוטוקול; יצירת סשן עם `setup-token`/API key/gateway.
**דרישה:** תהליך `claude` חי + מכונה ערה + מנוי מלא; ניתוק ~10 דק' ב-server mode מפיל.
**הכרעה:** אי אפשר לשלב RC ישירות כ-backend/UI. **אפשר:** לאפשר למשתמש להפעיל `claude --remote-control` על המכונה שלו **לצד** האפליקציה שלנו, ולהציג בלוח קישור לסשן. האפליקציה שלנו בונה transport משלה (§6). אין להשתמש ב-endpoints לא מתועדים או בעוגיות דפדפן.

## 10. ארכיטקטורת יעד מומלצת
```
דפדפן/מובייל ──SSE+POST──▶ Event Service (נפרד)
                              ├ Event Log (append-only) ─ DB מנוהל
                              ├ Dispatcher (קוד): Run←queued, fence, TTL
                              ├ Adapters: PlatformMA | PlatformAPI | CodeCloud | CodeLocal(pull) | CodeActions
                              └ Controller API (מפתחות Anthropic כאן בלבד)
PHP קיים (mbe-plus.com) ── הזדהות/SSO, UI סטטי, פרויקטים/מטלות (נשארים), ללא אירוע-זמן-אמת
סוכנים ──MCP (אסימון Run קצר-מועד)──▶ Controller   (ללא מפתח API)
```
| רכיב | תפקיד | מה לעשות בקיים |
|---|---|---|
| Conversation/Event store | מקור אמת | **להחליף** `channels/messages` + עמודות המצב |
| Dispatcher+fence | executor יחיד | **להחליף** `dispatch.php` (מנהל-מודל) בקוד דטרמיניסטי |
| Adapter MA | agent+env+session לכל NativeSession, SSE, resume ע"י `events.list` | חדש |
| Adapter Code | Actions/cloud: Run חד-פעמי; מקומי: pull דרך hook | **לשפר** `claude-code.yml`, `bridge/*` (דורמנטי) |
| קטלוג מטלות/פרויקטים/חיבורים/הרשאות/מכסה | | **לשמר/לשפץ** (`projects.php`, `connections.php`, `usage.php`) |
| שער regex (`gate`) | | **לשמר רדום**; לא מקור הגנה יחיד (F-7) |
| בדיקות ה-hook הגלובליים | | **לא לחבר מחדש** ברמת הריפו; רק opt-in לפי פרויקט |
| `monitor`, `checkin`, `listen.sh` לכל צ'אט, `bridge-pause` כפול | | **לפרוש** |
| UI | לשמר ממשק וטבלאות; להוסיף בורר route/model | **לשמר+להרחיב** |

**מכונת מצבים של Run:** `queued → claimed(fence) → running → {awaiting_user | awaiting_agent} → {completed | failed | interrupted | expired}`; רק `completed/failed/interrupted/expired` סופיים; `interrupted` דורש אישור עצירה מה-executor או תפוגת lease לפני Run חדש על אותו ענף.
**מצבי משתתף:** `connected(lease) → stale → expired → cleaned`.
**מיפוי ענף:** `Run → branch claude/<conv>-<run>`, worktree/sandbox בלעדי; commit = בכל מסירה.
**תצפיות ועלויות:** כל `Run` רושם `route, model, executor, payer, tokens, cost_est, active_seconds`; **מקור מדידה:** לפי backend (MA: `usage.list_cost`/`session.usage`; API: usage בתשובה; Code-מנוי: "לא ניתן להמיר לדולרים"); תצוגה נפרדת "מכסה מנוי / קרדיט API / תשתית".
**מיגרציה:** שיחות קיימות מיובאות לקריאה בלבד כ-Conversation חדשה עם היסטוריה; מטלות נשארות; ערוצים ישנים לא מחוברים מחדש.

## 11. משפחות סשנים
מופרד מ-subagent threads (עד 25, באותו sandbox/vault, בתוך סשן MA) וממשימות workflow: אלה פנימיים ל-Run אחד. **משפחה** = Conversations/Runs נפרדים עם `parent_run_id`.
- מתאם יוצר ילד דרך Controller: `spawn_session(task, context_refs, branch, route, model, budget, max_depth)`.
- כל ילד: checkout/worktree/sandbox משלו וענף משלו; **ללא כתיבה לענף של אחר**.
- תקשורת: `message_parent`, `message_child`, `message_sibling` (דרך ה-Event Log; אירוע `agent_request` בלבד מעיר).
- תוצאת ילד ← אירוע `child.result` ← מתעורר מתאם idle **רק אם** הוא ממתין ל-`child.result` (רישום תלות), אחרת רק נרשם.
- עצירה: `cancel(run_id, cascade)` מפיץ ל-Controller; כל ילד מקבל `Interrupt`.
- בלמים: `max_depth`, `max_children`, `max_msgs_per_min`, תקציב טוקנים/עלות לכל משפחה, מניעת מעגל (`causation chain`), התראה אנושית בחריגה.
- **שירות נדרש:** Controller. **כלי MCP מוצעים (לא קיימים):** `spawn_session`, `message_session`, `get_session_status`, `await_results`, `cancel_session`, `list_family`, `handoff` — כולם קוראים ל-Controller עם אסימון Run קצר-מועד המוגבל ל-`conv`/משפחה/ענף; מפתח ה-API נשאר בצד ה-Controller. ב-MA: MCP דרך `mcp_servers` + vault לאסימון; לאמת בריצה (`session.error`) ולא לפי "Connected".

### 16.1 האם GitHub יכול להיות המאזין? [הסקה על בסיס תיעוד GitHub ו-Claude Code Action; חלק לא נבדק]
- **כן, ל-Run של Code:** ה-controller מפעיל workflow (`workflow_dispatch`/`repository_dispatch`) רק כשיש בקשה אמיתית; ה-runner מריץ את `claude` בהתקנה הרשמית, מדווח תוצאה בקריאה אחת חוזרת. בין בקשות — **אפס** תהליכים, אפס פניות, אפס טוקנים. זה מחליף את `listen.sh` ואת המנהל-מודל לצד ה-Code בענן.
- **לא כמאזין חי:** job ב-Actions הוא ריצה מוגבלת בזמן עם מכסת דקות; להחזיק אותו "ממתין" כמאזין שורף דקות ואינו מתאים. גם ל-Code **מקומי** GitHub אינו עוזר (אין תהליך לדחוף אליו).
- **לא לממשק:** GitHub אינו דוחף עדכונים לדפדפן/מובייל. הממשק צריך ערוץ דחיפה אחר (§16.5).
- GitHub webhooks (PR, workflow_run) כן שימושיים: **נכנסים** אלינו בעת אירוע, בלי חיבור פתוח.
- [לא נבדק]: הגבלות ספציפיות של `claude-code-action` על ריצות מתמשכות/תגובה לאירועים; ייבדק ב-Phase 0.

### 16.2 חיוב: איפה הבעיות (לשתי המסלולים שלכם)
- **Platform (קרדיט API):** תקין ונתמך. חייב להיות **מפתח API** מארגון Console (המנוי לא משמש ל-Managed Agents/Messages API). הקרדיט החודשי של התוכנית חל רק על מפתח של ארגון Console מקושר. אין בעיה.
- **Claude Code על המנוי:** תקין **כשאתם** מתחברים למנוי בבינארי הרשמי (CLI, או ה-Action הרשמי עם `CLAUDE_CODE_OAUTH_TOKEN` שלכם). הבעיה היחידה: אסור שהאפליקציה שלנו תנתב בקשות של **משתמשים אחרים** דרך הכניסה שלכם (Legal & Compliance). אם משתמשי הלוח הם אתם בלבד — [הסקה] זה אישי ותואם; אם יש משתמשים נוספים, כל אחד מחבר חיבור משלו, או שהם עוברים ל-API.
- שני הצדדים: עלויות אינן ניתנות להשוואה — מנוי = מכסה/חלון שימוש, לא דולרים; Platform = דולרים + $0.08/שעה פעילה. הממשק יציג כל אחד ביחידה שלו ולא יבצע המרה.
- שימוש ב-`claude -p`/SDK עם מנוי נספר במכסה של המנוי (Help Center 2026-10-07) ומתחרה בשימוש האינטראקטיבי שלכם.

### 16.3 מגבלות דינמיות למשפחת סשנים
כל מגבלה היא **פרמטר מדיניות** (`max_children`, `max_depth`, `max_msgs_per_min`, `budget_usd`/`budget_tokens`) הניתן לשינוי בכל רמה (משתמש→פרויקט→שיחה→Run) ו**רק מצמצם מהאב לבן**. מעליהן **תקרות מערכת קשיחות** שאינן ניתנות לחריגה גם כשהמתאם מבקש. מתאם יכול לבקש הרחבה דרך אירוע `limit_increase_request`; הרחבה מעל ברירת המחדל דורשת אישור אדם. ברירת מחדל מוצעת: 3 ילדים, עומק 1. ההגדרות נשמרות במסד ונקראות בכל `spawn`.

### 16.4 מצב הייצור — צעדי בדיקה (בלי ניחוש)
1. בפאנל: האם יש Cron Jobs/תהליכים ל-claude-tasks. 2. ב-claude.ai: Routines/Triggers פעילים שמפנים ללוח. 3. `health.php` (קריאה בלבד, דרככם) ל-`long_poll_max`/`bridge_paused`. 4. Resource Usage ל-2026-11-02. עד אז הדוח מתייחס לייצור כ-[לא ידוע].

### 16.5 דרישה מחייבת: אפס polling מבוסס-זמן
הנתון שלכם: קריסה ב-~400 פניות בו-זמנית; 10 צ'אטים × פנייה לדקה × 50 משתמשים = 500/דקה + שאר האפליקציות. **מסקנה: כל שיטה שבה מספר הפניות גדל עם (צ'אטים × זמן) נפסלת.** [הערה: 400 הוא נתון בעל הלוח, לא נמדד בדוח; המספרים שלי ב-load-model.md הם הערכות בלבד.]
עיקרון: **פניות פרופורציונליות לאירועים (הודעות אמיתיות), לא לזמן.** צ'אט שקט = 0 פניות.
| צד | מנגנון | פניות כשהשיחה שקטה |
|---|---|---|
| ממשק (דפדפן/מובייל) | **דחיפה** — מועמדים: (א) שירות חיבורים מנוהל חיצוני (pub/sub מנוהל: ה-PHP רק *מפרסם* פעם אחת בעת אירוע, הדפדפן מחובר לשירות החיצוני ולא לשרת שלנו); (ב) Web Push (PWA, כבר קיים service-worker) להתעוררות כשהאפליקציה סגורה; (ג) שירות SSE עצמאי (אפשרות B). רענון נוסף רק ב-focus/חזרה לרשת ולא בטיימר | **0** |
| MA | webhook נכנס → controller → GET אחד; SSE רק בזמן ריצה פעילה | 0 |
| Code ענן | `workflow_dispatch` בעת בקשה; webhook חוזר בסיום | 0 |
| Code מקומי | hook של התור הבא (מושך פעם אחת בתחילת תור), ללא מאזין | 0 |
| ניתוק/חזרה | פנייה אחת `since=last_seq` | 1 לכל חזרה |
**תקרות מוצעות (להערכה ובדיקה, לא מדודות):** אפס בקשות מבוססות-טיימר מהלקוחות; קצב כולל מהלוח לשרת המשותף ≤ 1–2 בקשות/שנייה בשיא ו**≤ 5% מערך הקריסה שדווח (≈20 בו-זמנית)**; מחסום קצב לכל משתמש; כל 429/503 עוצר ושולח התראה. ארכיטקטורת B נשארת, אך כעת "שירות האירועים" יכול להיות **שירות דחיפה מנוהל** (ללא שרת לתחזק) ולא בהכרח תהליך משלנו — החלטה על ספק: [לא ידוע], נבחן ב-Phase 0 (עלות/מגבלות חיבורים/אחסון אירועים/ביקורת אבטחה).
