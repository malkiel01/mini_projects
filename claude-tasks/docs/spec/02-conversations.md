# פרוסה 02 — רשימת שיחות, עדכון חי, מחשב כבוי

תלויה ב-01. ברירות מחדל: ש5-ב (תוקף 12 שעות), ש6-א (צלצול), ש7 (רשימת שיחות).

## מה בונים
1. **רשימת שיחות:** "➕ שיחה חדשה", רשימה לפי `updated_at`, שינוי שם, ארכוב (לא מחיקה). כל שיחה — `cc_session_id` משלה.
   הכותרת — 40 התווים הראשונים של ההודעה הראשונה, עד ששינו.
2. **צלצול בדפדפן:** `EventSource('https://ntfy.sh/<topic>/sse')` כל עוד הדף גלוי; על `reply` — `messages since_seq`
   לשיחה. מחליף את הבדיקה כל 3 שניות של 01; היא נשארת רק כגיבוי כשה-EventSource נכשל, באותם גבולות.
3. **מצב בזמן עבודה:** הגשר מעדכן `bridge-progress {id, claim_id, line}` — לכל היותר פעם ב-10 שניות, רק כשהשתנה
   (למשל "🔧 Bash: npm test", "✏️ עורך lib/x.php"), מתוך אירועי `tool_use` שבזרם. בדף — שורה אחת מתחת להודעה.
4. **מחשב כבוי (ש5-ב):** "מחובר" = `last_seen` ≤ 7 דק'. לא מחובר → הודעה נשמרת, בדף "🔌 המחשב לא מחובר — ייענה כשיידלק".
   הגשר שעולה ומוצא הודעה `queued` בת יותר מ-12 שעות → `bridge-stale` → `stale`, בדף "⏰ ההודעה חיכתה X שעות — לשלוח
   עכשיו?" [שלח] [בטל]. "שלח" → `queued` מחדש.
5. **עלות:** לכל תשובה — עלות ומשך; בראש השיחה — סך השיחה; במסך — סך היום. (`total_cost_usd` הוא הערכה של הלקוח — לכתוב "≈".)
6. **עצירה:** כפתור "⏹ עצור" להודעה בטיפול → `stop-request`; הגשר רואה בצלצול `{"t":"stop"}` → SIGINT לריצה.

## קריטריוני קבלה
1. שתי שיחות פתוחות: "תזכור את המספר 7" בא', "איזה מספר?" בב' → ב' לא יודעת; בא' — יודעת.
2. הדף פתוח, תשובה מגיעה → מוצגת תוך ≤ 2 שניות מ-`bridge-done`, **בלי** בקשות מתוזמנות מהדף (יומן הרשת).
3. גשר כבוי, נשלחה הודעה → "🔌" בדף. הגשר עולה אחרי דקה → נענית. אחרי 13 שעות (שעון מזויף בבדיקה) → `stale` ושאלה.
4. ריצה ארוכה → שורת מצב מתעדכנת, ≤ 6 עדכונים בדקה.
5. "⏹ עצור" → הריצה נעצרת תוך ≤ 5 שניות, ההודעה `failed` עם "נעצר בידי הבעלים"; ההודעה הבאה באותה שיחה עובדת.
6. ארכוב שיחה לא מוחק הודעות מהמסד.
