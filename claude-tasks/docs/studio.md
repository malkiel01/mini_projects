# סטודיו — צ'אט פיתוח מול Claude Platform

האפיון החדש של "מטלות לקלוד", שלב ראשון. מחליף את הגישה של `spec.md` (גשר, מאזינים, צ'אט מנהל) —
הקוד הישן נשאר רדום ולא נגענו בו. המסמך הזה קצר בכוונה: מה הוחלט, איך זה בנוי, ומה עוד לא נבדק.

תאריך: 2026-11-12 · קוד: `studio.php`, `studio-webhook.php`, `bin/studio-cron.php`, `lib/studio/`, `studio.html`,
`assets/js/studio.js`, `assets/css/studio.css` · בדיקות: `php claude-tasks/tests/studio.php`

| 2 | כרגע האפליקציה עובדת **רק דרך Claude Platform**. מסלול Claude Code הוא אופציה עתידית, ונעול בממשק ובשרת. |

## 2. העיקרון

**השיחה היא רשומה אצלנו.** היומן שלנו (`studio_events`) הוא מה שהממשק מציג. הפלטפורמה (Managed Agents) מריצה את
הסוכן בענן שלה; אנחנו שולחים אליה הודעה פעם אחת ומושכים ממנה אירועים רק כשיש ריצה פעילה.

```
דפדפן ──POST──▶ studio.php ──▶ Anthropic: POST /v1/sessions/{id}/events      (מטלה 3: פעם אחת להודעה)
דפדפן ◀─events─ studio.php ◀── Anthropic: GET  /v1/sessions/{id}/events      (מטלה 4: רק בזמן ריצה)
                studio-webhook.php ◀── Anthropic: "הסשן נעצר" (סוג + מזהה)    (מטלה 4: כשהדף סגור)
                bin/studio-cron.php (פעם בדקה) — רק לשיחות שרצות ולא סונכרנו   (רשת ביטחון)
```

- **צ'אט חדש** = שורה ב-`studio_convs`. מיידי, בלי תלות באף צ'אט אחר.
- **סשן** נוצר בהודעה הראשונה: סוכן + סביבה (פעם אחת לכל משתמש) ← סשן עם הריפו מחובר.
- **המצב** (`running` / `idle` / `needs_action` / `budget` / `terminated`) מחושב מהיומן, לא מסדר ההגעה של webhook.

## 3. כללי עומס (מחייבים)

| מצב | פניות לשרת שלנו | פניות לפלטפורמה |
|---|---|---|
| צ'אט שקט, דף פתוח או סגור | 0 | 0 |
| ריצה פעילה, הדף פתוח על השיחה | אחת כל 3 ← 6 ← 10 שניות, ונעצר כשהריצה נגמרת | לכל היותר אחת ל-4 שניות לשיחה, גם עם כמה לשוניות |
| ריצה פעילה, הדף סגור | webhook אחד בכל שינוי מצב | משיכה אחת לכל webhook; אחרת הקורן, פעם בדקה |
| לשונית מוסתרת | 0 | — |
| הקורן, כשאין ריצה פעילה | שאילתה אחת למסד | 0 |

**חריגה מודעת מהכלל "אפס polling מבוסס-זמן"** (דוח המחקר §16.5): בזמן שריצה פעילה והדף פתוח עליה, הדפדפן כן בודק
במרווח. זה פרופורציוני לעבודה פעילה ולא למספר הצ'אטים, ונעצר לבד. SSE אינו אפשרי באחסון הנוכחי. כדי לבטל גם את
זה צריך שירות דחיפה (Web Push או שירות חיצוני) — לא בשלב הזה.

429 / 402 מהפלטפורמה: לא מנסים שוב בלולאה. בממשק — הודעה; בקורן — השיחה נדחית לפי `retry-after`.

## 4. הרשאות ובלמים

"הרשאות מלאות" = כל כלי הסוכן (bash, קבצים, רשת) ב-`always_allow`, סביבה עם רשת פתוחה, והריפו מחובר עם אסימון
ה-GitHub של בעל הלוח — כך שהסוכן דוחף, פותח PR, ואם הותר לו גם ממזג.

| בלם | איך |
|---|---|
| רק בעל הלוח | `studioRequireOwner` — תפקיד `admin` בלבד. אין אסימוני עובדים בנקודת הקצה הזו. |
| תקציב לכל שיחה | ברירת מחדל 20$. נקבע ביצירת הסשן (אי אפשר להוסיף אחר כך); בתקרה השיחה נעצרת ואפשר להעלות. |
| מיזוג | מתג לכל שיחה, ברירת מחדל: מותר. כשכבוי — ההנחיה אוסרת מיזוג. **זו הנחיה לסוכן, לא חסימה טכנית.** |
| אסימון GitHub | עובר רק כ-`authorization_token` של משאב הריפו בסשן. לא בהנחיה, לא בהודעות, לא ביומן. |
| מפתח Anthropic | מהחיבור המוצפן של המשתמש. לא המפתח הגלובלי שב-`config.json`. |
| כללי הריפו | ההנחיה מחייבת: לקרוא `CLAUDE.md`, ענף + PR, בלי push ישיר ל-main, בלי force push, בלי מחיקת ענפים. |
| פעולה שמחכה לאישור | נתמך (`needs_action` ← אשר / דחה), למקרה שיתווספו כלים שדורשים אישור. |
| webhook | חתימה (standardwebhooks) מול הגוף הגולמי, חלון 5 דקות, כפילויות לפי `webhook-id`, התעלמות מסשנים שאינם שלנו. |

## 5. מה נבדק ומה לא

**נבדק** (`tests/studio.php`, 75 בדיקות מול פלטפורמה מדומה; ודף אמיתי בדפדפן מול אותה הדמיה): יצירת סוכן, סביבה
וסשן פעם אחת; צורת הבקשות; שליחה; סנכרון בשני סדרי עמודים; כפילויות; סמן שפג; חישוב המצב; אישור פעולה; תקציב;
מרווח הסנכרון; הקורן (כולל אפס פניות כשאין ריצה); 429; בידוד בין משתמשים; חתימת webhook; ואפס פניות מהדף כשהשיחה
שקטה.

**לא נבדק — אין מפתח API ואין גישה לשרת מסביבת הפיתוח:**

1. ריצה אמיתית מול Anthropic. צורת הבקשות נכתבה לפי התיעוד הרשמי (`platform.claude.com/docs/en/managed-agents/`:
   sessions, events-and-streaming, github, webhooks) ולפי `anthropics/skills` (`claude-api/curl/managed-agents.md`).
2. סדר העמודים והסימון ב-`GET …/events` — לא מתועד במפורש, ולכן הקוד מזהה אותו מהנתונים ותומך בשני הסדרים.
3. שה-API של GitHub (פתיחת PR, מיזוג) אכן מקבל הזדהות מתוך ארגז החול. התיעוד אומר שבקשות ל-GitHub מהריפו המחובר
   עוברות דרך proxy שמזריק את האסימון; לא אומת בריצה.
4. שה-webhook עובר את הגנת הבוטים של האחסון. אם לא — הקורן מכסה, בהשהיה של עד דקה.
5. שהקורן רץ בשרת (גרסת ה-PHP של שורת הפקודה). נראה בלוג הפריסה, בשלב "משימות מתוזמנות".

## 6. מה הלאה (לא בשלב הזה)

- **מסלול Claude Code** — נעול. כשיגיע: אותה שיחה ואותו יומן, מנוע אחר לכל הודעה, והיסטוריה שעוברת כחבילת הקשר.
- **צוות צ'אטים וסוכן מנהל** — כמה שיחות עם תפקידים, והודעה ביניהן כאירוע במסד שמפעיל ריצה אחת.
- **Web Push** בסיום ריצה, במקום הבדיקה במרווח כשהדף פתוח.
- **פרישת הקוד הישן** (גשר, מאזינים, מנהל, שער) והעברת `spec.md` לארכיון.

## 7. הפעלה — מה בעל הלוח עושה פעם אחת

1. בלוח: הגדרות ← חיבורים ← Anthropic (מפתח API מה-Console), ו-GitHub (אסימון עם הרשאת `repo` לריפו).
2. בלוח: 🛠 בכותרת ← סטודיו ← שיחה חדשה.
3. רשות, לעדכון מיידי כשהדף סגור: ב-Console של Anthropic ← Webhooks ← נקודת קצה עם הכתובת שמוצגת בהגדרות הסטודיו
   והאירועים `session.status_idled`, `session.status_run_started`, `session.status_terminated`,
   `session.budget_reached`; את הסוד (`whsec_…`) מדביקים בהגדרות הסטודיו.
