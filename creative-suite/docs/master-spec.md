# חבילת היצירה — תוכנית אב

חבילת אפליקציות לעריכת מסמכים ותמונות, בהשראת חבילת אדובי: כל אפליקציה **פרויקט בפני עצמו**, וכולן חולקות
**קובץ אחד** — `‎.mbe` — שנפתח בכל אחת מהן, ומכיל ייצוגים מוכנים לכל תוכנה אחרת.

המסמך הזה שייך ל**צ'אט המתכלל**. כל צ'אט של אפליקציה קורא אותו ואת `mbe-format.md` לפני שהוא מתחיל.

## 2. עקרונות

1. **מקור אמת אחד** — `document.json`. כל השאר (docx, pdf, png…) נגזר ממנו.
2. **שמור את מה שלא הבנת.** אפליקציה לא מוחקת מידע של אפליקציה אחרת — לעולם.
3. **כנות בייצוא.** כל ייצוג ושכל ייבוא — עם דוח פערים. בלי "כמעט" שקט.
4. **הכול בדפדפן או ב-PHP.** אין שרת מסמכים, אין Docker. עבודה כבדה — WASM / Canvas / WebGL בדפדפן; ייצוגים
   שצריך בלי דפדפן (API) — PHP, כמו ה-PDF של עורך התמלילים.
5. **עברית ו-RTL מהיסוד** — לא תוספת. גופנים עבריים חופשיים מוטמעים, bidi נכון בכל פלט.
6. **טלפון קודם** — שפת העיצוב `phone-first-design`. אפליקציה כבדה (רסטר, עימוד) — מותאמת קודם לטאבלט/מחשב,
   אבל **צפייה, ייצוא ועריכה בסיסית** עובדים בטלפון.
7. **כל אפליקציה עצמאית** (CLAUDE.md): תיקייה, `app.json`, משתמשים ונתונים משלה, בלי `require` מחוץ לתיקייה.
   הקוד המשותף מגיע **כעותק מסונכרן** (סעיף 4) — לא כתלות חיה.

## 4. מה משותף — ואיך הוא מגיע לכל אפליקציה

| מודול | מה | מקור |

| **ליבת הפורמט** | קריאה, כתיבה, אימות, המרת גרסאות, ניהול ייצוגים — JS (דפדפן) ו-PHP (שרת) | `creative-suite/mbe-core/src` |
| **שכבות וצבע** | הרכבת שכבות, מצבי מיזוג, שקיפות, המרות צבע | **בעלים: רסטר** (פרויקט 2) |

| **מעטפת ממשק** | סרגל כלים, לוח שכבות, לוח מאפיינים, חלון ייצוא — לפי `phone-first-design` | **בעלים: רסטר** (פרויקט 2); וקטורי ועימוד — אותו מראה |

**עבודה במקביל (הוכרע 2026-10-24: רסטר, וקטורי ועימוד נפתחים יחד):**
- **החוזה המשותף כבר קיים** — מודל השכבות והמשטחים ב-`mbe-format.md` (שכבות `raster` / `vector` / `frame` / `group`,
  `blend`, `opacity`), והמראה — הסקיל `phone-first-design`. כל אפליקציה בונה לפיהם, ואין צורך לחכות לאחרת.
- **"כלל השתיים":** בגרסה 1 כל אפליקציה בונה את מה שהיא צריכה **בתוך התיקייה שלה**. מודול משותף מחולץ ל-
  `creative-suite/<module>/src` (עם סנכרון ושער, כמו הליבה) רק כששתי אפליקציות כבר משתמשות באותו דבר — והבעלים
  שבטבלה הוא שמחלץ, בבקשה דרך הצ'אט המתכלל. כך המקביליות לא נתקעת, וגם לא נבנים שני מודולים שונים לאותו דבר.
- **שמות ומבנים משותפים** (שמות מצבי מיזוג, יחידות `pt`, צבע `sRGB`, מזהי שכבות) — רק כפי שהם ב-`mbe-format.md`.
  צריך משהו חדש במודל? בקשה ב-`creative-suite/docs/requests/`.

**ההפצה — כמו DevLoop:** עורכים רק במקור (`creative-suite/mbe-core/src`), וכלי סנכרון מעתיק לכל אפליקציה שרשומה
ב-`creative-suite/mbe-core/apps.json`; שער בפריסה עוצר עותק ששונה. אפליקציה נכנסת לרשימה **רק בהסכמת הצ'אט שלה**.

## 5. חיבור בין האפליקציות

- **דרך הקובץ** — העיקר: שומרים `.mbe` באחת, פותחים באחרת.
- **הטמעה** — `platform/docs/embed.md` (חתימת Ed25519, כבר משמש את עורך התמלילים בהצעות תקציב). למשל: העימוד
  מטמיע את עורך הרסטר לעריכת תמונה במקום. כל אפליקציה שמטמיעה או מוטמעת — לפי הפרוטוקול, בלי קיצורי דרך.
- **"פתח ב…"** — כפתור שמעביר את הקובץ לאפליקציה אחרת בחבילה (הורדה+פתיחה, או דרך השרת אם שתיהן מחוברות).
  יאופיין בפרויקט 2, כשיש שתי אפליקציות אמיתיות.

## 6. הנחיות לכל צ'אט של אפליקציה

1. קרא את CLAUDE.md, את המסמך הזה, את `mbe-format.md` ואת מסמך ההנחיות שלך ב-`docs/projects/`.
2. **אל תיגע בתיקייה של פרויקט אחר**, וגם לא ב-`creative-suite/` מלבד מסמך הפרויקט שלך (סטטוס ויומן).
3. צריך שינוי בפורמט או משהו מפרויקט אחר? כתוב בקשה ב-`creative-suite/docs/requests/<app>-<נושא>.md` ומזג ל-main. **אין צורך
   שבעל המערכת יעביר אותה** — היא מופיעה בדשבורד תחת "📨 בקשות לצ'אט המתכלל" עד שיש עליה הכרעה; הוא רק מזכיר לצ'אט המתכלל.
4. כל שמירה של `.mbe` עוברת את האימות של הליבה. כל ייצוג — עם `sourceSha256` ו-`gaps`.
5. מחזור העבודה של CLAUDE.md: ענף מ-`main`, PR, מיזוג, `conclusion: success`.
6. **התקדמות:** במסמך הפרויקט שלך יש קטע `## התקדמות` — יעדים `- [ ]` / `- [x]`. סמן `[x]` כשיעד הושלם ונפרס.
   הדשבורד (`creative-suite/dashboard/`) קורא את המסמכים בכל טעינה: הפסקה הראשונה = הסיכום, היעדים = האחוז.
   לאפליקציה שיש לה מסמך מעקב משלה (טבלת "תמונת מצב" עם ✅ / 🟡 / ⏳ / ⬜) — שורה במסמך הפרויקט:
   `**מעקב האפליקציה:** \`<app>/docs/roadmap.md\`` — והדשבורד מציג גם את התקדמות האפליקציה עצמה.

7. **שלושה קטעים במסמך הפרויקט** — הדשבורד מציג כל אחד בנפרד, כמשימות מתקפלות:
   - `## התקדמות` — המשימות של הצ'אט (אתה מסמן);
   - `## ממתין לבעל המערכת` — מה רק בעל המערכת יכול (להעביר הודעה, להחליט, לבדוק בטלפון). כשאתה צריך ממנו משהו —
     הוסף כאן שורה, לא רק בצ'אט. הוא או הצ'אט המתכלל מסמנים `[x]`. **מתחת לשורה, בהזחה:** `מדריך:` עם צעדים ממוספרים
     מדויקים, ו/או `פרומפט:` עם ההודעה שהוא מדביק בצ'אט (בהזחה של 4) — הדשבורד מציג אותם עם כפתור העתקה;
   - `## שיפורים מומלצים` — הצעות, לא חובה. הוסף כשאתה רואה משהו ששווה לעשות.

## 6א. הצוות — עבודה כצוות אחד (הוכרע 2026-10-25)

כל צ'אטי החבילה — המתכלל, המאפיין, הליבה, עורך התמלילים, רסטר, וקטורי ועימוד — הם **צוות קבוע אחד**
(`creative-suite/team/roster.json`) שמדבר **ישירות, בשני הכיוונים**: צ'אט ששולח הודעה מעיר את הנמען, והפרטים בקובץ ב-main.
בעל המערכת לא מעביר הודעות בין צ'אטים, ולא נפתח צ'אט חדש לכל משימה. הנוהל המלא: הסקיל `creative-suite-team`
(`.claude/skills/creative-suite-team/SKILL.md`).

## 7. מה הצ'אט המתכלל עושה

- **הדשבורד** — `creative-suite/dashboard/` (רק לבעל המערכת: החבילה `restricted`). רשימת הפרויקטים — מטבלת סעיף 3;
  לכל פרויקט — המסמך שהעמודה "סטטוס" מקשרת אליו. פרויקט חדש = שורה בטבלה + מסמך עם `## התקדמות`.

- מחזיק את `master-spec.md` ו-`mbe-format.md`, ומכריע בבקשות שינוי לפורמט.
- כותב מסמך הנחיות לכל פרויקט לפני שנפתח לו צ'אט, ומעדכן את טבלת הסטטוס.
- לא כותב קוד אפליקציות.
