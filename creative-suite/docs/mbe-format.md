# פורמט ‎`.mbe` — אפיון (גרסת פורמט 1.0)

הקובץ המשותף של חבילת האפליקציות. **לב הפרויקט** — כל אפליקציה בחבילה קוראת וכותבת אותו. המסמך הזה
מחייב את כל הצ'אטים; שינוי בו עובר רק דרך הצ'אט המתכלל.

> סטטוס: **גרסה 1.0 — ממומשת בליבה** (`creative-suite/mbe-core/`, 2026-10-23). הסעיפים המסומנים 🧪 הם השערות שצריך
> לאמת בניסוי לפני שננעלים. הסכמות הרשמיות: `creative-suite/mbe-core/schema/`.

---

## 1. מה הקובץ מבטיח — ומה לא

| מבטיח | לא מבטיח |
| --- | --- |
| קובץ אחד שכל אפליקציה בחבילה פותחת ועורכת, בלי לאבד מידע של אפליקציה אחרת | שלחיצה כפולה על `‎.mbe` תפתח את Word או פוטושופ — זה טכנית בלתי אפשרי (הן מזהות לפי סיומת וחתימה בתחילת הקובץ) |
| בתוכו **ייצוגים מוכנים** (PDF, Word, PNG, SVG…) שכל תוכנה זרה פותחת אחרי חילוץ או ייצוא | שעריכה בתוכנה זרה תחזור לבד לקובץ — היא חוזרת **רק כייבוא מפורש** (סעיף 7) |
| ייצוא בלחיצה של כל ייצוג כקובץ רגיל | נאמנות מלאה בכל ייצוג — כל ייצוג "מיטבי", ויש לו דוח פערים |
| קריאות לנצח: גם בלי האפליקציות — זה ZIP עם JSON ו-PNG | |

**ההכרעה (2026-10-22):** מכל + ייצוגים. נדחו: "פוליגלוט" (קובץ שהוא גם PDF וגם ZIP — שביר), ופורמט פנימי בלי
ייצוגים (לא עונה על הדרישה).

## 2. תקדימים — ומה לקחנו מכל אחד

| תקדים | מה לקחנו |
| --- | --- |
| **ODF** (‏odt/ods) | ZIP; הקובץ הראשון `mimetype` **לא דחוס** — כך מזהים את סוג הקובץ מהבתים הראשונים בלי לפתוח את ה-ZIP; תיקיית `Thumbnails/` |
| **OpenRaster** (‏ora) | שכבות רסטר כ-PNG + עץ שכבות ב-XML + **`mergedimage.png`** — תמונה משוטחת שכל מציג מראה |
| **Illustrator ‏`.ai` "PDF Compatible"** | מידע פרטי לצד ייצוג ציבורי בתוך אותו קובץ; תוכנה זרה רואה את הייצוג, אנחנו רואים הכול |
| **PSD "Maximize Compatibility"** | שמירת תמונה משוטחת כדי שתוכנה שלא מבינה שכבות תראה משהו |
| **IDML** | ייצוג פתוח של מסמך עימוד (מסגרות, שטפי טקסט, עמודי אב) — מקור השראה למודל העימוד |
| **OOXML / OPC** (‏docx) | חלקים + רשימת תוכן + קשרים; חלק לא מוכר נשמר — אנחנו מאמצים "שמור את מה שלא הבנת" |

## 3. המבנה

```
my-book.mbe                 ZIP (Deflate; בלי ZIP64 בגרסה 1 — סעיף 8)
├── mimetype                ראשון, לא דחוס: application/vnd.mbe+zip
├── manifest.json           מי, מה, איזו גרסה, רשימת חלקים וגיבובים
├── document.json           המודל הקנוני — מקור האמת היחיד
├── media/                  משאבים בינאריים, שם = sha256 + סיומת (תמונות, שכבות רסטר, גופנים מוטמעים)
├── apps/<app-id>/          מידע פרטי של אפליקציה (מצב תצוגה, הגדרות כלים) — אחרים שומרים בלי לגעת
└── renditions/             ייצוגים מוכנים, נגזרים בלבד
    ├── preview.png         חובה — תמונה ממוזערת (עמוד ראשון / לוח ראשון), עד 1024px
    ├── document.pdf        מומלץ לכל סוג
    ├── document.docx       למסמכי טקסט ועימוד
    ├── image.png           לרסטר — משוטחת, בגודל מלא
    ├── image.ora           לרסטר — עם שכבות (פוטושופ ו-GIMP פותחים ora/PSD; PSD — שלב מאוחר, סעיף 9)
    └── drawing.svg         לווקטורי
```

### `manifest.json`

```json
{
  "format": "mbe",
  "version": "1.0",
  "kind": "text",
  "created": { "app": "word-processor", "appVersion": "…", "at": "2026-10-22T10:00:00Z" },
  "modified": { "app": "raster", "appVersion": "…", "at": "…" },
  "document": { "path": "document.json", "sha256": "…" },
  "media": [ { "path": "media/ab12….png", "sha256": "ab12…", "type": "image/png", "bytes": 48213 } ],
  "renditions": [
    { "path": "renditions/document.pdf", "type": "application/pdf", "sourceSha256": "…", "by": "word-processor", "gaps": [] }
  ]
}
```

- `kind` — סוג המסמך הראשי: `text` · `layout` · `raster` · `vector` (הרשימה פתוחה). קובע איזו אפליקציה פותחת
  כברירת מחדל — **לא** מי מורשה לפתוח.
- `sourceSha256` של ייצוג = הגיבוב של `document.json` שממנו נגזר. לא תואם → הייצוג **מיושן**: לא מוצג כאמיתי,
  ומחדשים אותו בשמירה הבאה.
- `gaps` — מה לא עבר לייצוג (כמו "דוח הייבוא" של עורך התמלילים), למשל `["blend-mode:overlay → normal"]`.
- **JSON קנוני:** `document.json` ו-`manifest.json` נכתבים קנוניים לפי **RFC 8785** (מפתחות ממוינים לפי UTF-16, בלי
  רווחים, מספרים בצורת ECMAScript). **הגיבוב — על הבתים שבקובץ.** כך JS ו-PHP כותבים אותו מודל באותם בתים, וייצוג
  לא מסומן "מיושן" רק כי אפליקציה בשפה אחרת שמרה. (הכרעה 2026-10-23)

### `document.json` — המודל הקנוני

עקרון: **מעטפת משותפת אחת, תוכן לפי סוג.** כל אפליקציה מבינה את המעטפת; את התוכן — רק מה שהיא יודעת.

```json
{
  "units": "pt",
  "color": { "space": "sRGB" },
  "fonts": [ { "family": "David Libre", "embedded": "media/…woff2" } ],
  "styles": { "…": "…" },
  "surfaces": [
    {
      "id": "s1", "type": "page", "size": [595.3, 841.9], "master": null,
      "layers": [
        { "id": "L1", "name": "רקע", "type": "raster", "src": "media/….png", "opacity": 1, "blend": "normal", "visible": true, "locked": false },
        { "id": "L2", "name": "לוגו", "type": "vector", "paths": [ "…" ] },
        { "id": "L3", "name": "טקסט", "type": "frame", "box": [56, 56, 483, 730], "flow": "f1" }
      ]
    }
  ],
  "flows": { "f1": { "engine": "prosemirror", "doc": { "type": "doc", "content": [ "…" ] } } }
}
```

- `surfaces` — עמודים (עימוד, תמלילים), לוחות (ווקטורי), קנבס (רסטר). אותו מבנה לכולם.
- `layers` — עץ (קבוצה = שכבה עם `children`). סוגים בגרסה 1: `raster` · `vector` · `frame` (מסגרת טקסט/תמונה) · `group`.
- `flows` — **שטפי טקסט** שעוברים בין מסגרות ועמודים. התוכן הוא ה-JSON של ProseMirror — **אותו מודל שעורך התמלילים
  כבר שומר**, כדי שהוא לא יצטרך לתרגם. מסמך `text` = משטח אחד או יותר, שטף אחד שזורם בעמודים אוטומטיים.
- מזהים יציבים לכל דבר (`id`) — כדי שגרסה, הערה או הפניה ישרדו עריכה.
- **פירוט סכמת התוכן לכל סוג** — במסמכי הפרויקטים, ונכנס לכאן כשהוא נסגר. הסכמה הרשמית:
  `creative-suite/mbe-core/schema/document-1.json` (JSON Schema).

### כללי תקינות (נאכפים בליבה, הכרעה 2026-10-23)

| כלל | בפתיחה | בשמירה |
| --- | --- | --- |
| **הפניה למשאב** = כל מפתח `src` או `embedded`, בכל עומק — כולל בתוך שטף ProseMirror. חייבת להיות `media/<sha256>.<ext>` שקיים בקובץ. ‏`data:` ו-`https:` — נדחים. ‏`href` (קישור בטקסט) — מותר | שגיאה | שגיאה |
| **`renditions/preview.png`** | חסר — אזהרה (קובץ מבחוץ עדיין נפתח); מעל 1024px — אזהרה | **חובה** |
| **מזהים** ייחודיים בכל המסמך — משטחים ושכבות יחד; מסגרת שמפנה לשטף שלא קיים | שגיאה | שגיאה |
| **רשימות פתוחות** (סוגי שכבות ומשטחים, `kind`, `units`, `blend`) — נבדקות בתבנית, לא ברשימה סגורה, כדי שקורא 1.0 יפתח 1.x עם סוג חדש. ‏`opacity` ‏0–1, ‏`box` — 4 מספרים, ‏`size` — 2 מספרים חיוביים | שגיאה בצורה | שגיאה בצורה |
| **minor חדש** (למשל 1.7) — נפתח ונשמר בגרסה שלו, עם כל מה שלא הובן | — | — |
| **פרטיות:** כתובת מייל בכל מקום ב-manifest | אזהרה | אזהרה |

**משמעות לאפליקציות:** תמונה בתוך שטף טקסט (ProseMirror) צריכה `src: "media/…"` בתוך `.mbe` — אפליקציה שמחזיקה
תמונות בכתובת שרת ממירה אותן בייצוא ובחזרה בייבוא.

### תוכן שכבה `vector` (הכרעה 2026-10-24, מבקשת וקטורי)

`paths` בשכבה `vector` — רשימת פריטים, **בסדר ההצגה** (הראשון מאחור). שלושה סוגים:

**נתיב** (בלי `type`, או `type: "path"`):

```json
{ "id": "p1", "d": "M10 10 L90 10 C95 10 100 15 100 20 Z", "transform": [1, 0, 0, 1, 0, 0],
  "fill": { "color": "#1f3a5f", "opacity": 1 },
  "stroke": { "color": "#000000", "opacity": 1, "width": 1, "cap": "butt", "join": "miter", "miter": 4, "dash": [] },
  "fillRule": "nonzero", "shape": { "type": "rect", "box": [10, 10, 90, 40], "radius": 6 }, "name": "כפתור" }
```

| שדה | חובה | מה |
| --- | --- | --- |
| `id` | כן | ייחודי בכל המסמך — יחד עם משטחים ושכבות |
| `d` | כן | תחביר נתיב של SVG, **רק פקודות מוחלטות `M L C Q Z`**, ב-`pt` של המשטח. כל קורא מצייר אותו בלי ספרייה |
| `transform` | לא | `[a b c d e f]` כמו ב-SVG; ברירת מחדל — זהות |
| `fill` / `stroke` | לא | `null` = בלי. ‏`color` — `#rrggbb` ‏(sRGB), ‏`opacity` בנפרד. ב-`fill` אפשר `gradient` במקום `color`: `{ type: "linear", from, to, stops: [{ at, color, opacity }] }`. ‏`stroke`: ‏`width`, ‏`cap` (butt/round/square), ‏`join` (miter/round/bevel), ‏`miter`, ‏`dash` (ב-`pt`) |
| `fillRule` | לא | `nonzero` / `evenodd` |
| `shape` | לא | פרמטרים של צורה חיה (`rect`, `ellipse`, `polygon`, `star`, `line`). **`d` הוא תמיד האמת**; מי שלא מכיר `shape` מצייר את `d` ושומר את `shape` כמו שהוא |
| `name` | לא | שם בלוח השכבות |

**קבוצה:** `{ "id", "type": "group", "name", "children": [ …פריטים… ] }` — בלי `d` ובלי `transform` משלה; סדר הילדים =
סדר ההצגה. קבוצה בתוך `paths` ולא שכבה `group`, כדי שקבוצה באמצע שכבה לא תשנה את סדר ההצגה.

**טקסט קצר** (לוגו, כותרת — לא שטף): `{ "id", "type": "text", "text": "שלום\nעולם", "box": [x, y, w, h],
"font": { "family", "size", "weight" }, "align", "lineHeight", "auto", "fill", "stroke" }`. ‏`auto: true` — רוחב לפי התוכן;
`false` — גלישה ברוחב התיבה. כיוון — לפי התוכן (bidi). הגופן — ב-`fonts` של המעטפת עם `embedded: "media/…"`. בייצוא —
**קווי מתאר**, עם `gaps: ["text → outlines"]`. טקסט ארוך שזורם בין מסגרות — שכבה `frame` עם `flows`, כמו קודם; שני
המבנים חיים זה לצד זה.

**מי שלא מבין:** פריט עם `type` לא מוכר — מדלגים עליו בציור ושומרים אותו כמו שהוא (סעיף 4).
**בסכמה:** עד גרסה 1.1 של הליבה `paths` נבדק כרשימה בלבד; הבדיקה המלאה (`id`, ‏`d` בתבנית) — בקשה לליבה.

### הגדרות עימוד (`layout`) ועמודי אב (הכרעה 2026-10-24, מבקשת העימוד)

**`layout` בשורש `document.json`** — שם שמור; אף אפליקציה לא משתמשת בו לדבר אחר:

```json
"layout": { "facing": true, "binding": "right",
  "margins": { "top": 42.52, "bottom": 56.69, "inside": 56.69, "outside": 42.52 },
  "numbering": { "start": 1, "style": "arabic" } }
```

- `facing` — עמודים כפולים. ‏`binding` — `right` / `left` (ספר עברי — `right`). ‏`margins` — ב-`pt`; ‏`inside` = צד השדרה,
  ובעמודים כפולים מתחלף בין זוגי לאי-זוגי. ‏`numbering` — `start` ו-`style` (`arabic` / `hebrew`).
- אפליקציה שמעמדת עמודים (העימוד, ובעתיד גם עורך התמלילים) — **קוראת ממנו** ולא ממציאה שדה משלה.

**עמוד אב** = משטח `type: "master"`; עמוד מפנה אליו בשדה `master` (`id` של עמוד האב). עמוד האב מחזיק `name`, `size`,
`layers` (מסגרות שחוזרות בכל עמוד), ו-`running` — מספר עמוד וכותרת רצה **במיקום סמנטי**, כך ששינוי שוליים או כריכה
מזיז אותם לבד:

```json
{ "id": "mA", "type": "master", "name": "A", "size": [419.53, 595.28], "layers": [],
  "running": { "folio":  { "position": "bottom", "align": "outside", "size": 10 },
               "header": { "position": "top", "align": "center", "size": 9, "odd": "שם הספר", "even": "שם הפרק" } } }
```

`position` — `top` / `bottom`; ‏`align` — `outside` / `center` / `inside`; ‏`null` = בלי. **מי שלא מכיר עמודי אב** — לא מצייר
משטח `master` כעמוד, ושומר אותו כמו שהוא.

### מסגרות, שטפים וסגנונות פסקה (הכרעה 2026-10-25, מבקשת העימוד)

**מסגרת טקסט** — שכבה `frame` עם `flow`:

```json
{ "id": "t1", "type": "frame", "box": [56, 56, 300, 500], "flow": "f1", "columns": 2, "gutter": 12 }
```

`columns` — 1–12, מימין לשמאל; `gutter` — הרווח בין טורים ב-`pt`.

**מסגרת תמונה** — שכבה `frame` עם `src` (במקום `flow`):

```json
{ "id": "i1", "type": "frame", "box": [40, 40, 170, 128], "src": "media/<sha256>.jpg", "px": [1200, 800],
  "fit": "cover", "focus": [0.5, 0.5], "zoom": 1, "wrap": "box", "wrapGap": 8 }
```

`px` — גודל התמונה בפיקסלים (כדי לעמד בלי לפענח אותה); `fit` — `contain` / `cover`; `focus` — מה נשאר בחיתוך (0–1 לכל
ציר); `zoom` — 1–10; `wrap` — `none` / `box` (טקסט עוקף את המסגרת במרחק `wrapGap` ב-`pt`). `wrap` מתאים לכל מסגרת, גם לצורה
וקטורית בעתיד.

**סדר השרשור — רשימה אחת בשטף**, לא מספור בכל מסגרת:

```json
"flows": { "f1": { "engine": "prosemirror", "doc": { … }, "frames": ["t1", "t2", "t3"], "autogrow": true, "style": "body" } }
```

- `frames` — מזהי המסגרות בסדר הזרימה. **כל מזהה ברשימה — שכבת `frame` קיימת שה-`flow` שלה הוא השטף הזה, ומופיע פעם אחת.**
  רשימה ולא `flowIndex`: מקום אחד לסדר, בלי מספרים כפולים או חורים, והוספה או מחיקה לא ממספרות מחדש.
- `autogrow` — טקסט שלא נכנס מוסיף עמודים ומסגרות בסוף. `style` — סגנון ברירת המחדל של השטף, שם מ-`styles`.
- שטף **בלי** `frames` (עורך התמלילים: שטף אחד שזורם בעמודים אוטומטיים) — חוקי, ומי שלא מעמד במסגרות שומר אותו כמו שהוא.

**סגנונות פסקה** — `styles.<שם>`; השמות `body`, `h1`, `h2`, `h3` שמורים לגוף ולכותרות 1–3:

```json
"styles": { "body": { "name": "גוף", "font": "Noto Serif Hebrew", "size": 11, "leading": 15, "align": "justify",
                      "weight": 400, "spaceBefore": 0, "spaceAfter": 4, "indent": 12 } }
```

מידות ב-`pt`; `align` — `justify` / `right` / `center` / `left`; `weight` — ציר `wght` (1–1000). פסקה (`paragraph`) → `body`,
כותרת (`heading`, `level` 1–3) → `h1`…`h3`; הסימון `bold` = אותו גופן במשקל 700. שמות הצמתים והסימונים — כמו ב-TipTap של
עורך התמלילים, כדי ששטף יעבור בין העורך לעימוד בלי תרגום. **כל אפליקציה שכותבת סגנונות פסקה ל-`.mbe` — במבנה הזה.**

## 4. גרסאות של הפורמט

- `version` = `major.minor`.
- **minor** — רק תוספות. קורא ישן פותח קובץ חדש ו**שומר את מה שלא הבין** (שדות לא מוכרים ב-JSON, קבצים לא מוכרים
  ב-ZIP, תיקיות `apps/` של אחרים). זה חוק — לא המלצה. כך אפליקציה אחת לא מוחקת עבודה של אחרת.
- **major** — שבירה. קורא ישן מסרב בהודעה ברורה ("הקובץ נוצר בגרסה חדשה — עדכן"), ולא מנסה לנחש.
- כל major חדש מגיע עם ממיר מהקודם, בספריית הליבה.

## 5. מי קורא ומי כותב מה

| אפליקציה | `document.json` | כותבת ייצוגים |
| --- | --- | --- |
| עורך התמלילים | שטפים, סגנונות, עמודים אוטומטיים; שכבות/מסגרות — מציג כתמונה, שומר כמו שהן | ‏pdf, docx, preview |
| עיצוב רסטר | שכבות רסטר וקבוצות; וקטורי וטקסט — מציג משוטח, שומר כמו שהם | ‏png, ora, preview |
| וקטורי | נתיבים, צורות, טקסט קצר; רסטר — כתמונה מקושרת | ‏svg, pdf, preview |
| עימוד | הכול: מסגרות, שטפים, עמודי אב; רסטר ווקטורי — כמשאבים מוצבים | ‏pdf, docx (מיטבי), preview |

כלל: **אפליקציה עורכת רק את מה שהיא מבינה, ושומרת את כל השאר בית-לבית.**

## 6. איפה הקבצים חיים (הכרעה 2026-10-22: גם וגם)

- **בשרת** — ספרייה לכל אפליקציה (כמו עורך התמלילים היום), עם גרסאות. בשרת המודל יכול להישמר פרוס (שורות במסד +
  קבצים), וה-`.mbe` נארז בהורדה. נתונים בשרת → `--exclude` ב-`deploy.yml` לפני הכתיבה הראשונה.
- **במכשיר** — "הורדה כ-‎.mbe" ו"פתיחת ‎.mbe" מכל אפליקציה; ב-PWA מותקן — `file_handlers` ב-manifest כדי ש"פתח
  באמצעות" במחשב יפתח את האפליקציה הנכונה לפי `kind`. 🧪 לבדוק תמיכה בפועל (Chrome/Edge במחשב — כן; אנדרואיד/iOS — מוגבל).
- זיהוי: סיומת `‎.mbe`, ו-`mimetype` בתחילת הקובץ (`PK…mimetypeapplication/vnd.mbe+zip`). הסיומת נבדקה:
  השימוש הקודם היחיד שנמצא — קובצי משחק MVP Baseball 2005, מיושן.

## 7. עריכה בתוכנה זרה

**אין סנכרון שקט חזרה.** ייצוג הוא צילום, לא ערוץ דו-כיווני. התהליך:

1. מייצאים `document.docx` → עורכים ב-Word → שומרים.
2. "ייבוא לתוך ‎.mbe" באפליקציה המתאימה → **דוח ייבוא** (מה עבר, מה אבד) → נשמר **כגרסה חדשה**, הישנה בהיסטוריה.
3. מה שאין ל-Word מקום בשבילו (שכבות רסטר, מסגרות) נשמר מהגרסה הקודמת לפי `id`, ככל שאפשר — והדוח אומר.

🧪 **ניסוי ש1 — "הקובץ הוא גם docx":** האם Word פותח ZIP של `.mbe` ששמו שונה ל-`.docx`, אם החלקים של Word יושבים
בשורש ושלנו בצד. אם כן — אפשר בעתיד מצב "תואם Word" למסמכי טקסט. לא תנאי לגרסה 1; דורש Word אמיתי — בעל המערכת.

## 8. גודל

- `media/` לפי גיבוב — תמונה שמופיעה 10 פעמים נשמרת פעם אחת.
- ייצוגים מכפילים גודל. ברירת מחדל: **preview + pdf תמיד**, השאר לפי סוג. אפשרות "קובץ קל" — preview בלבד
  (הייצוגים נבנים בייצוא).
- תקרה רכה: אזהרה מעל 200MB. **קשיחה (גרסה 1): 1GB פתוח ו-10,000 קבצים.**
- **ZIP64 — לא בגרסה 1.** קובץ ZIP64 נדחה בקוד `zip64-unsupported` עם הודעה ברורה, והליבה לא כותבת אותו. נדרש רק
  מעל 4GB או 65,535 קבצים — הרחק מעל התקרה. ייכנס ב-minor כשתקרה תעלה (הכרעה 2026-10-23).
- PNG לשכבות רסטר (בלי אובדן). WebP/AVIF — לא בגרסה 1.

## 9. מה לא בגרסה 1

ZIP64 (סעיף 8), PSD אמיתי (מבנה בינארי מורכב; ora מכסה GIMP/Krita, ו-PSD — בהמשך, ספריית צד שלישי בדפדפן), IDML, CMYK והפרדות
צבע להדפסה, שיתוף בזמן אמת, חתימה דיגיטלית, הצפנה.

## 10. אבטחה

קובץ `.mbe` מגיע ממשתמשים ונפתח בדפדפן ובשרת — מתייחסים אליו כעוין:

- **ZIP:** אין נתיבים עם `..`, `/` מוביל או `\` (zip-slip); תקרה לגודל פתוח ולמספר קבצים; יחס דחיסה חריג = דחייה
  (zip-bomb). לא מחלצים לדיסק — קוראים מהזיכרון.
- **אין קוד בקובץ:** אין סקריפטים, ‏SVG עובר ניקוי (בלי `<script>`, ‏`on*`, ‏`foreignObject`, הפניות חיצוניות).
- **אין הפניות חיצוניות:** כל משאב בתוך `media/` — קובץ לא "מתקשר הביתה" ולא נשבר כשאתר נופל.
- **גופנים:** מוטמעים רק גופנים חופשיים (OFL ודומיהם); אחרים — בשם בלבד, עם גופן חלופי (כמו "גופן מוחלף" בעורך).
- **גיבובים:** חלק שהגיבוב שלו לא תואם ל-`manifest.json` — דוח "הקובץ פגום חלקית", לא קריסה.
- **פרטיות:** `manifest` שומר שם אפליקציה וזמן — לא שם משתמש ולא מייל.
