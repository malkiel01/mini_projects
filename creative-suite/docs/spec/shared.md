## 2. הסתירה עם CLAUDE.md — ואיך היא נפתרת

CLAUDE.md: **כל אפליקציה עצמאית** — משתמשים, מסד ועוגייה משלה, בלי `require` מחוץ לתיקייה, ויכולה לצאת לדומיין משלה.
ענן משותף נראה כמו ההפך. **הפתרון (הכרעה 1): הענן הוא עוד אפליקציה עצמאית, והאחרות מתחברות אליו ב-API — לא בקוד.**

| הכלל | איך נשמר |
| --- | --- |
| משתמשים ומסד משלה | לענן — משתמשים ומסד **משלו** (`suite-cloud/data/`). אפליקציה שומרת רק "החשבון שלי מקושר לענן X" ואסימון |
| בלי `require` מחוץ לתיקייה | האפליקציות מדברות עם הענן **ב-HTTPS**, כמו עם Google Drive. הלקוח (JS + PHP) — **עותק מסונכרן** בתוך כל אפליקציה, כמו `mbe-core` |
| יכולה לצאת לדומיין משלה | הענן הוא כתובת. אפליקציה בדומיין אחר מתחברת לאותו ענן, או לא מתחברת בכלל |
| עובדת בלי הענן | **חובה.** כל מה שמשותף נשמר גם מקומית (סעיף 5): בלי ענן — הספרייה והגופנים של האפליקציה עצמה, כמו היום |

**ההתחברות לענן החבילה** — כמו "כניסה עם הכלים הדיגיטליים" (`platform/docs/sso.md`), אבל מהכיוון של הענן: האפליקציה מפנה
ל-`suite-cloud/connect`, המשתמש מאשר פעם אחת, והאפליקציה מקבלת **אסימון חתום** (Ed25519, כמו `platform/docs/embed.md`)
שמוגבל לחשבון אחד ולהרשאות שאושרו (קבצים / ספריות / העדפות). ניתוק — מהענן או מהאפליקציה, ומבטל את האסימון.

### 2.1 עצמאית וגם ממשפחה — חיבור ישיר לכל ענן (הכרעה 9)

| מה האפליקציה מחוברת אליו | מה יש למשתמש |
| --- | --- |
| **לאף ענן** | כמו היום: הספרייה של האפליקציה בלבד |
| **ישירות ל-Drive / Dropbox / OneDrive / SFTP / WebDAV / FTP** (אחד או כמה) | לשונית לכל ענן ב"המסמכים שלי"; פתיחה ושמירה ישירה. האסימון — **במסד של האפליקציה**, מוצפן |
| **לענן החבילה** | כל הכוננים שמחוברים בענן החבילה (בלי לחבר שוב בכל אפליקציה), הכונן הפנימי, הספריות (גופנים, צבעים…), והעדפות שמסתנכרנות בין האפליקציות |
| **לשניהם** | שניהם, זה לצד זה (הכרעה 5) |

- **קוד אחד:** החיבור לכל ספק — **מודול מסונכרן אחד** (JS + PHP), כמו `mbe-core`. **הבעלים — ענן החבילה**, ואותו קוד רץ
  בענן החבילה ובכל אפליקציה. אין אפליקציה שכותבת OAuth משלה.
- **מה רק ענן החבילה נותן:** הכונן הפנימי, ספריות משותפות (סעיף 4), צוותים, והעדפות מסונכרנות. חיבור ישיר נותן **קבצים** בלבד.
- **סודות:** מזהי ה-OAuth של כל ספק — **בהגדרות השרת של כל אפליקציה**, או מתקבלים מענן החבילה כשהיא מחוברת אליו. לעולם לא
  בקוד ולא בצ'אט. בלי מזהה של ספק — הכפתור שלו לא מופיע.

### 2.2 תפריט המשתמש — הממשק לכל זה (הכרעה 10)

**הממשק — פעם אחת, ב-`ui-core`** (`account.js`, ‏`files-window.js`, ובשרת `php/account/`), עותק מסונכרן בכל אפליקציה; **הנתונים
— במסד ובתיקייה של האפליקציה עצמה** (כך היא נשארת עצמאית). האפליקציה כותבת רק חיבור קטן: מי המשתמש המחובר, איפה המסד שלה,
והקטע של ההגדרות שלה. התפריט, הפריטים והחוזה (`accountMenu(...)`) — `requests/account-menu.md` סעיפים 3–4.

**מה מהאפיון הזה נכנס לתפריט:**

| פריט בתפריט | מה מכאן |
| --- | --- |
| 📁 **המסמכים שלי** | "המבנה" (הכרעה 5) — לשונית "באפליקציה" + לשונית לכל ענן מחובר; אותו חלון גם לפתיחה ולשמירה. "אחרונים", סל וגרסאות (סעיף 6) |
| ☁️ **עננים מחוברים** | סעיף 2.1: חיבור / ניתוק לכל ענן, ובהם ענן החבילה; ענן ברירת מחדל לשמירה |
| ⚙️ **הגדרות אישיות** | "העדפות" (סעיף 4) — כלליות זהות בכל האפליקציות, ו"שמירת ההגדרות בענן" רק כשמחוברים לענן החבילה |
| 🛠 **ניהול** | מכסת האחסון הפנימי, ספק בינה מלאכותית (סעיף 6) — למנהל בלבד |

## 3. ענן החבילה — אפליקציה חדשה `suite-cloud/`

| חלק | מה |
| --- | --- |
| **חשבון חבילה** | זהות מהשער (כמו כל אפליקציה), ועוד חשבון משלו כשמנותק. **אותו מייל = אותו אדם** (`sso.md` סעיף 4) |
| **כוננים** | רשימת כוננים לכל חשבון ולכל צוות — כל אחד בעץ משלו (הכרעה 5) |
| **ספריות** | גופנים, צבעים, סגנונות, תבניות, נכסים, מברשות, העדפות — אישיות ושל צוות (סעיף 4) |
| **מנהל** | נפח לאחסון הפנימי לכל משתמש / צוות; אילו ספקים מותרים; מפתחות הספקים — **בהגדרות השרת** |
| **API** | קבצים (רשימה, קריאה, כתיבה, העברה, שינוי שם, סל), ספריות, העדפות, התראות שינוי |
| **ממשק** | דף קטן משלו: הכוננים, הספריות, הצוותים, החיבורים — לפי `phone-first-design` |

### 3.1 הכוננים

אותה טבלה חלה **גם על חיבור ישיר מאפליקציה** (סעיף 2.1) — עם אותו מודול. ההבדל היחיד: בחיבור ישיר, האסימונים והסיסמאות
נשמרים **במסד של האפליקציה**, לא של ענן החבילה. הכונן הפנימי — רק בענן החבילה.

| כונן | איך מתחברים | ההרשאה ומה נשמר | מה לא |
| --- | --- | --- | --- |
| **פנימי (שלנו)** | אוטומטי, בנפח שהמנהל אישר (ברירת מחדל — 0 עד שמאשרים) | קבצים ב-`suite-cloud/data/files/` — **`--exclude` ב-`deploy.yml` לפני הכתיבה הראשונה** | — |
| **Google Drive** | OAuth, הרשאת `drive.file` (רק קבצים שהאפליקציה יצרה או שהמשתמש בחר) | אסימון רענון — מוצפן במסד | גישה לכל ה-Drive — לא מבקשים |
| **Dropbox** | OAuth, תיקיית אפליקציה (`Apps/חבילת היצירה`) | אסימון — מוצפן | — |
| **OneDrive** | OAuth (Microsoft), הרשאה לתיקיית האפליקציה (`Files.ReadWrite.AppFolder`) | אסימון רענון — מוצפן | גישה לכל ה-OneDrive — לא מבקשים |
| **FTP / SFTP / WebDAV** (שרת עצמי, Nextcloud, NAS) | כתובת, משתמש וסיסמה שהמשתמש מקליד | הסיסמה — מוצפנת במסד; FTP לא מוצפן — אזהרה, ועדיפות ל-SFTP / FTPS | — |
| **תיקייה במחשב** | File System Access, **בדפדפן בלבד** (Chrome / Edge במחשב) | ההרשאה — בדפדפן (IndexedDB); השרת לא רואה את הקבצים | בטלפון, ב-Safari, ובשרת |

**סודות:** מזהי ה-OAuth והסודות של Google, ‏Dropbox ו-Microsoft, ומפתח ההצפנה של האסימונים — **רק בהגדרות השרת** של
ענן החבילה או של האפליקציה (קובץ מחוץ לגיט, כמו כל `config` בריפו), לעולם לא בקוד ולא בצ'אט. בלי מפתח של ספק — הכונן שלו
פשוט לא מופיע. אפליקציה שמחוברת לענן החבילה יכולה לקבל ממנו את המזהים במקום להחזיק אותם.

**הממיר משתמש בכוננים** (`spec/README.md` סעיף 5.5): כשקובץ בכונן משתנה מבחוץ (Word שמר `ספר.docx` ב-Drive) — Drive
ו-Dropbox שולחים התראת שינוי, FTP — בדיקה תקופתית, ובמחשב — בדיקה כשהלשונית חוזרת. כולם מגיעים ל-`reconcile` של הליבה.

## 4. הספריות — מה משותף, ואיך כל אפליקציה משתמשת בו

כל פריט בספרייה: `{ id, kind, name, rev, data | file }`. ‏`rev` — גיבוב התוכן; שינוי = `rev` חדש.

| ספרייה | מה בפנים | מי משתמש |
| --- | --- | --- |
| **גופנים** | הגופנים החופשיים המובנים (OFL — היום מפוזרים בכל אפליקציה) + גופנים שהמשתמש מעלה (הכרעה 7) | כולן |
| **צבעים וערכת מותג** | דוגמיות (= `swatches` של וקטורי ג3), פלטות, לוגו, גופני מותג | כולן |
| **סגנונות** | סגנונות פסקה ותו (המבנה של `styles` ב-`mbe-format.md`), סגנונות צורה (מילוי + מתאר) | עורך, עימוד, וקטורי |
| **תבניות** | מסמך / ציור / תמונה / ספר מוכנים (`.mbe` עם `template: true`) | כולן |
| **נכסים** | סמלים ורכיבים (וקטורי), תמונות, לוגואים | כולן |
| **מברשות** | מברשות וקטוריות ורסטר | וקטורי, רסטר |
| **הגדרות פיתוח** | Presets של "חדר פיתוח" ו-LUT | חדר פיתוח, רסטר |
| **העדפות** | שפה, ערכת תצוגה (בהיר / כהה), יחידות (מ"מ / pt / px), קיצורי מקלדת, שם תצוגה (`collab.md` סעיף 8) | כולן |

**בפועל, בכל אפליקציה:** בורר הגופנים, לוח הצבעים, רשימת הסגנונות וחלון הנכסים מציגים שלוש קבוצות: **"במסמך"**,
**"שלי"** ו**"של הצוות"**. גרירה מהספרייה מכניסה את הפריט למסמך (קישור + עותק — סעיף 5). "שמור לספרייה" — מכל פריט במסמך.

## 5. נכס מהענן בתוך `.mbe` — קישור + עותק (הכרעה 6)

```json
"fonts": [ { "family": "Rubik", "embedded": "media/<sha256>.woff2",
             "lib": { "cloud": "<cloud-id>", "item": "fnt_123", "rev": "<sha256>" } } ]
```

- **`lib`** — שדה רשות אחד, **באותו מבנה לכל סוג נכס** (גופן, דוגמית, סמל, סגנון, מברשת): מאיזה ענן, איזה פריט, ואיזו
  גרסה הועתקה. התוכן עצמו **תמיד** בקובץ (`media/`, `symbols`, `swatches`, `styles`) — כמו היום.
- **בפתיחה עם ענן:** `rev` שונה מהספרייה → פס עדין "2 נכסים עודכנו בספרייה — לעדכן?" (לא אוטומטי — שינוי סמל יכול להזיז עימוד).
- **בלי ענן, או ענן של מישהו אחר:** הקובץ נפתח מהעותק, ו-`lib` נשמר כמו שהוא ("שמור את מה שלא הבנת").
- **פרטיות:** `cloud` הוא מזהה אקראי של הענן — לא כתובת ולא מייל (`mbe-format.md` סעיף 10).

## 7. הנחיות לכל אפליקציה
