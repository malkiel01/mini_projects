## 1. הרעיון, בלשון בעל המערכת

קובץ אחד שנפתח בכל סוגי המערכות העיצוביות — עימוד, רסטר, וקטורי, עורך תמלילים, וגם Word ו-Photoshop — ו**תמיד
שומר על ההגדרות שלו**.

## 2. מה נבנה עד היום — ואיפה הפער

הקובץ `.mbe` (מכל ZIP + `document.json` + ייצוגים מוכנים) מבטיח **שלא יאבד מידע** — לא ש**כל מקום יערוך הכול**.
הכלל "אפליקציה עורכת רק את מה שהיא מבינה, ושומרת את השאר בית-לבית" (`mbe-format.md` סעיף 5) מייצר בפועל:

| מעבר | מה קורה היום | איפה זה כתוב |
| --- | --- | --- |
| עימוד → עורך התמלילים | נערך רק השטף של המסגרת הראשונה בעמוד הראשון; השאר — תמונה (`preview.png`) בראש המסמך | `word-processor/README.md`, "‎.mbe" |
| עורך → וקטורי | המכתב נפתח כרקע PDF לקריאה בלבד | `projects/vector-studio.md`, יומן 2026-10-25 |

**השורש:** הקובץ נבנה כ**מכל של צילומים**. צילום הוא חד-כיווני, ולכן "שומר על ההגדרות" נכון רק בתוך החבילה,
ו"נפתח בכל המערכות" נכון רק אחרי חילוץ.

**העיקרון החדש:** הזיכרון לא חייב להיות **בתוך** הקובץ שנפתח בחוץ. הוא אצל הממיר; הקבצים שבחוץ (docx, pdf, png) הם
"פנים" של אותו מסמך, וכל אחד נושא **מזהה** שמחזיר אותו אל הזיכרון.

## 5. האפיון המשולב

### 5.1 שלושה חלקים

```
ספר/                         ← התיקייה של בעל המסמך (ענן, מחשב, או ספרייה בשרת)
├── ספר.docx                 ← "פנים" לוורד: docx אמיתי, בלחיצה כפולה
├── ספר.pdf                  ← "פנים" להדפסה / לקריאה (רשות)
└── .ספר.mbe                 ← הזיכרון (נסתר): המודל, הגרסאות, השלבים
```

1. **הזיכרון** — `.mbe`, כמו היום, ועוד: **מזהה מסמך**, **יומן שלבים** וגרסאות (5.3). זה מקור האמת היחיד.
2. **הפנים** — קבצים רגילים שכל תוכנה פותחת. בכל אחד — **מזהה המסמך + הגרסה שממנה נגזר** (5.2). ב-docx גם עותק
   של המודל (`customXml`), כדי שקובץ שחוזר במייל בלי הזיכרון עדיין יתמזג.
3. **הממיר** — הרחבה של `mbe-core` (הכרעה): פותח, מזהה, ממזג, רושם שלב, ומחדש את כל הפנים. כל אפליקציה מקבלת
   אותו בעותק המסונכרן של הליבה, כמו היום.

### 5.2 זהות — "אותו קובץ ולא קובץ שהוחלף"

| מה | איפה בתוך docx | שורד שמירה ב-Word? |
| --- | --- | --- |
| `mbe-doc-id` (UUID קבוע) | מאפיין מותאם, `docProps/custom.xml` | כן — Word שומר מאפיינים מותאמים 🧪 |
| `mbe-base` (גיבוב הגרסה שיצאה) | מאפיין מותאם | כן 🧪 |
| המודל המלא בגרסה שיצאה | `customXml/item*.xml` | כן — Word שומר חלקי customXml 🧪 |
| מזהה לכל פסקה | סימנייה נסתרת (`_mbe_p<id>`) או `w14:paraId` | חלקית — העתק-הדבק ופיצול פסקה משנים 🧪 |

בחזרה: אותו `doc-id` → אותו מסמך. `base` שווה לגרסה האחרונה → עריכה רגילה. `base` ישן יותר → **התפצלות**, וממזגים
מול הגרסה ההיא (5.4). אין `doc-id` → docx זר: ייבוא רגיל כמו היום, עם דוח.

### 5.3 יומן שלבים וגרסאות (בתוך הזיכרון)

כל **מעבר** בין אפליקציות או אנשים הוא שלב: `{ id, at, app | "external:word", who?, kind: "create|edit|export|return|merge", base, result, note }`.
הפרטיות של `mbe-format.md` סעיף 10 נשמרת: **בלי מייל**. "מי" — שם תפקיד או כינוי שהמשתמש נתן ("המגיה"), לא זהות.
גרסה = עותק של `document.json` בכל שלב (משאבי `media/` לפי גיבוב — בלי כפילות). חזרה לשלב = שחזור הגרסה שלו כגרסה חדשה.
**פתרון לשאלה הפתוחה 3 ב-`mbe-format.md`** (היסטוריה בתוך הקובץ או רק בשרת): בתוך הזיכרון, ובשרת — אותו יומן פרוס.

### 5.4 מיזוג — כשהפנים חוזרות

מיזוג **תלת-כיווני**: הבסיס (`base`, מתוך `customXml` או מהיומן) ↔ מה שחזר מ-Word ↔ הגרסה הנוכחית אצלנו.

- **טקסט** — לפי מזהה פסקה: שינוי בצד אחד — נכנס; אותה פסקה בשני הצדדים — **שאלה** (הכרעה), כמו "קבל / דחה" במעקב שינויים.
- **מה שאין ל-Word מקום בשבילו** (מסגרות, שטף בין מסגרות, עמודי אב, שכבות, הגדרות HarfBuzz) — חוזר מהבסיס כמו שהוא.
- **עיצוב שנעשה ב-Word** (סגנון, גופן, שוליים) — נכנס רק אם יש לו מקבילה במודל; אחרת — בדוח.
- **אחרי המיזוג:** שלב `merge` ביומן, וכל הפנים נכתבות מחדש — כולל `ספר.docx` עם `base` חדש.

### 5.5 איפה הקובץ יושב — כל האפשרויות (הכרעה), לפי שכבות

| מסלול | איך הממיר יודע ששמרת | הערות |
| --- | --- | --- |
| **העלאה ידנית / מייל** | המשתמש מעלה את ה-docx שחזר | הבסיס — תמיד עובד, לכל נמען |
| **ספרייה בשרת** (קיימת בכל אפליקציה) | השמירה עוברת דרכנו | כמו היום |
| **תיקייה במחשב דרך הדפדפן** (File System Access) | בודק שינוי בכל פתיחה / חזרה ללשונית | Chrome / Edge במחשב בלבד |
| **ענן** (Google Drive / Dropbox) | התראת שינוי מהענן | עובד גם אצל נמען בלי המערכת; דורש חיבור חשבון |
| **תוכנה מותקנת** | מרגישה כל שמירה | **מתנגש בעיקרון 4** ("הכול בדפדפן או ב-PHP") — דורש החלטה מפורשת של בעל המערכת לפני שבונים |

כל המסלולים נכנסים לאותה פעולת ליבה: `reconcile(face) → { docId, base, changes, conflicts }`.

### 5.6 "כל אפליקציה עורכת הכול" — מה זה דורש

הממיר פותר את Word; הוא **לא** פותר את העריכה בתוך החבילה. בשביל זה צריך את מה שכבר רשום ב-`master-spec.md`
סעיף 4 — ומוקדם יותר מ"כלל השתיים":

1. **שטף טקסט אחד** — אותו מודל ProseMirror ואותה סכמת צמתים בכל אפליקציה (היום העימוד מבין חלק).
2. **הגדרת עמוד אחת** — `layout` בשורש בלבד; `attrs.page` בשטף — נגזר ממנו (סוגר את הסתירה בסעיף 2).
3. **מציג משותף** לכל סוגי השכבות (raster / vector / frame), כדי שכל אפליקציה **תציג** הכול נכון ותערוך לפחות
   טקסט ומיקום. עריכה מלאה של סוג "זר" — דרך **הטמעה** של האפליקציה שלו (`master-spec.md` סעיף 5), בתוך אותו מסך.

## 7. מה פתוח

1. ממשק הליבה המדויק (`identify`, `reconcile`, `journal`) — מול הצ'אט של `mbe-core`.
2. Photoshop: פנים `.psd` או `.tif` עם שכבות (+ מזהה ב-XMP) — אחרי הספר. היום אין כותב PSD (`mbe-format.md` סעיף 9).
3. תוכנה מותקנת — רק בהחלטה מפורשת על עיקרון 4.
4. סדר: (א) זהות + יומן בליבה → (ב) docx עם מזהה בעורך התמלילים → (ג) מיזוג טקסט → (ד) העימוד על אותו זיכרון → (ה) ענן.
