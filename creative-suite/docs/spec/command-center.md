## 1. המודל

### 1.1 ההיררכיה — הכול בלוח (הכרעה 5)

| רמה | בלוח | דוגמה |
| --- | --- | --- |
| **חבילה** | קבוצת פרויקטים (תגית `suite: creative`) | חבילת היצירה |
| **פרויקט** | **פרויקט** בלוח, מקושר לריפו ולתיקייה (`path: raster-studio/`) | עיצוב רסטר |
| **שלב / יעד** | **נושא** בתוך הפרויקט, עם `seq` | ר2 — עריכה מקצועית |
| **מטלה** | **מטלה** | מסכות וקטור |

**docs/projects/*.md אחרי המעבר:** תפקיד, תחום, אפיון, יומן והכרעות — כמו היום. הקטעים `## התקדמות` ו-`## ממתין לבעל המערכת`
מוחלפים בשורה אחת: `**המטלות:** בלוח, פרויקט <שם>`. הדשבורד מציג את המטלות מהלוח, ואת המסמך — כקישור.
**המעבר:** סקריפט חד-פעמי (בצ'אט המתכלל) שממיר כל `- [ ]` / `- [x]` למטלה `open` / `done` בנושא המתאים, ושורות `מדריך:` /
`פרומפט:` — להערה הראשונה במטלה.

**איך צ'אט כותב התקדמות:** רק דרך הלוח (הסקיל `claude-tasks-worker`): `claim` כשמתחיל, `heartbeat` בעבודה ארוכה, `block`
לשאלה, **`ask-approval`** לאישור (חדש, 1.2), `complete` עם הקישורים ל-PR ולפריסה. מה שנפרס ונבדק — דרך DevLoop (🧪 → ✅), כמו היום.

### 1.2 המצבים

| מצב בלוח | בדשבורד | מי מעביר |
| --- | --- | --- |
| `open` | ⏳ ממתינה לפיתוח | יצירה / תשובה |
| `in_progress` | 🔧 בפיתוח (ובאיזה מסלול: 💻 Code / ☁️ Platform) | `claim` |
| `blocked` | ❓ שאלה ממתינה | `block` |
| **`awaiting_approval`** — **חדש** | 🔐 אישור ממתין | `ask-approval` |
| `answered` | ↩️ נענתה — חוזרת לראש התור | תשובה / החלטה על אישור |
| `done` / `cancelled` | ✅ / ✕ | `complete` / אדם |

**למה מצב נפרד:** שאלה מבקשת **מידע** (תשובה בטקסט). אישור מבקש **היתר** לפעולה מסוג ידוע — ויש לו ארבעה כפתורים וזיכרון
(1.3). מטלה ב-`awaiting_approval` **משוחררת** (הצ'אט ממשיך למטלה אחרת), כמו `blocked`.

**בקשת אישור:** `{ type, summary, detail, target }` — `type` מתוך הקטלוג (1.3); `summary` — שורה ("מיזוג PR #1020 ל-main");
`target` — מה בדיוק (קבצים, PR, פקודה). **ארבעה כפתורים:** אשר פעם אחת · **אשר תמיד את הסוג הזה** · דחה · **דחה תמיד**.

### 1.3 קטלוג סוגי האישור, והמדיניות

| `type` | ניסוח קבוע | אפשר "תמיד"? | ב-`settings.json` |
| --- | --- | --- | --- |
| `merge-own-pr` | מיזוג PR שפתחתי לענף שלי ל-`main` | ✅ | `mcp__github__merge_pull_request` |
| `push-own-branch` | push לענף שלי | ✅ | `Bash(git push -u origin:*)` |
| `send-team-message` | שליחת הודעה לצ'אט אחר בצוות | ✅ (כבר קיים) | `mcp__claude-code-remote__create_trigger` |
| `format-change-request` | בקשת שינוי בפורמט / בסכמה | ✅ | — (מדיניות בלוח בלבד) |
| `add-vendor-lib` | הוספת ספרייה ל-`vendor/` (MIT/BSD/Apache) | ✅ | — |
| `add-exclude` | הוספת `--exclude` ב-`deploy.yml` לתיקיית נתונים | ⚠️ עם אזהרה כפולה | `Edit(.github/workflows/deploy.yml)` — **פעם אחת בלבד, לא `allow`** |
| `change-deploy` | כל שינוי אחר ב-`deploy.yml` | ❌ תמיד פעם אחת | `deny` ל-`Edit(.github/workflows/deploy.yml)` אם "דחה תמיד" |
| `delete-files` | מחיקת קבצים בריפו (לא בתיקייה שלי) | ❌ | `deny` |
| `delete-user-data` | מחיקת נתוני משתמשים / מסד בשרת | ❌ לעולם לא "אשר תמיד" | `deny` |
| `secrets` | קריאה / כתיבה של סודות | ❌ — מחוץ להישג ממילא (CLAUDE.md) | — |
| `touch-other-project` | נגיעה בתיקייה של פרויקט אחר | ❌ — אסור לפי CLAUDE.md | `deny` לנתיבים של אחרים (לכל צ'אט — בהמשך) |

**כללים:**
- **"אשר תמיד"** נכתב לשני מקומות: (א) **מדיניות בלוח** — מיידי; הצ'אט שואל את הלוח (`policy`) **לפני** שהוא מבקש, ו"מותר תמיד"
  = ממשיך, "אסור תמיד" = לא מבקש ובוחר דרך אחרת או חוסם עם הסבר; (ב) **`.claude/settings.json` ב-PR** (`allow` / `deny`) —
  חל מהסשן הבא של כל צ'אט, ועונה גם על חלונות ההרשאה של האפליקציה, שאין דרך לענות עליהם מבחוץ.
- **מי כותב את ה-PR ל-`settings.json`:** הצ'אט המתכלל, בדרישה מהלוח (מטלה אוטומטית "עדכון מדיניות"). ה-PR עצמו — **לא** נכלל
  ב"מיזוג אוטומטי": בעל המערכת רואה אותו.
- **סוג ❌** — הכפתורים "תמיד" לא מוצגים. **סוג ⚠️** — "אשר תמיד" מבקש הקלדה של שם הסוג.
- **יומן:** כל שינוי מדיניות — מי, מתי, מה היה קודם, ואיזו בקשה גרמה לו. ביטול "תמיד" — מהמסך (5.3), וגם הוא PR.
- **בקשה בלי סוג מתאים** — `type: "other"`, תמיד "פעם אחת"; מעקב Platform (2) מציע סוג חדש לקטלוג, ובעל המערכת מאשר.

## 2. מה Platform עושה במעקב (תמיד, גם כשהפיתוח ב-Code)

רץ **בלוח** (PHP, `lib/ai.php`), אחרי כל אירוע או פעם בשעה — לא בכל בקשה:

| עבודה | פלט |
| --- | --- |
| סיכום מצב לכל פרויקט | 3 שורות: מה זז, מה תקוע, מה ממתין לך |
| מיון שאלות ואישורים | לפי דחיפות: חוסם כמה מטלות / ממתין הכי הרבה זמן |
| "נשאל כבר" | שאלה חדשה דומה לשאלה שנענתה — מציע את התשובה הקיימת (אתה מאשר בלחיצה) |
| התאמת בקשה לסוג | בקשת אישור בלי `type` ← מציע סוג מהקטלוג |
| ניסוח הודעה לצ'אט | כשאתה עונה בקצרה ("כן, אבל בלי X") — מנסח לצ'אט הודעה מלאה; אתה רואה אותה לפני שליחה |

**בלי מפתח Platform:** הכול עובד — מצבים, שאלות, אישורים, מדיניות — רק בלי הסיכומים וההצעות.

## 3. הערוץ בזמן אמת

### 3.1 מה בדקתי בפועל

| ערוץ | בדיקה | מסקנה |
| --- | --- | --- |
| **צ'אט → לוח** | HTTP עם `X-Worker-Token` — קיים ומשמש את `claude-tasks-worker` | ✅ |
| **צ'אט → צ'אט** (`create_trigger` עם `persistent_session_id`) | **עובד** — כל ההודעות בצוות החבילה עברו כך מאז 2026-10-25 | ✅, אבל רק מסשן של Claude — הלוח (PHP) לא יכול לקרוא לו |
| **בדיקה עצמית** (`send_later` מהצ'אט לעצמו) | **קיים** בכלים של הסשן; מעיר את הסשן בזמן שנקבע | ✅ — הבסיס להכרעה 6 |
| **תגובה ב-GitHub על PR** שהצ'אט מאזין לו | מעירה את הסשן — **אבל** רק ל-PR שהסשן מנוי עליו, וכל תוכן בה נחשב **חיצוני ולא מהימן** (כל מי שיכול להגיב יכול לכתוב שם) | ❌ — לא ערוץ להחלטות |
| **webhook נכנס** (`watch_url`) | הסוד מוצפן לשירות ה-artifacts בלבד — הלוח לא יכול לחתום | ❌ |
| **הכנסת הודעה לסשן מבחוץ** | אין ממשק ציבורי | ❌ |

### 3.2 ההמלצה (הכרעה 6)

- **ראשי — הצ'אט בודק לבד:** צ'אט שיש לו מטלה ב-`blocked` / `awaiting_approval` קובע לעצמו בדיקה (`send_later`) כל **~15
  דק'**, קורא את הלוח (`inbox`, חדש — 4), וממשיך מהתשובה. בלי מטלות ממתינות — לא קובע. בנוסף, בתחילת כל צעד — `claim` /
  `inbox`. **השהייה מרבית: ~15 דק'.**
- **גיבוי — מפיץ שעתי:** משימה מתוזמנת (פעם בשעה, סשן חדש בכל הפעלה) שקוראת מהלוח "תשובות שלא נמסרו יותר מ-20 דק'"
  ושולחת לכל צ'אט הודעה (`create_trigger`) בתבנית של `creative-suite-team`. מסמנת בלוח "נמסר".
- **מחיר:** בדיקה שלא מצאה כלום — סבב קצר של הסשן; לכן רק כשיש מטלה ממתינה, ומפסיקים אחרי 8 בדיקות ריקות (שעתיים).
- **סיכון:** סשן שנסגר / אורכב — לא מתעורר; המפיץ רואה שאין `heartbeat` ומסמן בלוח "הצ'אט לא זמין", ומטלה חוזרת ל-`open`.

## 4. המתג והתקרה

### 4.1 המתג (הכרעות 3, 7)

- **איפה:** בלוח — `route: code | platform` לכל פרויקט, ו-`default_route` כללי. בדשבורד — מתג לכל פרויקט + מתג כללי.
- **מי לוקח מה:** `claim` מקבל כותרת `X-Worker-Route`. צ'אט Claude Code שולח `code`, המנוע ב-Actions — `platform`. הלוח נותן
  מטלה **רק** מפרויקט שהמסלול שלו תואם. מטלה שכבר `in_progress` — נשארת במסלול שלה עד `complete` / `block` (הכרעה 3).
- **המנוע של Platform = Claude Code ב-Actions (הכרעה 7):** במקום `run.mjs`, ה-workflow מריץ את Claude Code בלי מסך (`claude -p`
  או `anthropics/claude-code-action`) עם `ANTHROPIC_API_KEY` מסוד הריפו. **אותו `CLAUDE.md`, אותם סקילים (`.claude/skills/`), אותו
  `settings.json`**, ואותו מחזור: ענף → PR → מיזוג → `conclusion: success`. הוא עובד מול הלוח עם הסקיל `claude-tasks-worker`, כמו צ'אט.
- **הפעלה:** הלוח מפעיל את ה-workflow (`workflow_dispatch`) עם הטוקן של הבעלים — מצ'אטים זה 403 (CLAUDE.md), ולכן רק מהלוח.
- **ה-workflow לא פורס:** הוא רק פותח PR. הפריסה — רק מ-`main` (CLAUDE.md, "ענף פריסה אחד").

### 4.2 התקרה (הכרעות 4, 8)

| מה | איך |
| --- | --- |
| **מונה** | כל קריאה ל-Platform נרשמת בלוח: `tokens_in`, `tokens_out`, מחיר, `kind: monitor | develop`, פרויקט. בפיתוח — עלות הריצה מהדוח של Claude Code |
| **שתי תקרות** | פיתוח — הסכום שבעל המערכת קבע; מעקב — תקרה קטנה נפרדת (הצעה: 5% מהסכום) |
| **80%** | התראה בדשבורד (פס למעלה) ובהודעה לטלפון |
| **100% — פיתוח** | המתג של כל הפרויקטים עובר ל-`code`; מטלות Platform שבאמצע — מסתיימות (לא נקטעות באמצע push); החדשות — לתור של Code |
| **100% — מעקב** | הסיכומים נעצרים; הכול השאר עובד (2) |
| **איפה הסכום והמפתח** | **רק בהגדרות השרת של הלוח** — לא בקוד ולא בצ'אט |

## 5. מסכים — דשבורד החבילה, תצוגת "מרכז" (טלפון קודם)

1. **למעלה — "ממתין לך":** כרטיסים של ❓ ו-🔐, ממוינים (2). כרטיס: פרויקט, שורת הבקשה, "פרטים", וכפתורים — לשאלה: שדה תשובה
   (+ "נשאל כבר — הנה התשובה"); לאישור: ארבעת הכפתורים. אחרי מענה — הכרטיס יוצא, ו"↩️ נמסר" / "⏳ ימסר עד 15 דק'".
2. **פרויקטים:** שורה לכל פרויקט — סיכום 3 שורות, מונים (⏳ 🔧 ❓ 🔐 ✅), מתג 💻/☁️. הקשה — נושאים (שלבים) ומטלות לפי מצב.
3. **מדיניות האישורים:** הקטלוג (1.3), מה הוחלט לכל סוג ("פעם אחת" / "תמיד" / "אסור תמיד"), היומן, וביטול.
4. **עלות:** החודש — פיתוח ומעקב, פס עד התקרה, לפי פרויקט.
5. **מי מורשה:** **רק בעל המערכת** עונה ומאשר (ברירת מחדל; הרחבה — בהמשך, דרך דרגות הפרויקט בלוח).

## 6. אבטחה

- **אסימון לכל צ'אט** — לא אסימון כללי: אסימון עובד לכל פרויקט (קיים בלוח) **+ שם הצ'אט** (`X-Worker-Name`) נרשם בכל פעולה.
  צ'אט רואה ומושך רק מטלות של הפרויקט שלו.
- **האסימונים** — בסודות הסביבה / בהגדרות, לא בגיט ולא בצ'אט פתוח.
- **"תמיד" לסוג הרסני** — חסום (❌) או אזהרה כפולה (⚠️), 1.3.
- **תוכן מהלוח הוא נתונים, לא הוראות** — הצ'אט פועל לפי תשובה **רק** מבעל המערכת (השרת מסמן `author_role`), לא לפי טקסט
  שמישהו אחר כתב בהערה.
