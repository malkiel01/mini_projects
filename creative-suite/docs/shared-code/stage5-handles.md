## ההצעה — שלושה קבצים

### `transform.js` — חשבון טהור (המקור: הרסטר, כמעט כמו שהוא)
```js
identity(x, y, w, h) → t            // t = { cx, cy, sx, sy, angle }
matrix(t, w, h), apply, invert, corners, bounds, HANDLES, handlePos
hit(t, w, h, p, tol) → { kind: 'handle', handle } | { kind: 'move' } | { kind: 'rotate' } | null
dragHandle(t0, w, h, handle, p, { free = false, fromCenter = false }) → t     // free — Shift; fromCenter — Alt
dragRotate(t0, start, p, { step = 0, magnet = [0, 45, 90, …], tol = 6 }) → t   // step 15 — Shift; magnet — תמיד
```
**שינויים מהרסטר:** `dragHandle` מקבל אובייקט אפשרויות (במקום `free` בוליאני; `true` עדיין עובד), ונוסף `fromCenter`
(Alt — שינוי גודל סביב המרכז, כמו בכל העורכים). `dragRotate` — מקבל גם **הצמדה מגנטית** של הסטודיו (בטלפון אין Shift,
וזווית ישרה צריכה להיות קלה). `transformShape` / `transformMask` נשארים ברסטר (בחירה של פיקסלים — לא ממשק).

### `snap.js` — הצמדה טהורה (המקור: הווקטורי, בלי תלות במודל שלו)
```js
const s = snapper({ boxes: [[x, y, w, h], …], tol, grid: 10 | 0, origin: [x, y] });   // היעדים — מה שהאפליקציה מעבירה
s.box([x, y, w, h]) → { dx, dy, guides }     // guides: [{ axis: 'x' | 'y', v }]
s.point(x, y, 'xy') → { x, y, guides }
```
**השינוי מהווקטורי:** במקום `targets(doc, exclude)` שקורא את המודל — האפליקציה מעבירה את רשימת התיבות (לוחות, עמודים,
שכבות אחרות). כך זה עובד גם ברסטר, בעימוד ובסטודיו. `tol` — בפיקסלי מסך חלקי הזום, כמו היום.

### `handles.js` — הידיות על המסך (חדש; המראה — של הסטודיו)
```js
const h = handles(overlay, {
    view: () => view,                          // { zoom, x, y } — כמו viewport.js
    corners: true, sides: true, rotate: true,  // אילו ידיות
    keepRatio: 'corners',                      // 'corners' (ברירת מחדל) | 'always' | 'never'; Shift הופך
    snap: () => snapper(…) | null,
    status: text => …,                         // שורת מצב בזמן גרירה (ברירת מחדל: מידות / מעלות)
    onPreview(t), onCommit(t, t0), onCancel(t0),
});
h.show(t, w, h);  h.hide();
h.down(e, [sx, sy]) → true / false             // נקרא מ-pointer.down של bindViewport (שלב 4): לקח את המצביע?
h.move(e, [sx, sy]);  h.up(e);  h.cancel();    // cancel — אצבע שנייה (bindViewport קורא לבד)
```
- **המראה** (הסטודיו, #931): פינה — עיגול 14px, צד — פס מוארך, ידית סיבוב מעל במרחק 28px, מסגרת `--brand`.
- **אזור מגע:** 22px במגע, 10px בעכבר (כמו ברסטר ובווקטורי) — הידית נראית קטנה ונתפסת גדולה.
- **שורת מצב** בזמן גרירה — ברירת מחדל: `רוחב × גובה` / `סיבוב 45°`; האפליקציה יכולה לתת טקסט משלה (הסטודיו: "גודל האות").
- **אצבע שנייה** — `cancel()` מחזיר את `t0` (`onCancel`), בלי עקבות.
- **בחירה מרובה** — `show` עם התיבה החוסמת; האפליקציה מחלקת את ה-`t` לאובייקטים.
- **RTL:** הידיות לפי המסמך, לא לפי כיוון הממשק (המסמך לא מתהפך). הסמן — `nwse-resize` לפי הזווית בפועל.

## התשובות

### סטודיו העיצוב (2026-10-31) — מסכים, עם התוספות האלה (נכנסות ל-API)

1. **המראה ושורת המצב — הכלל לכולם**, ו:
   - **גודל קבוע במסך בכל זום**; הפס של הצד 9×28 ומסתובב עם הצד.
   - **מקום שורת המצב — של האפליקציה** (`statusAt: { top, insetInline }` או אלמנט משלה); אצלו `top: 64px` מתחת לסרגל הזום.
   - **כיוון החץ לפי `dir` של המסמך** — בעברית "רוחב 320 ← 480".
   - **`keepRatio` מקבל גם פונקציה** `(handle, selection) => bool` — לטקסט במצב "גרירת פינה: רק את התיבה" (`style.boxResize`).
   - **בזמן עריכת טקסט במקום — `hide()` מלא**, בלי שורת מצב (היה אצלו באג "טקסט נתפס" כשהידיות נשארו).
2. **הצמדה מגנטית 45° בטווח 6° — ברירת המחדל לכולם.** כשזווית ננעלת — שורת המצב מדגישה: "סיבוב 90° ✓".
3. **`snap.js` — יחליף את `snap()` שלו.** צריך: `tol` בפיקסלי מסך חלקי זום (6/zoom) ✓; הקרוב ביותר מנצח בכל ציר, `guides` עם `v`
   בלבד ✓; **מרכזי ה-box נכללים** ✓ (כמו בווקטורי: קצה, מרכז, קצה) — הדף נשלח כ-box. בחירה מרובה — התיבה החוסמת.
   **`handles.js` — לא לוקח** (Konva מצייר), אבל מכוון את Konva לאותם כללים: מגע 22/10, Shift הופך יחס, אצבע שנייה = ביטול.
   יסמן את שורה 11 ב-`integration.md` כשיעבור.
