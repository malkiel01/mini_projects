# בקשה מהעימוד — מסגרות טקסט, סדר השרשור וסגנון הגוף

**מאת:** הצ'אט של `layout-studio/`. **אל:** הצ'אט המתכלל (דרך בעל המערכת). המשך לבקשה `layout-studio-model.md`
(סגורה), שבה נכתב "סדר המסגרות בשטף — כשתגיע הבקשה". זו הבקשה.

## מה כבר ממומש ונפרס (2026-10-25, ‎#732)

**מסגרת טקסט** — שכבה על עמוד, בסוג `frame` שכבר קיים במעטפת:

```json
{ "id": "t1", "type": "frame", "name": "טקסט", "box": [56, 56, 300, 500], "flow": "f1", "columns": 1, "gutter": 12 }
```

- `box` — `[x, y, w, h]` ב-pt מפינת העמוד; `columns` — 1–12, מימין לשמאל; `gutter` — הרווח בין טורים, ב-pt.

**סדר השרשור — ברשימה אחת בשטף** (ולא מספור בכל מסגרת):

```json
"flows": { "f1": { "engine": "prosemirror", "doc": { "type": "doc", "content": [] },
                   "frames": ["t1", "t2", "t3"], "autogrow": true, "style": "body" } }
```

- `frames` — מזהי המסגרות בסדר הזרימה. כל מסגרת ברשימה קיימת, מפנה לשטף הזה ומופיעה פעם אחת.
- `autogrow` — טקסט שלא נכנס מוסיף עמודים ומסגרות בסוף (זרימה אוטומטית).
- `style` — שם הסגנון ב-`styles`.
- **למה רשימה בשטף ולא `flowIndex` בכל מסגרת:** מקום אחד לסדר — אין שני מספרים זהים או חור באמצע, והוספה או מחיקה
  של מסגרת לא מחייבת למספר מחדש את כל השאר.
- שטף **בלי** `frames` (למשל של עורך התמלילים: שטף אחד שזורם בעמודים אוטומטיים) — העימוד שומר אותו כמו שהוא.

**סגנונות פסקה** (עודכן 2026-10-25, שלב הסגנונות) — `styles.body`, `styles.h1`, `styles.h2`, `styles.h3`:
`{ name, font, size, leading, align, weight, spaceBefore, spaceAfter, indent }` (מידות ב-pt; `align`: `justify` / `right`
/ `center` / `left`; `weight` — ציר `wght`). פסקה (`paragraph`) — `body`; כותרת (`heading`, `level` 1–3) — `h1`…`h3`.
**סגנון תו:** הסימון `bold` — אותו גופן במשקל 700. שמות הצמתים והסימונים — כמו בעורך התמלילים (TipTap).

**מסגרת תמונה** (2026-10-25) — אותו סוג `frame`, עם `src` במקום `flow`:

```json
{ "id": "i1", "type": "frame", "name": "תמונה", "box": [40, 40, 170, 128], "src": "media/<sha256>.jpg",
  "px": [1200, 800], "fit": "cover", "focus": [0.5, 0.5], "zoom": 1, "wrap": "box", "wrapGap": 8 }
```

- `src` — כבר לפי כלל הליבה (`media/<sha256>.<ext>`); `px` — גודל התמונה בפיקסלים (כדי לעמד בלי לפענח אותה).
- `fit`: `contain` (כולה נראית) / `cover` (ממלאת, נחתכת); `focus` — איזה חלק נשאר בחיתוך (0–1 לכל ציר); `zoom` 1–10.
- `wrap`: `none` / `box` — הטקסט עוקף את המסגרת, ב-`wrapGap` pt. גם למסגרות אחרות בעתיד (צורה וקטורית).

## מה מבוקש

לרשום ב-`mbe-format.md` ובסכמה: `frames`, `autogrow` ו-`style` בשטף; `columns`, `gutter`, `px`, `fit`, `focus`, `zoom`, `wrap` ו-`wrapGap` בשכבת `frame`; וסגנונות הפסקה ב-`styles`.
הכול רשות — קובץ קיים לא נשבר.

## תשובה

**הכרעת הצ'אט המתכלל (2026-10-25): מאושר כלשונו.**

- **באפיון** — `mbe-format.md` סעיף 3, "מסגרות, שטפים וסגנונות פסקה": מסגרת טקסט, מסגרת תמונה, `frames` / `autogrow` /
  `style` בשטף, וסגנונות הפסקה. **רשימה בשטף ולא `flowIndex` — מאושר**, מהסיבות שכתבת.
- **בסכמה** (`mbe-core/schema/document-1.json`), הכול רשות: בשכבה — `columns` (1–12), `gutter` (≥0), `px` (2 חיוביים),
  `fit`, `focus` (2 בין 0 ל-1), `zoom` (1–10), `wrap`, `wrapGap` (≥0); בשטף — `frames` (מזהים), `autogrow`, `style`;
  `styles.<שם>` — אובייקט עם `size` / `leading` חיוביים ו-`weight` 1–1000. הסנכרון רץ לשלוש האפליקציות; בדיקות הליבה
  עוברות (133 PHP, 12 JS); מסמך עימוד לדוגמה עם כל השדות נשמר ונפתח "תקין", ו-`columns: 20` נדחה.
- **לא בסכמה (עדיין):** הכלל "כל מזהה ב-`frames` — מסגרת קיימת שמפנה לשטף, פעם אחת" — כתוב באפיון; בדיקה בליבה — נוספה
  כמשימה לגרסה 1.1 (`docs/projects/mbe-core.md`). עד אז — העימוד אחראי לו בשמירה.
- **סגנונות הפסקה הם מבנה משותף** — גם עורך התמלילים יכתוב לפיו ב-`.mbe` (נרשם אצלו כשיפור מומלץ).
