# בקשה מעיצוב רסטר לצ'אט המתכלל — ר2: עריכה לא הורסת בשכבת `raster`

**מאת:** עיצוב רסטר (`raster`) · **תאריך:** 2026-10-25
**סטטוס:** הוכרע 2026-10-25. משותף עם סטודיו העיצוב (`design-studio`): הצרכים שלו (חיתוך, היפוך / סיבוב, מסכה עם
ריכוך ופינות מעוגלות, פילטרים, צל) נכנסו לכאן. רקע: `raster-studio/docs/layer-ai.md`, ‏`creative-suite/docs/projects/raster-studio-full.md` (ר2).

הכול תוספות (פורמט 1.x), בשכבה מסוג `raster` שכבר קיימת. **לא מבוקש סוג שכבה חדש.**

## העיקרון: `src` הוא תמיד המראה הסופי, והשדות החדשים הם מתכון

- **`src`:** תמיד התוצאה האפויה של השכבה — אחרי מסכה, פילטרים, סגנון והתאמה. קורא שלא מכיר את השדות מצייר את `src`
  ורואה בדיוק את מה שהמחבר ראה. זה כולל כל אפליקציה בחבילה היום, ואת קורא 1.0.
- **שאר השדות:** "מתכון" לעריכה חוזרת. אפליקציה שמבינה אותם יכולה לחשב מחדש את `src` מ-`source` ומהמתכון.
- **`baked`:** ה-sha256 של `src` שהמתכון הפיק. אפליקציה שלא מכירה את המתכון וערכה את הפיקסלים של `src` שומרת את השדות
  כמו שהם (כלל השמירה), אבל ה-`src` החדש לא תואם ל-`baked`. מי שמבין את המתכון מזהה מזה שהמתכון לא תקף, ומציג את השכבה
  כרסטר רגיל. זה אותו מנגנון שסטודיו העיצוב כבר מיישם ב-`apps/greeting-cards/`.

## השדות

```json
{ "id": "L7", "type": "raster", "name": "דיוקן", "src": "media/<sha>.png", "baked": "<sha256 של src>",
  "source": "media/<sha>.png",
  "crop": [120, 40, 800, 600],
  "transform": [-1, 0, 0, 1, 800, 0],
  "mask": { "src": "media/<sha>.png", "density": 1, "feather": 0, "enabled": true },
  "vectorMask": { "d": "M0 0 L100 0 L100 100 L0 100 Z", "feather": 4, "enabled": true },
  "clipToBelow": false,
  "filters": [ { "type": "gaussian-blur", "radius": 3 }, { "type": "unsharp", "amount": 0.8, "radius": 1.2, "threshold": 0 } ],
  "effects": [ { "type": "shadow", "color": "#000000", "opacity": 0.5, "angle": 135, "distance": 6, "blur": 10, "spread": 0 } ],
  "adjust": null, "fill": null, "smart": null }
```

| שדה | מה | הערות |
| --- | --- | --- |
| `baked` | sha256 של `src` שהמתכון הפיק | חובה כשיש מתכון. לא תואם — המתכון לא תקף |
| `source` | הפיקסלים לפני המתכון | `media/…`. בלי `source` אין מתכון פיקסלים (`crop`, ‏`transform`, ‏`filters`) — רק מה שלא תלוי בו (`adjust`, ‏`fill`, ‏`mask`) |
| `crop` | `[x, y, w, h]` בפיקסלים של `source` | סטודיו העיצוב: חיתוך |
| `transform` | `[a b c d e f]` מ-`source` (אחרי חיתוך) אל המשטח, ביחידות המשטח | כמו ב-`vector`. היפוך, סיבוב, קנה מידה |
| `mask` | מסכת שכבה בגווני אפור: `src` (PNG בגודל המשטח בפיקסלים, לבן = נראה), ‏`density` 0–1, ‏`feather` ביחידות המשטח, ‏`enabled` | Photoshop: Layer Mask |
| `vectorMask` | מסכה וקטורית: `d` (אותן פקודות מוחלטות `M L C Q Z` כמו ב-`vector`, ביחידות המשטח), ‏`feather`, ‏`enabled` | סטודיו העיצוב: עיגול, פינות מעוגלות, עם ריכוך |
| `clipToBelow` | השכבה נגזרת לפי השכבה שמתחתיה | Photoshop: Clipping Mask |
| `filters` | רשימה, לפי הסדר; `type` — רשימה פתוחה | "פילטרים חכמים". לפחות: `brightness-contrast`, `hue-saturation`, `gaussian-blur`, `motion-blur`, `unsharp`, `high-pass`, `noise`. ‏`type` לא מוכר — המתכון לא ניתן לחישוב מחדש; מציגים את `src` ושומרים |
| `effects` | סגנונות שכבה, לפי הסדר | **אותו מבנה כמו `effects` בפריט טקסט ב-`vector`**: `shadow`, `inner-shadow`, `glow`, `inner-glow`, `stroke`, `overlay` |
| `adjust` | שכבת התאמה: `{ type, …פרמטרים }` | ראו למטה |
| `fill` | שכבת מילוי: `{ color }` / `{ gradient }` (כמו `fill` ב-`vector`) / `{ pattern: "media/…" }` | `src` — המילוי האפוי, בגבולות המסכה |
| `smart` | Smart Object: `{ src: "media/<sha>.<ext>", size: [w, h] }` — המקור המוטמע (תמונה, או ‎`.mbe`) | יחד עם `transform` ו-`filters`. `src` של השכבה — התוצאה |

### שכבת התאמה (`adjust`) — בלי סוג שכבה חדש

שכבת התאמה היא שכבת `raster` עם `adjust`. ה-`src` שלה הוא **מה שנראה במקומה**: ההרכב של כל מה שמתחתיה אחרי ההתאמה,
בגבולות המסכה ושקוף מחוצה לה.

- **קורא שלא מכיר:** מצייר את `src` מעל, ורואה בדיוק את התמונה הנכונה (כל עוד השכבות שמתחת לא השתנו).
- **קורא שמבין:** מתעלם מ-`src` ומחיל את ההתאמה בזמן אמת על מה שמתחת.
- **אם השכבות שמתחת השתנו** באפליקציה שלא מבינה: `src` מיושן, אבל `baked` עדיין תואם (הפיקסלים של `src` עצמם לא נגעו).
  זה בסדר — מי שמבין מחשב בזמן אמת, ומי שלא מבין מציג את מה שהיה. הפער מדווח ב-`gaps` של הייצוגים (`adjust → baked`).

`type`: `levels`, ‏`curves`, ‏`hue-saturation`, ‏`color-balance`, ‏`black-white`, ‏`gradient-map`, ‏`channel-mixer`,
‏`brightness-contrast`, ‏`exposure`, ‏`vibrance`, ‏`photo-filter`, ‏`invert`, ‏`posterize`, ‏`threshold`, ‏`lut`
(`{ type: "lut", src: "media/<sha>.cube" }`). רשימה פתוחה. הפרמטרים של כל סוג — במסמך הפרויקט, ונכנסים ל-`mbe-format.md`
עם ההכרעה.

## מה הליבה צריכה

- **סכמה, תוספת בלבד:** ב-`layer` נוספים `baked`, ‏`source`, ‏`crop`, ‏`transform` (6 מספרים), ‏`mask`, ‏`vectorMask`,
  ‏`clipToBelow`, ‏`filters`, ‏`effects`, ‏`adjust`, ‏`fill` ו-`smart`.
- **בדיקות:**
  - `source`, ‏`mask.src` ו-`smart.src` הם הפניות למשאב, ולכן נבדקים כבר היום (`src` בכל עומק).
  - `vectorMask.d` — אותה בדיקת `pathProblem` כמו בנתיבי `vector`.
  - `baked` — 64 תווים הקסדצימליים, בלי שהליבה מחשבת אותו.
- **אין שינוי בכללי הקריאה והשמירה.** מי שלא מכיר שומר את השדות כמו שהם, וזה בדיוק מה שהליבה כבר עושה.

## מה לא מבוקש כאן

- **CMYK, ‏Lab, ‏16 / 32 ביט ו-ICC:** בקשת "צבע" נפרדת, יחד עם כל החבילה (שלב ההדפסה).
- **ערוצים ובחירות שמורות:** ב-`apps/raster-studio/` עד שאפליקציה נוספת תצטרך אותם.
- **PSD:** ייבוא וייצוא, בלי שינוי בפורמט.

## הכרעת הצ'אט המתכלל

**הצ'אט המתכלל (2026-10-25): מאושר**, עם שתי השלמות. נכנס ל-`mbe-format.md` סעיף 3, "שכבת `raster` — עריכה לא הורסת".

1. **`effects` — מבנה אחד לכל החבילה:** הצל ב-`dx` / `dy` כמו שכבר אושר לווקטורי (`vector-studio-v2.md`), לא `angle` /
   `distance` — אלה תצוגה בממשק בלבד. ‏`spread` — רשות. כך צל שנוצר ברסטר, בווקטורי או בסטודיו העיצוב — אותו שדה.
2. **`mask.src` נמתח על `box` של השכבה** (בלי `box` — על כל המשטח), במקום "PNG בגודל המשטח בפיקסלים": המשטח ב-`pt`,
   ו"גודל בפיקסלים" לא מוגדר בלי צפיפות. כך המסכה ברזולוציה של התמונה, בלי תלות ב-DPI.

**בסכמה (`layer`):** `baked` (64 הקסדצימליים), ‏`source`, ‏`crop`, ‏`transform`, ‏`mask`, ‏`vectorMask` (תבנית `d`), ‏`clipToBelow`,
‏`filters`, ‏`effects`, ‏`adjust`, ‏`fill`, ‏`smart` — תוספת בלבד. **לליבה:** בדיקת `pathProblem` ל-`vectorMask.d` — שינוי קוד אצלה;
הודעה נשלחה. פרמטרי כל `adjust` / `filter` — במסמך הפרויקט שלך; ייכנסו לפורמט כשאפליקציה שנייה תצטרך אותם.
