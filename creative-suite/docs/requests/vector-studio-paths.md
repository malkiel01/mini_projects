# בקשה מווקטורי (`vector-studio/`) לצ'אט המתכלל — מודל הנתיבים, והצטרפות לליבה

**מאת:** הצ'אט של פרויקט 3 (`vector-studio/`) · **תאריך:** 2026-10-24
**סטטוס:** ממתין להכרעה. עד שתוכרע, האפליקציה כותבת לפי ההצעה כאן. אם תוכרע אחרת, משנים באפליקציה לפני
שהשמירה הראשונה של `.mbe` נפרסת.

## 1. תוכן `paths` בשכבה `vector` — להוסיף לאפיון ולסכמה

היום `paths` ב-`schema/document-1.json` הוא `{"type": "array"}` בלי פירוט. ההצעה:

```json
{
  "id": "p1",
  "d": "M10 10 L90 10 C95 10 100 15 100 20 Z",
  "transform": [1, 0, 0, 1, 0, 0],
  "fill":   { "color": "#1f3a5f", "opacity": 1 },
  "stroke": { "color": "#000000", "opacity": 1, "width": 1, "cap": "butt", "join": "miter", "miter": 4, "dash": [] },
  "fillRule": "nonzero",
  "shape": { "type": "rect", "box": [10, 10, 90, 40], "radius": 6 },
  "name": "כפתור"
}
```

| שדה | חובה | מה |
| --- | --- | --- |
| `id` | כן | ייחודי בכל המסמך, כמו שכבות ומשטחים |
| `d` | כן | תחביר נתיב של SVG, **רק פקודות מוחלטות `M L C Q Z`**, ביחידות `pt` של המשטח. כל קורא מצייר אותו גם בלי ספרייה |
| `transform` | לא | מטריצה `[a b c d e f]` כמו ב-SVG. ברירת מחדל: זהות |
| `fill` | לא | `null` = בלי מילוי. `color` — `#rrggbb` ב-sRGB. או `gradient` במקום `color` (למטה) |
| `stroke` | לא | `null` = בלי מתאר. `cap`: ‏`butt`/`round`/`square`; ‏`join`: ‏`miter`/`round`/`bevel`; ‏`dash` — מספרים ב-`pt` |
| `fillRule` | לא | `nonzero` / `evenodd` |
| `shape` | לא | הפרמטרים של צורה חיה (`rect`, `ellipse`, `polygon`, `star`, `line`). **`d` הוא תמיד האמת**; מי שלא מכיר את `shape` מצייר את `d` ושומר את `shape` כמו שהוא |
| `name` | לא | שם בלוח השכבות |

**מעבר צבע (ליניארי בגרסה 1):**

```json
"fill": { "gradient": { "type": "linear", "from": [0, 0], "to": [100, 0],
          "stops": [ { "at": 0, "color": "#ffffff" }, { "at": 1, "color": "#1f3a5f", "opacity": 0.5 } ] } }
```

**למה:**
- `d` מנורמל לפקודות מוחלטות: העימוד (שמציג את הצורות שלנו) והרסטר (שמציג אותן משוטחות) צריכים לפענח
  ארבע פקודות בלבד, לא את כל התחביר של SVG.
- `shape` לצד `d` ולא במקומו: צורה נשארת עריכה כפרמטרים אצלנו, ושום אפליקציה אחרת לא חייבת להבין אותה.
- צבע ב-`#rrggbb` ו-`opacity` בנפרד: ככה זה מתאים ל-`color.space: "sRGB"` של המעטפת, ולא מחייב לפענח `rgba()`.

**הבקשה:** סעיף קצר ב-`mbe-format.md` ("תוכן שכבה `vector`"), והסכמה ב-`document-1.json` עם `d` ו-`id`
כחובה. שאר השדות פתוחים, כמו שאר הרשימות הפתוחות.

## 1א. קבוצות בתוך `paths` (נוסף 2026-10-24)

פריט ב-`paths` יכול להיות גם קבוצה: `{ "id": "g1", "type": "group", "name": "לוגו", "children": [ …פריטים… ] }`.
בלי `d` ובלי טרנספורמציה משלה — הזזה ושינוי גודל עוברים לילדים. סדר הילדים הוא סדר ההצגה.

**למה לא שכבה `group`:** קבוצה של כמה צורות באמצע שכבה. כשכבה, היא הייתה עולה לראש השכבה ומשנה את סדר ההצגה,
או מחייבת לפצל את השכבה לשלוש.
**משמעות לאחרים:** פריט עם `type: "group"` מציירים לפי הילדים. מי שלא מכיר קבוצות שומר אותן כמו שהן (כלל "שמור
את מה שלא הבנת"). `id` של ילדים — ייחודי בכל המסמך, כמו כל מזהה.

## 2. טקסט בשכבה וקטורית

טקסט קצר (לוגו, כותרת) נשמר כשכבה `frame` עם `box` ו-`flow` של ProseMirror, כמו בעימוד. כך לא נוצר מודל
טקסט שני. **הבקשה:** לאשר את זה, או לומר אם העימוד מתכנן מבנה אחר למסגרת טקסט.

## 3. הצטרפות לליבת `.mbe`

**הבקשה:** להוסיף ל-`creative-suite/mbe-core/apps.json`:

```json
{ "vector-studio": { "js": "assets/js/mbe", "php": "lib/mbe" } }
```

ולהריץ את הסנכרון. הצ'אט של וקטורי **מסכים** לכניסה הזו (master-spec, סעיף 4).
