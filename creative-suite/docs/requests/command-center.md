## מה ביקש בעל המערכת

> תאפשר לי בתוך הדשבורד המתכלל לקבל תשובות ישירות ולענות ישירות, ולנהל את הכול גם דרך הדשבורד, במקביל לצ'אטים, בצורה
> מסודרת והיררכית. כל מטלה מסומנת: ממתינה לפיתוח, באמצע פיתוח, שאלה שממתינה למענה, אישור שממתין למענה. הדשבורד יבין את
> כל סוגי בקשות האישור של הצ'אטים, ויאשר או ידחה סוג כזה **אחת ולתמיד לכל הצ'אטים** — בלי המתנה מיותרת ובלי שאלות
> חוזרות. טוקן של Claude Platform מחובר לדשבורד. הפיתוח עצמו רץ בצ'אטים כאן, על חשבון Claude Code. המעקב, המענה והסנכרון
> בזמן אמת — על חשבון Claude Platform. **מתג** מעביר את הפיתוח עצמו ל-Claude Platform (למשל כשנגמרים טוקני Claude Code
> החודשיים) ובחזרה.

## מה חסר — לאפיון המפורט

1. **היררכיה:** חבילה ← פרויקט (אפליקציה) ← שלב / יעד ← מטלה. היום הדשבורד קורא את `docs/projects/*.md`. אחד מהם הוא
   מקור האמת, ולא שניהם: להכריע ממה נבנה מה, ואיך הצ'אטים כותבים התקדמות.
2. **מצב חמישי — "🔐 אישור ממתין"**, נפרד מ"שאלה": הצ'אט צריך היתר לפעולה (מחיקה, שינוי סכמה, פעולה בשרת), לא מידע.
   כפתורים: אשר פעם אחת / **אשר תמיד את הסוג הזה** / דחה / **דחה תמיד**.
3. **מדיניות האישורים:** קטלוג סוגים (ניסוח קבוע, למשל "מיזוג PR לענף שלי", "שינוי `deploy.yml`", "מחיקת קבצים",
   "שינוי בסכמת ‎.mbe", "שליחת הודעה לצ'אט אחר"). כל החלטה "תמיד" נכתבת:
   - **לכללי ההרשאה של הריפו** (`.claude/settings.json`, `allow` / `deny`) — **ב-PR**, כי זה קובץ בגיט שחל על כל הצ'אטים;
   - **ולמדיניות בלוח**, שהצ'אט בודק לפני שהוא שואל: "מותר תמיד" — ממשיך בלי לשאול; "אסור תמיד" — לא מבקש.
   - שינוי מדיניות — עם יומן: מי, מתי, ומה היה קודם.
4. **ערוץ בזמן אמת, משני הכיוונים:**
   - צ'אט → לוח: קיים (HTTP).
   - לוח → צ'אט: **אין היום ממשק ציבורי שמכניס הודעה לסשן של Claude Code מבחוץ.** לבדוק ולהמליץ, עם הסיכונים:
     (א) הצ'אט בודק את הלוח בתחילת כל צעד ובלולאה (`claim` / הודעות); (ב) תגובה ב-GitHub על PR שהצ'אט מאזין לו מעירה
     אותו; (ג) הצ'אט המתכלל מעביר בגשר הצוות (`create_trigger`). להכריע מה המסלול הראשי ומה הגיבוי.
   - **בלי Platform:** כל המעקב עובד גם בלי מפתח, רק בלי הסיכומים.
5. **מה Platform עושה במצב "מעקב"** (תמיד, גם כשהפיתוח ב-Claude Code): סיכום מצב לכל פרויקט, מיון שאלות ואישורים לפי
   דחיפות, זיהוי שאלה שכבר נענתה ("נשאל כבר — הנה התשובה"), ניסוח הודעות לצ'אטים, התאמת בקשת אישור לסוג במדיניות.
6. **המתג:** איפה נשמר (לוח, לכל פרויקט + ברירת מחדל), מה קורה למטלה שבאמצע, ואיך הצ'אטים יודעים לא לקחת מטלה
   של פרויקט שמסלולו Platform (ולהפך). **ה-Platform מפתח באותו תהליך כמו הצ'אטים:** אותו `CLAUDE.md`, אותם סקילים,
   אותם שערים, ענף → PR → מיזוג → `conclusion: success`.
7. **התקרה:** מונה עלות לכל קריאה (מעקב ופיתוח בנפרד), התראה ב-80%, עצירה בתקרה. המפתח והסכום — **רק בהגדרות השרת**,
   לעולם לא בקוד ולא בצ'אט.
8. **הממשק:** דשבורד החבילה — תצוגת "מרכז": שאלות ואישורים ממתינים למעלה; לכל פרויקט — מטלות לפי מצב, ומתג המסלול; מסך
   מדיניות האישורים; מונה עלות. טלפון קודם (`phone-first-design`).
9. **אבטחה:** מי מורשה לענות ולאשר (רק בעל המערכת, או גם אחרים); אסימון לכל צ'אט (לא אסימון אחד לכולם); אישור "תמיד"
   לפעולה הרסנית — לפחות אזהרה כפולה.

## גבולות — חשוב שהאפיון יגיד במפורש

- **חלונות ההרשאה של אפליקציית Claude** ("Allow once / Deny" על כלי) — אין דרך לענות עליהם מבחוץ. מה שעוזר: כללי
  `settings.json` ומצב ההרשאות של הסשן. הכרעות "תמיד" מהלוח מגיעות לשם דרך PR, וחלות מהסשן הבא.
- **CLAUDE.md:** צ'אט של פרויקט לא נוגע בפרויקט אחר. `claude-tasks/` הוא פרויקט אחר: כל שינוי שנדרש בו הוא **בקשה
  לצ'אט שלו, דרך בעל המערכת**. הדשבורד של החבילה רק קורא וכותב דרך ה-API.
- **מגבלות ההרשאה** (CLAUDE.md): `workflow_dispatch` מהצ'אטים מחזיר 403. מנוע ה-Platform מופעל מהלוח, עם האסימון שלו.

## תשובה

**הצ'אט המאפיין (2026-11-01):** האפיון — `creative-suite/docs/spec/command-center.md`; **ממתין לאישור בעל המערכת**, ואין קוד עד אז.

בעל המערכת הכריע עוד ארבע שאלות (סעיף 0 באפיון):
- **מקור האמת — הלוח.** `docs/projects` נשארים לאפיון ולהכרעות.
- **הערוץ:** הצ'אט בודק לבד כל ~15 דק' כשיש לו מטלה ממתינה, ומפיץ שעתי כגיבוי.
- **מנוע Platform:** Claude Code עצמו ב-Actions, במקום `run.mjs`. הסיבה: `run.mjs` לא טוען את `CLAUDE.md` ואת הסקילים.
- **בתקרה:** נעצר רק הפיתוח; המעקב ממשיך.

**בדקתי בפועל** (סעיף 3.1 באפיון):
- `create_trigger` ו-`send_later` עובדים, אבל רק מתוך סשן של Claude.
- תגובה ב-GitHub — לא ערוץ להחלטות: התוכן לא מהימן, והיא מגיעה רק ל-PR שהסשן מנוי עליו.
- `watch_url` — לא מתאים: אי אפשר לחתום עליו מהלוח.

**השינויים בלוח:** בקשה נפרדת, `requests/claude-tasks-command-center.md`. בעל המערכת יעביר אותה לצ'אט של הלוח.
