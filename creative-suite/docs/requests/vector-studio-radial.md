# בקשה מווקטורי (`vector-studio/`) לצ'אט המתכלל — מעבר צבע עגול (`radial`)

**מאת:** הצ'אט של פרויקט 3 (`vector-studio/`) · **תאריך:** 2026-10-24
**סטטוס:** ממתין להכרעה. עד שתוכרע, האפליקציה כותבת לפי ההצעה כאן. אם תוכרע צורה אחרת, משנים באפליקציה
(הקורא מחכה רק לשדות שכאן, אז ההמרה פשוטה).

## מה מבקשים

תוספת אחת לשורת `fill` שבטבלה של "תוכן שכבה `vector`" ב-`mbe-format.md` (סעיף 3, אושר ב-#708). היום יש רק
`gradient` מסוג `linear`. ההצעה — סוג נוסף, לצידו:

```json
"fill": { "gradient": { "type": "radial", "center": [50, 50], "radius": 40,
                        "stops": [{ "at": 0, "color": "#ffffff" }, { "at": 1, "color": "#2d4a8a", "opacity": 0 }] } }
```

| שדה | מה |
| --- | --- |
| `type` | `"radial"` |
| `center` | `[x, y]` — מרכז העיגול, בקואורדינטות של הנתיב (כמו `from`/`to` של `linear`; זז עם `transform`) |
| `radius` | רדיוס ב-`pt`, גדול מ-0. העצירה `at: 0` במרכז, `at: 1` על ההיקף, ומעבר לו — הצבע האחרון |
| `stops` | בדיוק כמו ב-`linear` |

**בלי מוקד ובלי אליפסה** — כמו `radialGradient` בלי `fx`/`fy`, ו-`ShadingType 3` ב-PDF עם רדיוס פנימי 0.
קורא שלא מכיר את `radial` — מצייר בצבע של העצירה הראשונה (זה מה שווקטורי עושה עם סוג לא מוכר).

## הנוסח המוצע לשורה ב-`mbe-format.md`

> ב-`fill` אפשר `gradient` במקום `color`: `{ type: "linear", from, to, stops: [{ at, color, opacity }] }` או
> `{ type: "radial", center, radius, stops }` (מרכז ורדיוס ב-`pt`, בלי מוקד).

## לא נוגעים

- לא בסכמה של הליבה (`paths` עדיין `array` עד גרסה 1.1) ולא בקוד שלה.
- `.mbe` שכבר נשמרו — לא משתנים.
