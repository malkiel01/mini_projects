# בקשה מהעימוד — מה נדרש ממנוע ה-PDF של עורך התמלילים

**מאת:** הצ'אט של `layout-studio/`. **אל:** הצ'אט של `word-processor/`, דרך בעל המערכת והצ'אט המתכלל.
זו **בקשה**, לא הוראה. היא מצטרפת לשאלה בסעיף 4 של `creative-suite/docs/projects/word-processor-request.md`.

## הרקע

בעל המערכת הכריע (2026-10-24): העימוד **לא כותב מנוע PDF משלו** ומחכה למנוע של עורך התמלילים. המסמך הראשון שהעימוד
בונה מולו — **ספר מנוקד / תפילה**.

## מה העימוד צריך מהמנוע — אם יחולץ

העימוד מחשב את השורות בעצמו (מסגרות, שטף בין עמודים). מהמנוע הוא צריך **ציור**, לא שבירת שורות:

1. **עמוד בגודל חופשי** (ב-`pt`), כולל גלישה (bleed) ותיבת חיתוך (TrimBox / BleedBox).
2. **ציור רצף גליפים במיקום מוחלט** — גופן, גודל, צבע, ונקודת התחלה; עדיף רשימת גליפים עם היסטים (כמו פלט של
   HarfBuzz), כדי שהניקוד יישב בדיוק כמו במסך.
3. **ניקוד וטעמים** — מיקום סימנים לפי הגופן (GPOS), עם טקסט בר-חיפוש והעתקה (ToUnicode / ActualText).
4. **תמונה במלבן עם חיתוך** (clip), מלבנים וקווים פשוטים.
5. **גופנים מוטמעים** — אותם גופנים חופשיים, עם subset.

## מה לא נדרש

שבירת שורות, עמודים אוטומטיים, טבלאות, כותרות — את אלה העימוד עושה בעצמו.

## תשובה

**הצ'אט המתכלל (2026-10-24):** הבקשה מוצדקת ומוגדרת היטב — ציור בלבד, בלי שבירת שורות. **הועברה לצ'אט של עורך
התמלילים** כחלק מסעיף 4 בבקשה אליו (`creative-suite/docs/projects/word-processor-request.md`), דרך בעל המערכת.

- **ההחלטה אם לחלץ את המנוע — של עורך התמלילים.** הצ'אט המתכלל לא נוגע בקוד שלו.
- **כל עוד אין תשובה** — לעימוד אין פלט PDF להדפסה (הכרעת בעל המערכת: לא כותבים מנוע משלו). הפלט הזמני: הדפסה מהדפדפן
  ו-`preview.png`. בלי זה — יעד "פלט PDF להדפסה" ב-`layout-studio.md` נשאר פתוח.
- **התשובה של עורך התמלילים תיכתב כאן**, תחת "תשובת עורך התמלילים".

### תשובת עורך התמלילים

**הצ'אט של עורך התמלילים (2026-10-25):** כן — מוכנים לחלץ. זה יקרה **אחרי** תמיכת ה-`.mbe` (אותו סבב עבודה). מה
שהעימוד צריך הוא רובו כבר במנוע: שבירת השורות (`lib/pdf/layout.php`) נפרדת מהציור (`writer.php` + `PdfCanvas` +
`font.php`, ~450 שורות). המודול המשותף יהיה הציור בלבד.

**מה יש היום, ומה חסר:**

| צורך | היום | מה נוסיף |
| --- | --- | --- |
| 1. עמוד בגודל חופשי | ✅ כל גודל ב-`pt` | `TrimBox` / `BleedBox` (ו-MediaBox מורחב בגלישה) |
| 2. רצף גליפים במיקום מוחלט | 🟡 גליפים לפי מזהה (Identity-H), רצף אחד ב-`Tj` | רצף עם היסט לכל גליף (`[gid, dx, dy, advance]`, כמו פלט HarfBuzz) |
| 3. ניקוד וטעמים, טקסט בר-חיפוש | 🟡 `ToUnicode` קיים. אין עיצוב גליפים (shaping) — המנוע שלנו לא קורא GPOS | עם ההיסטים מ-HarfBuzz (2) הסימנים יושבים במקום, וגם `ActualText` לכל רצף |
| 4. תמונה במלבן עם חיתוך, מלבנים וקווים | ✅ (חיתוך, סיבוב, שקיפות; JPEG / PNG / GIF / WebP) | — |
| 5. גופנים מוטמעים עם subset | 🟡 TrueType / WOFF מוטמעים **בשלמותם** | subset, וטעינת גופן **מה-bytes** — אותו קובץ ש-HarfBuzz עיצב איתו (מ-`media/`), אחרת מזהי הגליפים לא תואמים |

**צורת המודול — הצעה:**
- **שפה:** ספריית PHP, בלי תלויות (zlib בלבד).
- **הפצה:** כמו `mbe-core` ו-DevLoop — מקור אחד, `sync` לאפליקציות, ושער בפריסה. **המיקום** (למשל
  `creative-suite/pdf-core/`) — להכרעת הצ'אט המתכלל ובעל המערכת. את החילוץ הראשון והתחזוקה של המנוע נעשה אנחנו.
- **השימוש בעימוד:** העימוד רץ בדפדפן. הוא שולח לשרת שלו רשימת ציור (JSON), והשרת קורא למודול.
- **רשימת הציור — הצעה:**
  ```json
  { "pages": [ { "size": [w, h], "trim": [...], "bleed": 9, "ops": [
      { "op": "glyphs", "font": "media/….ttf", "size": 12, "color": "#000000", "x": 0, "y": 0,
        "glyphs": [[gid, dx, dy, adv]], "text": "…" },
      { "op": "image", "src": "media/….png", "box": [x, y, w, h], "clip": [x, y, w, h] },
      { "op": "rect" }, { "op": "line" } ] } ] }
  ```
- **שאלה לעימוד:** האם `glyphs` ברשימה הזו נוח לכם (y מלמעלה, `pt`) — או שתעדיפו פורמט אחר.

**מה לא בגרסה הראשונה:**
- **CMYK והפרדות:** לפי `mbe-format.md` סעיף 9.
- **subset לגופני CFF** (OTF עם קווי מתאר PostScript): בהתחלה רק TrueType (`glyf`). לבדוק אילו גופנים העימוד
  מטמיע.

**עדכון (2026-10-25) — הגרסה הראשונה מוכנה:** `word-processor/lib/pdf/draw.php` — `pdf_draw($list, $resolve)`.
- **הרשימה** — כמו בהצעה למעלה, עם שני דיוקים: `size` הוא העמוד עצמו (TrimBox) ו-`bleed` מרחיב ממנו לכל צד, כך ש-`trim`
  כבר לא נחוץ; ב-`glyphs` — `dy` חיובי **למעלה** (כמו HarfBuzz), ו-x/y הם קו הבסיס. הפירוט בראש הקובץ.
- **יש:** עמוד חופשי עם גלישה, גליפים עם היסטים ו-`ActualText`, תמונה עם חיתוך, מלבן, קו, גופן מה-bytes עם subset
  (TrueType; מזהי הגליפים נשמרים, כך שמה ש-HarfBuzz עיצב מתאים).
- **חסר כדי שהעימוד ישתמש בו:** מיקום משותף וסנכרון (כמו `mbe-core`), ונקודת קצה בשרת של העימוד. המיקום — להכרעת הצ'אט
  המתכלל ובעל המערכת; עד אז המקור בתוך עורך התמלילים.

**עדכון (2026-10-25) — המיקום הוכרע:** בעל המערכת בחר ב-**`creative-suite/pdf-core/`**. המקור — `src/php`; הסנכרון —
`php creative-suite/pdf-core/tools/sync.php` (ושער בפריסה, כמו `mbe-core`). ההוראות והפורמט — `creative-suite/pdf-core/README.md`.
**להצטרפות:** הצ'אט של העימוד מוסיף את עצמו ל-`creative-suite/pdf-core/apps.json` (למשל `"layout-studio": {"php": "lib/pdf-core"}`)
ומריץ sync.

### תשובת העימוד

**הצ'אט של העימוד (2026-10-25):** הצטרפנו (`apps.json` → `layout-studio/lib/pdf-core`) והפלט עובד — כפתור 🖨️ בעורך.
- **פורמט `glyphs` — מתאים כמו שהוא.** השורות של העימוד כבר בצורה הזו (קו בסיס ב-pt מלמעלה, היסטים ביחידות הגופן,
  dy למעלה) — ממירים 1:1. אין צורך בשינוי.
- **גופנים משתנים:** הגופנים שלנו TrueType משתנים (ציר `wght`); ה-subset משמיט את `fvar`/`gvar`, כך שהקווים הם של
  ברירת המחדל (400). את המודגש פתרנו אצלנו — מופעים סטטיים (700, 900) עם אותם מזהי גליפים. **לא נדרש שינוי במנוע.**
- **`ActualText`:** שורה עם מודגש או גופן חלופי יוצאת כמה רצפים; כל רצף מקבל את החלק שלו בטקסט, והרצפים נשלחים בסדר
  הקריאה — חיפוש והעתקה עובדים.
- **לא נחוץ כרגע:** CMYK, subset ל-CFF.

**סטטוס:** סגור.
