## בכל הערה (כל שעה)

1. `git fetch origin main`. קרא את השורה שלך כאן ואת מה שנשאר.
2. **עבוד** על הדבר הבא ביעד. כל צעד: ענף, בדיקות, PR, מיזוג ו-`conclusion: success`. סמן `[x]` במסמך הפרויקט ואת התא ב-`integration.md`.
3. **שאלה לבעל המערכת לא עוצרת, ולא נשלחת אליו.** כתוב אותה ב-"## לבדיקה בסוף" במסמך הפרויקט, עם `מדריך:` /
   `פרומפט:`, ועבור לפריט הבא. הכרעה שאפשר לקבל בלעדיו — המתכלל מכריע.
   תלות בצ'אט אחר — הודעה ישירה (`creative-suite-team`), ועבור הלאה.
4. **בסוף ההערה** — שורה אחת ביומן של מסמך הפרויקט: מה נעשה, PR.

## הקצב — כל 5 דקות, ומשתנה מהדשבורד (2026-11-01)

**בעל המערכת:** "תעורר את הצ'אטים כל 5 דקות, עם אפשרות לשנות את הזמן דרך הדשבורד."
**מגבלה:** משימה מתוזמנת לא יכולה לרוץ יותר מפעם בשעה (המערכת דוחה תדירות גבוהה יותר). לכן הקצב המהיר נעשה
**בשרשרת:** כל צ'אט קובע לעצמו את ההערה הבאה.

1. **בסוף כל הערה** (כולל הערה שעשתה עבודה), קרא את הקצב:
   `https://mbe-plus.com/mini_projects/creative-suite/dashboard/cadence.php?chat=<role>` → `{ "minutes": 5, "paused": false }`.
   - בלי תשובה (הכתובת עוד לא קיימת, או שגיאה) — **5 דקות**.
   - **חובה לשלוח עוגייה** — לשרת יש בדיקת "האם אתה אדם", ובלעדיה מגיע `<script>` במקום JSON:
     `curl -s -b 'humans_21909=1' 'https://mbe-plus.com/mini_projects/creative-suite/dashboard/cadence.php?chat=<role>'`.
     תשובה שאינה JSON — כמו שגיאה (5 דקות).
   - `paused: true` — לא קובעים הערה. המשימה השעתית תעיר אותך, ותבדוק שוב.
2. `send_later` עם `delay_minutes` = הקצב, והודעה: "⏰ קו הגמר — המשך (שרשרת)". **הערה אחת בלבד בתור:** אם כבר קבעת
   הערה שעוד לא הגיעה, אל תוסיף עוד אחת.
3. **רשת הביטחון — המתכלל** (לא משימה שעתית לכל צ'אט): פעם בשעה הוא בודק מי נעצר ומעיר אותו.
4. **כשהיעד הושלם / תקוע לגמרי** — לא קובעים עוד הערה; כותבים דוח ומודיעים למתכלל.
5. `<role>` — כמו ב-`creative-suite/team/roster.json` (למשל `raster`, `word-processor`).

**הדשבורד** (מרכז הניהול): מסך "⏱ קצב" — דקות לכל צ'אט ולכולם (מינימום 1), והשהיה. הנתון נשמר בשרת, ו-`cadence.php`
ציבורי לקריאה בלבד (ברשימת `public` של השער), בלי שום מידע מלבד הדקות וההשהיה.

## הדוח — כשהיעד הושלם (או כשכל מה שנשאר תלוי באחרים)

`creative-suite/docs/reports/<app>.md`:

1. **מה נבנה** — רשימה, עם PR לכל פריט.
2. **בדיקות אוטומטיות** — הפקודות שהרצת והתוצאות (מספר עברו / נכשלו). פלט אמיתי, לא "אמור לעבוד".
3. **בדיקה בדפדפן** — Playwright ב-390px וב-1280px על הכתובת שנפרסה, צילומי מסך ב-`creative-suite/docs/reports/<app>/`, ולכל צילום שורה: מה בודקים ומה רואים.
4. **מה לא עובד / חסר** — בכנות.
5. **מה בעל המערכת צריך לבדוק בעצמו** — צעדים ממוספרים, כמו ב"מדריך".

אחרי שהדוח מוזג ונפרס (`conclusion: success`): הודעה לצ'אט המתכלל — "הדוח מוכן". **לא לבעל המערכת.**

**תקוע לגמרי** — כל מה שנשאר תלוי בבעל המערכת או בצ'אט אחר. כתוב דוח חלקי, ו"לבדיקה בסוף", והודע למתכלל.
