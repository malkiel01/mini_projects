# פרק 2 — מודלי החיוב ומנוע התמחור

## 2.1 העיקרון: קטלוג גמיש, מנוע אחד

כל אפליקציה מגדירה **מוצרים**, ולכל מוצר **מחירים**. כל מודל עסקי — מנוי, יחידה, שימוש, שילובים —
הוא צירוף של אותם אבני בניין. מנוע החיוב לא יודע מה זה "דוח" או "טוקן"; הוא יודע לכפול כמות במחיר לפי
כללים.

```
מוצר (product)          "AI — טוקנים"                 סוג: metered
  └─ מחיר (price) v3     0.4 אג' לכל 1,000 טוקנים       מדרגות, מכסה כלולה, חיוב: prepaid
```

## 2.2 סוגי מוצרים

| סוג | מה | דוגמאות מהפרויקט |
| --- | --- | --- |
| `plan` | מנוי — מחזורי, מחיר קבוע למחזור | מגדלור "דפדפן", שעון נוכחות בסיס, מתכונים פרימיום |
| `seat` | כמות בתוך מנוי — מחיר × כמות למחזור | ילד/מכשיר נוסף במגדלור, עמדה בשעון נוכחות |
| `unit` | חד-פעמי, לפי יחידה | הצעת תקציב לשנה, אימות חתימה, פרויקט נגרות |
| `metered` | נמדד, מסוכם בסוף מחזור או יורד מהארנק | טוקנים, SMS, עובדים פעילים, GB |
| `credit_pack` | חבילת קרדיט — טעינת ארנק בסכום/ביחידות | "1,000 קרדיטים ב-49 ₪" |
| `addon` | תוספת למנוי | אחסון 2GB, מודול נוסף |

## 2.3 שדות המחיר

| שדה | ערכים | הערות |
| --- | --- | --- |
| `amount` | אגורות (שלם) | לעולם לא float. גם שבר אגורה ליחידה נשמר כ-`amount_micros` (מיליוניות ₪) ל-metered |
| `currency` | `ILS` (ברירת מחדל), `USD`, `EUR` | ❓ מטבע אחד או כמה |
| `tax_behavior` | `inclusive` / `exclusive` | מחיר לצרכן — כולל מע"מ (חובה בחוק להציג כולל); לעסקים — אפשר לא כולל |
| `interval` | `month` / `year` / `week` / `none` | + `interval_count` (כל 3 חודשים) |
| `billing_scheme` | `per_unit` / `tiered` / `package` / `flat` | |
| `tiers` | `[{up_to, unit_amount, flat_amount}]` | `tiers_mode`: `graduated` (כל מדרגה במחירה) / `volume` (כל הכמות במחיר המדרגה) |
| `package_size` | למשל 1,000 | "לכל 1,000 טוקנים", עיגול למעלה |
| `included` | כמות כלולה במחזור | "1M טוקנים כלולים במנוי" |
| `aggregate` | `sum` / `max` / `last` / `unique` | איך מסכמים שימוש במחזור (2.4) |
| `trial_days` | מספר | ניסיון חינם |
| `min_charge` / `cap` | אגורות | מינימום/תקרה למחזור |
| `version` | מספר | **מחיר לא נערך** — רק גרסה חדשה |
| `active` | בוליאני | מחיר לא פעיל לא נמכר, אבל מנויים קיימים ממשיכים |

## 2.4 מדידה (metered) — איך מסכמים

| `aggregate` | שימוש | דוגמה |
| --- | --- | --- |
| `sum` | סכום כל האירועים במחזור | טוקנים, SMS, סריקות |
| `max` | השיא במחזור | **עובדים פעילים** (שעון נוכחות), מכשירים |
| `last` | הדיווח האחרון במחזור | GB מאוחסנים בסוף החודש |
| `unique` | מספר מזהים שונים (`meta.subject`) | עובדים שדיווחו לפחות פעם אחת |

אירוע שימוש נושא `idempotency_key` — אותו מפתח פעמיים נספר פעם אחת. אירוע שמגיע אחרי סגירת המחזור (עד
48 שעות) נכנס לחשבונית הבאה עם `period` המקורי.

## 2.5 ארנק (קרדיט מראש)

```
יתרה = Σ wallet_tx.amount   (נגזרת — לא עמודה שמתעדכנת)
```

| תנועה | סימן | מקור |
| --- | --- | --- |
| `topup` | + | תשלום על `credit_pack` / טעינה בסכום חופשי |
| `grant` | + | מכסה חודשית במנוי, מתנה מהמנהל, פיצוי |
| `usage` | − | אירוע `usage_record` של מוצר prepaid |
| `reserve` / `release` | −/+ | שריון לפני פעולה ארוכה (AI) ושחרור ההפרש |
| `expire` | − | קרדיט מתנה שפג (❓ האם קרדיט שנקנה פג — בחוק, קרדיט ששולם עליו עדיף שלא יפוג) |
| `refund` | − | החזר כספי על טעינה (רק מהיתרה שלא נוצלה) |
| `adjust` | ± | תיקון ידני של המנהל — חובה סיבה, נרשם בביקורת |

- **יחידת הארנק:** ❓ ש"ח (אגורות) או "קרדיטים". ההמלצה: **ש"ח** — שקוף ללקוח, ומחיר כל מוצר נשאר בש"ח.
  אפליקציה שרוצה להציג "קרדיטים" ממירה בתצוגה.
- **ארנק לכל חשבון, לא לכל אפליקציה** — אבל אפשר "סל" (`wallet.scope = app`) כשקרדיט נקנה לאפליקציה מסוימת.
- **טעינה אוטומטית:** "כשהיתרה יורדת מ-X — טען Y" מטוקן שמור. מגבלה: עד N טעינות ביום (הגנה מלולאה).
- **יתרה שלילית:** אסורה כברירת מחדל (`allowed:false`). אפשרות למנהל: מסגרת אשראי לחשבון (`credit_limit`).
- **התראות:** `wallet.low` (מתחת לסף), `wallet.empty` — webhook לאפליקציה ומייל ללקוח.

## 2.6 מנוי — מחזור החיים

```
           trial ──(נגמר, יש אמצעי תשלום)──▶ active ◀──(שולם)── past_due
             │                                 │  ▲                 │
     (נגמר, אין אמצעי)                   (כשל חיוב)│               (14 יום)
             ▼                                 ▼  │                 ▼
        incomplete ─────(שולם)──────────▶   past_due            canceled / paused
                                               │
                   cancel_at_period_end ──▶ canceled (בסוף המחזור)
```

| מצב | זכאות (`entitlement.active`) |
| --- | --- |
| `trialing` | כן |
| `active` | כן |
| `past_due` | **כן, בחסד** (ימים מוגדרים למחיר; ברירת מחדל 7). אחריהם — לפי מדיניות האפליקציה |
| `paused` | לא (או קריאה בלבד — האפליקציה מחליטה לפי `entitlement.state`) |
| `canceled` | לא |
| `incomplete` | לא (התשלום הראשון לא עבר) |

**שינויים באמצע מחזור:**

- **שדרוג** — מיידי. זיכוי יחסי על הזמן שנותר בתכנית הישנה + חיוב יחסי על החדשה, נגבה מיד.
- **שנמוך** — בסוף המחזור (ברירת מחדל), כדי לא להחזיר כסף.
- **שינוי כמות (seats)** — הוספה: חיוב יחסי מיידי; הורדה: מהמחזור הבא.
- **ביטול** — `at_period_end` (ברירת מחדל) או `now` עם זיכוי יחסי לארנק או החזר (בחוק — פרק 10).
- **חישוב יחסי:** לפי שניות (`(end − now) / (end − start)`), עיגול לאגורה לטובת הלקוח.

**עיגון תאריך (anchor):** מנוי שמתחיל ב-31 בחודש מתחדש בסוף כל חודש (30/28). אפשרות לאחד את כל המנויים של
חשבון לתאריך אחד → חשבונית אחת בחודש.

## 2.7 חשבונית חודשית מאוחדת

חשבון עם כמה מנויים וכמה אפליקציות מקבל **מסמך אחד למחזור**, עם שורה לכל רכיב:

```
חשבונית מס/קבלה 10234 — אוקטובר 2026 — משפחת כהן
  מגדלור — תכנית "אפליקציות" (1.10–31.10)                 39.00
  מגדלור — מכשיר נוסף × 1                                    10.00
  מתכונים — פרימיום                                          19.00
  מתכונים — AI: 412,000 טוקנים (200,000 כלולים)              0.85
  ─────────────────────────────────────────────
  סה"כ לפני מע"מ  58.35   מע"מ 18%  10.50   לתשלום  68.85
```

- `invoice_line.app` — כך מסך המנהל מפלח הכנסה לפי אפליקציה.
- **"יחסי לפי האפליקציות"** (הבקשה המקורית): כל שורה שייכת לאפליקציה; הנחת חבילה (למשל 10% על 3+ אפליקציות)
  מחולקת יחסית בין השורות.

## 2.8 הנחות, קופונים ומבצעים

| | דוגמה |
| --- | --- |
| `coupon` | 20% ל-3 חודשים; 50 ₪ פעם אחת; חודש חינם |
| `promotion_code` | קוד שהלקוח מקליד — `TOOLS2026` |
| הנחת חבילה | 3 אפליקציות ומעלה — 10% |
| הנחה ידנית | המנהל, ללקוח מסוים, עם סיבה |

## 2.9 מס ומע"מ

- מע"מ לפי שיעור בהגדרות (18% ב-2026), **נשמר על כל חשבונית** בשיעור שהיה ביום הוצאתה.
- **עוסק פטור** — אין מע"מ בכלל; המחירים סופיים; מסמך = קבלה (פרק 7).
- לקוח בחו"ל (B2B) — ייצוא שירותים, מע"מ 0% (סעיף 30(א)(5)), בכפוף לבדיקה עם רו"ח ❓.
- עיגול: מע"מ מחושב על סה"כ החשבונית, לא לכל שורה.

## 2.10 דוגמאות מלאות מהפרויקט

**מגדלור — "אפליקציות" 39 ₪ לחודש, עד 3 מכשירים, מכשיר נוסף 10 ₪:**
`plan` 3900 אג' / חודש + `seat` 1000 אג' / חודש, `included` 3.

**שעון נוכחות — 49 ₪ כולל 5 עובדים, אחר כך מדרגות:**
`plan` 4900 + `metered active_employees` `aggregate:max`, `included:5`, `tiers graduated`: 6–20 → 8 ₪, 21–50 → 6 ₪, 51+ → 4 ₪.

**מתכונים — AI בקרדיט:**
`metered ai_tokens` `prepaid`, `package_size:1000`, `amount_micros` לכל 1,000; `credit_pack` 2000 אג' → 2000 אג' בארנק (+ בונוס 10%).

**הצעות תקציב — הצעה לשנה:**
`unit budget_year` 29900 אג', `entitlement` לפי `meta.year`.
