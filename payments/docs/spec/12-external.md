# פרק 12 — תוסף חיצוני: תשלומים לכל אתר ומערכת — בגישה סגורה

> הוכרע (2026-10-24):
> 1. התוסף **אינו רק** הגבייה של האפליקציות שלי — אפשר לחבר אותו **לכל אתר או מערכת עתידית**.
> 2. **אין גישה חופשית.** רק מי שהמנהל-המפתח מאשר, **תחת חשבון הפלטפורמה שלו**, מקבל גישה: קוד גישה, ואזור
>    ניהול משלו להגדרות, לדרישות ולקריטריונים — בגמישות מרבית.
> 3. **בלי כתובת משלו** בשלב זה. נשאר בתוך הפלטפורמה (`mini_projects/payments/`). `pay.mbe-plus.com` — שמור
>    לעתיד, רק אם יתברר שצריך (12.8).

## 12.1 המבנה: שלוש רמות

```
המנהל-המפתח (בעל המערכת)          ← רואה הכול, מאשר מי נכנס, קובע מה מותר לכל אחד
  └─ מנוי מאושר (tenant) — משתמש פלטפורמה שאושר     ← "אזור ניהול" משלו
        ├─ עוסקים (merchant) — פטור / מורשה / חברה, סולק ו-Morning משלו
        ├─ מערכות מחוברות (client) — אתר, אפליקציה, מערכת — כל אחת עם קוד גישה
        ├─ מוצרים, מחירים, קישורי תשלום, טפסים
        ├─ כללים וקריטריונים (12.4)
        └─ הלקוחות המשלמים שלו, החשבוניות, הדוחות
              └─ הלקוח המשלם — רואה רק דף תשלום ו"החשבון שלי"
```

- **המנהל עצמו הוא המנוי הראשון** — האפליקציות שלו בכלים הדיגיטליים הן "מערכות מחוברות" אצלו.
- **מנוי רואה רק את שלו.** אין חשיפה בין מנויים — לא לקוחות, לא מפתחות, לא דוחות.
- **הלקוח המשלם לעולם אינו משתמש פלטפורמה** (העיקרון מ-CLAUDE.md נשמר).

## 12.2 הכניסה — רק באישור

1. משתמש פלטפורמה מבקש גישה (או המנהל מזמין אותו).
2. **המנהל מאשר** במסך "מנויים" של התוסף, וקובע לו **מגבלות** (12.5).
3. המנוי נכנס לתוסף דרך הפלטפורמה, ורואה רק את אזור הניהול שלו.
4. בכל מערכת שהוא מחבר — יוצר **קוד גישה** (12.3).
5. המנהל יכול **להשהות** מנוי בכל רגע — כל קודי הגישה שלו מפסיקים לעבוד מיד, ודפי התשלום שלו מציגים "לא זמין".

**מה זה דורש מהפלטפורמה:** היום תוסף פתוח **רק למנהל** (`can_use` ב-`platform/lib/gate.php`). צריך שתוסף יוכל
להיפתח גם **למשתמש עם אישור ישיר** (כמו `"restricted"`), אבל אף פעם לא דרך קטגוריה. נכתבה בקשה:
`payments/docs/requests/plugin-direct-grants.md`. עד שהיא תמומש — רק המנהל נכנס (מספיק לשלבים 1–5).

**הזהות:** התוסף מקבל את המשתמש מהשער (`PLATFORM_USER`: `sub`, שם, מייל) ומחזיק **חשבון מנוי משלו** מקושר
ל-`sub` — כמו כל אפליקציה (`platform/docs/sso.md`). התוסף לא קורא את מסד הפלטפורמה.

## 12.3 קוד גישה

לכל מערכת מחוברת, בכל סביבה (`test` / `live`):

| קוד | איפה מותר | מה מותר |
| --- | --- | --- |
| **קוד סודי** (`sk_…`) | **רק בשרת** של המערכת | הכול (פרק 4.3), רק בתוך המנוי שלו |
| **קוד גלוי** (`pk_…`) | בדפדפן / באפליקציה | רק לפתוח דף תשלום על **מחיר שהוגדר מראש**, ולהציג מחירון. **אף פעם לא סכום חופשי** |
| **מפתח Ed25519** | זוג אצל המערכת, הציבורי בכתובת שלה | כמו קוד סודי, בלי סוד משותף — לאפליקציות שכבר עובדות כך |
| **סוד webhook** (`whsec_…`) | בשרת | אימות ההודעות שהתוסף שולח |

- **החתימה** בקוד סודי — HMAC-SHA256 על אותה מחרוזת כמו Ed25519 (`פעולה \n זמן \n nonce \n sha256(גוף)`). הסוד
  עצמו לא נשלח — רק מזהה הקוד והחתימה.
- הקוד מוצג **פעם אחת** ביצירה; אחר כך רק 4 תווים אחרונים. נשמר מוצפן.
- **החלפה** עם חפיפה (ברירת מחדל 7 ימים); **ביטול מיידי** בלחיצה.
- **הגבלות לכל קוד:** כתובות IP, אתרים מותרים (לקוד גלוי), פעולות מותרות, תוקף.
- **`live` רק אחרי אישור המנהל** לכל מערכת; `test` — מיד, מול סולק מדומה.

## 12.4 כללים וקריטריונים — גמישות מרבית

במקום הגדרות קבועות — **מנוע כללים**: כל כלל הוא "**כש**… **אז**…", לפי סדר עדיפות, ברמת המנוי, העוסק,
המערכת או המוצר (הספציפי גובר).

**תנאים (כש…)** — אפשר לשלב כמה:

| תנאי | דוגמה |
| --- | --- |
| מערכת / מוצר / סוג מוצר | "באתר X", "במוצר מנוי" |
| סכום | "מעל 1,000 ₪", "בין 50 ל-200" |
| סוג לקוח | פרטי / עסק, לקוח חדש / חוזר, מספר תשלומים קודמים |
| אמצעי תשלום | "בביט", "בכרטיס מחו"ל" |
| זמן | ימים, שעות, טווח תאריכים (מבצע) |
| שדה בטופס / `meta` מהמערכת | "עיר = ירושלים", "מסלול = שנתי" |
| כמות / שימוש | "מעל 100,000 טוקנים בחודש" |

**פעולות (אז…)**:

| פעולה | דוגמה |
| --- | --- |
| להתיר / לחסום אמצעי | "ביט רק עד 500 ₪" |
| לנתב לסולק | "כרטיסים מחו"ל → PayPal" |
| תשלומים | "מעל 1,200 ₪ — עד 6 תשלומים" |
| מחיר | הנחה, תוספת (עמלת אמצעי), מחיר מיוחד, מדרגות |
| לדרוש | שדה (ח"פ לעסק), אישור תנאים, אימות טלפון, 3DS |
| אישור ידני | "מעל 5,000 ₪ — ממתין לאישור שלי לפני חיוב" |
| מסמך | סוג מסמך, עוסק מנפיק, הערה על המסמך |
| מדיניות | ימי חסד, ניסיונות חוזרים, תפוגת קרדיט, טעינה אוטומטית — לכל מוצר |
| הודעה | מייל / webhook / התראה אליי |

- **"בדיקה"** — מסך שבו מזינים עסקה דמיונית ורואים אילו כללים חלים ומה התוצאה, לפני שמפעילים.
- כל שינוי בכלל — בביקורת, עם גרסה (אפשר לחזור).
- הכללים נשמרים כ-JSON (`rule`: `scope`, `priority`, `when`, `then`, `active`) — כך מוסיפים תנאי או פעולה חדשה
  בלי לשנות את מבנה המסד.

## 12.5 מה המנהל קובע לכל מנוי

| | |
| --- | --- |
| **סטטוס** | ממתין · פעיל · מושהה · סגור |
| **מגבלות** | מספר עוסקים, מערכות מחוברות, מחזור חודשי מרבי, סכום מרבי לעסקה |
| **מה פתוח לו** | אילו סולקים, אילו אמצעים, קישורי תשלום, טפסים, מנויים, שימוש מדוד, `live` |
| **הסולק** | הסכם משלו (המפתחות שלו) — **ברירת המחדל**, כך הכסף נכנס ישר אליו ולא דרכי |
| **עמלה** ❓ | אם בעתיד המנהל יגבה מהמנויים על השירות — המנוי עצמו הוא "לקוח משלם" של המנהל, דרך אותו מנגנון |

## 12.6 בלי קוד

- **קישור תשלום + קוד QR** — מוצר/מחיר (או סכום לבחירה, לתרומות, עם מינימום ומקסימום), אמצעים, תשלומים, תוקף,
  מגבלת שימושים. מדביקים בוואטסאפ, במייל, באתר.
- **כפתור להטמעה** — שתי שורות בכל אתר (גם וורדפרס/וויקס), עם קוד גלוי. אירוע הדפדפן לא משמש להחלטה — רק
  ה-webhook או שאילתה מהשרת.
- **טופס תשלום** — שדות לבחירה; התשובות במסך הניהול וב-webhook.

## 12.7 למתכנתים (של המנוי)

תיעוד מלא (דף + OpenAPI) — **נגיש רק למנויים מאושרים** (מאחורי השער), ספריות ב-PHP וב-JavaScript, סביבת
בדיקות, יומן קריאות לכל מערכת, שליחת webhook לבדיקה ושליחה חוזרת.

## 12.8 למה לא כתובת משלו (עכשיו)

| שיקול | מסקנה |
| --- | --- |
| הגישה סגורה ותחת חשבון הפלטפורמה | **בתוך הפלטפורמה זה הכי פשוט** — השער כבר מזהה ומאשר |
| דף התשלום ללקוח המשלם | עובד מכל כתובת; ממותג לפי המערכת של המנוי |
| Apple Pay באתר | דורש אימות דומיין אצל הסולק — אפשר גם על `mbe-plus.com` (בקשה לפלטפורמה אם צריך קובץ בשורש) |
| מיתוג נייטרלי ("pay." במקום "mini_projects") | נחמד, לא הכרחי |
| יציאה מהפלטפורמה בעתיד | כל הקישורים נבנים מ**כתובת בסיס אחת** בהגדרות — מעבר ל-`pay.mbe-plus.com` יהיה שינוי אחד + הפניה |

**ההמלצה: לא עכשיו.** הקוד נכתב כך שהמעבר יהיה קל (כתובת בסיס, בלי `require` מחוץ לתיקייה), ואם יידרש —
`pay.mbe-plus.com`.

## 12.9 אבטחה נוספת

- קוד גלוי לא קובע סכום; סכום חופשי רק בקישור שהמנוי יצר, עם גבולות.
- CORS רק לכפתור ולקוד הגלוי, רק מהאתרים שהוגדרו.
- הגבלת קצב לכל קוד ולכל IP; ניסיונות כרטיס כושלים → חסימה זמנית.
- השהיית מנוי = כל הקודים שלו מתים מיד.
- כל מנוי ומערכת רואים רק את שלהם (404 על השאר).
