# פרק 12 — תוסף חיצוני: תשלומים לכל אתר ומערכת

> הוכרע (2026-10-24): התוסף **אינו רק** הגבייה של האפליקציות בכלים הדיגיטליים. הוא **שירות תשלומים עצמאי**
> שאפשר לחבר לכל אתר או מערכת עתידית — גם בדומיין אחר, גם לא ב-PHP, וגם בלי קוד בכלל.

## 12.1 מה משתנה

| לפני | אחרי |
| --- | --- |
| "אפליקציה" — תיקייה בריפו שנרשמת בעצמה | **"לקוח מערכת" (`client`)** — כל מערכת: אפליקציה פנימית, אתר חיצוני, וורדפרס, אפליקציית מובייל, מערכת של צד ג' |
| רישום רק עצמי (Ed25519 + `key_url`) | **שתי דרכים:** רישום עצמי (כמו היום), **או** יצירה במסך המנהל — מקבלים מפתחות להדבקה |
| חתימה רק Ed25519 | **Ed25519 או מפתח סודי (HMAC)** — כמו Stripe; מתאים לכל שפה ולכל מערכת |
| SDK ב-PHP בלבד | PHP, JavaScript/Node, תיעוד HTTP מלא (OpenAPI), ותוסף וורדפרס בהמשך |
| תשלום רק דרך API | גם **בלי קוד**: קישורי תשלום, כפתור להטמעה, טופס תשלום |
| חי בתוך הפלטפורמה | **נייד**: אפשר להריץ אותו בדומיין משלו (`pay.<domain>`), עם כניסת מנהל משלו |

כל השאר — הליבה, הסולקים, אמצעי התשלום, החשבוניות, ריבוי העוסקים — **לא משתנה**. רק "מי מתחבר" מתרחב.

## 12.2 סוגי לקוחות מערכת

| סוג | דוגמה | איך מתחבר |
| --- | --- | --- |
| `internal` | מגדלור, מתכונים | רישום עצמי, Ed25519 (פרק 4) |
| `server` | אתר תדמית עם אזור מנויים, מערכת CRM, אפליקציה בדומיין אחר | מפתח סודי מהמנהל, או Ed25519 — קריאות שרת-לשרת |
| `static` | דף נחיתה, אתר בלי שרת, וויקס / וורדפרס בלי קוד | **קישורי תשלום וכפתור** בלבד — בלי סוד בדפדפן |
| `mobile` | אפליקציית אנדרואיד | דרך השרת של האפליקציה (`server`), או קישור תשלום שנפתח בדפדפן |

## 12.3 מפתחות

לכל לקוח מערכת, בכל סביבה (`test` / `live`):

| מפתח | צורה | איפה מותר | מה מותר |
| --- | --- | --- | --- |
| **מפתח סודי** | `sk_live_…` | **רק בשרת** | הכול (פרק 4.3) |
| **מפתח ציבורי** | `pk_live_…` | בדפדפן / באפליקציה | רק: לפתוח דף תשלום על **מוצר/מחיר שהוגדר מראש במסך המנהל**, ולהציג מחירון. **לעולם לא סכום חופשי** — כך אי אפשר "לשלם 1 ₪ על מוצר של 500" |
| **מפתח Ed25519** | זוג אצל הלקוח, הציבורי ב-`key_url` | בשרת | כמו מפתח סודי, בלי סוד משותף |
| **סוד webhook** | `whsec_…` | בשרת | אימות ה-webhooks שהתוסף שולח (HMAC), למי שלא עובד עם Ed25519 |

**החתימה ב-HMAC** (חלופה ל-Ed25519, אותה מחרוזת):

```
X-Pay-Key:       sk_live_…  (המזהה — הקידומת, לא הסוד המלא; ראו למטה)
X-Pay-Time:      1761300000
X-Pay-Nonce:     <32 hex>
X-Pay-Signature: hex(HMAC-SHA256(secret, action \n time \n nonce \n sha256hex(body)))
```

- הסוד **לא נשלח** בבקשה — רק מזהה המפתח (`key_id`) והחתימה. כך גם אם בקשה נחשפת ביומן, הסוד לא נחשף.
- החלפת מפתחות ("גלגול"): מפתח חדש ותקופת חפיפה (ברירת מחדל 7 ימים) שבה שניהם עובדים.
- הגבלות לכל מפתח: כתובות IP (אופציונלי), `origins` למפתח הציבורי, פעולות מותרות.
- מפתח נשמר אצלנו **מוצפן**; מוצג פעם אחת ביצירה (אחר כך רק 4 תווים אחרונים).

## 12.4 בלי קוד

### קישור תשלום
במסך המנהל: בוחרים עוסק, מוצר/מחיר (או "סכום לבחירת הלקוח" — לתרומות), כמות, אמצעים, תשלומים, תוקף, מגבלת
שימושים → מקבלים **קישור קבוע** (`pay/l/<קוד>`) ו**קוד QR**. מדביקים בוואטסאפ, במייל, באתר. אחרי תשלום — קבלה
אוטומטית, ואופציונלית הפניה לכתובת ו-webhook.

### כפתור להטמעה
```html
<script src="https://pay.mbe-plus.com/embed.js" async></script>
<a class="mbe-pay" data-key="pk_live_…" data-price="price_…">לתשלום</a>
```
- פותח את דף התשלום בחלון/שכבה; בסיום — אירוע JS (`mbe-pay:success`) והפניה.
- עובד בכל אתר (גם וויקס / וורדפרס בבלוק HTML). **לא סומכים על האירוע** לשום החלטה — רק על webhook או שאילתה מהשרת.

### טופס תשלום
דף תשלום מתארח עם שדות שמוגדרים במנהל (שם, טלפון, הערה, שדות חופשיים) — לרישום לאירוע, תרומה, הזמנה פשוטה.
התשובות נשמרות ומוצגות במסך המנהל ונשלחות ב-webhook.

## 12.5 מפתחים

- **תיעוד ציבורי** — `payments/docs/api/` כדף HTML + **OpenAPI** (`openapi.json`), עם דוגמאות ב-curl, PHP ו-JS.
- **ספריות:** `sdk/php/PaymentsClient.php` (קובץ אחד), `sdk/js/` (Node, ESM, בלי תלויות), `embed.js` (דפדפן).
- **סביבת בדיקות** לכל לקוח (`sk_test_…`) עם סולק מדומה (`fake`) וכרטיסי בדיקה — אפשר לבנות בלי הסכם סליקה.
- **יומן קריאות** לכל לקוח במסך המנהל — בקשה, תשובה, קוד, זמן (בלי סודות) — לאבחון.
- **שליחת webhook לבדיקה** מהמנהל, ו"שליחה חוזרת" לאירוע.
- ❓ בהמשך: תוסף וורדפרס/ווקומרס, ו-Zapier/Make לחיבור בלי קוד.

## 12.6 עצמאות: התוסף כשירות משלו

כדי שיוכל לשרת אתרים מחוץ לפלטפורמה ואולי לצאת לדומיין משלו:

1. **שני מצבי ריצה** — `platform` (בתוך הכלים הדיגיטליים: השער מכניס את המנהל) ו-`standalone` (דומיין משלו:
   **מערכת מנהלים משלו** — מייל + סיסמה + אימות דו-שלבי, כי זה כסף). הקוד אחד; ההבדל ב-`data/config.json`.
2. **בלי `require` מחוץ לתיקייה** (כבר עיקרון). כל מה שהוא צריך — בתוכו.
3. **כתובת בסיס אחת** בהגדרות; כל הקישורים (דף תשלום, webhooks, מפתח ציבורי) נבנים ממנה. מעבר דומיין = שינוי
   אחד + הפניה מהכתובת הישנה.
4. **כמה מנהלים** עם הרשאות: בעלים, הנהלת חשבונות (קריאה + ייצוא), תמיכה (לקוחות, בלי החזרים) — ❓ כשיהיו.
5. **ריבוי עוסקים** (כבר הוכרע) הוא מה שמאפשר לשרת גם אתרים של אחרים בעתיד: כל עוסק עם סולק ו-Morning משלו.

## 12.7 אבטחה נוספת למצב החיצוני

- **מפתח ציבורי לא יכול לקבוע סכום** — רק מחיר שהוגדר. סכום חופשי (תרומה) — רק בקישור שהמנהל יצר, עם מינימום/מקסימום.
- **CORS** — רק ל-`embed.js` ולפעולות של המפתח הציבורי, ורק מ-`origins` שהוגדרו ללקוח.
- **הגבלת קצב** לכל מפתח ולכל IP; ניסיונות כרטיס כושלים מאותו IP/קישור → חסימה זמנית (הגנה מבדיקת כרטיסים גנובים).
- **reCAPTCHA / Turnstile** ❓ בקישורי תשלום ציבוריים עם סכום חופשי.
- לקוח מערכת חדש ב-`live` — **רק באישור המנהל**; ב-`test` — מיד.
- כל לקוח מערכת רואה רק את הנתונים שלו (404 על כל השאר).
