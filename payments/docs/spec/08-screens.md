# פרק 8 — המסכים

שלושה קהלים, שלושה ממשקים: **המנהל** (מאחורי השער), **הלקוח המשלם** (דף תשלום ו"החשבון שלי", ציבוריים),
ו**האפליקציה** (רכיבים קטנים שהיא מטמיעה). הכול בעיצוב phone-first (הסקיל), RTL, עברית.

## 8.1 ממשק המנהל — `payments/index.html`

ניווט תחתון בטלפון (5 לשוניות), צדדי במחשב. כל מספר כספי — עם ₪ וכולל/לא כולל מע"מ מסומן.

### 📊 סקירה
- **כרטיסי מספרים:** הכנסה החודש (מול החודש שעבר), MRR (הכנסה חודשית חוזרת), מנויים פעילים, יתרות ארנקים
  פתוחות (התחייבות!), כשלונות גבייה פתוחים.
- **פילוח לפי אפליקציה** — עמודות: הכנסה, מנויים, AI (טוקנים ועלות מול הכנסה — **רווחיות AI**).
- **דורש טיפול:** תשלומים שנכשלו, אפליקציות ממתינות לאישור, webhooks שנכשלו, פערי התאמה, מסמכים שלא הופקו.
- **פיד אחרון:** תשלומים ואירועים חיים.

### 👥 לקוחות
- חיפוש לפי שם / מייל / ח"פ / 4 ספרות / מזהה באפליקציה. סינון: אפליקציה, מצב מנוי, חוב.
- **כרטיס חשבון:** פרטי חשבונית · לקוחות מקושרים (אפליקציה + `external_id`) · מנויים · ארנק ותנועות · אמצעי
  תשלום (4 ספרות, תוקף) · חשבוניות ומסמכים · תשלומים · שימוש לפי מוצר · יומן ביקורת.
- **פעולות:** שליחת קישור תשלום (מייל/וואטסאפ/SMS) · זיכוי לארנק · החזר כספי (מלא/חלקי) · ביטול/השהיה/חידוש
  מנוי · הוספת הנחה · קישור/ניתוק חשבונות · רישום תשלום ידני (מזומן/העברה/צ'ק — פרק 6) · הפקת מסמך ידני.
  כל פעולה כספית — **אישור כפול** (סכום + "בטוח?") וסיבה חובה.

### 🧾 כספים
- **תשלומים** — רשימה, סינון לפי סולק/אמצעי/מצב/תאריך; פרטי עסקה כולל מזהה אצל הסולק.
- **חשבוניות ומסמכים** — מספר, לקוח, סכום, מצב, מסמך חשבונאי (קישור ל-PDF), מספר הקצאה.
- **החזרים.**
- **התאמה** (פרק 9.5) — פערים פתוחים, סימון "טופל".
- **ייצוא** — CSV/Excel לרו"ח לפי חודש: תשלומים, מסמכים, מע"מ, פילוח לפי אפליקציה ולפי סולק (עמלות).

### 🧩 אפליקציות ומוצרים
- **אפליקציות:** ממתינות (אישור/דחייה, עם `key_url` ו-origins לבדיקה) · פעילות · מפתח, webhook, "שלח אירוע
  בדיקה", יומן קריאות (100 אחרונות, עם קוד תשובה) · מיתוג לדף התשלום (שם, לוגו, צבע).
- **מוצרים ומחירים** לכל אפליקציה: יצירה; מחיר חדש = גרסה; "העבר מנויים מגרסה X ל-Y" (עם הודעה ללקוחות —
  חובה בחוק לפני העלאת מחיר, פרק 10); `grants` (מה המוצר נותן: features/limits) בעורך פשוט.
- **קופונים.**
- **תצוגה מקדימה** — "איך נראית החשבונית" ללקוח דמיוני עם כמויות.

### ⚙️ הגדרות
- **העסק:** שם, ח"פ/ע"מ, סוג עוסק, כתובת, לוגו, מע"מ, מטבע.
- **סולקים:** כרטיס לכל חיבור (פרק 5) — מצב test/live, מפתחות (נשמרים מוצפנים, מוצגים חלקית), אמצעים
  שמופעלים דרכו, עדיפות, "בדיקת חיבור". אפשר כמה במקביל.
- **אמצעי תשלום:** מה מוצג ללקוח, לפי סוג תשלום (פרק 6, המטריצה).
- **חשבוניות:** ספק (פרק 7), מפתחות, סוג מסמך ברירת מחדל, מייל אוטומטי ללקוח.
- **מדיניות גבייה:** ימי חסד, לוח ניסיונות חוזרים, הודעות, תקרת טעינה אוטומטית.
- **תבניות הודעות:** מייל/SMS — קבלה, כשל, חידוש קרוב, כרטיס פג.
- **יומן ביקורת** — מי עשה מה ומתי (קריאה בלבד).

## 8.2 דף התשלום — `pay/?c=…` (ציבורי)

```
┌─────────────────────────────┐
│ [לוגו האפליקציה] מגדלור       │
│                             │
│ תכנית "אפליקציות"            │
│ 39 ₪ לחודש · כולל מע"מ       │
│ חיוב ראשון היום, ואז ב-23 לכל │
│ חודש. ביטול בכל עת.           │
│ ─────────────────────────── │
│ פרטי חשבונית ▾ (שם, ח"פ)     │
│ קוד הנחה ▸                   │
│ ─────────────────────────── │
│ [ 💳 כרטיס ] [ bit ] [ Pay ]  │ ← רק האמצעים שמתאימים (מנוי ≠ bit)
│ ┌─────────────────────────┐ │
│ │  iframe של הסולק         │ │ ← שדות הכרטיס אצל הסולק, לא אצלנו
│ └─────────────────────────┘ │
│ ☐ קראתי ואני מסכים לתנאים     │
│ 🔒 התשלום מאובטח ע"י <סולק>   │
└─────────────────────────────┘
```

- **מה מוצג לפי החוק במנוי** (פרק 10): מחיר, תדירות, מועד החיוב הבא, איך מבטלים, תקופת ניסיון ומה קורה בסופה.
- אמצעי תשלום מסוננים לפי `mode` ולפי המטריצה (פרק 6.3).
- תשלומים (קרדיט/תשלומים בכרטיס) — אם `installments_max` > 1.
- אחרי הצלחה: "✅ שולם" + מספר מסמך + חזרה לאפליקציה (אוטומטית תוך 3 שניות).
- כשל: הודעה מהסולק בעברית + "לנסות שוב" / "אמצעי אחר".
- נגיש: ניגודיות, גדלי מגע, תוויות, `lang="he" dir="rtl"`, עובד בלי JS כבד.

## 8.3 "החשבון שלי" — `portal/` (ציבורי, בסשן)

- **המנויים שלי** — לכל אפליקציה: תכנית, מחיר, חידוש הבא, "שדרוג/שנמוך", **"ביטול"** (בשני קליקים — חובה
  בחוק שהביטול יהיה פשוט כמו ההרשמה).
- **יתרה** — סכום, תנועות אחרונות, "טעינה", טעינה אוטומטית (הפעלה/סף/סכום).
- **אמצעי תשלום** — החלפה (דרך דף הסולק במצב `setup`), הסרה.
- **חשבוניות וקבלות** — הורדת PDF.
- **פרטי חשבונית** — שם, ח"פ, מייל לקבלות.
- **שימוש** — גרף פשוט לפי חודש, לכל מוצר נמדד.

## 8.4 רכיבים לאפליקציות (`payments.js`)

רכיבי UI קטנים, בלי לוגיקה כספית — רק תצוגה וקריאה לשרת **של האפליקציה**:

- `<pay-button product="…">` — "לתשלום" / "לשדרוג".
- `<pay-balance>` — "יתרה: 18.40 ₪ · טעינה".
- `<pay-paywall>` — מסך "הפיצ'ר הזה בתכנית פרו" עם השוואת תכניות מ-`catalog`.
- `<pay-status>` — פס עליון "התשלום האחרון נכשל — לעדכון כרטיס" (במצב `past_due`).

## 8.5 הודעות ללקוח

| מתי | ערוץ | תוכן |
| --- | --- | --- |
| תשלום הצליח | מייל | קבלה/חשבונית מצורפת |
| תשלום נכשל | מייל (+SMS ❓) | סיבה כללית + קישור לעדכון אמצעי |
| חידוש קרוב (מנוי שנתי) | מייל, 7–30 יום לפני | סכום ותאריך + קישור לביטול — **חובה בחוק** |
| סוף ניסיון | מייל, 3 ימים לפני | מה יחויב ומתי |
| כרטיס עומד לפוג | מייל, חודש לפני | קישור לעדכון |
| קרדיט נמוך / נגמר | מייל + webhook לאפליקציה (שתציג בעצמה) | |
| שינוי מחיר | מייל, לפי החוק לפני השינוי | |

השליחה: SMTP של השרת (כמו שאר הכלים) ❓ או ספק (Morning שולח את המסמך בעצמו).
