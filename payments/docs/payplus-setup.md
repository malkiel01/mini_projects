# חיבור פייפלוס — מדריך לבעל המערכת

> המחבר נבנה לפי התיעוד הרשמי של פייפלוס (‏`docs.payplus.co.il`, ‏REST v1.0). שמות השדות בתשובת הבדיקה (IPN) —
> לפי התוסף הרשמי שלהם לוורדפרס, כי התיעוד לא מפרט אותם. נבדק מול "פייפלוס מדומה" (`tests/payplus.php`).
> **עוד לא נבדק מול השרת האמיתי שלהם** — הבדיקה הראשונה: עם מפתחות מסביבת הבדיקות של פייפלוס.

## מה צריך

- חשבון בפייפלוס עם **גישה לממשק** (מפתח ממשק ומפתח סודי) ו**דף תשלום** אחד לפחות.
- כדי שחידוש מנוי יעבוד: **שמירת כרטיס (טוקן)** מופעלת בחשבון.
- לקבלה מפייפלוס: ‏**Invoice+** (או חברת חשבוניות) מחוברת אצלם. אין? "הקבלה ממורנינג", ומחברים גם מורנינג.
- ביט, אפל וגוגל — אם הופעלו בדף התשלום אצלם.

## שלב א — בדיקות

1. מבקשים מפייפלוס גישה ל**סביבת הבדיקות** (‏staging).
2. שם: הגדרות ← הגדרות API — **מפתח ממשק** ו**מפתח סודי**; דפי תשלום — **המזהה של הדף** (מזהה ארוך).
3. בתוסף: הגדרות ← העוסק ← "+ פייפלוס · בדיקות" ← שלושת השדות ← מי מפיק את הקבלה ← שמירה. התוסף בודק לבד.
4. כרטיס בדיקה של פייפלוס: ‏5326-1402-8077-9844, תוקף 05/30, ‏CVV 000 (עובר); ‏5326-1402-0001-0120 — נדחה.

## שלב ב — כסף אמיתי

אותו דבר עם המפתחות האמיתיים ו"+ פייפלוס · כסף אמיתי" (רק הבעלים), ואז "מאושרת לכסף אמיתי" בכל מערכת.
לפני שמפעילים ללקוחות — חיוב אמיתי של ₪1 והחזר שלו.

## איך התוסף יודע ששולם

ההודעה מפייפלוס חתומה, ובכל זאת היא רק מזרזת: התוסף **שואל את פייפלוס** (‏IPN) מה מצב הדף, ורק אם אושר בסכום
המדויק — הקנייה נסגרת. בחיוב חוזר אין בפייפלוס מפתח ייחודיות — לכן לפני כל ניסיון חוזר התוסף שואל אם ניסיון קודם
עם אותו מפתח כבר עבר, ולא מחייב פעמיים.
