# חיבור מורנינג — מדריך לבעל המערכת

## מה צריך

- חשבון במורנינג (חשבונית ירוקה) בתוכנית **"בסט" ומעלה** — רק בה יש גישה לממשק.
- סליקה פעילה במורנינג (הסליקה המובנית שלהם, או חברת סליקה שחוברה אליהם).
- כדי שחידוש מנוי יעבוד: **שמירת כרטיס** מופעלת בהגדרות הסליקה במורנינג.

## שלב א — בדיקות (בלי כסף אמיתי)

1. נרשמים לסביבת הניסוי של מורנינג למפתחים (מהעמוד הראשי של התיעוד שלהם למפתחים).
2. שם: כלי פיתוח ← מפתחות ממשק ← יצירה. מקבלים **מזהה** ו**סוד**.
3. בתוסף: הגדרות ← העוסק ← "+ מורנינג · בדיקות" ← להדביק את שניהם ← שמירה. התוסף בודק לבד ומציג ✓ או את השגיאה.
4. מומלץ: בממשק מורנינג ← כלי פיתוח ← וובהוקים ← הוספה: הכתובת מהתוסף (כפתור העתקה), האירועים "מסמך נוצר"
   ו"תשלום התקבל", וסוד — אותו סוד שמדביקים בתוסף בשדה "סוד ההודעות".
5. לנסות קנייה מאחת המערכות בסביבת הבדיקות.

## שלב ב — כסף אמיתי

אותו דבר, בחשבון האמיתי, עם "+ מורנינג · כסף אמיתי" (רק הבעלים). ואז, בכל מערכת שגובה: "מאושרת לכסף אמיתי".
לפני שמפעילים ללקוחות — תשלום אמיתי של ₪1 והחזר שלו (פרק 11, שלב 8).

## מה מורנינג עושה, ומה התוסף

| | מורנינג | התוסף |
| --- | --- | --- |
| דף התשלום, פרטי הכרטיס | ✓ | — |
| שמירת הכרטיס (טוקן) | ✓ | שומר רק את מזהה הטוקן ו-4 ספרות |
| חשבונית מס/קבלה (320) או קבלה לפטור (400), מספר הקצאה | ✓ עם כל תשלום | שומר את מספר המסמך |
| מנויים, חידוש, ניסיון, מבצעים, ארנק, שימוש, ביטול, הודעות לפי החוק | — | ✓ |
| החזר כספי וחשבונית זיכוי | ✓ בממשק שלהם | "רישום החזר" — מעדכן את התשלום ואת הלקוח |

## מגבלות של מורנינג, ואיך התוסף מתמודד

- **אין שמירת כרטיס בלי חיוב** → ניסיון חינם מתחיל בלי כרטיס; בסופו הלקוח מקבל מייל, ובעמוד "החשבון שלי" — "תשלום עכשיו".
  אותו דבר להחלפת כרטיס: נשמר בתשלום הבא.
- **אין החזר דרך הממשק** → ההחזר בממשק מורנינג, ובתוסף "רישום החזר".
- **ההודעה שבסוף התשלום לא חתומה** → התוסף לא סומך עליה: שואל את מורנינג אם נוצר מסמך באסמכתא ובסכום המדויק.
- **אין מפתח ייחודיות בחיוב** → לפני כל ניסיון חוזר התוסף בודק אם ניסיון קודם כבר עבר (מחפש את המסמך) — כדי לא לחייב פעמיים.
