# אפיון: הגדרות לפי אלמנט — מוצר ← עמודה ← קומה ← רכיב

> מסמך עבודה. כל שלב נבנה ב-PR נפרד, נבדק, ממוזג ונפרס לפני הבא.
> התחלה: ספרייה. אחריה ארון בגדים ומטבח, ואז העברה למתכונים.

## 1. הבעיה

ההגדרות של ספרייה מפוזרות היום על שבע שכבות, בשיטות שונות, בלי סדר עדיפויות
גלוי:

| שכבה | דוגמה |
| --- | --- |
| טופס, ברמת המוצר | `doorType`, `lowerDoors`, `glassColumns`, `lowerH`, כל קבוצת "ויטרינה" |
| עורך העמודות | רוחב, גובה, פיצול ומדפים לכל עמודה (`columnsLayout`) |
| כרטיס רכיב בתלת מימד | חומר, מידות, מיקום, ידית (`partEdits`) |
| גימור לכל לוח | `partFinishes`, מבנה נפרד |
| כיוון פתיחה | `doorOpen`, מבנה נפרד |
| סוג מוצר | ברירות מחדל לא גלויות |
| מעבדת המוצרים | ברירות מחדל ושדות מוסתרים |

התוצאה: הגדרות שסותרות זו את זו. דוגמה מפרויקט אמיתי:
- "פיצול 850" מוגדר לכל העמודות, ו"ויטרינה מלאה" מוגדרת לעמודה הראשונה.
- הוויטרינה גוברת בשקט, ועורך העמודות ממשיך להציג פיצול שלא נבנה.

## 2. העקרונות (הוכרעו עם המשתמש)

1. **היררכיה אחת:** מוצר ← עמודה ← קומה ← רכיב. לכל הגדרה בית אחד.
2. **כל אלמנט עצמאי לגמרי.** לכל עמודה, קומה ורכיב יש את כל הפרמטרים שלהם. אין
   הגדרה כללית שדורסת אלמנטים, כמו `glassColumns` היום.
3. **המערכת ממליצה ולא כופה.** אחרי שינוי באלמנט היא מציעה "להחיל גם על…".
   ההחלה היא **העתקה חד-פעמית**: אין קישור, ומכאן והלאה כל אלמנט עצמאי.
4. **קומות ללא הגבלה** בעמודה.
5. **קומה = חזית + תוכן**, שני צירים עצמאיים:
   - **חזית:** ללא / דלת עץ / ויטרינה.
   - **תוכן:** מדפים / מגירות / ריק.
   - לכן "מגירות מאחורי דלת ויטרינה" או "מגירות מאחורי דלת עץ" הן פשוט צירופים.
     מגירות בלי דלת הן מגירות עם חזיתות גלויות.
6. **כרטיס אחד, שני שערים.** אותו כרטיס אלמנט נפתח מהטופס (רשימת העמודות
   והקומות) ומהתלת מימד (הקשה על החלק).
7. **שום הגדרה לא מבוטלת בשקט.** הגדרה שלא בתוקף מסומנת "לא בתוקף, כי…".
8. **פרויקטים קיימים לא משתנים.** כל פרויקט מומר אוטומטית, ובדיקת זהות מוכיחה
   שהוא נבנה בדיוק כמו קודם.

## 3. מבנה הנתונים

### 3.1 מוצר (נשאר בטופס)

- **מידות חיצוניות:** `width`, `height`, `depth`.
- **מספר עמודות:** `columns`.
- **גוף:** `bodyMaterial`, `innerMaterial`, `backMaterial`, `edgeMaterial`.
- **דפנות חיצוניות:** `sideLeftFinish`/`Material`, `sideRightFinish`/`Material`.
- **סיומות:** `plinthH`, `plinthSetback`, `crownH`, `wheels`.
- **תאורה:** `led`. בשלב 7 אולי יעבור לעמודה.
- **חיבורים:** `sidesOverTop`, `backMode`, `backGrooveDepth`, `backInset`, `edgeMode`. עובי
  הדפנות והמדפים יגיע מהחומר (שלב 5).
- **`newUnit`:** תבנית לעמודה חדשה, כלומר מה מקבלת עמודה שנוספת כשמגדילים את
  `columns`. זו ברירת מחדל ליצירה בלבד, שלא נוגעת בעמודות קיימות.

### 3.2 עמודה — `values.units[i]`

```js
{
  width: null | mm,        // null = מתחלק בשווה במה שנשאר (כמו היום)
  height: null | mm,       // null = גובה המוצר
  floors: [ … ],           // מלמטה למעלה; לפחות קומה אחת
}
```

### 3.3 קומה — `units[i].floors[j]`

```js
{
  height: null | mm,       // null = מתחלק בשווה בגובה שנשאר בעמודה
  front: {
    type: 'none' | 'wood' | 'glass',
    leaves: 'auto' | 1 | 2,             // auto = לפי רוחב דלת מקסימלי (LIMITS.doorWidth)
    material, finish,                    // דלת עץ: חומר וגימור (חלק / סטריפים / CNC)
    glass,                               // ויטרינה: סוג הזכוכית
    vitrine: { frame, sides, frameW, profile, frameMaterial, mullions },   // כמו היום, לכל קומה
    hinge, handle,
    hingeSide: 'auto' | 'left' | 'right' | 'top' | 'bottom',
  },
  interior: {
    type: 'shelves' | 'drawers' | 'empty',
    shelves: { count, gaps: [mm | null…], material: 'same' | <לוח> | <זכוכית>, mode: 'adjustable' | 'fixed' },
    drawers: { count, heights: [mm | null…], frontMaterial, finish, slide, handle },
    // מגירה מאחורי דלת = מגירה פנימית: החזית שלה נסוגה מאחורי הדלת, בלי ידית חיצונית
  },
}
```

**גבול בין קומות:** מדף קבוע בעובי מדף, כמו מדף הפיצול היום.

### 3.4 רכיב — `values.overrides[partId]`

מאחד את שלושת המבנים של היום (`partEdits`, `partFinishes`, `doorOpen`) למבנה אחד:

```js
{ material, size, move, yaw, edges, finish, open, travel, hingeSide, handle, hidden }
```

### 3.5 מזהים יציבים

עריכה של רכיב נשמרת לפי המזהה שלו, ולכן המזהים חייבים להישאר יציבים:

| רכיב | מזהה | הערה |
| --- | --- | --- |
| דלת | `door-<עמודה>` (קומה אחת), `door-<עמודה>-lo` / `-up` (שתי קומות) | **תואם לישן** |
| דלת בקומה 3 ומעלה | `door-<עמודה>-f<קומה>` | חדש |
| שתי כנפיים | סיומת `a` / `b` | כמו היום |
| מדפים | `shelf-…`, `lo-shelf-…`, `up-shelf-…`, `split-shelf-…` | כמו היום, ובקומה 3 ומעלה `f<קומה>-shelf-…` |
| מגירות | `drawer-<עמודה>-<קומה>-<מספר>` | חדש |

## 4. כללי בנייה

1. כל עמודה נבנית לפי `units[i]` בלבד. אין שדות כלליים שדורסים אותה.
2. גבהי הקומות: נעוץ מקבל את ערכו, אוטומטי מתחלק בשווה (`resolveShares`, כמו היום).
3. דלת מכסה את הקומה שלה, וחצי מחיצה מכל צד, בדיוק כמו היום.
4. מגירות:
   - בקומה בלי חזית, חזיתות המגירות גלויות (`drawer()` הקיים).
   - בקומה עם דלת, המגירות פנימיות: החזית נסוגה, ואין ידית.
5. **"לא בתוקף":** המודל מחזיר `inactive: [{ path, reason }]`. לדוגמה, "ידית בקומה בלי
   חזית ובלי מגירות" או "שפרוסים בוויטרינה בלי מסגרת".

## 5. המלצות

**מנגנון במודל:** `suggest(values, change)` מחזיר רשימת הצעות. כל הצעה כוללת:
- `what`: פרמטר בודד, קבוצה (למשל "כל הוויטרינה"), או אלמנט שלם.
- `from`: האלמנט שממנו מעתיקים.
- `targets`: על מה אפשר להחיל.
- `text`: הנוסח שמוצג.

**סוגי הצעות:**

| סוג | מתי | דוגמה |
| --- | --- | --- |
| אחידות | אחרי שינוי, כשהאלמנט שונה עכשיו ממקביליו | "עמודה 1 בגובה 2400, השאר 2560. להשוות?" |
| שכפול | אחרי בניית קומה או עמודה | "להחיל את הוויטרינה הזו גם על: [כל העמודות] [2] [3] [הקיצוניות]" |
| מקצועיות | שילוב בעייתי, מוצג ליד השדה | "זכוכית 4 בלי מסגרת — כדאי מחוסמת 6", "דלת ברוחב 700 — כדאי 2 כנפיים" |

- **יעדים:** כולן, עמודות מסוימות, הקיצוניות, לסירוגין, או "אותה קומה בשאר העמודות".
- **"לא, תודה":** נשמר ב-`values.dismissed` לפי הפרמטר והאלמנט, וההצעה לא חוזרת.
- ההחלה היא **העתקה חד-פעמית**. אחרי ההעתקה אין שום קישור.

## 6. כרטיס האלמנט (ממשק)

- **כרטיס עמודה:** רוחב, גובה, ורשימת קומות (הוספה, מחיקה, הזזה למעלה ולמטה,
  שכפול). כל קומה נפתחת לכרטיס קומה.
- **כרטיס קומה:**
  - גובה.
  - **חזית:** סוג, ואחריו השדות של הסוג שנבחר.
  - **תוכן:** סוג, ואחריו השדות של הסוג שנבחר.
- **כרטיס רכיב:** החריגות של `values.overrides`, כמו כרטיס הרכיב בתלת מימד היום.
- **מצב כל שדה:** ערך רגיל, ↺ לחזרה לברירת המחדל, או "לא בתוקף, כי…".
- **שערים:**
  - בטופס, תחת "עמודות", רשימה של עמודה 1, עמודה 2 וכו', שכל אחת פותחת כרטיס.
  - בתלת מימד, הקשה על דלת או מדף פותחת את כרטיס הקומה שלהם. מתוכו אפשר לרדת
    לרכיב ("רק לדלת הזו") או לעלות לעמודה.
- **פריסה:** הכרטיס בנוי מאותם רכיבי שדה בכל המקומות, ובטלפון מתמזער כמו כרטיס
  הרכיב היום.

## 7. שלבים

| שלב | מה | בדיקה עיקרית |
| --- | --- | --- |
| **1. מודל והמרה** ✓ | `units` ו-`floors` כמבנה פנימי. `migrateUnits(values)` הופך כל פרויקט קיים למבנה החדש. הבנייה עוברת לקרוא רק את `units`. הממשק לא משתנה: הטופס הישן ממשיך לעבוד, וההמרה רצה על כל בנייה | בדיקת זהות: מאות תצורות אקראיות של הפרמטרים הישנים, ובכל אחת "בנייה ישנה" מול "המרה ואז בנייה חדשה" — זהות מלאה של חלקים, פרזול, אזהרות ומזהים |
| **2. יכולות חדשות במודל** ✓ | קומות ללא הגבלה. ויטרינה לכל קומה. מגירות כתוכן קומה (גלויות, או פנימיות מאחורי דלת). `values.overrides` מאחד את שלושת מבני הרכיב. `inactive` | בדיקות מודל לכל צירוף חזית×תוכן. 3 קומות ומעלה. מזהים יציבים |
| **3. כרטיס האלמנט** ✓ | כרטיסי עמודה, קומה ורכיב, שנפתחים מהטופס ומהתלת מימד. ברגע שיש לפרויקט `units`, השדות הכלליים הישנים של דלתות וויטרינה יוצאים מהטופס | דפדפן, מחשב וטלפון: הפרויקט מהצילום — עמודה 1 ויטרינה מלאה, 2–5 עץ ומעליו ויטרינה — נראה ונערך נכון |
| **4. המלצות** ✓ | `suggest()`: אחידות, שכפול ומקצועיות. "להחיל גם על…" בכרטיס. `dismissed` | בדיקות מודל להצעות. דפדפן: החלה על עמודות נבחרות |
| **5. ניקוי הטופס ועוביים** ✓ | הטופס נשאר עם פרמטרי המוצר ו-`newUnit`. עובי הדפנות והמדפים נגזר מהחומר (דריסה גלויה + אזהרה). ＋ עמודה / מחיקת עמודה בכרטיסים | בדיקת זהות לפרויקטים קיימים אחרי ההמרה |
| **6. ארון בגדים ומטבח** (ארון ✓, מטבח — בהמשך) | אותו מודל: יחידה ← קומה ← רכיב | בדיקת זהות לכל אחד |
| **7. מתכונים** | המודל החדש כאבן בניין במתכונים, והעברת הספרייה למתכון | בדיקת זהות |

## 8. מה נמחק כשדה כללי (מומר לכל עמודה וקומה)

| שדה ישן | לאן |
| --- | --- |
| `glassColumns` | עמודה עם קומה אחת שהחזית שלה ויטרינה |
| `lowerH` + `columnsLayout.cols[i].split` | גובה הקומה התחתונה בעמודה |
| `lowerDoors`, `doorType` | `front.type` של הקומה התחתונה והעליונה |
| `doorFinish`, `doorMaterial`, `glassType`, `hinge`, `handle` | `front` של כל קומה |
| `vitrine*` | `front.vitrine` של כל קומה |
| `shelvesPerColumn` + `cols[i].shelves/gaps` | `interior.shelves` של כל קומה |
| `vitrineShelves`, `vitrineShelfGlass` | `interior.shelves.material` |
| `shelvesMode` | `interior.shelves.mode` |
| `shelfMaterial` | `interior.shelves.material` (ברירת מחדל ב-`newUnit`) |
| `partEdits`, `partFinishes`, `doorOpen` | `values.overrides` |

עד שלב 3 השדות הישנים ממשיכים לעבוד. ההמרה רצה בכל בנייה, כך שאין שינוי
שנראה למשתמש עד שהכרטיס מוכן.
