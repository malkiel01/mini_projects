# ניהול פרויקטים — שיפוץ ובנייה

אפליקציה למנהל פרויקטים של שיפוץ ובנייה. היא מנהלת את הלקוח, את בעלי המקצוע
ואת הפרויקט עצמו: כל שלב, הצעות המחיר שלו, האישורים, התשלומים והתיעוד מהשטח.

> **מצב: אפיון — טיוטה לאישור.** שום קוד עוד לא נבנה. השאלות הפתוחות בסוף
> המסמך, תחת "מה טרם הוכרע".

## מי משתמש באפליקציה

| תפקיד | מי זה | איך נכנס | מה רואה ועושה |
| --- | --- | --- | --- |
| **מנהל** | אתה | הפלטפורמה (`mp_session`) | הכול |
| **מנהל פרויקט** | עובד שלך שמנהל פרויקטים בשטח | הפלטפורמה, עם אישור ישיר לאפליקציה | רק הפרויקטים שהוקצו לו. מדווח ביצוע, מעלה תמונות, מבקש הצעות |
| **לקוח** | בעל הדירה או הבית | **קישור אישי סודי**, בלי סיסמה | הפרויקט שלו בלבד: סטטוס, הצעות לאישור, דרישות תשלום, העלאת אסמכתאות, תמונות |
| **עורך דין של הלקוח** | עו"ד מטעם הלקוח | קישור אישי סודי | אותו פרויקט, עם אישור משפטי לשלבים שדורשים אותו |
| **ספק / בעל מקצוע** | אדריכלית, קבלן, חשמלאי, נגר, אלומיניום, גז… | קישור אישי סודי *(שלב מאוחר)* | רק השלבים שלו: העלאת הצעת מחיר, דרישת תשלום, אסמכתאות |

**למה קישור סודי ולא משתמש בפלטפורמה:** הפלטפורמה נועדה למשפחת האפליקציות שלך.
לקוח שמקבל שם משתמש יכול לקבל בטעות גישה לאפליקציות אחרות, וגם יצטרך לחכות
לאישור מנהל. קישור אישי עובד מיד בטלפון, אפשר לבטל אותו בכל רגע, והוא פותח רק
את הפרויקט של אותו אדם.

**המשמעות לשער:** האפליקציה נשארת `"gate": true` ו-`"restricted": true`. רק
תיקיית הפורטל (`portal/`) והקריאות שלה ל-API מתווספות ל-`"public"`, והן בודקות
בעצמן את האסימון שבקישור. פירוט ב"מבנה טכני".

## הישויות

### כרטיס ספק / בעל מקצוע

- שם, שם עסק, ח.פ. / ע.מ., טלפון, וואטסאפ, אימייל, כתובת
- **תחום** — אחד או יותר: אדריכלות, עיצוב פנים, קבלן ראשי, שלד, חשמל, אינסטלציה,
  גז, אלומיניום, נגרות, ריצוף, טיח, צבע, מיזוג, איטום, הנדסה, פיקוח… (רשימה
  שהמנהל עורך)
- פרטי בנק (לתשלום)
- מסמכים: רישיון, ביטוח צד ג', תעודת עוסק — **עם תאריך תפוגה ותזכורת**
- דירוג פנימי והערות
- היסטוריה: באילו פרויקטים עבד, כמה הצעות נתן, כמה שולם לו

### כרטיס לקוח

- שם, ת"ז, טלפון, אימייל, כתובת מגורים
- **עורך הדין שלו** — כרטיס משלו (שם, משרד, טלפון, אימייל), מקושר ללקוח
- אנשי קשר נוספים (בן/בת זוג) — אופציונלי
- הפרויקטים שלו, ומצב כספי מצטבר

### פרויקט

- שם, כתובת הנכס, סוג (שיפוץ / בנייה / תוספת), לקוח, עו"ד, מנהל פרויקט
- תאריך התחלה ויעד מסירה
- תקציב: סכום החוזה מול הצעות שאושרו מול מה ששולם
- רשימת **שלבים**
- "צוות הפרויקט" — אילו ספקים משויכים, לאיזה שלב

### שלב (הלב של האפליקציה)

כל שלב עובר מסלול קבוע:

```
מתוכנן → איסוף הצעות → ממתין לאישור לקוח → ממתין לאישור עו"ד → מאושר
       → בביצוע → בוצע (עם תיעוד) → שולם וסגור
```

- **תבנית שלבים:** פרויקט חדש נפתח מתבנית (למשל: תכנון ואדריכלות, היתרים,
  הריסה, שלד, אינסטלציה, חשמל, גז, איטום, טיח, ריצוף, אלומיניום, נגרות, צבע,
  ניקיון ומסירה). אפשר להוסיף, למחוק ולשנות סדר.
- לכל שלב: תחום, ספק נבחר, תאריכי תכנון וביצוע בפועל, ו**האם דורש אישור לקוח**
  ו/או **אישור עו"ד** (ברירת מחדל לפי התבנית).
- ההחלטה אם לדלג על אישור — של המנהל, ונרשמת ביומן.

### הצעת מחיר

- שייכת לשלב ולספק. סכום, מע"מ כלול או לא, תוקף, תנאי תשלום, קובץ (PDF / תמונה)
- כמה הצעות לאותו שלב → **השוואה** בטבלה
- המנהל ממליץ על הצעה, ומעביר ללקוח לאישור
- **הלקוח מאשר בפורטל**: רואה את ההצעה (או את כל ההצעות, לפי בחירת המנהל), לוחץ
  "מאשר" או "דוחה + הערה". אחריו — אם נדרש — עו"ד.
- כל אישור נשמר עם: מי, מתי, מאיזה קישור, כתובת IP ודפדפן, ו**צילום מצב של
  ההצעה כפי שאושרה** (אם ההצעה תשתנה אחר כך, האישור הישן לא עובר אליה).

### אבן דרך לתשלום

- שייכת לפרויקט ולרוב גם לשלב. סכום (או אחוז מהחוזה), תאריך יעד
- כיוון: **לקוח → (מנהל / ספק)** — ראו שאלה 3
- מסלול:

```
מתוכנן → נשלחה דרישת תשלום → הועלתה אסמכתא → אושר שהתקבל
```

- **דרישת תשלום:** המנהל לוחץ "שלח" — הלקוח מקבל הודעה עם קישור, ובפורטל רואה
  סכום, פרטי העברה ומה כלול.
- **אסמכתא:** הלקוח או העו"ד מעלים צילום העברה / צ'ק / אישור בנק, עם סכום ותאריך,
  ומסמנים "שולם".
- **אישור קבלה:** המנהל מאשר שהכסף נכנס. רק אז האבן נסגרת. תשלום חלקי — נשאר פתוח
  עם יתרה.
- **תשלומים לספקים** — אותו מנגנון בכיוון ההפוך: המנהל מעלה אסמכתא שהעביר.

### דיווח ביצוע

- המנהל או מנהל הפרויקט מסמנים שלב "בוצע" — **חובה לפחות תמונה אחת** (ניתן לשנות)
- תמונות וסרטונים ישירות מהמצלמה בטלפון, עם הערה ותאריך
- גם בלי לסגור שלב: "עדכון מהשטח" — יומן התקדמות עם תמונות
- הלקוח רואה בפורטל את מה שהמנהל סימן כ"גלוי ללקוח" (ברירת מחדל: הכול)

### יומן ותזכורות

- לוח שנה של כל הפרויקטים: שלבים מתוכננים, אבני דרך לתשלום, פגישות, ביקורים
- תזכורות אוטומטיות:
  - אבן דרך לתשלום מתקרבת / עברה
  - הצעה שממתינה לאישור לקוח / עו"ד יותר מ-X ימים
  - שלב שהיה אמור להתחיל ולא התחיל, או להסתיים ולא הסתיים
  - הצעת מחיר שתוקפה פג; ביטוח של ספק שפג
- ערוץ התזכורות — ראו שאלה 5

### היסטוריה (יומן ביקורת)

כל פעולה בעלת משמעות כספית או משפטית נרשמת ולא נמחקת: יצירה ושינוי הצעה,
אישור, דחייה, דרישת תשלום, אסמכתא, אישור קבלה, סימון ביצוע. **מחיקה היא סימון
"בוטל", לא מחיקה פיזית.** זה מה שיעזור במחלוקת עם לקוח או ספק.

## מסכים

**ממשק המנהל (מאחורי השער):**

1. **לוח בקרה** — מה דורש פעולה היום: אישורים תקועים, תשלומים באיחור, שלבים
   באיחור, אסמכתאות שממתינות לאישור
2. **פרויקטים** — רשימה וכרטיס פרויקט: ציר שלבים, כספים, תמונות, יומן
3. **שלב** — הצעות, השוואה, אישורים, דיווחי ביצוע
4. **ספקים** ו**לקוחות** — כרטיסים, חיפוש, סינון לפי תחום
5. **יומן** — חודש / שבוע / רשימה
6. **כספים** — לכל פרויקט: חוזה, אושר, נדרש, שולם, יתרה
7. **הגדרות** — תבניות שלבים, תחומים, פרטי חשבון בנק להעברות, ערוצי הודעות

**הפורטל (קישור סודי):**

- לקוח / עו"ד: מצב הפרויקט באחוזים ובציר שלבים, "ממתין לאישורך", דרישות תשלום
  ואסמכתאות, גלריה מהשטח, מסמכים
- מותאם קודם כול לטלפון. בלי כניסה, בלי סיסמה.

## מבנה טכני

```
project-manager/
  app.json          gate + restricted; public = הפורטל בלבד
  index.html        ממשק המנהל (SPA)
  api.php           API של המנהל — מזהה משתמש מהפלטפורמה
  portal/
    index.html      הפורטל
    api.php         API של הפורטל — בודק אסימון מהקישור
  lib/              db.php, auth.php, files.php, notify.php
  cron.php          תזכורות (מורץ מ-cron של השרת עם מפתח)
  data/             .htaccess: Deny all
    pm.sqlite
    files/          הצעות, אסמכתאות, מסמכים
    media/          תמונות וסרטונים מהשטח
```

- **זהות המנהל:** קריאה בלבד מ-`platform/data/platform.sqlite` דרך העוגייה
  `mp_session`, בלי מערכת כניסה נפרדת. מנהל הפלטפורמה = מנהל כאן. משתמש פעיל
  אחר שקיבל גישה = מנהל פרויקט, ורואה רק את הפרויקטים שהוקצו לו.
- **אסימוני פורטל:** 32 בתים אקראיים, נשמרים כ-hash. לכל אחד: איש קשר, פרויקט,
  תפקיד, תאריך ביטול. אפשר לייצר מחדש קישור (הישן מת).
- **קבצים** לא נגישים ישירות — מוגשים דרך `api.php` אחרי בדיקת הרשאה.
- **תמונות** מוקטנות בדפדפן לפני העלאה. **סרטונים** — מגבלת גודל לפי מה שהשרת
  מרשה (ייבדק בשלב 6).
- **`public` ב-`app.json`** (משלב 4): `portal/`, `portal/**`, `portal/api.php`,
  `cron.php`. כל אחד מהם בודק אסימון בעצמו.
- **`deploy.yml`:** `--exclude='project-manager/data/*.sqlite*'`,
  `project-manager/data/files/`, `project-manager/data/media/`,
  `project-manager/data/config.json` — **באותו PR שיוצר את המסד**.

## מה טרם הוכרע

1. **מנהלי פרויקט:** רק אתה, או גם עובדים נוספים (כל אחד רואה את הפרויקטים שלו)?
2. **ספקים בפורטל:** האם ספקים צריכים גישה (להעלות הצעות ודרישות תשלום בעצמם),
   או שאתה מעלה הכול עבורם?
3. **זרימת הכסף:** הלקוח משלם **לך** ואתה משלם לספקים, או משלם **ישירות לכל
   ספק** ואתה רק עוקב? (או שניהם — לפי שלב)
4. **תשלום מקוון:** מספיקה העברה בנקאית + העלאת אסמכתא, או שצריך גם סליקה
   (אשראי / ביט)?
5. **ערוץ הודעות** ללקוח ולעו"ד: אימייל, וואטסאפ (קישור "שלח בוואטסאפ" שאתה
   לוחץ — או שליחה אוטומטית דרך ספק בתשלום), או SMS?
6. **אישור לקוח:** לחיצה על "מאשר" מספיקה, או נדרשת חתימה ביד על המסך?
7. **עו"ד:** אישור עו"ד נדרש בכל שלב, רק בשלבים מסוימים, או מעל סכום מסוים?
8. **חשבוניות:** האפליקציה רק מתעדת, או צריכה להפיק קבלות / חשבוניות (זה מחייב
   תוכנה מאושרת או חיבור לחשבונית ירוקה / iCount וכד')?
9. **מע"מ:** הסכומים נשמרים כולל או לפני מע"מ?
10. **סרטונים:** כמה ארוכים בערך? (משפיע על אחסון ועל מגבלת ההעלאה בשרת)
11. **הלקוח רואה הצעות מחיר של ספקים** — את כולן, רק את זו שנבחרה, או רק מחיר
    סופי שלך ללקוח (עם רווח שלך שהלקוח לא רואה)?
12. **`public` לפורטל:** אישור להוסיף את `portal/` ל-`"public"`. האפליקציה עצמה
    נשארת חסומה ו-`restricted`.

## גישה
