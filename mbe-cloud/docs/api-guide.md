# ענן MBE — מדריך החיבור וה-API

**לכל אפליקציה שרוצה להתחבר לענן MBE.** זה המסמך שנותנים לצ'אט של אפליקציה חדשה, עם ההנחיה "תתחברי לפי זה".
**זה מקור האמת:** כל שינוי ב-API של הענן או במודול הכוננים מעדכן את המדריך הזה באותו PR.

> עודכן: 2026-11-08 · הענן: `https://mbe-plus.com/mini_projects/mbe-cloud/` · מודול הכוננים: `mbe-cloud/drives/`
> סימון: ✅ קיים ונפרס · 🛠️ שלב 2, בבנייה (`spec-2-share-token.md`) · 🗓️ מתוכנן (`spec-0-vision.md` סעיף 9)

---

## 1. הכלל: שיטת חיבור אחת

**כל אפליקציה מתחברת לענן בדרך אחת בלבד:** מודול הכוננים (`drives/`), עם מתג "ענן MBE" אצל המשתמש. המודול כבר מבצע
את כל הצעדים: רישום, `connect.php`, החלפת קוד חתומה, ואסימון קצר לדפדפן. אסור לכתוב לקוח משלכם, אסור להעתיק את הקוד
ולשנות אותו, ואסור להחזיק בשרת שלכם סיסמה, מפתח או אסימון ארוך של הענן.

| מי | איך מתחבר | מה מקבל |
| --- | --- | --- |
| **אפליקציה, בשם משתמש שלה** | מודול הכוננים: המשתמש מאשר פעם אחת ב-`connect.php` | חיבור (`connection`) שנשמר אצל האפליקציה, ואסימון לדפדפן ל-15 דקות |
| **צ'אט של Claude בלי מסך** — **החריג היחיד** (סעיף 7) | מפתח קריאה (`mbe_pat_…`) שמנהל הענן יוצר | קריאה בלבד של מה ששותף עם חשבון השירות שלו |

**מפתח הקריאה אינו דרך חיבור של אפליקציה.** אפליקציה שמבקשת `mbe_pat_` תקבל סירוב. לאפליקציה יש מסך, ולכן היא
מתחברת דרך המתג.

**האפליקציה נשארת עצמאית** (`CLAUDE.md`, "אפליקציה פנימית עצמאית"). המשתמשים, המסד והעוגייה נשארים שלה. הענן לא יודע
את ה-`id` של המשתמש אצלה. הוא מקבל רק את ה-`sub` של הפלטפורמה, כדי לוודא שזה אותו אדם (סעיף 2). האפליקציה שומרת רק "המשתמש
שלי X מחובר לחיבור `c_…`". בלי ענן, כל האפליקציה עובדת כמו קודם.

## 2. איך זה עובד

```
 הדפדפן של האפליקציה          השרת של האפליקציה (Drives.php)                  ענן MBE
 ───────────────────          ───────────────────────────────                  ───────
 drives.connect() ─────────▶  drives_connect: רישום (פעם אחת) + state ─────▶  client_register
          ◀── url ──────────
 ניווט ────────────────────────────────────────────────────────────────────▶  connect.php?client&scope&state&return
                                                                                המשתמש מאשר (נכנס דרך השער אם צריך)
          ◀──────────────────────────────── 303 ‹return›?code&state ──────────
 ─────────────────────────▶  drives_callback: בודק state, ──── חתום ──────▶  connect_exchange {code}
                              שומר connection ליד המשתמש     ◀── connection, account.name, scope, cloud_id
          ◀── 303 ‹back›?cloud=connected
 drives.suite.list() ──────▶  drives_token ─────────────────── חתום ──────▶  access_token {connection}
          ◀── token (15 דק'), api ◀──────────────────────────────────────────
 ──────── X-Cloud-Token: <token> ─────────────────────────────────────────▶  api.php?action=list …  (CORS לפי origin)
```

- **שרת-לשרת = חתימה.** לאפליקציה זוג מפתחות Ed25519 משלה, שנוצר אוטומטית במסד שלה. הענן מוריד את המפתח הציבורי
  מ-`drives_key`, ואת המפתח הפרטי הענן לעולם לא רואה.
- **לדפדפן = אסימון קצר.** 15 דקות, בזיכרון בלבד (לא `localStorage`), ומתחדש לבד.
- **רק אותו חשבון** (הכרעת בעל המערכת, 2026-11-08; `spec-0-vision.md` סעיף 6.3). המודול שולח את ה-`sub` של הפלטפורמה
  של המשתמש שלכם, והענן משווה אותו לחשבון שנכנס לענן, בשלוש נקודות:
  - **במסך האישור** (`connect.php`): ה-`sub` חתום במפתח של האפליקציה. אם הוא שונה ממי שנכנס לענן, מוצג "החיבור נדחה: החשבון באפליקציה אינו החשבון שלך", **בלי כפתור אישור**.
  - **ב-`connect_exchange`**.
  - **בכל `access_token`**.

  אי-התאמה, או `sub` חסר, מחזירה `403 account_mismatch`, והחיבור לא נוצר. **אדם אחד לא מתחבר לעולם לענן של אדם אחר**,
  ואין לזה עקיפה, גם לא למנהל.
- **ניתוק נבדק בכל קריאה,** בצד של הענן. גם אסימון שעוד לא פג נדחה מיד אחרי ניתוק.

## 3. ההצטרפות — מה משנים אצלכם

**PR אחד, בתיקייה שלכם, ועוד שורה אחת ב-`mbe-cloud/drives/apps.json`.** לא נוגעים בשום קובץ אחר של הענן.

### 3.1 העותק של המודול

1. שורה ב-`mbe-cloud/drives/apps.json`, לפי סדר א"ב. לפני ה-PR ממזגים את `main`:
   ```json
   "my-app": { "js": "assets/js/drives", "php": "lib/drives",
               "layers": ["files", "libs"], "files_scope": "files.app" }
   ```
   הנתיבים הם יחסיים לתיקייה של האפליקציה. כל אחד מהם הוא תיקייה שכולה של המודול.
   🛠️ **`layers`** הן השכבות שהאפליקציה תומכת בהן (סעיף 4): `files`, `libs`, `appdata`, `ai`. **`files_scope`** הוא
   ההיקף של שכבת הקבצים: `files`, `files.readonly` או `files.app`. בלי `layers`, ברירת המחדל היא `["files","libs","ai"]`
   ו-`files`, כמו היום.
2. `php mbe-cloud/drives/tools/sync.php` מעתיק את `drives.js` ואת `Drives.php` לשם.
3. **לא עורכים את העותק.** השער בפריסה (`sync.php --check`) עוצר עותק ששונה. צריך שינוי? מבקשים אותו מצ'אט הקוד של
   הענן, והוא משנה במקור.

### 3.2 השרת — שלוש שורות ב-`api.php` שלכם, לפני הטיפול הרגיל בפעולות

```php
require_once __DIR__ . '/lib/drives/Drives.php';
if (str_starts_with($action, 'drives_')) (new \SuiteCloud\Drives([
    'client'   => 'my-app',                                        // = ה-id ב-app.json, ושם התיקייה
    'name'     => 'האפליקציה שלי',                                  // מה שהמשתמש רואה במסך האישור בענן
    'dataDir'  => __DIR__ . '/data',                               // שם נוצר drives.sqlite
    'endpoint' => 'https://mbe-plus.com/mini_projects/my-app/api.php',   // כתובת מלאה ב-https
    'user'     => fn() => ($u = currentUser()) ? (string) $u['id'] : null,  // המשתמש שלכם. null = לא מחובר
    // 'sub'   => fn(string $user) => ?string,                     // לא חובה. ברירת המחדל: ה-sub מ-PLATFORM_USER של השער
    'back'     => 'https://mbe-plus.com/mini_projects/my-app/',   // לאן חוזרים אחרי האישור
]))->serve($action);
```

- **שם המחלקה `\SuiteCloud\Drives`** נשאר מהשם הקודם של הענן. הוא לא משתנה, כדי שעותקים קיימים לא יישברו.
- **`sub`** — **ה-`sub` עצמו חובה. בלעדיו אין חיבור. המפתח בהגדרות — לא חובה.**
  - **ברירת המחדל:** המודול לוקח את ה-`sub` מ-`$_SERVER['PLATFORM_USER']`, שהשער כותב לכל בקשה של אפליקציה עם `"gate": true`. לכן אפליקציה רגילה **לא צריכה שום שורה**.
  - **מתי מגדירים אותו:** רק באפליקציה שמנהלת את הקישור בעצמה. מחזיר את ה-`sub` שכל חשבון אפליקציה מקושר אליו (`platform/docs/auth.md` סעיף 4), או `null`.
  - **בלי `sub`:** למשל חשבון ישן בסיסמה, שעוד לא קושר, או אפליקציה מנותקת מהשער. אין הפניה לענן: `drives_connect` מחזיר `403 no_platform_account` עם ההודעה "כדי להתחבר לענן, קשרו קודם את החשבון לחשבון הפלטפורמה".
- **`user`** מחזיר את המזהה **שלכם**. הענן לא מקבל אותו לעולם. הוא רק נשמר אצלכם בטבלה `conns`.
- **אפליקציה בדומיין אחר:** אותו קוד. `endpoint` ו-`back` הם בכתובת שלכם, וה-origin שלכם נרשם אוטומטית ל-CORS.
  **רישום מ-origin שאינו `mbe-plus.com` נכנס ל-`pending`** עד שמנהל הענן מאשר (⚙️ ניהול ← לקוחות).

### 3.3 `app.json`

אם האפליקציה מאחורי השער (`"gate": true`), מוסיפים ל-`public`:

```json
"public": ["api.php?action=drives_key"]
```

הענן מוריד משם את המפתח הציבורי שרת-לשרת, בלי עוגייה. **זו הכתובת היחידה שצריך לפתוח.** כל שאר הפעולות `drives_*`
נקראות מהדפדפן שלכם עם העוגייה שלכם.

### 3.4 `deploy.yml` — הנתונים לא נדרסים

`<dataDir>/drives.sqlite*` מחזיק את **המפתח הפרטי** של האפליקציה ואת החיבורים של המשתמשים. הוא חייב להיות מוחרג
**לפני הפריסה הראשונה**:

- כבר מחריגים את `my-app/data/*`, או תיקייה שמכילה אותו? אין מה להוסיף. כך עשה `greeting-cards`, עם `data/studio/`.
- אחרת, שורה אחת: `--exclude='my-app/data/drives.sqlite*'`.
- **מפתח שנדרס = כל המשתמשים מנותקים.** הענן לא מכיר את המפתח החדש, ולכן המודול נרשם מחדש ונכנס ל-`pending` אם השתנה
  משהו. זה תיקון ידני.

**בתיקייה שלכם, אף פעם לא בגיט:** `drives.sqlite`. אין שום סוד אחר של הענן אצלכם.

### 3.5 הדפדפן

```js
import { createDrives } from './drives/drives.js';
const drives = createDrives({ endpoint: 'api.php' });     // ה-api.php שלכם, שם רץ Drives.php
```

הממשק המלא כתוב בראש `drives.js`. סעיף 5 כאן מפרט את הפעולות.

## 4. המתגים — מתג לכל שכבה, אותו דבר בכל אפליקציה

🛠️ **הכרעת בעל המערכת (2026-11-08):** החיבור אחד, ולכל שכבה מתג משלה (`spec-0-vision.md` סעיף 7.3). אפליקציה יכולה
להתחבר לשכבה אחת בלבד, למשל רק לקבצים, או לכולן.

**איפה:** בתפריט המשתמש (👤) של `ui-core` ← "☁️ עננים מחוברים". אפליקציה בלי `ui-core` מציגה אותו מבנה בדיוק בהגדרות
שלה. אין כפתורי "התחבר לענן" במקומות אחרים.

```
☁️ ענן MBE                       מחובר כ-דנה        ← כותרת. בלי חיבור: "לא מחובר"
   📁 קבצים                                 [●━]
   📚 נתוני מערכת · גופנים, צבעים, תבניות     [━○]
   🗂️ נתוני משתמש · ההגדרות והנתונים שלך כאן  [━○]
   🤖 בינה מלאכותית ⏳                        [●━]
```

- **מוצגות רק השכבות ש-`layers` מצהיר עליהן** (סעיף 3.1). אפליקציה עם שכבה אחת מציגה שורה אחת.
- **🤖 בינה מלאכותית** כמתג רביעי ממתינה להכרעת בעל המערכת. עד ההכרעה היא כתובה כאן כמתג רביעי.

| מצב | מה מציגים | `drives.status()` |
| --- | --- | --- |
| **לא מחובר** | הכותרת: "לא מחובר" · כל המתגים כבויים | `suite.connected === false` |
| **מחובר** | הכותרת: `suite.name` · כל מתג לפי ההיקפים של החיבור | `suite.layers` → `{files: true, libs: false, …}` |
| **שגיאה** | המתגים כבויים · שורה באדום: ההודעה, ו"נסו שוב" | `status()` זרק `DriveError` |
| **פעולה שצריכה שכבה כבויה** | "הפעולה הזו דורשת 📚 נתוני מערכת מענן MBE" · "הפעל" (פותח את התפריט על השורה הזו) | `DriveError` עם `code: 'layer-off'` ו-`layer`, או `'not-connected'` |

**הדלקת מתג:** `await drives.connect({ layers: ['libs'] })`. הדפדפן עובר למסך האישור בענן.
- **בחיבור ראשון:** המסך מפרט כל שכבה שנבחרה, למשל "<שם האפליקציה> מבקשת גישה ל: 📁 קבצים · 📚 נתוני מערכת".
- **בחיבור קיים:** המסך מציג רק את השכבה החדשה, והיא מתווספת **לאותו חיבור**.
- **בחזרה:** חוזרים ל-`back` עם פרמטר בכתובת:

| בכתובת | מה מציגים | אחרי זה |
| --- | --- | --- |
| `?cloud=connected` | הודעה קצרה (toast): "☁️ 📚 נתוני מערכת מחוברים" | מוחקים את הפרמטר מהכתובת (`history.replaceState`), ומרעננים את `status()` |
| `?cloud=denied` | הודעה: "לא אושר" | מוחקים את הפרמטר. המתג נשאר כבוי |
| `?cloud=error` | דף השגיאה של המודול, עם "חזרה לאפליקציה" | — |

**כיבוי מתג:** `await drives.disconnect({ layers: ['libs'] })`. השכבה נכבית מיד, בלי שאלה, כי היא מסירה רק הרשאה, ואפשר
להדליק אותה שוב. **כיבוי של המתג האחרון = ניתוק**, ולפניו שאלה אחת: "לנתק את ענן MBE? הקבצים והנתונים נשארים בענן,
ואפשר לחבר שוב בכל רגע." `drives.disconnect()` בלי `layers` מנתק הכול. **כיבוי וניתוק לא מוחקים שום דבר**, לא בענן
ולא אצלכם.

**כיבוי מהצד של הענן** (מתג בדף הענן, ב"🔗 חיבורים"): הקריאה הבאה לשכבה הזו מחזירה `layer-off`, וכיבוי של הכול מחזיר
`not-connected`. בפתיחה הבאה של התפריט המתגים מעודכנים, בלי שום קוד נוסף.

**הגירה:** חיבור קיים מקבל את השכבות של ההיקפים שיש לו היום (`files`, `libs`, `ai`), והמתגים שלהן מוצגים דלוקים.

**באפליקציית אנדרואיד (APK):** `connect.php` הוא כתובת מחוץ לתיקייה שלכם, ולכן הוא נפתח בדפדפן החיצוני (`CLAUDE.md`).
- **החזרה:** החזרה ל-`drives_callback` מגיעה לשם, **בלי** העוגייה של האפליקציה. המודול משלים את החיבור למשתמש שה-`state` נוצר בשבילו.
- **למה זה בטוח:** הענן כבר וידא שמי שאישר הוא אותו חשבון פלטפורמה (סעיף 2).
- **מה רואה המשתמש:** דף "החיבור לענן הושלם" וכפתור "חזרה לאפליקציה". באפליקציה עצמה לא צריך שום דבר.

## 5. הפעולות

### 5.1 בדפדפן, דרך המודול (הדרך הרגילה)

| קבוצה | פעולות | היקף |
| --- | --- | --- |
| **חיבור** ✅ | `status()`, `connect({layers?})` 🛠️, `disconnect({layers?})` 🛠️, `list()` (כל הכוננים) | — |
| **קבצים** ✅ `drives.suite` | `list(folder?)`, `stat(id)`, `read(id)` → `Blob`, `write(name, blob, {parent, ifRev, onConflict})` (עד 4MB), `upload(file, {parent, ifRev, onConflict, onProgress, signal})` (בחלקים של 8MB, כל גודל), `mkdir(name, parent?)`, `rename(id, name)`, `move(id, parent)`, `trash(id)`, `quota()` | `files` |
| **גופנים** ✅ `drives.fonts` | `list({builtin?})`, `load(item)` → `{face, bytes}`, `add(file, {family, weight, style})`, `license(item)` | `libs` |
| **בינה מלאכותית** ✅ `drives.ai` | `capabilities()`, `run(task, input, {signal})`. המשימות: `remove-background`, `segment`, `generate-image`, `inpaint`, `complete` | `ai` |
| **Dropbox** ✅ `drives.dropbox` | אותן פעולות כמו `suite`. הדפדפן מדבר עם Dropbox ישירות | — (חיבור נפרד: `link('dropbox')`) |
| **נתוני אפליקציה** 🗓️ `drives.appdata` | `get`, `put` (`ifRev`), `delete`, `list`, `changes(since)`, במרחבים `user` ו-`app` | `appdata` |
| **העדפות משותפות** 🗓️ `drives.prefs` | שפה, ערכת תצוגה, יחידות, שם תצוגה | `prefs` |

**`ifRev`** פירושו "שמור רק אם הקובץ לא השתנה מאז שקראתי". אם הוא השתנה, חוזרת השגיאה `conflict` עם ה-`rev` הנוכחי,
והאפליקציה מציעה "שמור כעותק". כך שתי אפליקציות לא דורסות זו את זו בשקט.

**`node`** = `{id, kind: 'folder'|'file', name, parent, size, sha256, mime, rev, created_at, updated_at, updated_by: {name, app}}`.
ה-`id` נשאר יציב גם אחרי שינוי שם או העברה, ולכן שומרים אותו ולא את הנתיב.

### 5.2 ה-API של הענן, למי שקורא לו ישירות

`POST https://mbe-plus.com/mini_projects/mbe-cloud/api.php?action=<פעולה>` עם גוף JSON. חריגים: `read` ו-`font_file`
הם `GET`, ו-`upload_chunk` הוא `PUT` עם גוף בינארי. **כל שגיאה היא JSON** (סעיף 8).

| פעולה | מי קורא | מה |
| --- | --- | --- |
| `cloud_key` | כל אחד | המפתח הציבורי של הענן, לאימות האסימונים |
| `client_register` | שרת האפליקציה | `{client, name, key_url, origins, return}` → `{status: active\|pending}`. שינוי ב-`key_url`, ב-`origins` או ב-`return` מחזיר את הלקוח ל-`pending` |
| `connect.php` (דף) | דפדפן המשתמש | `?client&scope&state&return&sub&exp&sig` (`sub` חובה; `exp` עד 10 דקות קדימה; ה-`state` חד-פעמי גם בענן; `sig` = Ed25519 של הלקוח על `"connect\n<client>\n<state>\n<sub>\n<exp>\n<return>"`, `kid.base64url`) → מסך אישור, או "החיבור נדחה" וחזרה עם `?error=account_mismatch` → `‹return›?code&state` (הקוד תקף 2 דקות, פעם אחת), או `?error=access_denied` |
| `connect_exchange` | שרת, חתום | `{code, sub}` → `{connection, account: {name}, scope, cloud_id}`. `sub` שלא תואם את מה שנחתם במסך, או את החשבון שאישר, מחזיר `403 account_mismatch`, והקוד נשרף |
| `access_token` | שרת, חתום | `{connection, sub}` → `{token, expires_in: 900}`. נבדק בכל פעם (`403 account_mismatch`). **חיבור מלפני הכלל, בלי `sub`:** אם הוא תואם — נרשם על החיבור. אם הוא שונה — אין אסימון, החיבור מסומן ומופיע בניהול (⚙️ ← לקוחות, "⚠️ לא אותו חשבון"), ולא מנותק אוטומטית |
| `disconnect` | שרת, חתום | `{connection}` → `{ok}` |
| `quota`, `list`, `stat`, `read`, `mkdir`, `write`, `upload_start`, `upload_chunk`, `upload_finish`, `rename`, `move`, `trash`, `restore`, `trash_list`, `purge`, `trash_empty` | דפדפן (אסימון) או שרת (חתום) | הקבצים. הגופים בטבלה של `spec-1-skeleton.md` סעיף 6 |
| `fonts_list`, `font_file`, `font_add`, `font_update`, `font_delete`, `font_license` | כנ"ל | הגופנים (`spec-2-fonts.md` סעיף 4) |
| `ai_capabilities`, `ai_run` | כנ"ל | הבינה המלאכותית (`spec-3-ai.md` סעיף 4) |
| `drives_config` | שרת, חתום | הגדרות הכוננים החיצוניים (App key של Dropbox) |

**החתימה, שרת-לשרת:**

```
X-Cloud-Client:     my-app
X-Cloud-Time:       <unix seconds>                 — סטייה של עד ±300 שניות
X-Cloud-Nonce:      <16–64 תווי hex>               — לא חוזר בתוך 10 דקות
X-Cloud-Signature:  <kid>.<base64(Ed25519(msg))>
X-Cloud-Connection: c_…                            — בפעולות בשם משתמש
msg = "<action>\n<time>\n<nonce>\n<sha256(hex) של הגוף>"
```

**האסימון, מהדפדפן:** `X-Cloud-Token: <token>` או `Authorization: Bearer <token>`. המודול שולח `X-Cloud-Token`, כי שרתים
בדרך מורידים לפעמים את `Authorization`. **CORS** פתוח רק ל-`origins` שנרשמו, ובלי עוגיות.

### 6.2 הכללים

- **מצהירים רק על מה שצריך** ב-`layers` (סעיף 3.1). הענן דוחה בקשה להיקף של שכבה שלא הוצהרה (`bad_request`).
- **שכבה נוספת = אישור נוסף, באותו חיבור.** המסך מציג רק את השכבה החדשה.
- **כל פעולה בודקת את ההיקף של השכבה שלה.** בלעדיו חוזר `403 forbidden` עם `{"scope": "…"}`, והמודול מתרגם אותו ל-`layer-off`.
- **אפליקציה מחוץ לחבילת היצירה שמבקשת `files`** נכנסת ל-`pending` עד שמנהל הענן מאשר (הכרעה 5). כשיהיה `files.app`
  (שלב 3), הוא יהיה ברירת המחדל לאפליקציה חדשה.

## 8. שגיאות

**כל שגיאה:** `Content-Type: application/json` וגוף `{"error":"<הודעה בעברית למשתמש>","code":"<קוד>"}`, לפעמים עם
שדות נוספים, למשל `rev` ב-`conflict`. **מחליטים לפי `code`, לא לפי ההודעה.** ההודעה מיועדת למשתמש ועשויה להשתנות.
אף פעם לא מוחזר דף HTML. היוצא מן הכלל הוא ניווט של דפדפן (`connect.php`, `drives_callback`), שבו מוצג דף.

| HTTP | `code` | מתי | מה עושים |
| --- | --- | --- | --- |
| 400 / 422 | `bad_request`, `bad_name`, `bad_checksum` | גוף, שם או סכום ביקורת לא תקינים | לתקן את הבקשה |
| 400 | `moved` | בקשה עם אסימון לכתובת הישנה `suite-cloud/` | לשלוח לכתובת שבשדה `use` |
| 400 | `token_in_url` | אסימון ב-`?token=` או `?access_token=` | לשלוח רק בכותרת `Authorization` |
| 401 | `unauthorized` | אין זהות: בלי אסימון, בלי חתימה ובלי עוגייה, או מפתח קריאה לא תקף | להתחבר. המודול מתרגם את זה ל-`not-connected` |
| 401 | `bad_token`, `expired` | האסימון של הדפדפן לא תקף או פג | המודול מבקש אסימון חדש ומנסה שוב, פעם אחת |
| 401 | `disconnected` | המשתמש ניתק בענן | המודול מוחק את החיבור, והמתג כבוי |
| 401 | `stale`, `replay`, `bad_signature`, `unknown_client`, `pending` | בעיה בחתימה או ברישום | המודול נרשם מחדש. `pending` = מחכים לאישור של מנהל הענן |
| 400 | `bad_identity` | `connect.php` בלי `sub`, בלי חתימה תקינה, או עם `exp` שפג | גרסה ישנה של המודול — לסנכרן (`sync.php`) |
| 403 | `no_platform_account` | למשתמש באפליקציה אין `sub` של הפלטפורמה | "כדי להתחבר לענן, קשרו קודם את החשבון לחשבון הפלטפורמה" |
| 403 | `account_mismatch` | המשתמש באפליקציה והמשתמש בענן הם לא אותו חשבון פלטפורמה | הודעה: "החשבון בענן שונה מהחשבון שלך כאן. היכנסו לענן באותו חשבון". אין עקיפה |
| 403 | `forbidden` | אין היקף מתאים (השכבה כבויה; מוחזר גם `scope`), או מפתח קריאה בפעולה שאינה קריאה | להציע להדליק את המתג של השכבה (סעיף 4). המודול: `layer-off` |
| 403 | `not-allowed` | ספק AI לא מותר למשתמש או לאפליקציה | הודעה למשתמש |
| 404 | `not_found` | הפריט לא קיים, **או** שאין גישה אליו. השגיאה זהה בכוונה | — |
| 409 | `conflict` | `if_rev` לא תואם. מוחזר גם ה-`rev` הנוכחי | להציע "שמור כעותק" |
| 409 | `name_taken` | שם תפוס, ונשלח `on_conflict: "fail"` | — |
| 413 | `too_large`, `too-big` | קובץ מעל התקרה, או קלט ל-AI גדול מדי | — |
| 413 | `quota_exceeded` | המכסה בכונן נגמרה. מוחזרים גם `quota` ו-`used` | הודעה למשתמש |
| 429 | `quota` | המכסה החודשית של AI נגמרה | הודעה למשתמש |
| 429 | `rate_limited` | מפתח קריאה: יותר מדי כישלונות | לחכות `Retry-After` שניות |
| 502 / 503 | `provider`, `no-provider` | ספק ה-AI נכשל, או שלא הוגדר ספק | "לא זמין — דרך הצ'אט (סקיל)" |
| 500 | `server` | תקלה בענן. הפרטים ביומן השרת | לנסות שוב מאוחר יותר |

**קודים ישנים עם מקף** (`no-provider`, `not-allowed`, `too-big`) נשארים כמו שהם בגלל אפליקציות קיימות. קוד חדש
נכתב תמיד עם קו תחתון.
