# ענן החבילה — ספריית הגופנים (אפיון, טיוטה לחברי הצוות)

**בעלים:** הצ'אט של ענן החבילה. **מקור:** `creative-suite/docs/spec/shared.md` סעיפים 4–5, הכרעה 7 (גופן שמשתמש
מעלה מוטמע, והאחריות לרישיון עליו). **ביקש:** בעל המערכת, דרך סטודיו העיצוב (2026-10-30): "להעלות את הפונטים שלי —
באזור אחד שמתאים לכל האפליקציות".

> סטטוס (2026-11-01): **נבנה** — גופנים שהמשתמש מעלה (2026-10-31), והגופנים המובנים (2026-11-01, סעיף 2.1).

---

## 1. מה זה

ספרייה אחת לכל חשבון, ובהמשך גם לכל צוות. מעלים גופן פעם אחת בדף של הענן, והוא מופיע בבורר הגופנים של כל אפליקציה
מחוברת, בקבוצה "שלי".

## 2. הפריט

```json
{ "id": "fnt_k3…", "kind": "font", "family": "Rubik", "weight": 700, "style": "normal",
  "format": "woff2", "size": 41230, "rev": "<sha256 של הקובץ>", "source": "user",
  "name": "Rubik Bold", "license_ack": true, "updated_at": "…",
  "url": "api.php?action=font_file&id=fnt_k3…&rev=<sha256>" }
```

- **פריט = קובץ אחד = משקל וסגנון אחד.** משפחה היא קיבוץ לפי `family`, לא פריט בפני עצמו. כך "Rubik" עם ארבעה משקלים
  מגיע כארבעה פריטים, ובורר הגופנים מקבץ אותם.
- **`rev`** — הגיבוב של הקובץ. גופן שהוחלף מקבל `rev` חדש, וזה מה שמפעיל את "עודכן בספרייה — לעדכן?" (`shared.md`
  סעיף 5).
- **`format`** — כמו שהועלה: `ttf` / `otf` / `woff2` / `woff`. ‏`FontFace` בדפדפן קורא את כולם. **אין המרה בשרת:** ב-PHP
  שלנו אין brotli, ולכן הענן לא ממיר ל-woff2. מי שרוצה קובץ קטן מעלה woff2.
- **`source`** — `user` (שהמשתמש העלה) או `builtin` (הגופנים החופשיים, OFL, שהיום מפוזרים בכל אפליקציה; יגיעו בהמשך).

### 2.1 המובנים (`source: builtin`)

- **10 קבצים, 9 משפחות, OFL:** Rubik, Heebo, Assistant, Frank Ruhl Libre, Noto Serif Hebrew (משתנים), Amatic SC, David
  Libre (רגיל ומודגש), Secular One. קבצי TTF שלמים (לא תת-קבוצה) — מתאימים גם להטמעה ב-PDF ול-HarfBuzz.
- **איפה:** `suite-cloud/fonts/builtin/` בגיט, עם `OFL-<משפחה>.txt` לכל אחד. הקטלוג `catalog.json` נבנה מהקבצים
  (`php suite-cloud/tools/fonts-catalog.php`), ושער בפריסה עוצר קטלוג לא מעודכן או גופן בלי רישיון.
- **הפריט:** כמו של המשתמש, ועוד `license` (שם קובץ הרישיון) ו-`axes` לגופן משתנה (`{"wght": [300, 900]}`; `weight` הוא
  ברירת המחדל, 400). מזהה יציב: `b_<משפחה>-<משקל>` או `b_<משפחה>-var`.
- **לא נוגעים באפליקציות:** `fonts_list` בלי `builtin=1` מחזיר רק את של המשתמש, כמו קודם. עם `builtin=1` (ב-JS:
  `drives.fonts.list({ builtin: true })`) — גם המובנים, בקבוצות משלהם (`families[].source`).
- **לא משתנים ולא נמחקים** (`builtin`, 403), ולא נספרים במכסה. `font_license?id=` מחזיר את טקסט הרישיון.
- **עוד לא:** Alef, Karantina, Suez One ו-Varela Round — בריפו יש רק תת-קבוצות woff2 (בכרטיסי ברכה), לא קבצים שלמים.

## 3. הקריאה של הפרטים מהקובץ

- **ttf / otf** — השרת קורא את טבלאות `name` (משפחה, תת-משפחה) ו-`OS/2` (משקל, נטוי). המשתמש לא ממלא כלום.
- **woff / woff2** — הקובץ דחוס, ולכן הדפדפן קורא ושולח את `family`, `weight` ו-`style` (בלקוח הענן — `FontFace` +
  קריאת הטבלאות). כשאין — לפי שם הקובץ, והמשתמש מתקן בדף.
- **אותה משפחה, משקל וסגנון כבר קיימים** → מחליפים את הקובץ: אותו `id`, `rev` חדש. לא נוצר כפיל.
- **בהעלאה מוצגת אזהרה אחת** (הכרעה 7, ו-`shared.md` סעיף 9.3): "ודא שהרישיון מתיר הטמעה". לא חוסמים, ונשמר
  `license_ack`.
- **מכסה:** הגופנים נספרים במכסת הכונן הפנימי. תקרה לגופן: 20MB (גופן עברי מלא הוא בדרך כלל 50–500KB).

## 4. ה-API

כל הפעולות ב-`suite-cloud/api.php`. לאפליקציה מחוברת נדרשת ההרשאה `libs` (`spec-1-skeleton.md` סעיף 7).

| פעולה | גוף | תשובה |
| --- | --- | --- |
| `fonts_list` | `?builtin=1` — גם המובנים | `{fonts:[פריט], families:[{family, source, items:[id]}]}` |
| `font_license` | `GET ?id=b_…` | טקסט ה-OFL של גופן מובנה |
| `font_add` | `{content_b64, filename, family?, weight?, style?, license_ack:true}` — עד 20MB | פריט (`replaced: true` אם הוחלף) |
| `font_file` | `GET ?id=…&rev=…` | הקובץ עצמו, עם `Cache-Control: immutable` (לפי `rev`) ו-CORS ל-origins של הלקוח |
| `font_update` | `{id, family?, weight?, style?}` — תיקון פרטים | פריט |
| `font_delete` | `{id}` | `{ok:true}`. קבצים שכבר הטמיעו את הגופן לא נפגעים, כי יש להם עותק |

**בלקוח הענן (JS):** `cloud.fonts.list()`, `cloud.fonts.load(item)` (מוסיף `FontFace` לדף ומחזיר את ה-bytes להטמעה),
`cloud.fonts.add(file)`.

## 5. בתוך `.mbe` — קישור + עותק

```json
"fonts": [ { "family": "Rubik", "weight": 700, "embedded": "media/<sha256>.woff2", "source": "user",
             "lib": { "cloud": "<cloud_id>", "item": "fnt_k3…", "rev": "<sha256>" } } ]
```

התוכן תמיד בקובץ; `lib` רק אומר מאיפה הגופן הגיע. בלי ענן, או בענן של מישהו אחר — הקובץ נפתח מהעותק.

## 6. הסדר

עודכן 2026-10-31: שכבת ה-AI (`spec-3-ai.md`) נכנסה לפני הגופנים, כי היא חוסמת את מ4 של סטודיו העיצוב. שתיהן צריכות
קודם חיבור אפליקציה.

1. **חיבור אפליקציה** (`connect` + אסימון).
2. **שכבת ה-AI ולקוח הענן.**
3. **ספריית הגופנים בענן:** הדף (העלאה, רשימה לפי משפחה, תצוגה מקדימה בעברית, מחיקה), ה-API, ו-`cloud.fonts`
   בלקוח. מכאן אפליקציה (הראשונה: סטודיו העיצוב) מציגה "שלי" בבורר.

הגופנים עדיין קודמים לצבעים, לסגנונות ולשאר הספריות.

## 7. לפני הענן — העלאה מקומית באפליקציה

אפליקציה שמעלה גופן מקומית לפני שהענן מוכן (IndexedDB + הטמעה בקובץ) **לא מפריעה:** הגופן מוטמע בלי `lib`, כמו
כל גופן שאינו מהענן. כשיש חיבור — "שמור לספרייה" שולח אותו ב-`font_add` ומוסיף `lib`. כדאי לשמור בצד המקומי את
הקובץ המקורי (לא רק תת-קבוצה), כדי שאפשר יהיה להעביר אותו לענן שלם.
