# 02 — טופס חכם: מסלול לכל תיק, מקור לכל בדיקה, יומן התיק

תלויה ב-: 01. דרישה: D6. הארכיטקטורה: `00-overview.md` §3.5, §3.7.

## 1. המטרה

הבעלים: "זה נראה כאילו כולם תקינים למרות שיש מלא תקלות […] צריך מסלול קל וברור מה צריך להשלים ומה חסר."
פתיחת תיק עונה מיד על שתי שאלות: **מה הבא בתור**, ו**מי אמר שזה בסדר**.

## 2. מה בונים

**לא משנים את רשימת הבדיקות, את השדות או את הסטטוסים** — הם של הבעלים. מוסיפים רק מטא-נתונים ותצוגה.

1. **מקור ושעה לכל בדיקה:** ב-`checks.<key>` נוספים `by` (שם), `via` (`ui` / `field` / `dropbox` / `api` / `ai` /
   `import`) ו-`at`. נכתבים בשרת בלבד, מהבקשה — לא מהקלט. בדיקה קיימת בלי מקור מוצגת "מייבוא ישן".
2. **"הבא בתור":** בראש התיק — הבדיקה הראשונה לפי סדר הקבוצות הקיים (חסר/לא קריא ← לאימות ← טרם נבדק), עם כפתור
   הפעולה שלה. כשאין — "התיק הושלם ✓".
3. **"הושלם" רק באדם:** מעבר ל-`verified` / `reported` / `not_applicable` מותר ב-`via: ui`, `field` ו-`import`
   (הייבוא הקיים — הבעלים מייבא נתונים שבדק, ולא משנים לו את זה). מקור אוטומטי (`dropbox`, `api`, `ai`) שמנסה לכתוב
   סטטוס כזה — נשמר כ-`document_present` ("לאימות"), והערך שהציע נשמר ב-`note`. (הכרעה ה7.) הכלל בפונקציה אחת
   (`finalAllowed($via)`), כדי ש-05 ו-06 יקבלו אותו בלי קוד נוסף. ייבוא של שדה שסומן ידנית (`manual_fields`) — לא
   דורס, כמו היום.
4. **רשימת התיקים לא משקרת:** תיק בלי אף בדיקה מאומתת לא מוצג "תקין" — מוצג "טרם נבדק" עם מספר הבדיקות הפתוחות.
   סינון מהיר: "חסר", "לאימות", "הושלם".
5. **יומן התיק:** לשונית "היסטוריה" בתיק, מ-`events`: מתי, מי, מאיזה מקור, מה השתנה (לפני ← אחרי), 50 אחרונים.
6. **ההערות:** שדה ההערות של התיק נפתח במלואו (לא חלון קטן), וכל בדיקה מציגה את ההערה שלה בלי לחיצה.

## 3. מה לא בונים כאן

קבצים ותצוגה מקדימה (03), העלאה מהשטח (04), זיהוי סוג מסמך ב-AI (06).
