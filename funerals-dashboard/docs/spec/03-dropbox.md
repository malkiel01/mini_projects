# 03 — Dropbox דו-כיווני: חיבור, תיקיות, webhook ו-cursor, תצוגה מקדימה

תלויה ב-: 01. דרישות: D2, D8. שאלות: ש1 (ברירת מחדל: חיבור לארגון), ש2 (ברירת מחדל: תיקייה ראשית ← חודש ← תיק).
הארכיטקטורה: `00-overview.md` §3.2, §3.6; הכרעה ה2.

## 1. המטרה

קובץ שמועלה באפליקציה נמצא בתיקיית התיק ב-Dropbox, וקובץ שנוסף לתיקייה ב-Dropbox מופיע בתיק — עם תצוגה מקדימה
בתוך האפליקציה.

## 2. מה הבעלים עושה פעם אחת (מטלה)

1. ב-Dropbox App Console: אפליקציה חדשה, **Full Dropbox**, הרשאות `files.metadata.read`, `files.content.read`,
   `files.content.write`, `account_info.read`.
2. Redirect URI: `https://mbe-plus.com/mini_projects/funerals-dashboard/api.php?action=dropbox_callback`.
3. Webhook URI: `https://mbe-plus.com/mini_projects/funerals-dashboard/dropbox-webhook.php`.
4. במסך המפתח של האפליקציה ← "Dropbox": להדביק App key ו-App secret. נשמרים מוצפנים (`secrets`). **לא ב-Settings
   של GitHub ולא בקוד.**

## 3. מה בונים

### 3.1 החיבור (מנהל ארגון)

1. ⚙️ הגדרות ← Dropbox ← "חיבור": OAuth 2 עם PKCE ו-`token_access_type=offline`; `state` חד-פעמי ב-session, קשור
   לארגון ולמשתמש. בחזרה — אסימון הרענון נשמר מוצפן לארגון, עם `account_id` ושם החשבון.
2. **בחירת תיקייה ראשית:** דפדוף בתיקיות החשבון (רק תיקיות), ובחירה. נשמרים ה-`id` והנתיב. **כל פעולה של האפליקציה
   מוגבלת לתיקייה הזו ולמה שבתוכה** — נתיב מחוצה לה נדחה בקוד, גם אם הגיע מבקשה.
3. ניתוק: מוחק את האסימון (ו-`/2/auth/token/revoke`). הקבצים ב-Dropbox לא נוגעים. רשימות הקבצים בתיקים נשארות,
   מסומנות "Dropbox מנותק".
4. אסימון גישה נשמר בזיכרון הבקשה בלבד; מתחדש מאסימון הרענון כשפג. רענון שנכשל (`invalid_grant`) → הארגון
   מסומן "צריך לחבר מחדש", הודעה למנהל, ושום פעולה לא נופלת בשקט.

### 3.2 תיקייה לכל תיק

1. **תיק חדש או תיק בלי תיקייה:** כפתור "פתיחת תיקייה" (וגם אוטומטית בהעלאה הראשונה) יוצר
   `<ראשית>/YYYY-MM/YYYY-MM-DD <שם>/` (תווים אסורים מוחלפים ב-`_`; כפילות → ` (2)`). נשמרים `dbx_folder_id` ו-
   `dbx_path` בתיק.
2. **חיבור תיקיות קיימות (ל-22 התיקים):** "סריקת התאמה" עוברת על תת-התיקיות של הראשית, ומציעה תיק לכל תיקייה לפי
   תאריך ושם (התאמה מלאה של השם אחרי ניקוי רווחים וניקוד). ההצעות מוצגות למנהל לאישור — **שום חיבור לא נעשה לבד**.
   תיקייה שלא הותאמה — "לא משויכת", עם בחירת תיק ידנית.
3. שינוי שם / העברה של התיקייה ב-Dropbox — הקישור נשמר לפי `id`, והנתיב מתעדכן בסנכרון.

### 3.3 מ-Dropbox לאפליקציה

1. **`dropbox-webhook.php`** (ב-`"public"`):
   - `GET ?challenge=X` → `X` כ-`text/plain`, עם `X-Content-Type-Options: nosniff`.
   - `POST` → בודק `X-Dropbox-Signature` (HMAC-SHA256 של הגוף ב-App secret, `hash_equals`). לא תקין → 403.
     תקין → מסמן `sync_pending` לארגונים של `account_id`-ים שבגוף, עונה 200 **מיד**, ואז (אחרי
     `fastcgi_finish_request` כשקיים) מריץ סנכרון — עד 8 שניות לארגון.
2. **סנכרון:** `list_folder` רקורסיבי על הראשית בפעם הראשונה (`cursor` נשמר לארגון), ואחר כך `list_folder/continue`
   עד `has_more: false`. כל קובץ בתוך תיקייה של תיק → שורה ב-`files` (ראו 3.5); `deleted` → מסומן נמחק (לא נמחק
   מהמסד). נעילה לכל ארגון (`BEGIN IMMEDIATE` על שורת הסנכרון) — שני סנכרונים במקביל לא כותבים פעמיים.
   `reset` מ-Dropbox → מתחילים מחדש בלי לשכפל.
3. **גיבוי ל-webhook:** פתיחת רשימה או תיק, כשהסנכרון האחרון של הארגון ישן מ-2 דקות → סנכרון (עד 5 שניות), והשאר
   ממשיך בפעם הבאה.
4. קובץ חדש שנכנס לתיק נרשם ב-`events` (`source: system`, `via: dropbox`). **הוא לא משנה סטטוס בדיקה בפרוסה הזו**
   — רק מופיע ברשימת הקבצים (שיוך לבדיקה — 04 ו-06).

### 3.4 מהאפליקציה ל-Dropbox

1. העלאה מהתיק (משרד, מנהל; שטח — 04): הקובץ עובר בשרת ל-`/2/files/upload` (עד 8MB), ומעל — ב-upload session בחלקים
   של 8MB. `mode: add`, `autorename: true`. גבול: 50MB לקובץ. סוגים: תמונה, PDF, מסמכי Office.
2. הקובץ נרשם מיד ב-`files` מתשובת Dropbox, כך שהוא מופיע בלי לחכות ל-webhook; הסנכרון שאחריו לא מכפיל (לפי `id`).
3. **בלי עותק קבוע בשרת:** הקובץ הזמני נמחק בסוף הבקשה, גם בכישלון.

### 3.5 טבלת `files` ותצוגה מקדימה

1. `files`: `org_id`, `case_id`, `dbx_id` (ייחודי), `path`, `name`, `size`, `rev`, `server_modified`, `deleted`, `added_via`
   (`dropbox` / `ui` / `field`), `added_by`, `kind` (סוג מסמך, ריק עד שמישהו בוחר).
2. בתיק: רשימת קבצים עם תמונה ממוזערת, שם, תאריך, ומי הוסיף. לחיצה → תצוגה בתוך האפליקציה:
   - תמונה: `get_thumbnail_v2` (גודל `w1024h768`) דרך `api.php?action=file_view`.
   - PDF ומסמכים: `get_preview` (PDF) דרך אותה כתובת.
   - "פתיחה ב-Dropbox" — קישור לנתיב בחשבון (לא קישור שיתוף).
3. `file_view` בודק הרשאה לתיק בכל בקשה; מטמון תמונות ממוזערות ב-`data/cache/thumbs/` (עד 200MB, הישן נמחק ראשון).
   כותרות: `Cache-Control: private`, ובלי `Content-Disposition` שמאפשר להריץ קוד (SVG ו-HTML — הורדה בלבד).
4. הקישורים הישנים (`folder_url`, `documents[].url`) נשארים ומוצגים כמו היום.

### 3.6 מסך המפתח

שורת "Dropbox" בבדיקות התקינות: App key מוגדר, לכל ארגון — מחובר / צריך חיבור מחדש, הסנכרון האחרון, webhook אחרון
שהתקבל, ושגיאה אחרונה.

## 4. מה לא בונים כאן

מסך עובד שטח וצילום (04), שיוך קובץ לבדיקה באופן אוטומטי (06), חיבור Dropbox אישי לכל עובד (ש1-ב').
