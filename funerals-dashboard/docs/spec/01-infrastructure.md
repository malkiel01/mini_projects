# 01 — תשתית: ארגונים, משתמשים והרשאות, חשבון מפתח, DevLoop

תלויה ב-: —. דרישות: D1, D3 (`owner-brief.md`). שאלה: ש3 (ברירת מחדל א' — כניסה דרך השער).
הארכיטקטורה: `00-overview.md` §3.1, §3.6, §3.7, §3.8.

## 1. המטרה

אחרי הפרוסה הזו האפליקציה יודעת **מי המשתמש, לאיזה ארגון הוא שייך ומה מותר לו** — ו-22 התיקים שבשרת יושבים בארגון
הראשון, כמו שהם. אין עדיין Dropbox, AI או API חדש: רק הבסיס שכולם נשענים עליו.

## 2. מה בונים

### 2.1 מסד: מיגרציה שמוסיפה בלבד

1. **גרסת סכמה** ב-`PRAGMA user_version`. היום 0. הפרוסה מעלה ל-1.
2. **לפני** כל קפיצת גרסה: עותק של המסד ל-`data/backup/funerals-<YYYYMMDD-HHMMSS>-v<from>.sqlite`
   (`VACUUM INTO`), 0600. נכשל הגיבוי → אין מיגרציה, והאפליקציה עונה 503 עם הודעה ברורה.
3. המיגרציה רצה בטרנזקציה אחת, ו**אידמפוטנטית** (ריצה שנייה לא משנה דבר).
4. טבלאות חדשות:

| טבלה | שדות עיקריים |
| --- | --- |
| `orgs` | `id`, `name`, `created_at`, `settings` (JSON) |
| `users` | `id`, `sub` (ייחודי), `email` (ייחודי, באותיות קטנות), `name`, `created_at`, `last_seen_at`, `active` |
| `members` | `org_id`, `user_id`, `role` (`admin` / `office` / `field`), `created_at`, `created_by` — מפתח: (`org_id`,`user_id`) |
| `invites` | `org_id`, `email`, `role`, `created_by`, `created_at`, `used_at` |
| `events` | `id` רץ, `org_id`, `case_id`, `at`, `actor_user_id`, `actor`, `source` (`ui` / `import` / `api` / `system`), `action`, `diff` (JSON) |
| `req_log` | `at`, `method`, `action`, `status`, `ms`, `user_id`, `error` — 1,000 שורות אחרונות בלבד |
| `secrets` | `name`, `org_id`, `value_enc`, `updated_at` — מוכן ל-03/05/06, ריק בפרוסה הזו |

5. `funerals` מקבלת `org_id INTEGER` (`ALTER TABLE … ADD COLUMN`). ארגון ראשון נוצר — **"חברה קדישא"** (`id=1`;
   המפתח משנה את השם במסך) — וכל תיק בלי `org_id` מקבל `1`. **שום שורה ב-`funerals` וב-`audit` לא נמחקת ולא
   משתנה מעבר לעמודה הזו.**
6. `audit` נשאר כמו שהוא (היסטוריה). מכאן כל שינוי נכתב ל-`events` דרך פונקציה אחת (`recordEvent()`).
7. `secret.key` — 32 בתים אקראיים ב-`data/secret.key` (0600), נוצר בבקשה הראשונה אם אין. פונקציות
   `secretPut()` / `secretGet()` (`sodium_crypto_secretbox`), עם בדיקה.

### 2.2 משתמשים וכניסה

לפי `platform/docs/sso.md` §0 ו-§4:

1. יש `PLATFORM_USER` עם `granted: true` → משתמש לפי `sub`; אין → לפי מייל (בלי תלות באותיות) ומקשרים; אין → משתמש
   חדש, פעיל. נרשם ב-`events` (`source: system`, `action: user_linked` / `user_created`).
2. **מזמינים, לא מאשרים:** משתמש חדש שיש לו הזמנה פתוחה במייל שלו → נהיה חבר בארגון ובתפקיד שבהזמנה, וההזמנה
   מסומנת `used_at`.
3. **מפתח** = `platform_admin: true` מהשער, בכל בקשה (לא נשמר כתפקיד). המפתח הראשון שנכנס אחרי המיגרציה נהיה
   גם `admin` של ארגון 1 — כך הבעלים לא ננעל מחוץ לתיקים שלו.
4. משתמש בלי ארגון ובלי הזמנה → מסך אחד: "עדיין לא שויכת לחברה קדישא. בקש ממנהל הארגון להזמין אותך במייל
   <המייל שלך>." בלי שום נתון.
5. משתמש עם כמה ארגונים → בורר ארגון בכותרת; הארגון הפעיל נשמר ב-session ונבדק מול `members` בכל בקשה.
6. `active = 0` → כמו "בלי ארגון", גם אם יש לו חברות.

### 2.3 הרשאות — בשכבה אחת

פונקציה אחת, `can(string $perm, ?array $case = null): bool`, ופונקציה אחת שמסננת שאילתות לארגון הפעיל
(`scope()`). כל נקודת קצה קוראת להן; אין בדיקת תפקיד מפוזרת.

| פעולה | שטח | משרד | מנהל | מפתח |
| --- | --- | --- | --- | --- |
| לראות תיקי הארגון | ✅ | ✅ | ✅ | ✅ כל הארגונים |
| לעדכן בדיקה / הערה / מיקום קבר | ✅ | ✅ | ✅ | ✅ |
| לשנות פרטי נפטר, תשלומים | — | ✅ | ✅ | ✅ |
| ייבוא, ייצוא | — | ✅ | ✅ | ✅ |
| להזמין, לשנות תפקיד, להשבית | — | — | ✅ (בארגון שלו) | ✅ |
| אסימון `ingest.php` | — | — | ✅ | ✅ |
| ליצור ארגון, לשנות שם ארגון | — | — | — | ✅ |
| מסך מפתח, DevLoop | — | — | — | ✅ |

ה-`ingest.php` הקיים ממשיך לעבוד **עם האסימון הקיים**, וכותב לארגון 1 (`source: import`).

### 2.4 מסכים

בעיצוב phone-first (הסקיל `phone-first-design`), בלי קישור "חזרה לכלים":

1. **הכותרת:** שם האפליקציה (D1), שם הארגון הפעיל (ובורר אם יש יותר מאחד), תפריט משתמש (שם, תפקיד, יציאה).
2. **⚙️ הגדרות ← חברים** (מנהל, מפתח): רשימת חברים עם תפקיד ופעיל/מושבת; "הזמנה במייל" + תפקיד; ביטול הזמנה.
   מנהל לא יכול להוריד את עצמו מ-`admin` אם הוא המנהל האחרון.
3. **⚙️ הגדרות ← ארגונים** (מפתח): רשימה, יצירה, שינוי שם, ומעבר לארגון.
4. **🛠️ מפתח** (מפתח בלבד):
   - **בדיקות תקינות:** מסד נפתח ונכתב; `data/` ו-`data/backup/` ניתנים לכתיבה; גרסת סכמה; גרסת האפליקציה;
     `secret.key` קיים ותקין (הצפנה ופענוח של ערך בדיקה); sodium ו-pdo_sqlite קיימים; הגיבוי האחרון ומתי.
     "חיבורים חיצוניים" — שורה לכל חיבור שעוד לא קיים ("Dropbox — פרוסה 03"), כך שהמקום מוכן.
   - **יומן בקשות ושגיאות** (`req_log`): 100 אחרונות, סינון "רק שגיאות".
   - **יומן פעולות** (`events`): 100 אחרונים, לכל הארגונים, עם מי/מקור/מה.
5. **DevLoop** — דרך המודול (`devloop/README.md`): קידומת `FD-`, אסימון `fdd_`, `items_file` = `dev/open-items.json`,
   `data_dir` = `data/dev`; 🐞 בכותרת למפתח בלבד; `is_developer` = `platform_admin`; `user_names` מ-`users`; `trace`
   — הבקשות והשגיאות האחרונות של הדפדפן. **הרישום ב-`devloop/apps.json` וב-`.devloop.json` — של הבקרה** (PROTOCOL
   §8); צ'אט הקוד מבקש אותו בהודעה, וכותב את קובץ החיבור בתוך התיקייה.
6. **מפת דרכים:** `dev/open-items.json` עם הפרוסות 02–07 (לדשבורד הפיתוח).
