# 02 — התיק

## איך נולד תיק (א2)

- **מ-Dropbox:** בתיקייה הראשית של הארגון נוספה תיקייה חדשה. הבינה מזהה שזו תיקיית נפטר: לפי המבנה, לפי השם, או לפי
  מסמך בתוכה. היא פותחת תיק וממלאת ממה שקראה: שם, תאריכים ות"ז.
- **מהאפליקציה:** משתמש פותח תיק, ונפתחת לו תיקייה ב-Dropbox בתבנית שהארגון הגדיר. ברירת המחדל: `חודש/תאריך שם`.
- **מניעת כפילות:** לפני שנפתח תיק, הבינה בודקת אם כבר יש תיק לאותו נפטר, לפי ת"ז, שם ותאריך. אם יש — היא מקשרת.
  אם יש ספק — היא שואלת.
- **התיקים הקיימים (22 של אוקטובר):** הבינה מקשרת כל אחד לתיקייה שלו. מה שלא בטוח — עולה כשאלה.

## הבדיקות (א6)

- **ברירת המחדל** (9): מסמך זיהוי נפטר, רישיון קבורה, מספר רישיון קבורה, מקור הזיהוי, אסמכתת תשלום, שירות בית
  ההספדים, רכישת קבר נוסף, זיהוי בן/בת זוג, דיווח לביטוח לאומי.
- **בהגדרות:** מוסיפים, משנים ומסירים בדיקות, ומשנים את הסדר שלהן. לכל בדיקה מגדירים:
  - **שם.**
  - **סוג:** מסמך, ערך (מספר, תאריך, טקסט) או כן/לא.
  - **סוגי המסמכים שעונים עליה**, שהבינה משתמשת בהם לזיהוי.
  - **תפקיד אחראי** (אופציונלי).
  - **חובה, או רק כשמתקיים תנאי** (למשל "זיהוי בן/בת זוג" רק כשיש רכישת קבר נוסף).
- הבדיקות מוגדרות פעם אחת אצל הבעלים, וארגון יכול לשנות אצלו. שינוי לא מוחק נתונים מתיקים קיימים.

## מצב של בדיקה

| מצב | מה זה אומר |
| --- | --- |
| חסר | אין מסמך או ערך |
| נמצא — ממתין לאישור | הבינה מצאה מסמך או ערך |
| ספק | הבינה לא בטוחה, ויש שאלה פתוחה |
| הושלם | אדם אישר (או כלל למידה שהוגדר כ"מאשר לבד") |
| לא רלוונטי | אדם סימן |

לכל בדיקה רואים **מקור** (Dropbox, בינה, ChatGPT, אדם), **מי ומתי**, ולחיצה פותחת את המסמך.

## סוף התיק (א13)

כשכל הבדיקות הושלמו או סומנו "לא רלוונטי", התיק עובר ל**ארכיון**. הוא יוצא מהמסך הראשי, נשאר בחיפוש, ואפשר להחזיר
אותו.

## היסטוריה

כל שינוי בתיק נרשם: מי עשה (אדם, בינה, ChatGPT), מתי ומה השתנה. זה גם הבסיס לעתיד (`07-future.md`).
