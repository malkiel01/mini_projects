# 00 — מבט-על: מה בונים, ואיך זה יושב בפלטפורמה

**המסמך המחייב:** `../owner-brief.md`. **חומר מקור:** `../legacy/SPEC.md` (רקע — לא החלטות מחייבות).
**האפיון של הבעלים** (`../legacy/owner-spec-<תאריך>.md`) **עוד לא הגיע.** כשיגיע הוא גובר על כל מה שכאן,
והמסמך הזה יעודכן. לכן כאן ננעל רק מה שנגזר מהכללים של mini_projects; כל השאר — ברירת מחדל שמסומנת.

## 1. מה בונים

אפליקציית ספרים יהודיים, בעברית, לטלפון קודם (SPEC §1):

| רכיב | מה |
| --- | --- |
| ספרים דיגיטליים | קריאה אונליין. ספר = קובץ HTML ארוך עם תגיות נסתרות שמחלקות אותו למקטעים |
| תכנים יומיים | הלכה יומית, חוק לישראל — מתחלפים לפי לוח עברי, חוזרים כל שנה |
| זמנים | זמני היום, לפי מיקום המכשיר או עיר שנבחרה |
| חנות | ספרים פיזיים — שלד בלבד; בלי תשלום, משלוח ומלאי |
| ניהול | הצוות מזין הכול: ספרים, תכנים יומיים, חנות |

מסך הבית: שישה כפתורים במרכז — סידור · תהילים · חנות ספרים · הלכה יומית · חוק לישראל · זמנים.

## 3. הארכיטקטורה

### 3.1 השרת 🟢 (⏳ ש1 על Laravel)

- **PHP 8.3 פשוט, בלי composer ובלי Node בשרת.** הפריסה היא rsync של קבצים, בלי `--delete` ובלי שלב התקנה.
- **מסד SQLite** בקובץ אחד: `sforno/data/sforno.sqlite`, עם מיגרציות אידמפוטנטיות שרצות לבד בבקשה הראשונה
  אחרי פריסה (פנקס בטבלת `meta`). **אין מיגרציה שמוחקת נתוני משתמשים.**
- **נתיב נתונים יחיד: `sforno/data/`.** כבר מוחרג ב-`deploy.yml` (`--exclude='/sforno/data/*'`) וחסום ב-
  `data/.htaccess`. נתיב נתונים חדש מחוץ לו — אסור; אם בכל זאת נדרש: `--exclude` ב-`deploy.yml` **לפני** הקוד.
- נתב API אחד (`api.php?action=…`), JSON בלבד, CSRF על כל פעולה משנה.

> **למה לא Laravel ולא MySQL (SPEC §2, §11.1):** שניהם דורשים צעדים בשרת (composer, `.env`, docroot ל-`public/`,
> משתמש מסד ידני ב-cPanel) שאין להם מקום בפריסה שלנו, ומקשים על המעבר לסאב-דומיין. SQLite עובר עם התיקייה.

### 3.2 הדפדפן 🟢

- `index.html` עם `lang="he" dir="rtl"`, JS ו-CSS בלי שלב בנייה, ניתוב ב-`#/…`.
- עיצוב — הסקיל `phone-first-design`, עם כחול `#2c5f8d` וזהב `#d4af37` כצבעי מותג (⏳ ש10).
- גופן — David Libre (OFL), **עותק** ב-`sforno/assets/fonts/` עם קובץ הרישיון (⏳ ש11).
- PWA: `manifest.webmanifest` ו-service worker (⏳ ש13) — בפרוסה של מסך הבית.

### 3.3 עצמאית — כדי לעבור לסאב-דומיין בהעתקה 🟢

זה המבחן של `owner-brief.md`, ולכן כל פרוסה נבדקת מולו:

1. **אין `require` / `include` לשום קובץ מחוץ ל-`sforno/`.** קוד שרוצים מהפלטפורמה (למשל הזיהוי ב-
   `document-templates/lib/platform.php`) — **קוראים ומעתיקים את הרעיון**, לא מצרפים.
2. **אין נתיב קבוע בקוד.** בסיס הכתובת (`/mini_projects/sforno/` היום, `/` בסאב-דומיין) נגזר בזמן ריצה
   מתיקיית הסקריפט. גם נתיב העוגייה. `grep -rn "mini_projects" sforno --include=*.php --include=*.js` — ריק.
3. **אין קישור "חזרה לכלים"**, אין `../index.html`, אין `../` שיוצא מהתיקייה בשום HTML או JS.
4. **עוגייה משלה** (`sf_session`), משתמשים משלה ומסד משלה.
5. כתובת הפלטפורמה (ל-`sso.php?action=config`) — נבנית מ-`SERVER_NAME` ומהגדרה אחת ב-`data/`, כך שבסאב-דומיין
   משנים ערך אחד.

### 3.4 התחברות — לפי `platform/docs/auth.md` 🟢

**שני סוגי אנשים, שלא מתערבבים (⏳ ש2):**

| מי | בפרוסות הקרובות |
| --- | --- |
| **צוות** — מפתח, מנהל, עורך תוכן | נכנס דרך הפלטפורמה: `$_SERVER['PLATFORM_USER']` מהשער. חשבון באפליקציה מקושר ל-`sub`. פרוסה 01 |
| **קורא** — הציבור | עד ההשקה — אין. הכול `restricted`. כשתגיע תשובה לש2 — פרוסה 07 |

- `app.json` נשאר `"gate": true` ו-`"restricted": true` עד פרוסת ההשקה. אף כתובת לא ב-`"public"` לפני כן, חוץ
  מאלה שמכונה חייבת (`devapi-*`, `health`) — ומפורטות בפרוסה.
- **המפתח** = מי ש-`platform_admin` שלו `true` בזהות. מתעדכן בכל כניסה; אין דרך להפוך למפתח מתוך האפליקציה.
- **ממשק הניהול** — `#/admin` באותה אפליקציה, מאחורי השער ובדיקת תפקיד. בלי כתובת סודית ובלי `DEV_MODE`
  (⏳ ש3).
- **בסאב-דומיין** השער לא עובד, ולכן שם ספורנו **מנותקת** (`auth.md` §2): הצוות נכנס ב"כניסה עם הכלים
  הדיגיטליים" (`sso.php`). פרוסה 01 בונה מחוברת בלבד, אבל **מבודדת את קריאת הזהות בפונקציה אחת** כדי שהמנותקת
  תתווסף בלי לגעת בשאר. המעבר עצמו — פרוסה 10, רק כשהבעלים יאמר (⏳ ש15).

### 3.5 ענן MBE ותוספים (app-rules §8) — ⏳ ש4

**לא צריך, בשלב הזה.** כל הנתונים במסד של ספורנו. אין `appdata` (הקוראים אינם משתמשי פלטפורמה), אין ספריית
הגופנים של הענן (עותק מקומי), אין תוסף תשלומים (החנות והתשלום נדחו). כשהתשלום יגיע — דרך תוסף התשלומים
(`payments/`), בבקשות חתומות, לא מנגנון משלנו.

### 3.6 חשבון המפתח (`PROTOCOL.md` §7) 🟢

DevLoop מהמודול המשותף (קידומת `SF-`, אסימון `sfd_`), יומן בקשות ושגיאות, יומן פעולות, בדיקות תקינות, ניהול
צוות, ומפת דרכים ב-`dev/open-items.json`. כולם בפרוסה 01.

## 4. החלטות מ-SPEC שנשארות 🟢

| מ-SPEC | ההחלטה |
| --- | --- |
| §3, §11.2 | `anchor` (נקודת עוגן של המנהל, חלק מהספר) נפרד מ-`bookmark` (של הקורא) — בשם, בסכימה ובממשק |
| §11.3 | הקורא מציג מקטע אחד; מעבר בין מקטעים דרך נקודות הציון. מיקום קריאה = מזהה מקטע + מיקום יחסי, לא פיקסלים |
| §11.4 | זמנים: הקורא בוחר מיקום מכשיר או עיר; סירוב להרשאה → העיר שנבחרה |
| §11.5 | אין paywall. ספר לא-חינמי — ה-API לא מחזיר את התוכן שלו בכלל; הקורא רואה "טרם זמין" |
| §11.7 | תכנים יומיים לפי (חודש עברי, יום), חוזרים כל שנה. אדר א' ואדר ב' — חודשים נפרדים (⏳ ש6 על אדר של פשוטה) |
| §11.8 | תאריך בלי תוכן → האחרון שקיים לפניו (עם גלישה אחורה מעבר לראש השנה), עם ציון התאריך שלו |
| §8 | חנות — שלד בלבד |
| §11.6 | ממצאי הקוד הישן (פירסור ב-regex, `innerHTML` בחיפוש, `color` בלי אימות, `<section>` תקנית) — **לא חוזרים**: הפרוסות של הספרים והקורא קובעות פירסור ב-DOMParser ורשימת עיצובים מותרת |

**מה מ-SPEC בוטל, ולמה:** Laravel ו-MySQL (3.1); הכתובת הסודית ו-`DEV_MODE` (3.4); `config/config.php` ידני
בשרת (המסד נוצר לבד); ריפו ופריסה נפרדים (`owner-brief.md` §2.1); Sanctum (§11.6 ממצא 8 — לא רלוונטי).
