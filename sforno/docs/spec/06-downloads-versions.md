# 06 — הורדות וגרסאות, ו-PWA

**תלויה ב:** 04, 05. **מקור:** §2 (PWA), §15, §14 (מיקום לפי גרסה). **קבלה מ-§21:** 6, 7.

## 1. מה בונים

1. **PWA:** `manifest.webmanifest`, service worker, התקנה. התקנה ≠ הורדת תוכן (§15).
2. **הורדה מפורשת בלבד** (§15) — לכל כותר/מהדורה, ולזמנים (07). שום דבר לא יורד מעצמו חוץ ממעטפת האפליקציה.
3. **מסך הורדות:** גודל, התקדמות, גרסה, תאריך, מחיקה, שגיאה. הורדה חלקית — "לא הושלמה", לא "זמין" (§21.6).
4. **בחירת גרסה** אצל המשתמש: פרסום חדש לא מחליף לו (§21.7); "יש גרסה חדשה — לעבור?".
5. **מעבר גרסה** עם התאמת מידע אישי לפי `sid`.
6. **עדכון תוכנה נפרד מעדכון תוכן** (§15).

## 2. איך ⚙️

- **מעטפת:** ה-service worker שומר את קובצי האפליקציה בגרסה (`version` מ-`app.json`). גרסה חדשה ← "עדכון זמין — לרענן",
  לא החלפה באמצע תפילה. עדכון תוכנה לא נוגע ב-IndexedDB של המידע האישי (§15).
- **תוכן:** חבילה לכל (מהדורה, revision): `source_html` + נכסים + `manifest` עם hash לכל קובץ. נשמרת ב-Cache API / IndexedDB.
  "זמין" רק כשכל ה-hash-ים אומתו.
- `navigator.storage.persist()` בבקשה הראשונה להורדה; אם נדחה — אומרים שהדפדפן עלול למחוק.
- **גרסה נבחרת** = פריט `pref` (05) לכל מהדורה. גם קריאה **מקוונת** מבקשת את ה-revision הנבחרת (§15).
- **בשרת:** revision שיש לה משתמשים פעילים או הערות — לא נמחקת (§15). (ספירה לפי ה-`ref` בפריטים האישיים.)

## 3. מעבר גרסה (§15)

לכל פריט אישי שמצביע ל-revision הישנה: `sid` קיים בחדשה ← מועבר; לא קיים ← נשאר צמוד לישנה ומוצג ברשימה "לא הותאמו", עם
הטקסט המקורי. **שום דבר לא נמחק בשקט.** אפשר לחזור לגרסה הקודמת כל עוד היא בשרת.

## 4. מחיקה

"מחיקת הורדה" מוחקת את החבילה מהמכשיר בלבד; הסימניות, ההערות וההגדרות נשארות (§15: "מחיקת הורדה אינה מחיקת ספרייה
אישית"). שתי פעולות נפרדות בממשק, בשמות שונים.
