# ספורנו — שחזור מגיבוי, צעד אחר צעד

אפיון 10 §4 (§19). קריטריון 👁 5: שחזור ידני לפי המסמך הזה **בסביבת הבדיקה** (mini_projects) — מצליח.

## מה יש בגיבוי

קובץ `sforno-<תאריך>-<שעה>-<מזהה>.zip` ב-`sforno/data/backups/` (חסום מהדפדפן, מחוץ לגיט, מחוץ לפריסה). בתוכו:

| רכיב | מה זה | בלעדיו |
| --- | --- | --- |
| `sforno.sqlite` | המסד (עותק עקבי, `VACUUM INTO`) | אין כלום |
| `secret.key` | מפתח ההצפנה | **ההערות ושמות התפילה לא מתפענחים לעולם** |
| `vapid.json` | מפתחות ה-Push | כל המנויים להתראות צריכים להירשם מחדש |
| `woo.json` | הכתובת והמפתחות של החנות | צריך להזין שוב במסך המפתח |
| `cron.token` | האסימון של המתזמן | הפקודה ב-cPanel צריכה להתעדכן |
| `db.json` | רק אם המסד עבר ל-MySQL | — |
| `sources/` | קובצי הייבוא (Word / PDF / תמונות) | התמונות בתוכן לא יוצגו |
| `_dev/` | קבצים שצורפו למטלות DevLoop | הצילומים במטלות |
| `manifest.json` | ספירות לפי טבלה ו-sha256 לכל רכיב | — |

גיבוי נוצר כל לילה (משימת הרקע `ops.backup`), נשמר 30 יום (האחרון — תמיד). בדיקת שחזור — פעם בחודש לבד, ובכל רגע מ-💾.

## 0. לפני הכול — האם צריך לשחזר?

מסך הפיתוח ← 🩺 **בדיקות**. "המסד — בדיקת השלמות נכשלה" או נתונים שנמחקו בטעות — כן. תקלה אחרת — לא; שחזור מחזיר את כל
המערכת לרגע הגיבוי, וכל מה שנעשה אחריו (קוראים שנרשמו, הערות, דיווחים) **הולך לאיבוד**.

## 1. לבחור גיבוי ולבדוק אותו

מסך הפיתוח ← 💾 **גיבויים** ← בגיבוי הרצוי: **"בדיקת שחזור"**. צריך לקבל ✓ בכל השורות (sha256, integrity_check, ספירות,
המפתח). ✗ — לבחור גיבוי קודם.

## 2. גיבוי בטיחות של המצב הנוכחי

💾 ← **"גיבוי עכשיו"**, ואז **"הורדה"** — למחשב. אם השחזור ישתבש, זה מה שמחזירים.

## 3. לעצור את המתזמן

cPanel ← **Cron Jobs** ← בשורה של ספורנו: להוסיף `#` בתחילת הפקודה (או למחוק זמנית). כך אף משימה לא כותבת למסד באמצע.

## 4. השחזור — אחת משתי הדרכים

### דרך א׳ — Terminal ב-cPanel (מומלץ)

```bash
cd ~/public_html/mini_projects        # התיקייה של הריפו בשרת
php sforno/tools/backup.php list                       # הגיבויים, עם ה-pid
php sforno/tools/backup.php verify <pid>               # בדיקה (כמו שלב 1)
php sforno/tools/backup.php apply <pid> --yes          # השחזור
```

`apply` עושה לבד: גיבוי בטיחות נוסף (`pre-restore`), חילוץ לתיקייה זמנית ובדיקה, ורק אז החלפה. **שום דבר לא נמחק:** מה
שהוחלף עובר ל-`sforno/data/.replaced-<זמן>/`. בלי pid — הגיבוי האחרון.

### דרך ב׳ — מנהל הקבצים של cPanel (בלי Terminal)

1. 💾 ← **"הורדה"** של הגיבוי הרצוי, ולפתוח את ה-zip במחשב.
2. מנהל הקבצים ← `sforno/data/` ← ליצור תיקייה `.replaced-<היום>` ולהעביר אליה: `sforno.sqlite`, `sforno.sqlite-wal`,
   `sforno.sqlite-shm` (אם קיימים), `secret.key`, `vapid.json`, `woo.json`, `cron.token`, ואת התיקייה `sources/`.
3. להעלות ל-`sforno/data/` את כל מה שב-zip **חוץ מ-`manifest.json`**, באותם שמות (את `sources/` ו-`_dev/` — כתיקיות).
4. הרשאות: הקבצים — 600, התיקיות — 700 (קליק ימני ← Change Permissions).

## 5. לוודא

1. לפתוח את ספורנו. מסך הפיתוח ← 🩺 **בדיקות** ← הרצה: **"המסד"** ו-**"גרסת הסכימה"** ✅. אם הגיבוי מגרסה ישנה יותר,
   המיגרציות החסרות רצות לבד בבקשה הראשונה.
2. קורא עם הערה (חשבון בדיקה): ההערה מוצגת — המפתח שוחזר נכון.
3. 💾 ← **"בדיקת שחזור"** על הגיבוי האחרון — ✓.

## 6. להחזיר את המתזמן

cPanel ← Cron Jobs ← להסיר את ה-`#`. אחרי 10 דקות — 🩺 "המתזמן" ✅.

## 7. ניקוי

כשהכול עובד שבוע — אפשר למחוק את `sforno/data/.replaced-<זמן>/` ואת קובץ ה-zip שבמחשב. לא לפני.
